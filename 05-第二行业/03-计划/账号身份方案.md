## 一、先明确分工：三者不要重复

新手最常见的错误是三件套说的是同一件事，浪费了三个曝光位。

| 元素 | 它负责什么 | 判据 |
|---|---|---|
| **头像** | 立**形象**——一眼看到"是谁" | 缩到 **96px** 还能辨出主体 |
| **昵称** | 立**定位**——一秒知道"拍什么" | **搜得到** + **念得出** |
| **简介** | 立**理由**——凭什么关注你 | 一句话说清，不喊口号 |

## 三、昵称：4 条判据 + 候选

### 3.1 ⚠️ 前提：搜索的包袱不该由昵称来背

**如果把"可搜性"放在最高权重，所有候选都会长成"身份词 + 品类词"的模板 —— 而这正是撞名的根源**（「程序员小厨」就是这么撞上的）。

**正确做法：三个位置各司其职。**

| 位置 | 它负责 | 具体手段 |
|---|---|---|
| **昵称** | **被记住** | 双关 / 画面 / 悬念 |
| **简介** | **被搜到** | 身份词 + 品类词 + 地域（"福州 · 程序员 · 做饭"） |
| **标题 + 口播** | **被推荐** | 内容关键词（平台的内容标签主要看这里） |

→ **结论：昵称不必背搜索的包袱，可以放开手脚追求记忆点。** 观众不会用"做饭"搜到你，但会因为你名字好记而回来找你。

### 3.2 为什么必须放弃"身份词 + 品类词"这条路

> 2026-10-02 联网核实：**这条路已被占满，而且你已经撞在里面了。**

| 问题 | 证据 / 说明 |
|---|---|
| **必然撞名** | 「程序员小厨」已被占用 —— **这不是运气差，是这条路的结构性问题**：所有程序员做饭的博主都会起「XX 小厨 / 厨房 / 灶台 / 菜谱」 |
| **无差异化** | 存量账号已很多：`IT小食哥`（西瓜视频，单条百万播放）、`张记小灶的厨房`（下厨房，简介直接写"能写代码，会下厨房"）… |
| **没有记忆点** | 描述型名字只回答"你是谁"，**不产生"记住你"的动力**。看完视频，观众记不住"程序员小厨" |

**记忆点只有三种来源**（这是选名的核心判据）：

| 机制 | 说明 | 例子 |
|---|---|---|
| **双关** | 脑力上的小惊喜 —— 秒懂的人会心一笑，**这一笑就是记忆点** | 断点续炖 |
| **画面** | 脑子里能放电影 —— 一个具体可想象的场景 | 工位到灶台 |
| **悬念** | 想知道"那是谁 / 为什么" —— 好奇心最抓人 | 她点的菜 |

### 3.3 判据（按权重排序）

| 优先级 | 判据 | 说明 |
|---|---|---|
| **1** | **记忆点** | 必须命中"双关 / 画面 / 悬念"三者之一，否则直接淘汰 |
| **2** | **低重名** | 「程序员小厨」的教训：撞名会稀释全部识别度 |
| **3** | **品类可猜** | 看完名字能猜到是做菜的。否则被推荐了也没人点进来 |
| **4** | **口播可复述** | 一句话说出去，别人能一次记住并念出来 |
| 5 | 可搜性 | **次要** —— 交给简介和标题去补 |

**硬性排除**：**不得含"孕妇 / 孕期 / 医生 / 营养"**（合规红线，见 [约束与红线](../01-战略与约束/约束与红线.md)）。

### 3.4 候选对比（新一版）

| 候选 | 字 | 记忆机制 | 独特性 | 品类可猜 | 口播 | 点评 |
|---|---|---|---|---|---|---|
| **她点的菜** ⭐⭐ | 3 | **悬念 + 隐藏双关** | **极高** | 高 | **极高** | 字面 = 老婆想吃的菜；"**点**"字暗藏程序员双关（点菜／调用方法）。3 字极简，**有温度、有悬念（"她"是谁）、几乎不可能撞名** |
| **断点续炖** ⭐ | 4 | **双关** | **极高** | 高 | **极高** | 「断点续传」→「断点续炖」。程序员一听就笑，**"炖"字同时暴露美食属性**。最强梗 |
| try 一下咸淡 | 5 | 双关 | 极高 | 中 | 中 | `try` 是最基础的语法，"尝咸淡"是做饭动作。**最好笑，但中英混排，搜索与输入都最差** |
| 锅在冒烟 | 4 | 双关 | 高 | 高 | 高 | 「冒烟测试」vs 锅冒烟，有紧迫感。**风险**：可能被误读成"翻车 / 做菜失败号" |
| 今晚有个需求 | 6 | 双关 | 高 | 低 | 中 | "老婆想吃什么"= 需求。程序员一眼懂，**但非程序员完全看不懂** |
| 工位到灶台 | 5 | 画面反差 | 高 | **极高** | 高 | 白天工位、晚上灶台。**最直白、最好搜**，代价是笑点弱 |
| 码农的围裙 | 5 | 画面 | 中 | 高 | 高 | "围裙"是"家"的符号，有画面感；**仍是"身份 + 物件"结构，撞名风险中等** |

### 3.5 ✅ 定稿理由

> ## 定稿：**「她点的菜」**（2026-10-02 确定）

**理由链**：

```
第一关 记忆点 → 悬念 + 双关，两种机制叠加
  悬念："她"是谁？为什么是"她点的"？ → 好奇心是免费流量
  双关："点菜"的"点" = 程序员调用方法 → 懂的人会心一笑
  ★ 关键：这两层不打架 —— 不懂技术的观众感到温度，懂技术的观众感到默契
第二关 低重名 → 3 字口语短句，不是"身份 + 品类"的模板结构，撞名概率极低
第三关 品类可猜 → "菜"字直接点明美食，不会跑偏成技术号
第四关 口播复述 → 3 字，念一次就记住
第五关 可延展 → 不绑定菜品、不绑定平台，做一年也不违和
第六关 合规 → 不含孕妇 / 孕期 / 医生 ✅
```

**为什么它比「断点续炖」更适合你**：梗名（断点续炖）的收益是"好笑"，但它**没有任何温度**；而你内容的核心恰恰是"给老婆做饭"这件事的温度。**「她点的菜」同时装下了你的两个身份：程序员的巧思（点）和准爸爸的温柔（她）。**

> ## 退路（**仅在查重撞名时启用**）
>
> **次选：「断点续炖」**
> 如果你更想要"记忆点炸裂"而不是温度，选它。**这是最容易被同行主动传播的一个名字**（程序员看到会截图发群，等于白送曝光）。

> **保底：「工位到灶台」**
> 如果前两个在平台上都被占用，用它。最直白、最好搜，是最稳的退路。
