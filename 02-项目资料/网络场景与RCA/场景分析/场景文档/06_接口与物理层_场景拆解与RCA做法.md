## 一、场景定义与边界

### 1.1 场景定义

聚焦交换机物理端口/接口层面的失效：端口link建立与状态（UP/DOWN/假link/震荡）、自协商、光模块与光口（发光/收光/兼容/UP不通）、线卡与板卡识别启动、线卡版本一致性、M0/SDA管理核健康、芯片中断寄存器/中断掩码、POE供电、聚合口（AP）、以及由物理层状态触发的控制面协议（RLDP/LLDP）异常。即从『报文进入端口→PHY/光模块→线卡SDK/芯片→中断/寄存器→端口状态表项』这一物理层数据通路上的根因。

### 1.2 边界判据

**属于本场景：**

- 端口物理层不UP、假link、频繁UP/DOWN、物理down协议up、显示状态与实际link不符
- 自协商/强制速率双工协商失败（指令未下发到芯片）
- 光模块不发光/收光异常/光转电不兼容/光口UP但不通
- 线卡/业务板卡无法识别、无法启动、版本与引擎不一致、M0/SDA管理核挂死
- 芯片中断寄存器掩码异常导致收发包中断
- POE不供电/过压/功率减半/漏电
- 聚合口无法启动、速率不回显、AGG配置导致互联异常
- RLDP/LLDP等因端口状态或描述触发的接口shutdown/进程重启

**不属于本场景（易误入，需外归）：**

- DHCP地址获取/中继/snooping（应归去：二层与环网 L2）
- ACL/端口安全/授权/镜像/QINQ配置未生效（应归去：二层与环网 / 认证准入 / 配置与功能生效 / 表项与转发）
- SNMP采集、WEB/EMB界面、ssh/telnet登录、配置保存丢失（应归去：管理运维面 MGMT）
- SVI/VRF/网关不通、组播转发、NAT大包、PPPoE拨号（应归去：路由协议 / 表项与转发 / 安全防护）
- 设备整机重启/死机/EMMC/DDR-ECC/SDK空指针（应归去：系统面 SYS）
- 以上跨域记录在Sheet8被标记为『接口与物理层』，但机理属管理/配置/认证/二层/转发/系统/安全防护等其他大场景，本底座 v2 已将其移入『未归类』（类型=机理属他场景待外归）并逐条标注建议去向，不在本场景子场景中保留跨域兜底桶

## 二、这个场景是怎么拆出来的

### 2.1 拆解维度

| 维度 | 取值 | 为什么按这个维度切 |
|---|---|---|
| 介质类型 | 电口／光口/光模块／POE口／线卡/板卡／聚合口(AP) | 决定可观测点与排查命令：电口看PHY/自协商，光口看transceiver/DDM，POE看power inline，线卡看slot/版本/M0 |
| 失效环节 | 协商建立／光模块收发／芯片/寄存器中断／供电(PSE)／版本/识别／管理核(M0/SDA)进程／控制面协议(RLDP/LLDP) | 定位失效点在物理通路的哪一跳 |
| 是否硬件相关 | 纯软件BUG／软硬件不一致／硬件退化/损坏／配置/版本操作触发 | 区分升级版本可解 vs 需返修/换件 |

### 2.2 拆解原则

1. **机理优先**：以「根因 + 方案」里的技术失效机理作为第一判据，不按主题字面归类。
2. **排查动作一致**：同一个子场景内的记录，必须能用**同一套排查动作**定位；做不到就再拆。
3. **不硬凑**：机理描述缺失的记录不强行塞进任何子场景；机理明确属于别的大场景的记录，标为「待外归」而非塞进兜底子场景。

## 三、子场景明细

### EXT-PHY-05　线卡/板卡版本不一致与识别启动异常（15 条）

- **机理定义**：引擎与线卡（CM/业务板）版本不一致、新增板卡不被当前版本识别、首上电/插卡后板卡无法启动、EMMC/版本同步失败导致板卡状态none或无法读取接口信息。
- **归类判据**：根因含『线卡与引擎版本不一致/无法自动同步、版本不支持该板卡、版本同步不成功、EMMC已知bug、线卡跨度过大』。
- **典型现象**：板卡显示none/无法识别；同网段ping不通因板卡版本不同步；新板卡插入不启动；所有FE线卡识别不到。
- **排查动作**：show version 看引擎与每线卡版本；show module / show slot 看板卡状态与识别；比对版本配套表手动同步线卡版本；插拔槽位/整机重启/小包升级单板；确认机型是否支持该板卡。
- **记录抽样**：
    - Sheet8行 117（CS20230724-2143381）：【赵宇5 升级】线卡不识别、严重影响核心业务---RG-S7808C
    - Sheet8行 130（CS20230707-2064872）：【主动服务】翠微小学核心交换机一张7808C-CM Ⅱ板卡无法识别，状态显示”none“
    - Sheet8行 140（CS20230625-1995204）：【PSC故障】【frt：7月7日】7808c交换机首次上电，业务板卡无法启动，断电重启交换机后，板卡可以正常启动，需要确认原因

### EXT-PHY-06　POE供电异常/不供电（14 条）

- **机理定义**：PSE供电电路或POE固件异常：MCU/POE固件版本丢失、PSE芯片OVLO过压保护阈值过低、双电源时软件误判输入电压导致功率反复减半至0、对class4 PD供电异常、超供电范围下电、关闭POE后底层仍使能漏电。
- **归类判据**：根因含『POE线卡MCU/固件丢失、OVLO过压保护、功率减半到0、class4 PD供电异常、供电范围44-57V、底层POE状态仍使能』。
- **典型现象**：整机或部分口不供电、AP掉线；电压过载告警；前八口不供电；关POE后仍漏电；多电源场景功率逐次减半。
- **排查动作**：show power inline 看每口供电/功率/电压/状态；show power inline consumption 看总功率与可用功率；核对电源数量与输入电压；升级POE修复版本；确认PD class与供电范围；必要时更换电源模块。
- **记录抽样**：
    - Sheet8行 27（CS20231130-2804850）：S7808C交换机POE供电异常
    - Sheet8行 187（CS20230421-1682385）：S3410-24TF-P 整机poe不供电
    - Sheet8行 189（CS20230418-1666817）：poe交换机供电异常

### EXT-PHY-01　端口无法UP（自协商/PHY缺陷/版本BUG）（8 条）

- **机理定义**：端口物理层link无法建立。根因多为 PHY芯片功能缺陷、强制速率/双工时上层下发的关闭自协商指令未落到芯片、或对端协商能力不匹配，以及特定版本已知口不UP缺陷。
- **归类判据**：接口 status 为 down/不亮，自环可UP（指向对端/协商），或对端为华为等异厂商；根因描述含『PHY芯片缺陷/自协商未下发/版本已知口不UP』。
- **典型现象**：电口/光口灯不亮、端口不UP、插拔线卡或重启可临时恢复、与特定对端互联协商不上。
- **排查动作**：show interfaces status 看 link/速率/双工；show interfaces GigabitEthernet 0/1 phy 看自协商与PHY寄存器；show interfaces transceiver 看收发光；对端环回自环验证；比对两端 speed/duplex 与自协商；确认机型版本是否在已知缺陷列表，升级版本。
- **记录抽样**：
    - Sheet8行 142（CS20230621-1980880）：上海政法学院7805C端口无法UP
    - Sheet8行 207（CS20230323-1534706）：电口不up
    - Sheet8行 232（CS20230227-1400029）：RG-S5310-48GT4XS-E 接口不亮

### EXT-PHY-02　端口异常UP/DOWN·假link·状态不同步（含UP不通/显示不符）（6 条）

- **机理定义**：端口状态机/LED与真实link不一致：未连线端口误报UP、频繁震荡、物理down但协议up、接口显示UP但业务不通、或显示收不到光实际正常。根因多为端口状态机缺陷、M0未完全挂死导致面板信息未刷新、或定制/版本BUG。
- **归类判据**：出现『假link/接口震荡/物理down协议没down/显示up但不通/显示收不到光实际正常』等状态不一致描述，非单纯协商失败。
- **典型现象**：未插线端口指示灯亮且UP；端口频繁UP/DOWN；物理接口down协议未down业务正常；接口UP但ping不通且光衰正常无错误帧；光口显示收不到光但实际状态正常。
- **排查动作**：show interfaces status / show interfaces counters errors 看 CRC/错包与真实link；show interfaces transceiver detail（待实机核对）看真实收发光与DDM；对比对端同口状态；diagnose-cmd 查 F卡/M0 端口状态缓存；升级至修复版本。
- **记录抽样**：
    - Sheet8行 73（CS20230919-2437167）：RG-S5750-24SFP4XS24DP-UPS57P 光口显示收不到光，实际接口状态正常
    - Sheet8行 290（CS20241215-4587014）：S5750C-28GT4XS-H物理接口down，协议没有down，业务正常
    - Sheet8行 324（CS20241028-4339001）：中央戏剧学院18K上4到6接口假link问题

### EXT-PHY-09　控制面协议/进程异常导致端口down或重启（RLDP/LLDP）（6 条）

- **机理定义**：因端口状态或接口描述触发控制面协议异常：接口描述符超过64字节触发LLDP进程重启/设备重启；S7808C-X自愈机制BUG或sda带外检测与SDK DMA统计同步冲突，误判单向链路导致RLDP超时shutdown接口。
- **归类判据**：根因含『LLDP接口描述超64字节、RLDP单通检测超时shutdown、sda带外误修复自愈』。
- **典型现象**：接口描述过长后LLDP进程频繁重启；RLDP把接口shutdown导致业务中断；设备异常重启。
- **排查动作**：show lldp 看进程状态/重启计数；show running-config interface 检查 description 长度（≤64字节）；show rldp 看接口被shutdown记录；调整sda带外检测周期/连续判定；升级修复版本。
- **记录抽样**：
    - Sheet8行 63（CS20231011-2534950）：RG-S6120-48XS8CQ【故障】S6120的LLDP进程重启
    - Sheet8行 446（CS20240510-3509382）：苏州建行外联区SW8接口RLDP单通检测down
    - Sheet8行 475（CS20240325-3291381）：RG-S6120-48XS8CQ lldp进程异常重启

### EXT-PHY-03　线卡M0/SDA管理核挂死→端口状态冻结（5 条）

- **机理定义**：线卡 M0（管理核固件）或 SDA 进程挂死，导致端口link状态无法变化、LED/面板口信息无法及时更新，多口无法UP。属芯片管理核固件/SDK缺陷。
- **归类判据**：根因含『M0 FW is NOT Running / M0挂死 / SDA进程挂死』，现象为多光口无法UP或面板信息不刷新。
- **典型现象**：slot线卡多口无法UP；拔插光纤/模块后端口震荡且状态不刷新；底层读取速率信息异常。
- **排查动作**：diagnose-cmd 查看 M0 状态（M0 FW is NOT Running）；show module / show slot 看线卡状态；插拔对应线卡或整机重启临时恢复；升级至 M0 修复版本（如 S7800C 12.6(2)B0203、S7900 12.5(4)B0501P4 等）。
- **记录抽样**：
    - Sheet8行 326（CS20241027-4334803）：浙江移动台州开发大道S7910E 设备端口无法UP
    - Sheet8行 367（CS20240912-4122677）：RG-S7910E 2/3板卡的多个光口无法正常up
    - Sheet8行 467（CS20240401-3330467）：2024-04-01 10:43 备注：17724834807，光口不亮，回电看下

### EXT-PHY-04　光模块/光口异常（发光/收光/兼容/UP不通）（4 条）

- **机理定义**：光模块侧异常：光转电模块被软件限制禁用、光模块不发光、收发光/DDM异常、或光口UP但无法通讯（EH卡/芯片版本BUG）。
- **归类判据**：根因含『光转电模块不支持/被禁止、光模块不发光、版本BUG导致光口灯亮不通讯/UP不通、WEB显示SFP类型与实际不符』。
- **典型现象**：升级后光转电模块不可用；1/8线卡光模块不发光下联中断；光口灯亮但不通讯；WEB显示SFP+而面板为SFP。
- **排查动作**：show interfaces transceiver 看 Tx/Rx 光功率与告警；show interfaces transceiver detail（待实机核对）看 DDM 阈值；show interfaces status 看真实link；替换模块/光纤交叉验证；核对版本对光转电/模块的支持矩阵。
- **记录抽样**：
    - Sheet8行 160（CS20230602-1876828）：【网络变更CS20230601-1874090】RG-S7805C升级15.3B0202后光转电模块无法使用
    - Sheet8行 264（CS20230203-1275134）：18012 100G卡与7808c 100G卡互联光口up但无法通讯
    - Sheet8行 587（CS20250913-5677576）：RG-S5310-48SFP4XS-E交换机光口互联，端口灯亮，但是不通讯

### EXT-PHY-08　芯片寄存器/中断掩码异常（收发包中断）（4 条）

- **机理定义**：线卡芯片 DMA 中断掩码寄存器异常：正确的软件中断掩码无法设置到线卡芯片，导致收发包中断不响应、线卡断流、业务中断。命中预警 WN20240411002。
- **归类判据**：根因含『芯片寄存器中断掩码异常、中断寄存器掩码未成功设置到寄存器、DMA中断掩码异常导致收发包中断不响应』。
- **典型现象**：线卡收发包中断不响应、业务中断；设备无法登录/断流；特定slot线卡异常。

### 4.6 成功 / 失败对比要点

核心是对比『正常口 vs 异常口』：同一线卡上选一个正常UP且业务正常的端口作为基线，对比 show interfaces status/phy/transceiver/counters 的输出——若异常口收发光、CRC、自协商与基线一致则多为对端/线缆，若异常口独有『link状态与LED/协议不一致、M0状态异常、掩码寄存器不符』则锁定本端芯片/M0/寄存器；多口同时异常优先看线卡级（show module/M0/版本），单口异常优先看介质（光模块/线缆/自协商）。

## 八、本场景关键结论

EXT-PHY 共 122 条工单。v2 取消跨域兜底桶 原跨域兜底分组（已取消）/11/12（原 53 条），仅保留 9 个真实物理层子场景（EXT-PHY-01~09，合计 65 条）；其余 57 条进入『未归类』——其中 4 条无根因无方案（机理缺失），53 条机理明确属其他大场景（机理属他场景待外归，已逐条标注建议去向，主要流向配置与功能生效、管理运维面、二层与环网、表项与转发、认证准入、路由协议、安全防护、系统面）。本大场景核心机理为：端口UP/异常状态(假link/M0挂死)、光模块收发、线卡版本不一致、POE供电电路、芯片中断寄存器掩码(WN20240411002)、聚合口、控制面协议(RLDP/LLDP)。最高频根因是『特定版本软件BUG』与『线卡/引擎版本不一致』；其次为POE供电电路缺陷与芯片中断寄存器掩码异常。端口假link/M0挂死与PHY协商失败的区分是现场最大难点，需依赖 show interfaces phy/transceiver 与 diagnose-cmd 读 M0 状态。
