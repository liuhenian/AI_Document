## 一、场景定义与边界

### 1.1 场景定义

认证准入（DS-AUTH）覆盖两类身份鉴别与授权：①终端上网准入——终端通过交换机接入网络时由NAS（交换机）与RADIUS服务器（SAM+/SMP/深澜/联软等）围绕身份的认证（802.1X / Portal / MAC无感知 MAB）、授权（VLAN/ACL随行）、计费（Accounting）交互链路；②管理面AAA——管理员登录设备本身及其SNMP/VTY/4A/aaa进程的鉴别与授权。核心失效均落在『终端/管理员 → NAS → 服务器』的AAA交互链路上。注：v1识别混入的管理面AAA记录中，row=316 经复核为POE供电误入（见未归类），其余管理面AAA记录保留在 DS-AUTH-01 并显式区分。

### 1.2 边界判据

**属于本场景：**

- 终端上网认证：802.1X、Portal/Web、MAC无感知（MAB）的触发、交互、成功/失败
- 认证后授权：服务器下发的授权VLAN、动态ACL/ACE、安全ACL（filter-id）的安装与随行
- 放行/免认证策略：direct-vlan、直通vlan、免认证站点、guest vlan、逃生等绕过/放通逻辑
- 下线/保活：无流量下线、重认证、记账（Accounting）报文、表项老化
- RADIUS服务器侧：可达性（dead/active）、key、主备切换、Access-Challenge/Accept/Reject返回
- 管理面AAA：管理员登录、SNMP ACL、VTY授权/计费、4A、aaa进程

**不属于本场景（易误入，需外归）：**

- 纯转发/路由/组播/STP等与本认证链路无关的故障 → 归网络/二层/三层大场景（如 EXT-FWD / DS-RT）
- DHCP地址分配本身（无认证耦合） → 归地址管理大场景（EXT-DHCP）
- 准入控制器（SAM/SMP）服务端自身纯业务bug且无交换机侧机理 → 应归服务端
- OSPF内存溢出、qinq标签剥除、POE供电等与认证核心链路关联弱的工单 → 见未归类（机理属他场景待外归）

## 二、这个场景是怎么拆出来的

### 2.1 拆解维度

| 维度 | 取值 | 为什么按这个维度切 |
|---|---|---|
| 接入方式 | 802.1X／Portal/Web／MAC无感知(MAB)／组合(1X+MAB+Portal)／管理面AAA(登录/SNMP/VTY) | 先判定『是谁在认证、用什么方式』，决定排查入口与命令集（show dot1x / show web-auth / show mab / aaa） |
| 认证阶段 | 触发/拦截／EAP/RADIUS交互／授权下发(VLAN/ACL)／上线后转发／下线/保活／放行策略 | 按失败发生在链路哪一环切分，对应不同失效点与排查动作 |
| 失效机理 | 软件机制缺陷(队列无锁/表项重复/时间截断/芯片位图)／底层表项残留/漂移／放行策略绕过／服务器侧异常／版本/能力不支持／管理面AAA缺陷 | 机理优先：同一子场景须能用同一套排查动作定位，机理不同则再拆 |
| 触发时序 | 常态／设备重启/升级后／迁移(跨VLAN/跨端口)／高并发/规模／长稳(49天时间截断) | 许多bug由特定时序触发，决定可否复现与定位路径 |

### 2.2 拆解原则

1. **机理优先**：以「根因 + 方案」里的技术失效机理作为第一判据，不按主题字面归类。
2. **排查动作一致**：同一个子场景内的记录，必须能用**同一套排查动作**定位；做不到就再拆。
3. **不硬凑**：机理描述缺失的记录不强行塞进任何子场景；机理明确属于别的大场景的记录，标为「待外归」而非塞进兜底子场景。

## 三、子场景明细

### DS-AUTH-02　Portal/Web 认证触发与页面交互失败（弹窗/重定向/TLS/队列）（28 条）

- **机理定义**：Web认证无法拦截HTTP/HTTPS触发重定向、portal页面无法弹出、TLS不兼容、web-auth消息队列/进程异常或FP重定向表项安装失败，导致认证无法发起或卡在交互阶段。
- **归类判据**：现象为『不弹窗/不重定向/弹出后认证失败/HTTPS不跳转/设备未注册/卡顿』，根因落在web-auth触发、重定向FP表项、TLS、消息队列、控制面性能。首步须以端口镜像抓HTTP/HTTPS重定向报文定位（见RCA做法步1）。
- **典型现象**：终端不弹portal页；微信url/免认证站点不生效；小米等终端因DSCP/QoS不弹窗；web-auth队列满（EVTLST_SEND Failed）；TLS证书不安全/HTTPS不跳转；CPP/安全通道导致控制面卡顿；重定向FP表项跨slice迁移失败；改静态IP后无法使用。
- **排查动作**：show web-auth / show web-auth user（待实机核对） / debug web-auth；show log | inc WEBAUTH；检查portal服务器连通与重定向配置（web-auth portal ip/url、free-ip）；抓包HTTP/HTTPS看是否重定向及TLS版本；show fp web-auth（待实机核对） 看重定向表项；show process/event-list 看 wba 队列（EVTLST_SEND、current event-list 是否达100000）。
- **记录抽样**：
    - Sheet8行 4（CS20231222-2909351）：RG-N18012\n，免认证微信url不行
    - Sheet8行 39（CS20231108-2686244）：RG-N18010-E\n 无法进行Web认证无法弹出认证界面
    - Sheet8行 48（CS20231031-2637647）：核心18K设备做web认证，所有小米手机都无法认证弹窗

### DS-AUTH-04　放行 / 免认证策略异常（绕过认证 or 合法放通失效）（15 条）

- **机理定义**：direct-vlan/直通vlan/免认证vlan配置删除或迁移后底层硬件(FP)表项残留，终端无需认证即可上网（绕过）；或反之直通/免认证策略未真正下发导致合法放通用户过不去。
- **归类判据**：现象为『接口开了认证但部分/全部终端免认证直接上网』或『免认证vlan/直通vlan不生效』，根因是放行策略在控制面与底层FP表项不一致（具认证绕过语义，区别于纯FP表项问题）。
- **典型现象**：删除direct-vlan后该vlan仍免认证；接口直通vlan在全局生效；免认证站点/微信url不生效；升级后user-group配置残留；网关模式XA线卡未默认deny IPv6致未认证流量放行。
- **排查动作**：show direct-vlan（待实机核对） / show web-auth free-ip / show running-config | sec direct|web-auth；show fp web-auth（待实机核对） / show access-list 看底层放行表项是否与配置一致；clear 残留表项或重配接口认证触发重新下发；对比『应放通vlan』与『实际FP表项』。
- **记录抽样**：
    - Sheet8行 33（CS20231127-2782201）：RG-S5310-48GT4XS设备部署无感知认证，终端无需认证就可以上网
    - Sheet8行 57（CS20231016-2558201）：【H客户】18K下部分终端无需web认证即可上网
    - Sheet8行 59（CS20231013-2547577）：RG-N18012接口开启认证后，部分的vlan不需要认证就可以上网

### DS-AUTH-07　MAC 无感知（MAB）触发 / 迁移 / 表项 / IPv6 冲突（15 条）

- **机理定义**：MAB认证触发时机异常（重启后、跨端口迁移、芯片时序）、无感知表项残留、频繁发送mab、无感知携带IP/IPv6与宽松模式冲突、用户组容量写死。
- **归类判据**：现象围绕『哑终端/无感认证』：无法触发、频繁mab、重启后不生效、迁移不支持、无感知后偶发弹窗、无流量下线记账异常、用户组2000限制。
- **典型现象**：重启后DOT1X未起就触发无感知致组件异常；下连口先up上联未通致mab超时；同交换机跨端口迁移不支持；mab优先于V6宽松致取不到V6；无感知无法携带IP（不支持valid-ip-auth）；无流量下线acct-session-time=0；用户组写死2000满额；无感上线后偶发弹窗（主备板未同步受控端口）。
- **排查动作**：show mab / show dot1x mac-auth-bypass；debug mab；show mac authentication（待实机核对） / show dot1x users（待实机核对） 看无感知表项与IP；show log 看 mab 触发与 quiet-period；核对 valid-ip-auth 支持与用户组容量（user-group）；对比正常与异常哑终端的上线/迁移流程。
- **记录抽样**：
    - Sheet8行 30（CS20231128-2791635）：RG-S2910-48GT4XS-E 接口下哑终端无法认证上网
    - Sheet8行 77（CS20230915-2418696）：部分哑终端出现网络时断时续现象
    - Sheet8行 95（CS20230823-2285300）：RG-S2928G-E V3 重启后无感知不生效

### DS-AUTH-09　已认证但无法上网 / 表项与资源残留（MAC漂移、路由出口、ARP/ND）（14 条）

- **机理定义**：认证成功后底层表项/路由出口/用户表残留或MAC地址在EH卡环回漂移、ARP/ND表项异常/不老化、准入子网容量不一致，导致已认证用户转发异常或丢包。
- **归类判据**：现象为『认证通过但仍无法上网/丢包/卡顿、MAC漂移、ARP/ND异常、表项残留』，失效点在认证后的转发面表项一致性。【与EXT-FWD/DS-RT边界】若认证表项本身残留(已下线却仍在)→本场景；若认证表项在但ARP/ND不刷新、纯转发面异常→下钻 EXT-FWD；若涉及路由出口/下一跳资源→下钻 DS-RT（见RCA做法步7判读与易混子场景判定表）。
- **典型现象**：EH卡准入管控下ARP流表环回致MAC迁移；华为AC/AP组播泛洪致双Mac；认证用户残留致路由出口/下一跳资源不足；IPv6 DAD代理缺陷致ND表空；ARP表vlan与无感vlan不一致；认证终端离线后ARP不老化；准入子网容量INC与实际不一致；DC卡下联认证正常但无法访问外网。
- **排查动作**：show mac address-table（看漂移/MAC迁移）、show arp / show ipv6 neighbors（看表项与老化）、show access-list / show dot1x users（待实机核对）（看在线表项）、show ip route / 下一跳资源；debug scc / show fp；对比正常与异常终端的 MAC/ARP/ND 与转发路径。
- **记录抽样**：
    - Sheet8行 13（CS20231218-2887117）：RG-N18010\n核心路由异常，全校断网，影响上万人
    - Sheet8行 99（CS20230822-2278920）：设备：18012，反馈INC上准后后汇聚和18K互相学习到了终端的的Mac地址
    - Sheet8行 107（CS20230808-2217302）：设备：18K,武汉大学18K上无线用户出现双Mac导致终端网路异常

### DS-AUTH-03　认证后异常掉线 / 无流量下线 / 表项老化（各类接入方式共性）（13 条）

- **机理定义**：用户认证上线后异常下线，根因多为无流量下线逻辑缺陷、聚合口/线卡不生效、表项老化异常、记账结束报文（code9/acct-session-time=0）或主动重认证超时。
- **归类判据**：现象为『认证成功后定时/无流量掉线、迁移后掉线、记账异常下线、主动重认证超时』，跨越1X/Portal/MAC但机理同属下线逻辑。
- **典型现象**：过1-2h/8h/固定周期掉线；无流量却被判下线；跨VLAN迁移后5分钟被dhcp-snooping误下线；下线logoff误伤同VLAN其他终端；记账结束code9/acct-session-time=0；开启主动重认证导致超时下线；portal成功后仍触发无感知重认证。
- **排查动作**：show dot1x/web-auth/mab user（待实机核对）（在线时长、下线原因）；debug dot1x/web-auth/mab 看下线触发；show log 看 OFFLINE/NO_TRAFFIC 原因；核对无流量下线配置与生效端口（聚合口/物理口差异）；抓RADIUS计费报文看 Accounting-Request/Response 与 session-time；对比正常终端与掉线终端的 snooping 表项。
- **记录抽样**：
    - Sheet8行 82（CS20230907-2371841）：【PSC故障】S7808C portal认证无法正常下线
    - Sheet8行 102（CS20230818-2261283）：SMP对接5310做有线web认证，认证成功后收到记账结束报文异常下线，原因是code9
    - Sheet8行 103（CS20230816-2252883）：RG-S7808C设备部署web认证，用户过1-2h就会下线，影响客户感知

### DS-AUTH-06　1X 授权 / 动态 ACL 下发失败（DOT1X installation acl failed）（13 条）

- **机理定义**：1X认证通过后服务器下发授权VLAN/ACL，SCC/桥组件处理acl id/ace时生成重复或校验失败、ACE容量未适配、受控模式判断分支错误，3min超时下线。

- **典型现象**：DOT1X installation acl failed；授权VLAN下发失败且1X表项未删致重认证失败；SCC对acl id转换生成2个acl下层校验失败；ACE总数未放开致表项已满；重认证旧ace未删；filter-id安全ACL大量安装致控制面卡顿。

- **记录抽样**：

    - Sheet8行 134（CS20230704-2048400）：【随硬件服销金牌】认证服务器下发ACL故障
    - Sheet8行 168（CS20230525-1841845）：【RG-S5310-48SFP4XS-E】【PS20230317007】【泰康人寿保险股份有限公司】【dot1x用户进行远程连接后，远程用户和本地用户切换发生重认证且认证失败】

### DS-AUTH-01　管理面AAA（管理员登录/SNMP/VTY/4A/aaa进程）（12 条）

- **机理定义**：管理员或网管对设备本身的鉴别授权链路异常：登录记账线程残留、NAS-IP/强密码检查、aaa进程内存越界重启、SNMP ACL/弱密码校验误判。
- **归类判据**：『是谁在认证』= 管理员/网管登录设备或SNMP/VTY访问，而非终端上网；典型含4A绕行、aaa new-model、snmp community/secret-dictionary、vty授权计费模版、aaa进程重启。【显式区分】本子场景承载管理面AAA类记录（v1识别为混入13条，其中row 316经复核为POE供电误入已移出未归类，本场景现含12条管理面AAA），其失效机理、排查动作（login/accounting/VTY/SNMP）与终端准入差异大，建议独立成大场景（见核对问题Q-AUTH-01）。
- **典型现象**：登录显示异常LOG/4A绕行告警；SNMP认证失败日志或ACL失效；vty授权计费命令未识别；管理口aaa认证失败；aaa进程coredump后登录/记账异常；升级后多出AAA组命令。
- **排查动作**：show aaa / show login / show snmp-server / show running-config | sec aaa|vty|snmp；看 login/accounting 日志与 aaa 进程状态（show process | inc aaa）；核对 NAS-IP、radius-server key、强密码策略（password policy / snmp-server enable secret-dictionary-check）；对比能登录与不能登录的管理员日志。
- **记录抽样**：
    - Sheet8行 37（CS20231114-2715713）：5750V2交换机登录用户残留问题。
    - Sheet8行 64（CS20231010-2529494）：中国移动通信集团辽宁有限公司营口分公司S5750H B74P7 用户登录登出后出现异常log产生4A绕行告警
    - Sheet8行 105（CS20230815-2250084）：S7910E设备snmp acl失效

### DS-AUTH-05　802.1X 认证交互与 EAP 协议异常（9 条）

- **机理定义**：EAPOL/EAP报文交互异常：eapol-tag未带VLAN、芯片初始化未加untag位图致EAP带tag、客户端异常EAP致软件越界、49天(32位时间)截断无法发EAP-Success、单MAB并发EAP摘链致1X挂死、用户名乱码。
- **归类判据**：现象为『1X认证不成功/卡在Request/反复失败/国产或麒麟终端异常』，根因在NAS与终端的EAP报文交互或1X组件内部处理。首步须以端口镜像抓EAPOL(802.1X)报文定位（见RCA做法步1）。【与DS-AUTH-08边界】若崩溃/失效发生在终端EAP报文处理阶段（NAS↔终端），归本子场景；若表现为无法向RADIUS服务器发送Access-Request（服务器交互路径中断），归 DS-AUTH-08。
- **典型现象**：应答EAP不带vlan tag；国产终端前24口认证不成功（芯片1位图未加untag）；设备起机>49天无法发EAP-Success；客户端异常EAP致越界；MAB并发EAP摘链1X挂死；用户名乱码致认证失败。
- **排查动作**：show dot1x interface / show dot1x users（待实机核对）；debug dot1x / debug eapol；终端侧与NAS侧镜像抓EAPOL(EAP)报文比对；show dot1x internal 看组件状态与coredump；检查芯片/端口位图、系统起机时间与49天截断；开启 dot1x user-name compatible 兼容模式验证。
- **记录抽样**：
    - Sheet8行 165（CS20230531-1868814）：RG-MAP852-SF PC接入MAP有线口后做有线802.1x认证失败
    - Sheet8行 167（CS20230529-1852616）：RG-S5310-48GT4XS-E 交换机进行纯1X认证不成功
    - Sheet8行 338（CS20241016-4280658）：国产终端dot1x认证异常

### DS-AUTH-08　RADIUS / 服务器侧异常（可达性/key/切换/进程）（6 条）

- **机理定义**：RADIUS服务器 dead/active 判断bug、radius探测状态不随网络变更、服务器key错误、主备切换异常、1X对接服务器进程coredump导致发不出radius报文。
- **归类判据**：现象为『服务器状态dead/active错误、认证超时、主服务器挂死后异常、对接服务器进程coredump』，失效点在NAS与RADIUS服务器交互侧。【与DS-AUTH-05边界】当1X进程coredump直接表现为无法向RADIUS服务器发送Access-Request（服务器交互路径中断）时归本子场景（row 169 属此类，固定归 DS-AUTH-08）；当崩溃发生在终端EAP报文处理（NAS↔终端）时归 DS-AUTH-05。
- **典型现象**：ping不通但状态active；radius探测dead不随网络恢复；key被改致通信异常并误切异常服务器；主服务器挂死后1X异常；1X进程启机/下线coredump致发不出radius报文；密码算法修订致与服务器key失败。
- **排查动作**：show radius-server（待实机核对）（状态dead/active、key、探测配置）；debug radius 看 Access-Request/Response 与 Challenge 次数；抓包RADIUS(1812/1813)看服务器返回码（Accept/Reject/Challenge）；核对 deadtime、NAS-IP、radius-server key；对比正常与异常服务器的响应时延。
- **记录抽样**：
    - Sheet8行 169（CS20230525-1837951）：【PS20230508025】【中规院】S53EDot1X对接联软认证服务器异常
    - Sheet8行 182（CS20230429-1720766）：RG-N18010 版本存在密码算法修订，导致密码丢失，与服务器对接key失败，导致设备无法进入并且全校用户无法认证
    - Sheet8行 480（CS20240318-3255454）：湖南农业大学 WEB认证以及无感知认证异常问题

## 四、RCA 根因分析怎么做（本场景）

### 4.1 技术链

现象（无法认证/绕过认证/认证后掉线或无法上网）→ 触发路径（终端发起EAP/HTTP → NAS拦截 → 与RADIUS交互 Access-Request/Challenge/Accept/Reject → 授权VLAN/ACL下发 → 表项安装/转发）→ 失效点（触发未识别/报文交互异常/服务器返回异常/授权表项下发失败/底层表项残留/放行策略绕过）→ 直接根因（软件机制缺陷/配置残留/版本不支持/容量超限/时序竞态）。

### 4.6 成功 / 失败对比要点

在同一台接入交换机上选取『正常认证并上网的终端』与『异常终端』做对照：比对 show dot1x/web-auth/mab user 表项、授权VLAN/ACL、ARP/ND、RADIUS返回码与debug日志；对Portal对比『能弹窗 vs 不能弹窗』的HTTP重定向报文与FP重定向表项（见步1抓包）；对1X对比『成功EAP-Success vs 卡在Request/Reject』的EAPOL抓包与Challenge次数；对管理面AAA，对比『能登录的管理员 vs 报错管理员』的login/accounting日志与aaa进程状态；对放行策略，对比『应放通vlan的FP表项』与『实际FP表项』是否残留。

## 八、本场景关键结论

本大场景145条按『机理优先』拆为9个子场景，修订后覆盖125条，未归类20条（约14%）。主要变更：高危项 A-01 将 row=316（POE供电误入）移出至未归类（机理属他场景待外归，建议去向=接口与物理层-POE供电异常）；A-06 将 row=353/483/559（根因字段为『-』，无机理）移出至未归类（机理缺失）。保留 v1 结论：确认混入管理面AAA记录（v1识别13条，row 316 复核为POE误入已移出，现 DS-AUTH-01 含12条管理面AAA），其机理与终端准入差异大，建议考虑移出。最集中子场景仍为 DS-AUTH-02（Portal/Web触发与交互失败，28条）、DS-AUTH-04（放行/免认证策略异常，15条）、DS-AUTH-07（MAC无感知，15条）、DS-AUTH-09（已认证无法上网，14条）。高频软件机理包括：direct-vlan删除后底层FP表项残留绕过认证、web-auth消息队列无锁计数溢出、SCC/桥组件ACL/ACE重复下发校验失败、49天(32位时间)截断无法发EAP-Success、EH卡准入管控下ARP环回致MAC漂移——均应是APM可观测与自愈的重点。
