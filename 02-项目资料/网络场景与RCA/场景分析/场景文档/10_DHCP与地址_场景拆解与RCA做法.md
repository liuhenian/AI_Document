## 一、场景定义与边界

### 1.1 场景定义

聚焦交换机作为 DHCP 服务端/中继/客户端或地址管理节点(snooping/binding)时，围绕 IPv4/IPv6 动态地址分配、租约生命周期、地址池与绑定表、中继转发、v6 地址配置等导致的地址获取失败、服务中断、地址相关连通/性能异常的故障集合。以「根因+方案」的机理为准，不局限于原表领域标签。

### 1.2 边界判据

**属于本场景：**

- DHCP 服务端/组件控制面进程异常（挂死/崩溃/内存泄漏）导致服务中断或设备重启
- 地址池与租约异常：获取不到地址、租约翻转、地址无法释放
- DHCP Snooping/中继转发与报文收发阻断导致拿不到地址
- 绑定表/保留地址异常（同 MAC 多绑定、地址切换）
- IPv6 地址配置异常（127 位掩码误判任播、版本不支持）
- DHCP 四步交互（Discover/Offer/Request/Ack）各环节失败

**不属于本场景（易误入，需外归）：**

- 控制面进程性能/资源占用导致的 ping 延时、卡顿（如 card_mon_info 进程占用）→ 归「设备资源占用异常(CPU/MEM)」大场景（见 row=17）
- 纯配置乱码/配置未生效且无 DHCP 报文收发直接阻断的，归「配置未生效与配置丢失」大场景；但 DHCP 报文因配置/广播冲突被阻断仍属本场景（row=78/742）
- PXE 已获取地址后 vxlan/sdk 转发不通、纯 IPv6 转发不通、DNS 解析/上联出口线路问题 → 归「转发/连通性」或「出口/上层业务」大场景（row=139/422/695）
- 仅描述为软件版本缺陷导致泛化“上网慢/不通”、无地址分发层明确机理的 → 归「软件版本缺陷/转发性能」大场景或留未归类（row=645/773/791/802/810/758）
- 无根因、仅排查诉求的 → 未归类（row=444）

## 二、这个场景是怎么拆出来的

### 2.1 拆解维度

| 维度 | 取值 | 为什么按这个维度切 |
|---|---|---|
| 设备角色 | 服务端(server)／中继(relay)／客户端/终端侧／地址管理(snooping/binding) | 判定故障发生在 DHCP 链的哪一节点：是交换机自己发不出/收不到、做服务端分配失败、做中继转发偏离，还是 binding 表异常。 |
| 地址类型 | IPv4 动态／IPv4 静态/排除/保留／IPv6 地址/前缀／租约(lease) | 区分 v4 动态分配、保留/排除地址、v6 地址配置、租约生命周期四类对象。 |
| 失效环节 | 地址分配(pool/binding)／租约生命周期(获取/续租/释放)／报文转发(四步交互阻断)／服务进程(挂死/崩溃/泄漏)／配置下发/生效 | 按机理链路定位失效发生在分配、租约、报文转发、进程还是配置环节。 |
| 根因属性 | 软件缺陷/BUG／版本不支持/能力缺失／配置错误／表项/状态不一致／资源泄漏 | 归类根因性质，用于沉淀常见根因模式与 APM 监控点。 |

### 2.2 拆解原则

1. **机理优先**：以「根因 + 方案」里的技术失效机理作为第一判据，不按主题字面归类。
2. **排查动作一致**：同一个子场景内的记录，必须能用**同一套排查动作**定位；做不到就再拆。
3. **不硬凑**：机理描述缺失的记录不强行塞进任何子场景；机理明确属于别的大场景的记录，标为「待外归」而非塞进兜底子场景。

## 三、子场景明细

### EXT-DHCP-01　DHCP 服务端/组件控制面进程异常致服务中断或设备重启（3 条）

- **机理定义**：交换机作为 DHCP 服务端或运行 DHCP 组件时，在分配地址的冲突检测(ping 检测)处触发空指针释放、或 DHCP 组件创建原始 socket 却不读取导致 sk_buff 累积内存泄漏、或 dhcpv6 地址冲突释放时进程异常，最终 DHCP 进程挂死/崩溃或设备热重启，DHCP 服务不可用。
- **归类判据**：故障表现为大面积获取不到地址、引擎离线/热重启、DHCP 服务异常；定位到 dhcp 进程挂死、空指针、sk_buff 内存泄漏、组件崩溃等控制面异常；与单纯地址池耗尽/配置错误无关。
- **典型现象**：终端大面积拿不到地址；主引擎重启/设备无故热重启；DHCP 服务进程挂死；内存使用率持续上涨。
- **排查动作**：确认是否设备重启/crash；show process cpu、show memory 看 dhcp 进程与内存曲线；show logging / crashinfo 看 dhcp 函数调用栈；debug ip dhcp 看分配是否卡在冲突检测；升级到指定修复版本。
- **记录抽样**：
    - Sheet8行 135（CS20230703-2045956）：【时效：7月10日】北京银行上海分行S8606交换机引擎异常离线，DHCP服务异常
    - Sheet8行 307（CS20241118-4446385）：工商银行北京分行RG-S7807E设备无故热重启
    - Sheet8行 320（CS20241030-4351576）：峡江县中医院 S7805C 异常重启

### EXT-DHCP-03　DHCP 报文收发/转发阻断导致获取不到地址（3 条）

- **机理定义**：由于 DHCP Snooping 功能软件异常丢弃 dhcp 报文、或通路广播方案与超融合广播方案冲突导致 DHCP 报文无法正常转发、或设备软件配置乱码导致无法主动发送 DHCP 报文，使终端无法完成地址协商。
- **归类判据**：终端拿不到地址；在故障设备上抓包发现 DHCP 报文被丢弃或未见发出；snooping 重启/规避广播冲突/重建配置后可恢复；根因指向报文收发/转发阻断而非地址池或租约。
- **典型现象**：下挂 AP/终端无法 DHCP 获取地址；snooping 重启后恢复；广播冲突导致 OAP 无法下发地址；配置乱码致无法发 DHCP 报文接入控制器(ONC)。
- **排查动作**：在终端侧与设备侧抓包比对 DHCP 四步交互是否完整；show ip dhcp snooping 看是否开启及丢包计数；检查 snooping 表项与信任口；排查广播域/VLAN 与超融合广播方案是否冲突；检查设备配置是否乱码/丢失并重下发；升级版本。
- **记录抽样**：
    - Sheet8行 78（CS20230914-2413919）：【故障处理】H客户宁波财经学院2920无法接入ONC
    - Sheet8行 248（CS20230216-1335168）：东北林业大学5750交换机下挂AP无法DHCP获取地址
    - Sheet8行 742（CS20260831-6976579）：【故障】无法下发地址到OAP设备

### EXT-DHCP-06　IPv6 地址配置异常（127 位掩码误判任播）（3 条）

- **机理定义**：在交换机上配置 IPv6 地址、掩码长度为 127 时，早期/特定版本不支持主机位全零地址，误识别为任播(anycast)地址而拒绝配置；或需特定版本才支持客户现网 IPv6 地址。
- **归类判据**：配置 127 位 IPv6 地址报错“不能配置任播地址”；升级到支持版本或配置奇数结尾规避后可配置；属版本能力/软件缺陷。
- **典型现象**：配置 127 位 ipv6 地址提示不能配置任播地址；S57H/S2910 等版本不支持现网 IPv6 地址。
- **排查动作**：show ipv6 interface、show running-config 看 ipv6 地址配置报错；核对版本 release note 对 127 位/任播的支持；show version 确认版本；升级到支持版本或用奇数结尾地址规避。
- **记录抽样**：
    - Sheet8行 54（CS20231023-2599858）：S8612E-Iseries 配置127位的ipv6地址提示不能配置任播地址
    - Sheet8行 67（CS20230925-2473653）：设备：S57H，现场在AGG10下配置配置 IPv6 地址，不使用通用前缀，当掩码长度为127时，提示报错。
    - Sheet8行 251（CS20230215-1331081）：【故障】RG-S2910-24GT4XS-Eipv6地址无法配置

### EXT-DHCP-02　DHCP 地址获取与租约异常（获取不到/租约翻转/无法释放）（2 条）

- **机理定义**：终端通过 DHCP 四步交互获取地址时，因触发租约翻转(lease flip)使已分配地址无法释放、或命中已知 BUG 导致终端无法正常获取地址；地址池虽有余量但分配链路/租约状态异常。
- **归类判据**：终端获取不到地址或地址长期不释放/频繁翻转；show ip dhcp binding 看到地址状态异常(长期 occupied 不释放)；非 snooping/中继/报文阻断导致。
- **典型现象**：大面积终端突然获取不到地址；地址无法释放需手动清除/重启；命中已知获取 BUG。
- **排查动作**：show ip dhcp binding 看租约状态/剩余时间；show ip dhcp pool（待实机核对） 看地址池余量；show ip dhcp server statistics（待实机核对） 看请求/分配计数；debug ip dhcp 看四步交互；在终端与服务器侧抓包确认 Discover/Offer/Request/Ack；升级修复版本。
- **为什么没有与相邻子场景合并**：本子场景仅 2 条。按「同一子场景内可用同一套排查动作定位」的粒度判据，其失效机理与排查动作与相邻子场景不交叉，故保留独立、不作合并；记录数少反映的是该故障模式在市场工单中发生频次低，而非拆分类别有误。
- **记录抽样**：
    - Sheet8行 75（CS20230918-2429181）：政府网络，大面积终端突然获取不到地址
    - Sheet8行 196（CS20230410-1623849）：【故障】S2910C--24GT2XS.-HP-E下联用户无法上网

### EXT-DHCP-04　DHCP 中继(Relay)转发异常（1 条）

- **机理定义**：配置 DHCP 中继后终端仍获取不到地址，因静态地址池掩码配置过大导致报文被错误送到 server 层面而非 relay 层面处理，中继未按预期转发 DHCP 请求。
- **归类判据**：已配置 ip helper / dhcp relay 但获取不到地址；定位为地址池掩码写大使报文路径偏离 relay；show ip dhcp relay（待实机核对） 可见中继配置但流量未走 relay。
- **典型现象**：中继配置后获取不到地址；缩小静态地址掩码后恢复。
- **排查动作**：show ip dhcp relay（待实机核对）、show running-config | include helper 看中继与地址池掩码配置；show ip dhcp relay（待实机核对） statistics 看中继转发计数；抓包看 Discover 是否到达服务器；核对 server/relay 层面转发路径；修正掩码或升级规避版本。
- **为什么没有与相邻子场景合并**：本子场景仅 1 条。按「同一子场景内可用同一套排查动作定位」的粒度判据，其失效机理与排查动作与相邻子场景不交叉，故保留独立、不作合并；记录数少反映的是该故障模式在市场工单中发生频次低，而非拆分类别有误。
- **记录抽样**：
    - Sheet8行 554（CS20251118-5943486）：中继配置了之后获取不到地址

### EXT-DHCP-05　DHCP 绑定表/保留地址异常（同 MAC 多绑定致地址切换）（1 条）

- **机理定义**：策略随行等场景下，相同 MAC 在设备 history(绑定历史)表中存在多个绑定表象，软件机制异常导致地址变动、分配不同地址，用户地址切换异常影响安全策略；与地址池满或排除地址边界相关。
- **归类判据**：同一 MAC 对应多个绑定表项；用户地址非预期切换；snooping log 存在同 MAC 分配不同地址；排除最后一个地址会偶发触发。
- **典型现象**：策略随行用户地址切换异常；同一终端 IP 频繁变化；地址池满或排除地址边界触发。
- **排查动作**：show ip dhcp binding / show dhcp snooping binding 看同 MAC 多表项；show logging 看 snooping 分配日志；核对 excluded-address 范围与地址池容量；扩容地址池/调整排除范围规避；等待版本修订分配逻辑。
- **为什么没有与相邻子场景合并**：本子场景仅 1 条。按「同一子场景内可用同一套排查动作定位」的粒度判据，其失效机理与排查动作与相邻子场景不交叉，故保留独立、不作合并；记录数少反映的是该故障模式在市场工单中发生频次低，而非拆分类别有误。
- **记录抽样**：
    - Sheet8行 100（CS20230822-2278280）：RG-N18012 策略随行用户地址切换异常，影响客户方核心安全策略

## 四、RCA 根因分析怎么做（本场景）

### 4.1 技术链

现象(拿不到地址/服务中断/地址相关不通) → 触发路径(终端请求/租约翻转/报文转发/中继/绑定/配置) → 失效点(池耗尽/租约不释放/报文丢弃/中继偏离/绑定冲突/进程挂死/v6 配置拒绝) → 直接根因(软件 BUG/版本不支持/配置错误/表项不一致/资源泄漏)

### 4.2 失效点分类

| 失效点 | 说明 | 典型记录（Sheet8行） |
|---|---|---|
| DHCP 服务进程挂死/崩溃 | 分配冲突检测空指针或 dhcpv6 冲突释放异常导致进程崩溃、设备重启 | 135、320 |
| 资源泄漏(sk_buff/内存) | DHCP 组件 socket 不读致 sk_buff 累积内存涨→热重启 | 307 |
| 租约翻转/地址不释放 | 触发 lease flip 地址无法释放致大面积拿不到 | 75 |
| 地址获取 BUG | 命中已知 bug 终端无法获取地址 | 196 |
| DHCP 报文丢弃/转发阻断 | snooping 异常丢包/广播冲突/配置乱码致报文收发失败 | 78、248、742 |
| 中继路径偏离 | 静态池掩码过大报文走 server 层未走 relay | 554 |
| 绑定表多表项 | 同 MAC 多绑定表象致地址切换 | 100 |
| v6 地址配置拒绝(任播误判) | 127 位主机全零误判任播不支持 | 54、67、251 |

### 4.3 排查动作步骤（按序执行）

> 标注「待实机核对」的命令，表示该写法尚未在真机/模拟器上确认，使用前请先验证。

| 步 | 动作 | 命令 / 观测点 | 判读 |
|---:|---|---|---|
| 1 | 确认现象与范围 | `show logging、终端 ipconfig/renew` | 区分“拿不到地址”/“拿到但业务不通”/“设备重启” |
| 2 | 检查 DHCP 四步交互 | `终端+设备抓包(Discover/Offer/Request/Ack)` | 缺失哪一步→定位在终端/链路/设备/服务器 |

### 4.6 成功 / 失败对比要点

成功定位均依赖“抓包确认四步交互 + 表项(binding/pool/relay/snooping)核对 + 进程/内存/crashinfo”三者交叉；失败案例多为仅有“升级版本”结论却无抓包与表项证据，无法区分是池/租约/报文阻断/转发，导致无法沉淀机理。

## 八、本场景关键结论

24 条中仅 13 条归入本大场景 6 个子场景（服务端进程崩溃、租约翻转/获取失败、报文收发阻断、中继路径偏离、绑定表多表项、v6 任播误判），其余 11 条未归类——其中 7 条机理明确属他场景（控制面进程性能/资源、vxlan/IPv6 转发、DNS/出口、转发/版本缺陷）已标『机理属他场景待外归』并给出去向，4 条根因方案均缺或仅现象+升级、无地址分发层明确机理（row=444/645/758/791）标『机理缺失』。重要：v1 经机理复核推翻了原工单旧线索里『CPU异常/配置未生效/控制面进程崩溃』的泛化归因——row=135/307/320 虽表现为设备重启，但崩溃函数定位在 DHCP 组件专属逻辑（ping 冲突检测空指针、dhcpv6 冲突释放、raw socket 不读致 sk_buff 泄漏），确属 EXT-DHCP 而非泛化 CPU/配置问题；row=78/742 虽被旧线索标『配置未生效』，机理实为 DHCP 报文被 snooping/广播冲突阻断，仍归本场景。DHCP 服务端进程在冲突检测/地址释放处的空指针与 sk_buff 泄漏是引发设备重启的高危根因模式，需以 crashinfo + debug 定位并升级指定版本。地址获取类故障首要看 DHCP 四步交互抓包与 binding/pool/relay 表项，先区分『拿不到(池/租约/报文阻断)』还是『拿到了但业务不通(转发/版本)』。
