## 一、场景定义与边界

### 1.1 场景定义

EXT-MISC（其他与未分类）是 889 条市场故障工单按「领域」切分后、无法归入五大深挖场景（管理运维面/认证准入/二层与环网/堆叠与虚拟化/路由协议）与其余五大场景（接口物理层/表项转发/无线接入/设备系统/DHCP）的溢出集合。它由 5 个源子领域合并而来：未分类对象(39)、QoS与ACL(14)、配置与持久化(4)、安全防护(2)、隧道与Overlay(1)，共 60 条。本场景承担两件事：① 对 39 条历史「未分类对象」逐条做机理复核与归位分发（分发不再设子场景，改为『未归类·type=机理属他场景待外归』逐条标注去向）；② 沉淀机理明确但溢出主分类体系的子场景（QoS与ACL、安全防护、配置与持久化），作为 RCA 底座的「兜底 + 溢出」层。

### 1.2 边界判据

**属于本场景：**

- 机理复核后仍无法归入其它 10 大场景、但机理明确的溢出功能域工单（QoS/ACL、安全防护、配置持久化）
- 历史「未分类对象」中能凭根因+方案/主题明确指向某功能域、需外归到其它 10 大场景的工单（移入『未归类』，type=机理属他场景待外归，逐条填建议去向，不再设分发层子场景）
- 根因与方案均缺失、仅能确认机理缺失的工单（入未归类，type=机理缺失）

**不属于本场景（易误入，需外归）：**

- 明确属于管理运维面/认证准入/二层与环网/堆叠与虚拟化/路由协议/接口物理层/表项转发/无线接入/设备系统/DHCP 等已定义大场景、且机理可定位的工单，应外归对应大场景（入本场景未归类并标 type=机理属他场景待外归）
- 根因+方案/主题均无任何指向、且无法推测功能域的工单，入未归类 type=机理缺失而非子场景
- 纯硬件物理损坏（非软件/配置机理）类工单，应优先归接口物理层/设备系统

## 二、这个场景是怎么拆出来的

### 2.1 拆解维度

| 维度 | 取值 | 为什么按这个维度切 |
|---|---|---|
| 处置去向 | 外归已存在10大场景(未归类·机理属他场景待外归)／归入本场景新建子场景(QoS与ACL/安全防护/配置持久化)／确实无法归类(未归类·机理缺失) | 每条未分类对象/溢出工单的最终归宿，决定其写入子场景、未归类还是归属建议 |
| 失效性质 | 软件BUG/版本缺陷／配置未持久化／ACL/策略表项机制／容量/资源预判错误／安全策略硬编码/可信链／机理缺失 | 按根因机理将失效归类，用于 RCA 失败时定位共性模式 |
| 可追溯性 | 版本可修复(升级解决)／需研发修复(规避/待版本)／机理缺失待补 | 判断该工单能否通过版本-缺陷库闭环，以及 APM 需补哪些可观测点 |

### 2.2 拆解原则

1. **机理优先**：以「根因 + 方案」里的技术失效机理作为第一判据，不按主题字面归类。
2. **排查动作一致**：同一个子场景内的记录，必须能用**同一套排查动作**定位；做不到就再拆。
3. **不硬凑**：机理描述缺失的记录不强行塞进任何子场景；机理明确属于别的大场景的记录，标为「待外归」而非塞进兜底子场景。

## 三、子场景明细

### EXT-MISC-01　QoS与ACL（ACL匹配/QoS调度/限速/统计异常）（11 条）

- **机理定义**：ACL/策略规则在解析、匹配或下发到硬件/软件转发面过程中异常（规则不生效、ACE 条目周期性消失、time-range 范围不生效、range 超容后容量预判错误被反复触发），以及 QoS 调度（SP 等）、限速（ratelimit）或统计（DSCP）因版本实现缺陷/未实现导致调度不生效、限速不准确或统计异常。ACL 与 QoS 同源「QoS与ACL」域，机理相邻，合并为一个子场景。
- **归类判据**：show access-list 有配置但 show access-list counters 不匹配/不增长；新增 ace 后过几分钟消失；range 超过容量后容量预判错误且周期性重试下发；acl deny 策略不生效但计数正常；策略随行/门禁访问不通但 acl 计数正常；配置 SP 调度后 COS 未达预期、可用带宽偏大；DSCP 数据统计异常（命令支持但未实现该功能）；ratelimit 限速不准确。
- **典型现象**：ACL 计数有收发但业务不通、新增 ace 3 分钟消失、time-range acl 部分 ace 显示 inactive、升级后 ACL 失效、终端策略随行故障、门禁系统不通、QoS SP 调度不生效、DSCP 统计异常、限速不准确致 COS 未生效。
- **排查动作**：1) show access-list <acl-name>（示例：show access-list guest-deny） / show qos / show policy-map（待实机核对） 核对 ACE、调度与限速配置；2) show access-list counters 看命中与收发计数，区分 ACL 匹配异常与 QoS 调度异常；3) 检查 time-range range 数量与容量上限，range 不超过 12 条，超容后重启相关进程临时规避；4) 升级到修复版本（如 B74P20 修复 ratelimit 精度）；5) 端口 in/out 方向分别验证逻辑。
- **记录抽样**：
    - Sheet8行 114（CS20230727-2164015）：【随硬件金牌】广州人行核心交换机DSCP数据统计异常
    - Sheet8行 157（CS20230609-1917998）：RG-S5750V2-48GT4XS-L【故障】无法ping通106.39.224.255 但是acl计数有收发
    - Sheet8行 172（CS20230522-1819861）：【高端三层】江西移动CDN交换机12.4版本不支持下发超/64位宽的ACL

### EXT-MISC-03　配置与持久化（7 条）

- **机理定义**：配置未正确保存/持久化，或 running 与 startup/导出配置不一致，重启后丢失或无法生效。
- **归类判据**：保存后 copy run 导出与 show run 不一致；启机后配置丢失；重启丢失 rldp/用户名密码；show run 不显示完整配置（tmp 空间为 0）；配置无法保存生效。
- **典型现象**：配置丢失/不一致/不生效、重启后 RLDP 或账号密码丢失、配置无法保存。
- **排查动作**：1) 先执行 show run 刷新再 copy running-config，避开一致性问题；2) dir / 检查 tmp 剩余空间（为 0 导致读取异常）；3) 核对 startup-config 与 running；4) 规避组件冲突（LDS 与 RLDP）或升级版本。
- **记录抽样**：
    - Sheet8行 238（CS20230223-1379060）：保存配置后copy run 导出的配置未更新，与设备上show run的配置不一致
    - Sheet8行 377（CS20240906-4087600）：设备：S5300-48GT4XS-E，设备启机后配置丢失
    - Sheet8行 463（CS20240416-3401877）：RG-S6000C-48GT4XS-E 主动探测时间与配置不一致

### EXT-MISC-02　安全防护（账号/密码/IPSG/可信校验）（5 条）

- **机理定义**：安全相关特性（IP Source Guard、强密码策略、可信版本校验、安全红线）因版本缺陷、硬编码或功能未实现，导致不生效或校验失败。
- **归类判据**：关闭强密码策略后仍不能输入简单密码；IPSG 不生效；灌装系统报安全校验失败；12.x 导入安全红线后无法改密；任何版本都出现相同安全校验报错；安全扫描提示。
- **典型现象**：密码策略失效、IPSG 不生效、安全校验失败、改密被阻、安全扫描提示。
- **排查动作**：1) show ip source guard / show running-config password policy 核对；2) 确认版本可信链，升级到可信版本（如 12.6(2)B0101S2）；3) 关闭 password policy strong 临时恢复；4) 关闭暴露端口（如 443）规避扫描。
- **记录抽样**：
    - Sheet8行 411（CS20240721-3844079）：客户启动S5860-24XB-U过程发现提示主程序丢失，对设备进行重新灌装系统，发现任何版本都出现相同的安全校验失败的报错。
    - Sheet8行 789（CS20260617-6700096）：RG-S2928G-E V3交换机安全扫描过程中出现提示
    - Sheet8行 799（CS20260528-6623378）：配置IP Source Guard不生效

## 四、RCA 根因分析怎么做（本场景）

### 4.1 技术链

现象（功能不生效/丢包/不通/告警）→ 触发路径（配置下发/版本命中/组件冲突/容量预判）→ 失效点（ACL 表项/容量、QoS 调度、安全特性、配置持久化）→ 直接根因（软件 BUG/硬编码/未实现/未持久化）

### 4.2 失效点分类

| 失效点 | 说明 | 典型记录（Sheet8行） |
|---|---|---|
| ACL 表项下发/容量预判错误 | range 超容后容量预判错误并周期性重试下发，误判已占满致新配置超容；ACE 周期性消失 | 815、817、284、489、787 |
| ACL/策略匹配异常 | 规则存在但计数不匹配、deny 不生效、策略随行/门禁不通 | 157、781、787、719 |
| QoS 调度/限速/统计不准确 | SP 调度 COS 未达预期、DSCP 统计异常（命令支持未实现）、ratelimit 限速偏大 | 805、114 |
| 安全特性不生效/校验失败 | IPSG、强密码策略、可信版本校验、安全红线硬编码 | 799、245、880、411、789 |
| 配置未持久化/不一致 | running 与 startup/导出不一致、重启丢失、tmp 空间满致读取异常 | 238、377、463、726、161、669、711 |
| 软件 BUG 泛化（命中已知 bug 升级解决） | 仅能定位到『已知软件 bug』，无深层子机理，靠版本升级闭环 | 25、68、85、137、205、323、339、359、428、669、747、754、805、811、828 |

### 4.3 排查动作步骤（按序执行）

> 标注「待实机核对」的命令，表示该写法尚未在真机/模拟器上确认，使用前请先验证。

| 步 | 动作 | 命令 / 观测点 | 判读 |
|---:|---|---|---|
| 1 | 确认现象归属功能域 | `show access-list / show qos / show ip source guard / show running-config` | 区分 ACL/QoS/安全/配置类，决定排查链路 |
| 2 | 核对规则实际下发与命中 | `show access-list counters；show access-list <acl-name>（示例：show access-list guest-deny）；show policy-map（待实机核对）` | 有配置但计数不增长=匹配/下发生效异常；range inactive=容量预判 |
| 3 | 检查 time-range/容量上限 | `show access-list 中 range 数量与 capacity` | range 超过 12 条易触发容量预判错误，需拆分或重启进程 |
| 4 | 校验配置持久化状态 | `show startup-config vs show running-config；dir 看 tmp 剩余空间` | 不一致/空间为 0=持久化或存储异常 |
| 5 | 比对版本-缺陷库 | `show version；已知 bug 库/发行说明` | 命中已知 bug 则升级到修复版本闭环 |
| 6 | 认证类不通下钻判读 | `show dot1x users / show web-auth user / show radius-server（待实机核对）；show arp / show ipv6 neighbors` | 认证表项在但 ARP/ND 不刷新=转发问题，下钻 EXT-FWD；认证表项本身残留/异常=本场景认证相关（归 DS-AUTH-09） |

### 4.4 所需可观测点

| 观测点 | 数据源 | 现状 |
|---|---|---|
| ACL/策略硬件表项实际状态 | 表项/配置 | 缺失（show run 与硬件表项不一致难直接观测，需 show access-list counters 间接推断） |
| 配置持久化/保存状态 | 配置 | 缺失（running/startup 一致性、tmp 空间无主动监控） |
| 版本-已知缺陷映射 | 版本/缺陷库 | 缺失（无法从版本号反查已知 bug 导致功能异常） |
| QoS 调度与限速实际效果 | 指标 | 部分缺失（DSCP 统计、COS 生效效果无连续指标） |
| 故障工单根因机理字段 | 工单 | 缺失（大量 '-'/无描述，机理数据采集断层） |

### 4.5 常见根因模式

| 根因模式 | 普遍度 | 典型记录（Sheet8行） |
|---|---|---|

| ACL 表项/容量机制缺陷 | 中 | 157、172、284、489、719、781、787、815、817 |

### 4.6 成功 / 失败对比要点

成功案例：能定位到具体失效点（如 range 超容容量预判、NAT 规则 ID 未下发、大小端算法、ebuff 未释放），并给出升级版本/规避配置闭环；失败案例：根因与方案均为 '-' 或仅写『升级版本规避 bug』，无失效点与触发路径，无法沉淀可复用机理，只能外归或留未归类。

### 4.7 易混子场景判定表

> 用于把本场景内相近的故障模式、以及与相邻大场景的边界区分开。按「现象 → 关键观测点 → 命中即归 → 否则下钻」的顺序判读。

| 现象 | 关键观测点 | 命中即归 | 否则下钻 | 判读依据 |
|---|---|---|---|---|
| 终端能拿到地址但访问被异常放行/绕过认证 | show fp entry 查免认证 FP 表项残留（如 guest/vlan 免认证表项）（待实机核对） | `DS-AUTH-04（认证放行绕过）` | 免认证FP表项干净则查认证表项→DS-AUTH-09 | 有免认证 FP 残留=认证放行绕过(04)；无残留但用户仍不通→继续判读09 |
| 已认证但无法上网/业务不通 | show dot1x users / show web-auth user / show radius-server 查认证表项；再 show arp / show ipv6 neighbors 查 ARP/ND 是否刷新（待实机核对） | `DS-AUTH-09（已认证但不通）` | 认证表项在但 ARP/ND 不刷新→EXT-FWD（转发问题）；认证表项本身残留/异常→本场景09 | 认证表项在但ARP/ND不刷新=转发面问题，下钻EXT-FWD；认证表项本身残留=DS-AUTH-09 |
| ACL/策略配置存在但业务不通、deny不生效 | show access-list <acl-name>（示例：show access-list guest-deny）配置 + show access-list counters 命中计数 | `EXT-MISC-01（ACL规则不生效）` | 规则计数不增/表项不在→EXT-FWD（表项未下发）；计数正常但业务不通→本场景01 | ACL计数不增=表项未正确下发，下钻EXT-FWD；计数正常但业务不通=ACL匹配/策略机制问题，归本场景01 |
| ACL/策略涉及URPF或路由策略(PBR)不生效 | show ip urpf / show route-map 查 URPF 与 PBR 配置下发（待实机核对） | `DS-RT（URPF/PBR路由类）或 EXT-MISC-01（纯ACL策略类）` | URPF配置失败属路由安全→DS-RT；PBR/MLLB异常→DS-RT；纯ACL匹配问题→本场景01 | URPF/PBR属路由协议机理，下钻DS-RT；纯ACL匹配问题归本场景01 |
| QoS SP调度/COS未达预期、限速不准确 | show qos / show policy-map（待实机核对） / show mls qos | `EXT-MISC-01（QoS部分）` | 调度生效但转发仍异常→EXT-FWD（快转丢包） | QoS调度/限速机理归本场景01 QoS部分；若调度正常但仍丢包→下钻EXT-FWD |

### 4.8 对 APM 产品的能力缺口

| 缺口 | 观测对象 | 数据源 | 采集方式 | 阈值 / 触发条件 | 优先级 |

## 八、本场景关键结论

修订后 EXT-MISC 仅保留 3 个机理明确的子场景：QoS与ACL(11，已合并原 EXT-MISC-02 QoS)、安全防护(5)、配置与持久化(7)，合计 23 条。原『分发层』分组（30 条）已按 A-03 取消，全部移入『未归类』type=机理属他场景待外归 并逐条标注建议去向（接入管理面/转发/二层/堆叠/路由/系统/物理层/认证/无线/DHCP 等）；原隧道分组(1) 因根因缺失按 A-06 移入未归类 type=机理缺失。另 5 条（318/464/550/710/716）及 719 同属机理缺失。最终 60 条覆盖：子场景 23 + 未归类 37 = 60，无增删改。39 条未分类对象均在『未分类对象归属建议』逐条登记。建议将 QoS与ACL 与 安全防护 升级为独立大场景。
