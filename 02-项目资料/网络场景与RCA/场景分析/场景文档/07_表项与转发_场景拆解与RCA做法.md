## 一、场景定义与边界

### 1.1 场景定义

聚焦交换机在表项（MAC/ARP/路由等软表，TCAM/FP/mystation/classid/ipmc/counter等硬表）与数据面转发（快转/软转、寄存器/驱动、资源、统计）环节的故障集合。以「根因+方案」的机理为准，重点区分软表学习/老化/残留、硬表下发/同步/残留/容量、芯片寄存器/底层驱动、快转面逻辑与丢包、表项与内存资源耗尽、系统介质/进程挂死等机理，不局限于原表领域标签。

### 1.2 边界判据

**属于本场景：**

- L2 软表（MAC/ARP）学习/老化/残留异常，含 CLI 与芯片表项不一致
- 转发硬表（TCAM/FP/mystation/classid/ipmc/PBR/ACL 表项）下发、安装、残留、容量超限或软硬表不一致
- 芯片寄存器/底层驱动/板卡兼容异常（中断掩码、QSGMII、TPID、MBOARD 等）
- 快转/转发面逻辑与封装缺陷导致丢包、泛洪或业务不通（快转封装、NFPP 限速、ERSPAN、overlay、哈希冲突）
- 表项与硬件/内存资源耗尽（TCAM/NHOP/Counter/FP 资源占满或残留积压）
- 端口/接口统计计数误增（drop/error 误统计，多为软件统计逻辑缺陷）
- 配置/功能未生效与表项操作异常（功能 enable 不生效、表项无法删除、配置时序冲突、DHCP 中继机制缺陷）
- 系统介质（ECC/UBIFS）错误与进程挂死导致控制面崩溃、转发中断

**不属于本场景（易误入，需外归）：**

- 纯配置未下发到运行态且无任何表项/转发表现，且无功能叠加触发的 → 归「配置未生效与配置丢失」大场景
- 纯 SNMP/NETCONF 北向采集协议本身缺陷且无表项/转发实质影响的（如 row 635 的 arp 冲突不上送）→ 偏向网管大场景，本场景仅收纳表项侧确有异常的
- 第三方终端自身进程崩溃（如 row 325 的 shine/GT 进程、IP 冲突在终端侧）→ 归外部依赖/终端，非交换机表项转发机理
- 设备零配置上线/CLI 管理面异常、EMB 配置刷写导致 wconf 未退出（如 row 855）→ 归「WEB/EMB/CLI 管理」大场景而非转发表项
- DHCP 地址分配租约本身（拿不到地址、租约翻转）无表项/中继转发机理的 → 归「DHCP 与地址」大场景；但 DHCP 中继机制缺陷/表项残留（row 558/484）属本场景
- 无根因、仅症状描述的工单（row 402/405/419/431/531/660/697/704/857）→ 未归类

## 二、这个场景是怎么拆出来的

### 2.1 拆解维度

| 维度 | 取值 | 为什么按这个维度切 |
|---|---|---|
| 表项类型 | 软表(MAC/ARP/路由)／硬表(TCAM/FP/mystation/classid/ipmc/Counter)／资源(NHOP/内存/磁盘) | 区分故障对象是控制面软表、数据面硬表还是系统/硬件资源。软表关注学习/老化/残留；硬表关注下发/同步/容量；资源关注占满/积压。 |
| 转发路径 | 快转(硬件转发面)／软转(CPU 转发)／未知/混合 | 判定报文走硬件快转还是 CPU 软转。快转面问题表现为封装/查找/限速/策略逻辑缺陷；软转问题表现为 CPU 收发包或控制面处理异常。 |
| 失效表现 | 未学习/不老化／未安装/错误命中／残留(删而不掉)／容量满/资源耗尽／计数误增／丢弃/不通／寄存器未设置／挂死/崩溃 | 按外在失效形态归类，是定位失效点的第一入口。 |
| 失效层次 | 控制面(软件/配置)／数据面(ASIC/寄存器/驱动)／资源面(内存/TCAM/磁盘)／系统面(介质/进程) | 判定失效发生在哪一层，决定排查工具链（CLI 表项 vs debug-ssa 寄存器 vs 资源/进程/介质日志）。 |
| 触发诱因 | 配置变更/功能叠加／版本缺陷/升级／长期运行/老化／设备重启/复位／无明确诱因 | 归纳触发条件，用于 APM 事件关联与变更回溯。 |

### 2.2 拆解原则

1. **机理优先**：以「根因 + 方案」里的技术失效机理作为第一判据，不按主题字面归类。
2. **排查动作一致**：同一个子场景内的记录，必须能用**同一套排查动作**定位；做不到就再拆。
3. **不硬凑**：机理描述缺失的记录不强行塞进任何子场景；机理明确属于别的大场景的记录，标为「待外归」而非塞进兜底子场景。

## 三、子场景明细

### EXT-FWD-01　L2 软表（MAC/ARP）学习/老化/残留异常（14 条）

- **机理定义**：MAC/ARP 转发表在软件侧出现学习失败、不老化或删除后 CLI/芯片残留：包括 mac 芯片中断导致端口学不到 MAC、老化消息在板间通告被过滤导致残留、efd 等相关进程卡死导致 ARP 学习停滞、镜像/端口安全等功能干扰 MAC 学习、以及命中已知版本 BUG 的 MAC 不老化。软表正确性直接决定二层转发。
- **归类判据**：表现为端口学不到下联 MAC/ARP、MAC 表项不老化、删除后 CLI 仍显示、动态 MAC 数量异常；show mac-address-table / show arp 可见异常；多数最终定位为软件 BUG 或进程卡死，升级版本或重启相关进程可恢复。
- **典型现象**：接入/核心学不到下联 MAC 或终端 ARP；MAC 表项长期不老化；删除 MAC 绑定后表象仍在；SNMP 读取动态 MAC 数量异常；学习异常伴随网络时断时续。
- **排查动作**：show mac-address-table、show mac-address-table count、show arp 确认软表内容；show mac-address-table aging-time 核对老化时间；show process 看 efd 等相关进程是否卡死；镜像/端口安全等可能干扰项逐项剥离；对比 SNMP 读数与实际表项；升级到修复版本或重启异常进程。

### EXT-FWD-04　快转/转发面逻辑与封装缺陷导致丢包或不通（10 条）

- **机理定义**：硬件快转面在报文封装、查找、限速或策略逻辑上存在缺陷，导致业务丢包、泛洪或跨网段/跨设备不通：如快转封装报文时 MAC 异常、源进源出报文被丢弃、NFPP 对上联口 ARP 限速误丢转发面 ARP、ERSPAN 功能将 ARP 请求内部丢弃、qinq tag 列表标签发送异常、VXLAN 虚拟 MAC 与终端 ARP 在 arp 抑制组件处的逻辑冲突、MAC 哈希冲突致数据找不到出接口而泛洪、以及超融合/PR52 广播方案冲突、跨网段不通等版本 BUG。
- **归类判据**：表现为 ping 丢包、部分业务不通、泛洪、视频花屏；多在开启特定功能或功能叠加后触发；抓包可见封装/标签/转发路径异常；多数以升级版本或规避（关功能/改方向）解决。
- **典型现象**：IPv6 ping 丢包（快转封装 MAC 错）；接口出方向 drop 致上下行不对称；NFPP 限速丢 ARP 致终端学不到网关；ERSPAN 后断网；qinq 转发异常；VXLAN 虚拟 MAC 冲突打 ARP 变更日志；MAC 哈希冲突泛洪；超融合广播冲突下行不转发。
- **排查动作**：在上下行口抓包比对封装 MAC/VLAN 标签/转发路径；debug 转发面或查快转/express 表；检查 NFPP/ACL/qinq/ERSPAN/overlay 等功能的配置与版本已知问题；核对 MAC 哈希冲突并静态绑定；对比正常板与异常板转发行为；升级到修复版本或临时规避。

### EXT-FWD-02　转发硬表下发/安装/残留不一致（FP/TCAM/mystation/classid/ipmc/PBR/ACL）（8 条）

- **机理定义**：软件转发决策正确，但下发到 ASIC/FP/TCAM 的硬表存在未安装、错误表项、多余放行表项或删除后残留：如 mystation 表项未安装导致命中不到本机 MAC、FP 表项错误/容量满、PBR 在 AP/SVI 多口应用且下一跳变更时多缓存一份放行表项优先命中、CLI 删除 PBR 后底层残留、ipmc 表项未下发、ip source guard/classid 等表项安装失败。本质是软硬表不一致。
- **归类判据**：表现为业务按错误路径转发、特定表项不生效、新增 ACL 无法加载、PBR 走错下一跳；对比 show 软件配置与 show tcam（待实机核对）/show fp entry（待实机核对）/show acl res（待实机核对）/show ip fib（硬表侧统一）等硬表可见不一致或残留；多因 FP 组件下发逻辑缺陷。

### EXT-FWD-06　端口/接口统计计数误增（drop/error 误统计）（7 条）

- **机理定义**：软件统计逻辑缺陷将协议上送、CPP 上送、ACL deny 或硬件无法过滤的报文误计入接口 drop/error，或协议层统计错误落到端口，导致计数持续增长但实际业务无丢包或计数错位：如 CPP 上送协议丢包展示在上联口 drop、out 方向 ACL deny 报文显示到接口 drop、arp 单播被误统计成 error、协议统计落端口致 drop 虚增、counter 关联失败致流统不准。

### 4.1 技术链

### 4.6 成功 / 失败对比要点

定位核心是三组对照：①软表 vs 硬表——用 show ip route/show arp（软件决策）对 show ip fib（硬表侧统一）/show tcam（待实机核对）/show fp entry（待实机核对）（硬件实际），若软表正确而硬表缺失/错误即硬表未同步(02)，若删除后硬表仍在即残留；②命中 vs 不命中——在接口抓包区分报文是被快转正常转发、被 ACL/NFPP deny、还是根本未查到表项而泛洪/丢弃，结合 debug 转发面确认是封装错(04)还是查找失败；③正常板 vs 异常板——同型号/同版本对比寄存器(run-system-shell/debug-ssa)、资源占用(show tcam utilization（待实机核对）/show acl res（待实机核对）/show memory)与计数器，快速锁定是寄存器(03)还是资源耗尽(05)；统计误增(06)必须用长 ping/业务拨测证明『计数涨但无真实丢包』以排除真实丢包子场景(04)。

### 4.7 易混子场景判定表

> 用于把本场景内相近的故障模式、以及与相邻大场景的边界区分开。按「现象 → 关键观测点 → 命中即归 → 否则下钻」的顺序判读。

## 八、本场景关键结论

表项与转发（EXT-FWD）81 条工单可归纳为 8 类机理：L2 软表(MAC/ARP)学习/老化/残留 14 条、转发硬表(FP/TCAM/mystation/classid/ipmc/PBR/ACL)下发与残留不一致 8 条、芯片寄存器/底层驱动/板卡兼容 8 条、快转/转发面逻辑与封装缺陷 10 条、表项与硬件/内存资源耗尽 8 条、端口统计计数误增 7 条、配置/功能未生效与表项操作异常 11 条、系统介质/进程挂死 4 条。最突出的共性是『软件 BUG 导致软硬表不一致或表项未安装/残留』，约六成以上最终以升级版本解决，版本质量与表项同步/下发机制是核心风险点。另有 11 条归入未归类：其中 9 条缺乏根因/机理描述（多为无描述或仅写『软件问题』），2 条机理明确但属外部依赖/终端（row 325）与 WEB/EMB/CLI 管理面（row 855）、待外归，是 RCA 数据治理的明显短板。对比定位的三大抓手是『软表 vs 硬表命中差异』『真实丢包 vs drop 计数误增』『正常板 vs 异常板寄存器/资源』。
