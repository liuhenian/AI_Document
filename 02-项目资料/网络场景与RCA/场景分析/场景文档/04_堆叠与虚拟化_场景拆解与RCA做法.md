## 一、场景定义与边界

### 1.1 场景定义

涵盖锐捷 VSU（虚拟交换单元）堆叠系统的全生命周期故障：堆叠组建（版本/标识/授权一致性）、角色选举（主/备/候选）、主备倒换、堆叠链路 VSL 的保活与分裂、双主（dual-active）与双主检测（DAD）、成员上下线震荡与恢复、配置同步丢失/回滚；以及堆叠虚拟化在 VSU 之上承载的网关冗余（VRRP 虚地址/虚MAC/双主）和堆叠场景特有的管理/功能面软件缺陷（SNMP 采集、POE 供电、MAC 表、健康度、环境监控告警）。机理优先于主题/原表标签/旧归类线索。

### 1.2 边界判据

**属于本场景：**

- VSU 组建失败（版本/serial number/boot/授权不一致或组建过程软件 BUG）
- VSL 链路物理/协议异常（UP/DOWN、错帧、协商失败、负载不均衡）
- 堆叠分裂（VSL 保活超时、线卡/芯片寄存器中断掩码、DMA 异常触发）及伴生双主
- 主备倒换（引擎/板卡切换）及倒换后控制面进程挂死、表项不同步、能力框架异常
- 成员/备机设备异常重启、上下线震荡、断电后无法重组/恢复
- 堆叠场景配置同步丢失/回滚（断电/升级后配置未持久化）
- VRRP 在 VSU 上的虚地址不可达、主备切换、双主、虚 MAC 学习时序异常
- 堆叠场景特有的 SNMP/POE/MAC/健康度/环境监控告警软件缺陷

**不属于本场景（易误入，需外归）：**

- 通用端口『主备模式』（非 VSU 端口冗余）残留导致转发异常 → 应归『端口冗余与转发大场景』（row=118）
- 纯 ACL/ACE 匹配错乱且未触发 VSU/VRRP 倒换 → 应归『ACL/ACE 异常大场景』
- 纯硬件 ECC/内存位翻转且非堆叠链路相关 → 应归『硬件老化与故障』
- 非 VSU 场景的普通 SNMP/网管采集异常 → 应归『网管采集大场景』
- 盒子单机（非 VSU）的电源/风扇告警 → 应归对应单机环境监控场景

## 二、这个场景是怎么拆出来的

### 2.1 拆解维度

| 维度 | 取值 | 为什么按这个维度切 |
|---|---|---|
| 故障阶段 | 组建期／运行期／倒换期／解体/恢复期 | 组建期=VSU 未成功建立或热加入；运行期=稳态下的链路/分裂/管理面异常；倒换期=主备角色变化瞬间及之后；解体/恢复期=断电/断 VSL 后成员重加入或无法恢复 |
| 触发事件 | VSL链路异常／主备倒换／成员上下线／版本升级／断电/异常掉电／配置操作／无明确诱因 | 定位入口事件，决定优先看链路、角色、还是配置同步 |
| 堆叠形态 | 盒式VSU／框式VSU／口字形／一对多/多对一／热加入 | 框式与盒式在 VSL 分布、线卡、健康度算法上差异大；口字形/集中单卡是已知的分裂风险部署 |
| 失效点 | 链路层／控制面进程／表项同步／配置同步／芯片/寄存器／管理/功能面／虚拟化网关 | 同一套排查动作对应同一类失效点 |

### 2.2 拆解原则

1. **机理优先**：以「根因 + 方案」里的技术失效机理作为第一判据，不按主题字面归类。
2. **排查动作一致**：同一个子场景内的记录，必须能用**同一套排查动作**定位；做不到就再拆。
3. **不硬凑**：机理描述缺失的记录不强行塞进任何子场景；机理明确属于别的大场景的记录，标为「待外归」而非塞进兜底子场景。

## 三、子场景明细

### DS-STACK-05　成员上下线震荡与设备异常重启 / 恢复异常（11 条）

- **机理定义**：成员/备机设备异常重启或上下线震荡：升级版本降级 BUG、ECC 芯片异常、dhcp coredump、boot 版本不一致被主机反复推送升级、TIPC 断开超时被主机 reset、断电后除 VSL 外所有端口无法 up、断电重启后业务不通。失效点为成员设备生命周期/重启恢复。
- **归类判据**：现象含『备机频繁重启/异常重启/无法 telnet-SSH/断电后端口全 Down/无法重组 VSU/业务不通』，根因指向版本降级、ECC、coredump、TIPC、boot 不一致、断电恢复。
- **典型现象**：备机频繁重启；Device2 重启后无法 telnet；一台设备 ECC 重启；VSU 设备 dhcp coredump 重启；备机下电重加电后除 VSL 口外全 Down 无法重组；主机运行超 250 天 TIPC 拒绝备机重连。
- **排查动作**：1) show switch virtual 看成员在线/角色；2) show logging 抓重启原因（ECC/coredump/TIPC reset）；3) dir 或收集死机脚本/cores；4) show ver 逐成员核对版本与 boot 一致性；5) 断电恢复类先重启主机（非备机）再重连 VSL，升级修复版本（如 12.6(3)B0101）。
- **记录抽样**：
    - Sheet8行 180（CS20230509-1759590）：RG-S6120-20XS4VS2QXS VSU组建失败，备机频繁重启
    - Sheet8行 676（CS20250519-5178042）：追觅科技 RG-S6150-48VS8CQ-X VSU备机异常重启
    - Sheet8行 741（CS20260901-6980389）：德银融资租赁有限公司RG-S5750V2-48GT4XS-Lvsu升级B74P22备机频繁重启

### DS-STACK-04　电源 / 风扇 / 环境监控告警误报（VSU 场景）（7 条）

- **机理定义**：VSU 虚拟化上下文下，电源功率、风扇、电压等环境监控软件 BUG 或阈值临界误判，产生告警误报或无法恢复；含框式/盒式内存利用率算法在 VSU 下未考虑各线卡总内存不同的缺陷。失效点为环境监控/算法。
- **归类判据**：根因含 VSU 场景下电源功率低/电压/风扇 line fail/内存利用率误算，且实际硬件正常或仅为临界预警；多命中已知预警（WN20220425002 等）。
- **典型现象**：VSU 切换后电源功率低告警消失；低功率告警无法恢复；风扇 line fail 但温度/转速正常；VSL 电压临界预警；框式各板卡内存显示 90%+ 实为算法错误。
- **排查动作**：1) show env / show power / show fan 看实际供电、温度、转速；2) 比对告警阈值与版本已知预警库；3) show memory / snmp 算法核对（框式需区分主板与线卡总内存）；4) 拔插风扇或打补丁/升级版本（如 12.5(4)B0201、12.5(4)B0501P1_SP1）。
- **记录抽样**：

    - Sheet8行 213（CS20230317-1506917）：【无锡移动SPN/OTN】电源告警供电不足问题
    - Sheet8行 271（CS20230129-1254475）：RG-S7810C设备状态灯异常变红，显示alarm日志为电源功率低

### DS-STACK-06　堆叠组建失败与版本 / 标识 / 授权 / 配置同步不一致（7 条）

- **机理定义**：VSU 组建前置条件缺失（软件版本不一致、底层 serial number 不一致、双机授权未导入）或组建过程软件 BUG 导致组建失败；以及断电/升级后配置文件同步逻辑缺陷导致配置丢失/回滚（备机 rename 时序、CLI 框架未持久化、MGMT 口多虚一丢失）。失效点为组建一致性/配置同步。
- **归类判据**：现象含『组建 VSU 失败/异常/建立失败』且根因为版本/serial/授权不一致或组建 BUG；或根因为断电/升级后配置丢失/命令丢失。
- **典型现象**：serial number 不一致导致组建异常；版本不一致组建有问题；导入双机授权提示备机未导入；断电后配置为空/丢失；引擎切换后 no vrrp preempt 命令丢失；升级后 MGMT 口变两个且 IP 消失。
- **排查动作**：1) show switch virtual 与 show ver 逐成员核对版本/serial number/boot；2) show switch virtual config 看授权与域配置；3) dir 看主备 config.text 与 config.text.tmp；4) 比对主备 show running-config 找差异；5) 升级到一致版本后重新组建，配置丢失类升级修复版本（如 11.4(1)B74P7S3、B58P2）。

### DS-STACK-09　堆叠场景功能面软件缺陷（POE、MAC、健康度、接口选择、双主检测报文）（7 条）

- **机理定义**：VSU 场景特有的功能面软件缺陷：组建/热加入后 POE 不供电或功率未下发到硬件；VSU 后 MAC+IP 静态绑定致 MAC 表项查询为空（需 port-security 查）；健康度计算误扣 VSL 口带宽致 recovery；VSL 端口被占用致 INC 接口无法选择；FP 默认表项误丢弃双主检测（DAD）LLC 报文致端口 drop；软件异常改写 CPLD 致批量接口 down。失效点为功能面表项/寄存器。
- **归类判据**：现象含 POE 不供电、MAC 表空、健康度/recovery、接口被选不到、端口 drop 且根因指向双主检测报文被 FP 丢弃、CPLD 被改写。
- **典型现象**：组建 VSU 后 POE 不供电；热加入 POE 功率未下发；MAC 表项为空需 port-security 查；断开 VSL 进 recovery 因健康度误算；INC 接口因曾作 VSL 无法选；端口持续 drop 因 DAD 的 LLC 报文被 FP 默认策略丢弃；CPLD 被改写致批量接口红灯 down。
- **排查动作**：1) show switch virtual recovery / show switch virtual health（待实机核对）看健康度与 recovery；2) show port-security all 查被绑定的动态 MAC；3) show interfaces GigabitEthernet 0/1（待实机核对）看 drop 计数，必要时 fp_tcam 置 0 验证 DAD 报文被过滤；4) 热加入 POE 查 poe 控制面就绪与功率下发；5) CPLD 改写类升级补丁（如 B9P74_SP2）。
- **记录抽样**：
    - Sheet8行 199（CS20230404-1597189）：RG-S6120-24XMG4XS4VS-UP-E 组建vsu后poe不供电
    - Sheet8行 749（CS20260821-6939527）：S5310-24GT4XS-P-E 热加入S5310-24GT4XS-EVSU场景，导致POE功率为正常下发到硬件，poe供电异常
    - Sheet8行 658（CS20250609-5267751）：RG-S5300-24GT4XS-E客户想查询mac，但设备mac表项中为空，客户涉密环境

### DS-STACK-01　VSU 分裂（VSL 保活超时 / 芯片寄存器 / DMA 中断异常触发）（6 条）

- **机理定义**：VSL 保活报文超时或线卡/芯片 DMA 中断掩码寄存器异常，造成收发包中断，VSU 管理面无法交互，主动触发分裂；常伴双主。失效点为 VSL 保活机制或线卡寄存器。
- **归类判据**：现象含『VSU 分裂/断开/双主』且根因指向 VSL 保活超时、保活线程被中断延迟、DMA/中断掩码寄存器异常、低流量环境芯片寄存器异常（预警 WN20240411002）等。
- **典型现象**：VSU 分裂、业务中断；分裂后双主；VSL 管理帧无法交互；线卡断流。
- **排查动作**：1) show switch virtual 看拓扑与成员状态、是否 split/recovery；2) show switch virtual link（待实机核对）看 VSL 状态与错帧；3) show logging | include VSL/SPLIT/DUAL 抓分裂与保活超时日志；4) 查线卡寄存器/DMA 中断掩码（需研发协助 dump）；5) 核对预警 WN20240411002 命中。
- **记录抽样**：
    - Sheet8行 104（CS20230816-2251781）：RG-S5750-48GT/4SFP-E vsu分裂
    - Sheet8行 223（CS20230306-1437774）：丝路基金测试汇聚交换机S6000C VSU分裂

### DS-STACK-02　VSL 链路 / 堆叠口物理与协议异常（UP/DOWN、错帧、协商失败、负载不均）（6 条）

- **机理定义**：VSL 物理链路或协议协商异常：光模块 TX 功率/信号异常、微控制器问题、M0 芯片挂死、已知软件 BUG 导致 VSL 口 UP/DOWN 震荡或无法协商；或 VSL 负载均衡算法缺陷导致流量集中少数链路占满带宽。失效点为 VSL 链路层/协商。
- **归类判据**：主题/根因含 VSL 接口 UP/DOWN、VSL 链路协商不稳定/错帧、VSL 端口无法协商、VSL 负载不均衡，且为物理/协议层而非保活超时分裂。
- **典型现象**：VSL 接口反复 UP/DOWN 致业务震荡；VSL 错帧报错；4 条 VSL 仅 2 条承载流量、高峰期卡顿；VSL down 引发整机接口/电源/风扇 down。
- **排查动作**：1) show switch virtual link（待实机核对）看各 VSL 链路状态、错帧、丢包计数；2) show interfaces VSL 1（待实机核对）看光衰/TX/RX、CRC；3) show switch virtual config 核对 VSL 成员与负载模式；4) 换光模块/线卡、分散 VSL 到多张卡；5) 命中 BUG 则升级版本（如 11.4(1)B74P7、12.6(2)B1304、12.5(4)B0501P4）。
- **记录抽样**：
    - Sheet8行 151（CS20230615-1956721）：【H客户】【过保超标】S8605E堆叠VSL链路协商不稳定，有报错帧

### DS-STACK-03　主备倒换与倒换后控制面 / 表项 / 进程异常（6 条）

- **机理定义**：主备（引擎/板卡）切换触发：进程挂死被 HAM 杀掉（dm_app 信号丢失、vfw socket 超时）、FP 表项不同步、能力框架 cap 数据库就绪信息丢失导致线卡挂死、或倒换收敛时间超标。失效点为控制面进程/表项同步/能力框架。
- **归类判据**：现象含『主备切换/引擎切换』且根因指向进程挂死、表项异常、cap 就绪丢失、倒换收敛超时；与 VSL 分裂无直接因果。
- **典型现象**：syslog 提示主备切换但业务可能无影响；切换后备机 FP 表项异常；切换后 vfw-server 反复重启；多次切换后线卡 resetting 起不来；主机宕机后业务切换 >36s。
- **排查动作**：1) show switch virtual 看当前角色与切换历史；2) show logging | include SWITCH/HAM/dm_app/vfw 抓倒换与进程重启；3) show process 看 dm_app/vfw 状态与挂死检测；4) 线卡挂死时查 cap 数据库 ssd_cap/ssc_cap 的 ready/real_time 字段；5) 收集死机脚本/cores（参考 support 文档）。
- **记录抽样**：

    - Sheet8行 109（CS20230803-2195967）：【H客户】交换机VSU主备切换
    - Sheet8行 124（CS20230719-2120232）：RG-S2910-48GT4XS-L 三组一对多镜像没有流量，影响客户服务器业务

### DS-STACK-07　VRRP / 虚拟网关冗余异常（虚地址、主备切换、双主、虚 MAC）（6 条）

- **机理定义**：VSU 之上承载的 VRRP 网关冗余异常：VRRP 组 ID/虚地址配置不一致导致虚 IP 不可达；ACL time_range 增删触发 VRRP 主备切换；VRRP 双主；主备引擎切换致 VRRP 角色快速变化引发虚 MAC 下发/删除时序异常使桥组件无法学习；虚地址 ping 不通命中 SVI/WN 缺陷。失效点为虚拟化网关冗余。
- **归类判据**：现象含『VRRP 主备/双主/虚地址不通/虚 MAC/抢占命令』且发生在 VSU 场景，根因指向 VRRP 组配置、ACL 触发、虚 MAC 时序、SVI/WN 缺陷。
- **典型现象**：跨版本 VRRP 组 ID 不一致虚 IP SSH 异常；删除空闲 ACE 触发 VRRP 切换；网络变更重启后 VRRP 双主；主备引擎切换后备机无法学习虚 MAC 发大量广播；ping 不通 VRRP 虚地址；引擎切换后 no vrrp preempt 丢失；VRRP 主机重启后终端丢包超 30 个。
- **排查动作**：1) show vrrp / show vrrp brief 看各 VLAN 的 VRRP 组、虚 IP、主备角色；2) 核对两端 VRRP group-id 与虚地址一致性；3) show logging | include VRRP 抓切换与双主；4) 桥组件侧 show mac-address table 看虚 MAC 学习；5) ACL 触发类查 time_range 线程与 ACE 顺序，规避为先去 ACL 调用再删 ACE 重配。
- **记录抽样**：
    - Sheet8行 29（CS20231129-2795099）：XC交换机设备无法通过虚IP访问ssh登录设备
    - Sheet8行 159（CS20230602-1877019）：【H客户】【独立服销金牌】删除空闲ACE触发VRRP主备切换
    - Sheet8行 356（CS20240922-4164501）：【项目实施】华兴银行 S7808C-X 交换机口字形组网，VRRP的主机重启后，终端丢包超30个。

### DS-STACK-08　堆叠场景 SNMP / 管理面采集异常（5 条）

- **机理定义**：VSU 场景下网管采集软件缺陷：拆堆叠未还原单机仍按成员返回、带外管理口无法获取监控项、SNMP OID 子节点仅显示单框、升级后 MGMT 口多虚一变双口且 IP 消失、框式内存利用率算法未区分主板/线卡总内存。失效点为管理面采集/算法。

- **记录抽样**：

## 四、RCA 根因分析怎么做（本场景）

### 4.1 技术链

现象（分裂/双主/倒换/端口 down/告警）→ 触发路径（VSL 保活超时/寄存器异常/倒换/版本不一致/断电）→ 失效点（链路层/控制面进程/表项同步/配置同步/芯片寄存器/管理面/虚拟网关）→ 直接根因（软件 BUG/版本不一致/配置残留/算法缺陷）

### 4.6 成功 / 失败对比要点

成功定位的工单普遍具备：show switch virtual/link 状态可读、版本与 serial 一致性已核对、倒换/syslog 日志完整、coredump/死机脚本已收集，并能命中已知预警或 BUG 库（如 WN20240411002、WN20220425002、品控 60349/49385/64394）。失败或停留在『未定性』的多因：缺机理（row=361/295/421 根因为空）、纯端口冗余残留误归入（row=118）、未收集死机脚本（row=676）、仅标注硬件退化无日志（row=449/361）。机理清晰是归入子场景的前提。

### 4.7 易混子场景判定表

> 用于把本场景内相近的故障模式、以及与相邻大场景的边界区分开。按「现象 → 关键观测点 → 命中即归 → 否则下钻」的顺序判读。

| 现象 | 关键观测点 | 命中即归 | 否则下钻 | 判读依据 |
|---|---|---|---|---|
| 设备分裂/双主 | show switch virtual 是否 split/recovery；show logging 是否出现 VSL 保活超时/DMA 中断掩码寄存器异常 | `DS-STACK-01（VSL 保活超时/芯片寄存器致分裂双主）` | 若仅 VSL 口 UP/DOWN 震荡未触发 split → DS-STACK-02；若 VSL 口 down 但非堆叠口、纯光衰协商问题 → 端口冗余与转发/物理层大场景 | 分裂必有保活超时或芯片寄存器异常日志；纯链路震荡无 split 状态即非 01 |
| VRRP 双主 / 虚地址不通 | show vrrp 是否双主；show switch virtual 是否同时分裂 | `DS-STACK-07（VSU 上 VRRP 冗余异常）` | 若 VRRP 双主由 VSU 分裂同时引发 → 先归 DS-STACK-01 再关联 07；若非 VSU 场景的 VRRP → 可靠性大场景 | VRRP 组/虚 MAC 时序问题且发生在 VSU 上下文即归本场景 |
| 端口 down / 接口异常 / 批量接口红灯 | 是否为 VSL 口；是否伴 CPLD 被改写或 DAD LLC 被 FP 默认策略丢弃日志 | `DS-STACK-09（功能面：CPLD 改写、DAD 报文被 FP 丢弃）` | 若通用物理口光衰/协商问题 → 物理层大场景；若纯转发丢包且表项异常 → 表项与转发大场景 | CPLD 被改写或 fp_tcam 默认策略丢弃 DAD 报文属 VSU 功能面缺陷，非通用转发 |
| 主备切换后业务异常 | 切换后进程挂死/表项不同步（show process、cap real_time）/ 配置差异（show running-config diff） | `DS-STACK-03（进程/表项/能力框架）或 DS-STACK-06（配置同步丢失）` | 若切换后虚 MAC 学习异常 → DS-STACK-07；若转发不通且非表项 → 表项与转发大场景 | 进程挂死与 cap real_time=0 归 03；配置丢失归 06；虚 MAC 时序归 07 |
| 环境告警（电源/风扇/电压）误报判定 | show env/power/fan 实际值是否正常；VSU 切换后告警是否消失 | `DS-STACK-04（VSU 上下文监控算法误报）` | 实测硬件确实异常 → 硬件老化与故障大场景 | 实采正常或切换后消失且命中 WN 预警即判误报归 04 |

### 4.8 对 APM 产品的能力缺口

## 八、本场景关键结论

DS-STACK 65 条工单中，真正由 VSU 堆叠机理触发的占绝大多数，集中在 VSL 链路异常、堆叠分裂（保活超时/芯片寄存器 DMA 异常）、主备倒换后的控制面/表项异常、成员重启恢复、组建一致性、VRRP 虚拟网关六类。软件 BUG（含已知预警 WN20240411002、WN20220425002）是最高频根因，多靠版本升级解决。管理/功能面缺陷（SNMP/POE/健康度/监控告警）在 VSU 上下文被放大，是堆叠特有的隐性故障。未归类共 4 条：row=118 为端口主备模式残留应移出（机理属他场景待外归）；row=361、295、421 为根因空缺机理缺失（295=VSU异常分裂、421=VRRP双主，均属本场景范畴但缺机理待补）。VRRP 类（07）虽属『虚拟化』，但是否独立成大场景需与上游核对。
