## 一、场景定义与边界

### 1.1 场景定义

聚焦交换机接入层（下联无线 AP、无线终端、有线终端）在纳管、连通、地址获取、性能、供电、VLAN/标签、镜像等环节的故障集合。原始数据由原「无线接入(30 条)」与「终端与组网(21 条)」合并而成。根因主要落在交换机侧软件缺陷、二层/三层表项(MAC/ARP)异常、资源耗尽、配置未生效/不支持、以及少量硬件/固件故障；少量机理涉及交换机与无线协同(CAPWAP/AC/option43/POE)或终端认证放通。以「根因+方案」的机理为准，不局限于原表领域标签。v2 修订：EXT-ACC-04 经逐条复核（见 A-10）确认 22 条均为版本/转发缺陷，无实质 MAC/ARP 或 DHCP 记录需回流，改为按「明确转发机理 / 纯版本 bug」两子类细化并补区分排查动作。

### 1.2 边界判据

**属于本场景：**

- AP 与 AC 的纳管通道异常：CAPWAP 封装/负载均衡、option43 云模式、管理 VLAN 不通、POE 供电不足、聚合成员口配置未加载导致 AP 掉线/无法上线
- 终端(无线/有线)地址获取异常：DHCP snooping/relay 处理、MAC 表满、subvlan 迁移 vid 未通告、dhcpv6 snooping 漫游震荡导致获取不到/获取多个 IP
- MAC/ARP 表项学习/老化异常(不老化、容量满、未通告)致终端同网段/直连/跨卡不通
- 软件版本缺陷致转发丢包/卡顿/网速慢/偶发不通(含资源耗尽、分片解析、无流量下线、广播位地址丢弃等明确机理)
- 配置/能力/协议与标签异常：命令不支持、配置迁移、qinq/vlan tag 逻辑、编解码不匹配、功能(ferr-url)不支持、认证放通(free-url)、端口镜像 tag/芯片行为差异
- 接入侧硬件/固件故障(fpga 固件掉)致直连终端不通

**不属于本场景（易误入，需外归）：**

- 纯核心/汇聚路由协议(OSPF/BGP/静态路由)不通 → 归「路由与三层(DS-RT)」大场景
- AC/WLC 控制器自身软件缺陷(非交换机侧) → 归无线控制器独立场景(待建)
- 终端操作系统/网卡驱动/终端自身问题 → 归终端侧(待建)或留现场定位
- 交换机 DHCP 服务端/中继进程崩溃、租约翻转等纯地址分发机理 → 归「DHCP 与地址(EXT-DHCP)」大场景；接入侧 snooping 表现（表项/丢弃/震荡）按机理优先归本场景 EXT-ACC-02
- 端口物理损坏/光模块/线缆 → 归物理层/端口硬件(待建)
- 上联出口/NAT/安全策略导致的业务不通 → 归出口/安全(待建)

## 二、这个场景是怎么拆出来的

### 2.1 拆解维度

| 维度 | 取值 | 为什么按这个维度切 |
|---|---|---|
| 接入对象 | 无线终端／有线终端／AP(纳管对象) | 区分故障对象：是下联 AP 与 AC 的纳管关系、无线终端接入、还是普通有线终端接入；决定首要排查链(CAPWAP vs 空口 vs 有线端口)。 |
| 失效环节 | 纳管通道(CAPWAP/AC/option43/POE/管理VLAN)／地址获取(DHCP/snooping)／二层连通(MAC/VLAN)／三层连通(ARP/路由)／转发性能(丢包/卡顿/分片)／配置与能力／硬件/固件 | 按机理链路定位失效发生在哪一环节，是 RCA 定界的核心维度。 |
| 根因性质 | 软件版本缺陷/BUG／表项异常(不老化/满/未通告)／资源耗尽/泄漏／配置未生效/不支持／协议/编解码异常／硬件/固件故障 | 归类根因性质，用于沉淀常见根因模式与 APM 监控点。 |
| 影响范围 | 单终端／多终端/同端口组／整机/整网／AP 批量掉线 | 单终端多为终端或端口问题；多终端/整机多为交换机侧表项/版本/广播域问题；AP 批量掉线指向纳管通道。 |

### 2.2 拆解原则

1. **机理优先**：以「根因 + 方案」里的技术失效机理作为第一判据，不按主题字面归类。
2. **排查动作一致**：同一个子场景内的记录，必须能用**同一套排查动作**定位；做不到就再拆。
3. **不硬凑**：机理描述缺失的记录不强行塞进任何子场景；机理明确属于别的大场景的记录，标为「待外归」而非塞进兜底子场景。

## 三、子场景明细

### EXT-ACC-04　软件版本缺陷-丢包/卡顿/性能劣化（22 条）

- **机理定义**：设备软件版本存在已知缺陷，在转发面/快转/芯片处理上导致终端侧丢包、卡顿、网速慢或偶发不通，升级版本恢复。本子场景只收录『版本/软件缺陷』机理的记录，不含 MAC/ARP 表项类（归 EXT-ACC-03）与 DHCP snooping 类（归 EXT-ACC-02）。内部按可归因程度分两类：(A) 有明确转发机理——全局下一跳资源泄漏满致软件转发时延大(row 66)、广播位地址(.0/掩码)默认丢弃(row 144)、无流量下线 bug 误判在线终端掉线(row 214)、IPv6 分片报文芯片未匹配偏移送控制面被 dhcp snooping 匹配丢弃(row 864)；(B) 纯版本 bug/版本问题，无具体表项机理但症状与升级解法一致（其余 18 条）。A-10 复核：22 条均非实质 MAC/ARP 或 DHCP 记录，故不回流，仅按两类细化并补区分排查动作。
- **归类判据**：根因表述为软件版本 bug/版本问题/已知缺陷，或具明确转发机理(资源满、分片、无流量下线、广播位地址)；症状为终端卡顿/丢包/网速慢/偶发不通；升级版本解决；排除 MAC/ARP 表项(EXT-ACC-03)与 DHCP snooping(EXT-ACC-02)后归入本子场景。
- **典型现象**：无线有线均卡顿；终端丢包/网速慢；偶发不通；升级后恢复；全局下一跳满时延大；分片下行被丢弃；无流量下线误掉线；.0 地址 ping 不通。
- **排查动作**：（A 类·明确转发机理）show version 比对已知缺陷库；show cpu / show cpu-protect 看控制面压力；show ip next-hop（待实机核对）与资源计数看是否耗尽；show interfaces counters 看分片/丢弃；查无流量下线配置；与正常版本对比定位明确丢包点。（B 类·纯版本 bug）show version 确认版本并比对已知 bug 库；show interfaces counters 看错包/丢包；与同型号正常运行版本做配置与版本对比；升级到指定修复版本验证。

    - Sheet8行 66（CS20230928-2494440）：【项目实施+Z20230805-05131】无线用户用户上网卡顿
    - Sheet8行 96（CS20230823-2282877）：RG-S7808C 无线终端经常无法上网

### EXT-ACC-01　AP 纳管异常(AP 掉线/无法上线 AC)（8 条）

- **机理定义**：AP 通过 CAPWAP 隧道与 AC 纳管，交换机侧需保证 AP 管理 VLAN 可达、POE 供电、上行聚合、option43 正确下发。任一环节异常(CAPWAP 封装基于源目 IP 的负载均衡无法满足、option43 使 AP 变云模式、POE 功率不足、管理 VLAN 不通、聚合成员口配置丢失、软件缺陷致 AP 管理通道中断)导致 AP 批量掉线或无法上线。
- **归类判据**：症状为 AP 频繁掉线/大面积掉线/无法上线 AC；根因落在 CAPWAP 负载均衡、option43 云模式、POE 供电、管理 VLAN 不通、聚合成员口配置丢失、或软件缺陷致 AP 管理通道中断；排查动作统一为「查 AP 状态→查纳管通道(管理 VLAN/POE/聚合/option43)→查 AC 连通」。
- **典型现象**：大面积 AP 掉线；AP 无法上线 AC；POE 功率不足部分 AP 不供电；设备重启后 AP 口无成员口直连不通；500 台 AP 因命令不支持批量掉线。
- **排查动作**：show ap / show wlan ap（待实机核对）/ show ac(配合 AC)确认 AP 在线状态与离线原因；show poe 看端口供电功率与剩余功率；show running-config interface(聚合口)核对成员口与 port-group；show lldp / ping 管理 VLAN 网关确认管理通道；查 option43 下发；比对 config.text 与 running 配置；升级或补命令规避。
- **记录抽样**：
    - Sheet8行 14（CS20231215-2878441）：AP频繁掉线，设备负载不均衡
    - Sheet8行 16（CS20231214-2872124）：上海市嘉定第一中学无线AP掉线
    - Sheet8行 88（CS20230905-2358226）：S7808C 下联ap大面积掉线，无线业务影响严重

### EXT-ACC-02　终端地址获取异常(DHCP/IP 分配)（5 条）

- **机理定义**：终端/AP 通过 DHCP 获取地址；交换机侧 DHCP snooping/relay、MAC 表容量、subvlan 迁移通告、dhcpv6 snooping 漫游处理异常导致获取不到 IP、获取多个 IP 或因 DHCP 表项震荡断网。包含断电重启后地址分配软件问题、snooping 从错误套接字收包致丢弃、subvlan 迁移 vid 未通告快转、dhcpv6 snooping 5s 防误删触发表项乒乓。注意：MAC 表满（如 row=97 实为 MAC 不老化/满致获取不到 IP）机理属表项类，跨场景同机理已登记；本子场景只收 snooping/binding/通告/震荡类。
- **归类判据**：症状为获取不到地址/获取多个 IP/因 DHCP 处理导致断网；根因涉及 DHCP snooping 表项与丢弃、subvlan/dhcpv6 表项未通告或震荡、断电重启后分配软件问题；排查动作统一为「查 snooping/binding→查 subvlan/dhcpv6 表项→debug dhcp」。
- **典型现象**：无线用户获取不到地址；AP 断电重启后无法 DHCP；DHCP snooping 误丢弃致无法获取；iPhone 因 dhcpv6 snooping 表项震荡断网。
- **排查动作**：show ip dhcp snooping / show dhcp snooping binding 看表项与丢弃；show running-config | inc dhcp/subvlan 核对；debug ip dhcp / debug dhcpv6 看四步交互与表项添加删除时序；清 MAC/重启恢复；升级版本。
- **记录抽样**：
    - Sheet8行 97（CS20230822-2280943）：交换MAC表项容量满，无线用户获取不到IP地址
    - Sheet8行 138（CS20230630-2017400）：【400派单】【河南财经政法大学】N18012作为极简网关的核心，设备断电重启后造成全校无线ap无法获取IP地址，影响全校师生正常访问网络

### EXT-ACC-03　MAC/ARP 表项学习/老化异常致不通（4 条）

- **机理定义**：端口多次震荡或版本缺陷触发 MAC 地址学习后不老化(容量满或长期不刷新)、ARP 学习失败(CPP 阈值满、软件 bug、跨线卡迁移未通告)、subvlan 迁移后 vid 未通告快转，使终端同网段/直连/跨卡数据不通。
- **归类判据**：症状为直连/同网段/管理 VLAN/跨线卡不通；根因明确为 MAC 不老化、MAC 表满、ARP 无法学习、vid 未通告快转；排查动作统一为「show mac/arp→看老化与计数→清表项/升级」。
- **典型现象**：mac 地址不老化引起数据不通；ARP CPP 阈值满 PC 学不到网关 ARP；带源网关 ping 不通；清 MAC 重触发 ARP 后上网正常；阿里定制版本 arp 学习异常。
- **排查动作**：show mac-address-table / show mac-address-table count 看是否满或不老化；show arp 看网关 ARP 是否学到；show cpu-protect(CPP)看 ARP 阈值是否满；clear mac-address-table / clear arp 临时恢复；debug arp 看学习过程；跨线卡场景核对迁移通告；升级修复版本。
- **记录抽样**：
    - Sheet8行 237（CS20230223-1380196）：【微信管家】南海校区办公室区域连接无线偶发持续十几分钟连接后无可用网络
    - Sheet8行 417（CS20240626-3730587）：金山智能产业园 RG-S2910V2-24GT4XS-L 19层所有无线用户上网异常
    - Sheet8行 722（CS20250220-4824193）：【故障】直连同网段无法互通

### EXT-ACC-06　接入侧硬件/固件故障（1 条）

- **机理定义**：接入设备 FPGA 固件掉线/硬件寄存器异常，导致特定直连终端不通。属于硬件/底层故障，需固件重刷或硬件替换，机理不在软件版本缺陷范畴。与 EXT-ACC-04 软件版本缺陷严格区分（本类为硬件寄存器/固件层而非转发面 bug）。
- **归类判据**：根因为硬件/固件层(fpga 固件掉了)；症状为直连特定终端不通、ping 不通；需 U 盘软件重刷或硬件处置；排查动作统一为「show platform/diag→确认 fpga/固件状态→重刷或替换」。本条仅 1 条(row 9)，机理为独立硬件/固件类，与相邻子场景判据不交叉，按 A-09 不合并。
- **典型现象**：直连 77 不通，在对接交换机上 ping 不通，fpga 固件掉。
- **排查动作**：show version / show platform 看 FPGA/固件版本与状态；diag 诊断；核对对接设备能否 ping 通直连终端；U 盘重刷固件或申请备件替换；与软件版本缺陷类(EXT-ACC-04)区分(本类为硬件寄存器/固件层而非转发面 bug)。
- **为什么没有与相邻子场景合并**：本子场景仅 1 条。按「同一子场景内可用同一套排查动作定位」的粒度判据，其失效机理与排查动作与相邻子场景不交叉，故保留独立、不作合并；记录数少反映的是该故障模式在市场工单中发生频次低，而非拆分类别有误。

### 4.6 成功 / 失败对比要点

用『正常终端 vs 异常终端』(同 VLAN/同交换机能否上网、表项是否生成、IP 是否获取)快速定界到端口/终端还是交换机侧；用『单终端 vs 多终端』(单终端多为终端或端口，多终端/整机多为交换机侧表项/版本/广播域)区分层级；用『升级前后版本对比』与『跨卡/跨设备迁移复现』判断表项类(如 row=237 跨线卡迁移复现)；成功案例均有 show version+表项+对比证据，失败/未归类案例多为根因方案空白导致无法沉淀机理。

## 八、本场景关键结论

51 条中 46 条具备可支撑 RCA 的机理(含明确软件缺陷/表项/配置/硬件)，5 条根因方案均缺置未归类。从根因层看，「无线接入」与「终端与组网」二者高度同源：EXT-ACC-04(22 条)与 EXT-ACC-03(4 条)均为交换机侧软件缺陷、MAC/ARP 表项异常，对无线终端与有线终端一视同仁(如 row=19 无线有线均卡顿、row=592 无线有线不定时卡顿)。A-10 修订：对 EXT-ACC-04 共 22 条逐条复核原始工单根因，确认全部为版本缺陷或明确转发机理（下一跳资源满/分片/无流量下线/广播位地址），无实质 MAC/ARP 或 DHCP 记录，故不机械回流，改为按『明确转发机理(A类 4 条) / 纯版本 bug(B类 18 条)』两类细化并补区分排查动作，避免粒度过粗。仍存在一条「无线域专属」子集——EXT-ACC-01(AP 纳管/CAPWAP/AC/option43/POE，8 条)与 EXT-ACC-02 中 DHCP 相关(5 条)，需无线团队协同。总体根因模式以「软件版本已知缺陷」为最普遍(高)，其次为 MAC/ARP 表项异常与 DHCP snooping 处理(中)，配置未生效/资源耗尽/硬件为低。
