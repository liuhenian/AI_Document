## 2. 任务分解（WBS）

```
WBS-0 Leader：需求分析 → 任务规划 → 格式规范 → 下发 → 最终评审 → 发布
WBS-1 数据AI-A：交换机/网络厂商（Cisco/Juniper/Arista/华为/H3C/Nokia/HPE Aruba/Extreme/NVIDIA/ZTE）
   ├─ 1.1 厂商总览表（10行）
   ├─ 1.2 每厂商 ≥3 条技术条目（9字段），其中 AI 相关 ≥1 条
   ├─ 1.3 近10年演进时间线（传统/AI 双轨）
   ├─ 1.4 数据质量自评 + 全量来源清单
   └─ 1.5 三轮修订（v1.0→v1.1→v1.2→v1.3）
WBS-2 数据AI-B：APM/可观测厂商（Datadog/Dynatrace/New Relic/Cisco(AppDynamics+Splunk)/Elastic/
       Broadcom/IBM Instana/Grafana Labs/SolarWinds/OpenTelemetry生态）
   ├─ 2.1 厂商总览表（10行）
   ├─ 2.2 每厂商 ≥3 条技术条目（9字段），AI 相关 ≥1 条
   ├─ 2.3 eBPF 系（Pixie/Cilium-Hubble/Coroot/Groundcover）单列子章
   ├─ 2.4 数据质量自评 + 全量来源清单
   └─ 2.5 三轮修订（v1.0→v1.1→v1.2→v1.3）
WBS-3 评审AI（行业专家角色）：对 A、B 各三轮评审
   ├─ 3.1 第1轮：覆盖度 + 来源真实性（链接可达、无编造）
   ├─ 3.2 第2轮：技术深度 + 原理正确性 + 效果量化 + 案例对应
   ├─ 3.3 第3轮：分析深度 + 用户场景相关性 + 建议可执行性
   └─ 3.4 每轮输出 P0/P1/P2 问题清单 + 合格/不合格结论
WBS-4 整合AI：合并 A/B 终稿 → 统一编号/去重/交叉引用 → 输出正式报告
WBS-5 Leader：最终评审（覆盖率/来源可信/技术深度/分析深度 四维打分）→ 发布
```

## 3. 执行顺序与依赖（流水线与并行）

```
[Leader 规划] --> 并行启动 --> [数据AI-A 初稿] ---\
                              [数据AI-B 初稿] ----> [评审AI 第1轮] --> [A/B 第1轮修订]
                                                      --> [评审AI 第2轮] --> [A/B 第2轮修订]
                                                      --> [评审AI 第3轮] --> [A/B 第3轮修订 v1.3]
[Leader 最终评审] --> [整合AI 汇总] --> 正式 .md
```
- A 与 B 完全独立，**并行执行**；
- 评审依赖数据稿，**串行三轮**，每轮直接下发到对应数据AI；
- 整合串行，最后 Leader 发布。

## 4. 角色定义与提示词要点

| 角色 | 职责 | 关键约束 |
|---|---|---|
| Leader AI | 规划、规范、下发、终审、发布 | 不亲自写数据章节，只做判断与规范 |
| 数据AI-A | 交换机厂商数据收集与分析 | 只用 S/A 级来源支撑时间/背景/案例；链接必须自检 |
| 数据AI-B | APM厂商数据收集与分析 | 同上；eBPF 与 AIOps 深度优先 |
| 评审AI | 三轮评审，必须指出问题 | 每轮 ≥8 问题、≥3 P0/P1；不允许"全部通过" |
| 整合AI | 合并成单一 md | 不改技术结论，只做结构统一与去重 |

## 5. 文档格式结论（已固化到 00-任务规范与格式标准.md）

- 技术条目 9 字段固定顺序；
- 来源 S/A/B/C/D 分级，S/A 支撑官方事实；
- 报告 7 大章（摘要/总览/厂商逐一/时间线/对比/落地建议/来源清单）+ 质量自评；
- 版本 v1.0→v1.3 演进，修订记录逐条对应评审问题编号。

## 6. 风险与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| 官网反爬/无法访问 | 来源缺失 | 改用官方 GitHub / 官方 PDF / 官方 YouTube 关键页；仍失败则登记缺口 |
| AI 编造链接 | 报告不可信 | 评审第1轮强制抽检；数据AI禁止编造，缺失即声明 |
| 时间信息不精确 | 时间线不准 | 允许"据X推断"，但必须写明依据 |
| 内容量过大导致截断 | 交付不完整 | 分厂商分段写盘，先覆盖后加深 |
| 结果过于营销化 | 无技术价值 | 第2轮评审专门打击"只有营销词无原理"的条目 |
