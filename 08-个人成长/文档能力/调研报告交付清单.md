## 二、骨架自检（搭完骨架就查一次）

- [ ] 第 1 章是「第一屏」：结论 / 3 条依据 / 唯一建议 / 请确认什么
- [ ] 有「范围与口径」章：调研了谁、时间窗、信源等级、**不覆盖什么**
- [ ] 有横向对比表（行=维度，列=厂商）
- [ ] 分厂商要点是「做了什么 / 为什么这么做 / 边界在哪」，不是功能罗列
- [ ] 共性结论 ≤ 3 条，每条挂证据编号
- [ ] 「对我们的启示」落到「谁改什么」，不是「值得关注」
- [ ] 有取舍表（做 / 不做 / 重启条件）
- [ ] 待定事项每条带 owner + 日期 + 影响哪条结论
- [ ] 标题全部是论断式，连读能成摘要

---

## 三、交付检查（A 档不过不交）

### A 档 · 阻断项

- [ ] 第一屏 200 字内出现结论、建议、请确认事项
- [ ] 每条结论在证据映射表里都有 1 个 A 级或 2 个 B 级来源
- [ ] 所有厂商宣称（收益 / 领先 / 首发）标了来源或「厂商自述」
- [ ] 写明了「暂不做 X」及理由
- [ ] 每条待定事项有 owner + 日期
- [ ] 空话词汇清零（见下表）
- [ ] 三句话转述测试通过（结论 / 要做什么决定 / 最强理由）
- [ ] 没有把推断写成事实句

### B 档 · 质量项

- [ ] 横向对比表存在且维度统一
- [ ] 每个标题都能独立成句
- [ ] 段落 ≤ 5 行；正文 ≤ 5 页
- [ ] 每张图表被正文引用，且有一句「这说明什么」
- [ ] 数字都带口径（时间窗 / 样本 / 基线）
- [ ] 术语首次出现有定义
- [ ] 源冲突已并列并判定
- [ ] 一稿删掉 ≥ 20% 的字
- [ ] 附录齐：时间线 / 信源总表 / 术语表 / 证据映射表
- [ ] 反方三个问题都能找到答案位置

### C 档 · 加分项

- [ ] 文首一行「本版结论相对上版的变化」
- [ ] 关键结论配一页图，决策者可只看图
- [ ] 结尾给出「如果只做一件事，先做哪件」

## 四、空话清零表（交付前全文搜一遍）

| 搜这些词 | 替换方向 |
|---|---|
| 能力较强 / 比较完善 / 相对成熟 | 支持 X、Y；不支持 Z |
| 生态完善 / 生态丰富 | N 个官方集成，其中 A、B 为一线 |
| 显著提升 / 大幅优化 / 明显改善 | 在 <条件> 下从 A 到 B（来源，日期） |
| 业界领先 / 行业标杆 | 删，或补排序依据 |
| 建议关注 / 值得关注 | 建议做 X，先 A 后 B |
| 深入分析 / 仔细梳理 | 删 |
| 众所周知 / 显而易见 | 补来源或删 |
| 赋能 / 抓手 / 闭环 / 组合拳 | 换成人话动词 |
| 基本 / 大致 / 差不多 | 给区间或给样本量 |
