内核模块中动态内存分配的函数主要分为以下几类，按使用频率和场景排列：

## 一、通用内存分配（最常用）

### 1. **kmalloc 家族**
```c
void *kmalloc(size_t size, gfp_t flags);
void *kzalloc(size_t size, gfp_t flags);        // 分配并清零
void *kmalloc_array(size_t n, size_t size, gfp_t flags);  // 数组分配（防溢出）
void *kcalloc(size_t n, size_t size, gfp_t flags);        // 数组分配并清零
void *krealloc(const void *p, size_t new_size, gfp_t flags); // 重新分配
void kfree(const void *ptr);
```

### 2. **vmalloc 家族**（分配虚拟连续但不一定物理连续的大内存）
```c
void *vmalloc(unsigned long size);
void *vzalloc(unsigned long size);              // 分配并清零
void *vmalloc_user(unsigned long size);         // 给用户空间映射的
void *vmalloc_node(unsigned long size, int node); // NUMA 感知
void vfree(const void *addr);
```

### 3. **页分配器**
```c
unsigned long __get_free_page(gfp_t gfp_mask);  // 分配一页
unsigned long __get_free_pages(gfp_t gfp_mask, unsigned int order); // 2^order 页
unsigned long get_zeroed_page(gfp_t gfp_mask);  // 清零的一页

// 返回 page 结构体
struct page *alloc_page(gfp_t gfp_mask);
struct page *alloc_pages(gfp_t gfp_mask, unsigned int order);
void __free_page(struct page *page);
void __free_pages(struct page *page, unsigned int order);
void free_page(unsigned long addr);
void free_pages(unsigned long addr, unsigned int order);
```

## 二、专用内存池和缓存

### 4. **Slab 缓存**（高频分配同类型对象）
```c
struct kmem_cache *kmem_cache_create(const char *name, size_t size,
                                     size_t align, unsigned long flags,
                                     void (*ctor)(void *));
void kmem_cache_destroy(struct kmem_cache *cachep);
void *kmem_cache_alloc(struct kmem_cache *cachep, gfp_t flags);
void kmem_cache_free(struct kmem_cache *cachep, void *objp);
void *kmem_cache_zalloc(struct kmem_cache *cachep, gfp_t flags);
```

### 5. **mempool**（内存池，保证在内存压力下也能分配）
```c
mempool_t *mempool_create(int min_nr, mempool_alloc_t *alloc_fn,
                          mempool_free_t *free_fn, void *pool_data);
mempool_t *mempool_create_node(int min_nr, ...);  // NUMA 版本
mempool_t *mempool_create_kmalloc_pool(int min_nr, size_t size);
mempool_t *mempool_create_slab_pool(int min_nr, struct kmem_cache *cache);
void *mempool_alloc(mempool_t *pool, gfp_t gfp_mask);
void mempool_free(void *element, mempool_t *pool);
void mempool_destroy(mempool_t *pool);
```

## 三、特殊分配器

### 6. **DMA 内存分配**
```c
void *dma_alloc_coherent(struct device *dev, size_t size,
                         dma_addr_t *dma_handle, gfp_t flag);
void dma_free_coherent(struct device *dev, size_t size,
                       void *cpu_addr, dma_addr_t dma_handle);
void *dma_alloc_noncoherent(...);  // 不同步缓存的
void *dma_alloc_wc(...);           // 写合并的
```

### 7. **cmalloc/devm_ 资源管理版本**（自动释放）
```c
void *devm_kmalloc(struct device *dev, size_t size, gfp_t gfp);
void *devm_kzalloc(struct device *dev, size_t size, gfp_t gfp);
void *devm_kmalloc_array(...);
void *devm_kcalloc(...);
void *devm_krealloc(...);
char *devm_kstrdup(struct device *dev, const char *s, gfp_t gfp);
// 不需要手动释放，设备注销时自动释放
```

## 四、内存分配的核心 GFP 标志

所有分配函数都需要 `gfp_t flags` 参数，常见标志：

```c
GPF_KERNEL         // 标准内核分配，可能睡眠（最常用）
GPF_ATOMIC         // 原子分配，不能睡眠（中断上下文用）
GFP_USER           // 为用户空间分配
GFP_HIGHUSER       // 高端内存的用户分配
GFP_DMA            // DMA 可用内存
GFP_DMA32          // 32位 DMA 可用内存
__GFP_ZERO         // 分配并清零（kzalloc 内部用）
__GFP_RECLAIM      // 允许回收
__GFP_NOWARN       // 分配失败不打印警告
__GFP_NORETRY      // 不重试
```

## 五、Linux 内存分配层次关系

```
用户空间调用
    ↓
kmalloc/vmalloc (最常用)
    ↓
kmem_cache_alloc (Slab 分配器)
    ↓
alloc_pages/get_free_pages (伙伴系统)
    ↓
__alloc_pages_nodemask (核心页分配)
    ↓
物理内存
```

## 六、典型使用场景

```c
// 1. 小内存分配（< 128KB，物理连续）
struct my_struct *data = kmalloc(sizeof(*data), GFP_KERNEL);

// 2. 大内存分配（物理不一定连续）
void *large_buf = vmalloc(10 * 1024 * 1024);

// 3. 高频固定大小对象（网络包、inode等）
static struct kmem_cache *my_cache;
my_cache = kmem_cache_create("my_obj", sizeof(struct my_obj), 
                             0, 0, NULL);
struct my_obj *obj = kmem_cache_alloc(my_cache, GFP_KERNEL);

// 4. 需要 DMA 的硬件驱动
dma_addr_t dma_addr;
void *dma_buf = dma_alloc_coherent(dev, size, &dma_addr, GFP_KERNEL);

// 5. 驱动开发中避免手动释放
struct my_drv_data *drv_data = devm_kzalloc(dev, sizeof(*drv_data), GFP_KERNEL);
// 驱动卸载时自动释放，无需手动 kfree
```

## 七、监控这些函数的跟踪点

回到你的需求，要监控模块的内存分配，这些是内核中对应的 tracepoint：

```bash
# kmalloc 相关
/sys/kernel/debug/tracing/events/kmem/kmalloc
/sys/kernel/debug/tracing/events/kmem/kfree
/sys/kernel/debug/tracing/events/kmem/kmem_cache_alloc
/sys/kernel/debug/tracing/events/kmem/kmem_cache_free

# 页分配相关
/sys/kernel/debug/tracing/events/kmem/mm_page_alloc
/sys/kernel/debug/tracing/events/kmem/mm_page_free

# vmalloc
# 需要 kprobe，没有直接 tracepoint
```
