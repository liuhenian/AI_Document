# 1 方法论 05 · 产品线新功能方向发现法

> **一句话结论**：这份方法论回答的是「**对于我们产品（交换、路由、AC、AP、园区）和公司内部，下一件值得做的事是什么**」。注意答案单位不是「某条产品线再补一个能力」，而是「**某类受益人在某一步被卡住、补上之后他多了一个什么动作**」——这个动作落在产品线内、跨线组合层、公司内部工程、还是售前支撑物，是方向卡里的一个字段，不是问题的前提（见 [[#1.2.2 与 04 的分工：分界在对象，不在受益人|§1.2.2]]）。产出物是一份**功能方向组合（feature direction portfolio）**——每条方向带受益人、带归属、带价值定性、带证据、带可验证的第一段。它**不产出**需求文档（PRD）、不产出排期、不产出技术方案。那些都发生在方向被批准之后。

> **v1.1 修订（2026-10-29，本次口径调整）**：**受益人不设限**（客户、售前、内部开发、内部测试四类平权，见 [[#1.3.1 五条产品线与四类受益人|§1.3.1]]）；**交付形态不设限**（设备内功能、网管、云管、内部工具、测试工具、开放接口均可，见 [[#1.3.2 三个参数（B1–B3）|§1.3.2]]）；**组织方式不设限**（不再强制用七段生命周期归类，可自选轴或自定义，见 [[#1.4.2 通道 A · 场景倒推：组织轴可自选（默认四轴）|§1.4.2]]）。**唯一没有放开的是能力包线（B2）**——芯片、软件栈、认证是工程现实，与部门口径无关，放开它会让整份清单变成「什么都可能、一个都做不了」。三项放开与一项保留的区别，见 [[#1.3.3 参数填错的四种跑偏|§1.3.3]]。
>
> **修订理由（用户原话）**：「我在寻找的时候，都要判断，只要有可能我都会做，不要单纯的局限于部门的情况。」→ **发现阶段的宽度就是价值**；收窄应当发生在判档阶段，不应当发生在搜索阶段。

> **v1.2 修订（2026-10-29，答案单位修正）**：v1.1 放开了受益人、交付形态、组织方式三项**参数**，但 [[#1.2.2 与 04 的分工：分界在对象，不在受益人|§1.2.2]] 的「回答什么」仍写着「产品线…下一个能力做什么」——**这一行才是搜索空间的隐含闸门，它比三项参数更硬**。v1.2 把它改成「对于产品，或者公司内部，能做什么」，并补了四个落点表与三条连带判断。**改动性质：取消「答案必须挂在一条产品线上」这个前提；判据强度不变。**

> **本文与 [[方法论04-新方向发现法-从约束与证据到可规划的方向组合|方法论 04]] 的关系**：骨架同源（三通道合流 → 三道筛 → 方向卡 → 组合视图），**分界不在受益人，而在对象**。04 的对象是「数据能不能用」（取值有效性、多源一致性、采集完整性……）；本文的对象是「产品能力能不能补齐某个动作」（网络流程、设备能力、内部工程效率）。**把 04 的判据直接套到产品线上会得出错误结论**，两者的分工见 [[#1.2.2 与 04 的分工：分界在对象，不在受益人|§1.2.2]]。

## 1.1 体例说明（全文档强制）

英文一律保留并给中文：正文用 `中文（English）`；专有名词用「原名 + 括注中文」；批量术语用两列表。命令、代码、路径、URL、版本号、标准编号（如 `IEEE 802.11be`）不翻译。

**证据四级**（与 04 的三级不同，本文把「厂商营销材料」单独降为 C 级，原因见 [[#1.4.3 通道 B · 供给外溢：四类供给源与竞品三层判据|§1.4.3]]）：

| 级别 | 含义 | 本文用法 |
|---|---|---|
| **A** | 公司内一手事实（工单原文、丢标原因、POC 记录、测试用例与漏测记录、开发缺陷单、报价与 License 记录） | 可单独作为「有人被卡住」的成立依据 |
| **B** | 外部一手事实（标准条款、芯片手册、竞品官方配置手册／命令参考、release note 限制条款、招标文件技术参数表） | 用于证明「有人做了」「做到什么程度」「这是入场券」 |
| **C** | 厂商营销材料与二手信息（官网彩页、发布会、第三方评测、媒体报道） | **只能用于发现线索，不得作为方向成立依据** |
| **D** | 本文推导 | 必须写依据链，不得当事实引用 |

**第 0 条铁律（沿用 04，并加一条扩容）**：

> **链接不通的证据不算证据；只到「宣称」级的证据也不算证据。**

任何一条 B 级证据在写进文档前，必须逐条点开核验，并把「核验方式 + 状态 + 日期」写进附录。核验不通过的，要么换一条，要么降级为「待核」并明确标注。**不接受「我记得友商有这个功能」**——友商彩页上有这个词，和友商真的把它做出来了，是两件不同的事。

## 1.2 这份方法论解决什么问题

### 1.2.1 三句话定位

1. **输入**：一份产品与团队清单（哪几条产品线、哪些交付物、哪几个内部团队）+ 一批既有证据（工单、丢标原因、实施记录、漏测记录、竞品手册、标准条款）。
2. **过程**：三条通道生成候选（组织轴自选）→ 三道筛判档（对外三分类／对内三判据）→ 写成方向卡。
3. **输出**：一份 8~12 条的功能方向组合，分「差异化／补齐／取证／观察」四层，每条附受益人、归属、触发条件与停止条件。

> **为什么方向数量从 6~9 条放宽到 8~12 条**：受益人与形态放开后，候选空间变宽了，但合格判据没有放松——所以是「进来的多了，出去的也没变松」。3~4 人小组的真实承载力上限约 12 条，再多就变成清单而不是组合。

### 1.2.2 与 04 的分工：分界在对象，不在受益人

| 维度 | [[方法论04-新方向发现法-从约束与证据到可规划的方向组合\|方法论 04]] | 方法论 05（本文） |
|---|---|---|
| 回答什么 | 内部 APM 能力下一步做什么 | **对于我们产品（交换／路由／AC／AP／园区）和公司内部，下一件值得做的事是什么**——不限于「某条产品线下再补一个能力」 |
| **受益人** | 内部开发、内部测试 | **内部开发、内部测试、园区客户（含集成商／驻场）、售前方案**——四类平权 |
| **对象（真正的分界）** | **数据能不能用**（取值有效、多源一致、采集完整、现场可复原） | **能力能不能补齐某个动作**（网络流程、设备能力、内部工程效率） |
| 交付形态 | 平台内的能力／证据 | **不限**：设备内功能、网管、云管、内部工具、测试工具、开放接口 |
| 现象的组织方式 | 五类**数据判断动作**（固定分类） | **轴可自选**，默认四轴，允许自定义 |
| 供给盘点 | 同赛道／邻赛道／跨赛道／标准协议 | 同形态竞品／相邻形态（云管、NaaS）／标准与联盟／芯片与 SDK |
| 价值判据 | 合法性／新颖性／可规划性 | 合法性／**对外三分类 + 对内三判据**／可行包线 |
| 档位 | A／B／C | A／B／C + **补齐清单**（第四类，见 [[#1.5.5 判档规则：三档 + 一张补齐清单\|§1.5.5]]） |

一句话：**04 判「这个数能不能用」，05 判「这个能力补上之后，谁多了一个什么动作、他会不会真的用」**。受益人重叠，对象不重叠，所以判据不能互换。

#### 1.2.2.1 为什么答案单位不是「某条产品线的下一个能力」

把这一栏写成「产品线（交换／路由／AC／AP／园区）下一个能力做什么」，后果不是措辞问题，而是**发现阶段就把搜索空间切窄**：

- 写候选时，人会下意识先问「这条挂在哪条线上」，挂不上的**在成稿前就被自己删掉了**；
- 于是「五条线都受益、但没有一条线肯出人」的方向（统一遥测管道、统一数据模型、跨线取证工具）系统性消失；
- 内部开发／内部测试受益的方向也挂不上产品线，同样消失——**而 v1.1 刚把这两类受益人提到平权，若答案单位不变，平权是无效的**。这是 v1.2 必须改这一行的真正原因。

真实的答案单位是一句话，**这句话里没有「产品线」**：

> **某类受益人在某一步判断不了／做不到 → 补上之后他多了一个什么动作。**

产品线只是这个动作**最终被装进哪里**，属于归属字段（[[#1.3.2 三个参数（B1–B3）|§1.3.2]] 的 B1），是「往哪放」的问题，不是「算不算」的问题。同一句话允许落在四个不同位置：

| 落点 | 判据 | 例子 | 谁受益 |
|---|---|---|---|
| **单条产品线内的功能** | 对外三分类（入场券／差异化／增收） | 交换机的端口级丢包定位 | 客户侧 |
| **跨产品线的组合层** | 对外三分类 + D-a／D-b（[[#1.5.3 差异化五来源（D-a 至 D-e）\|§1.5.3]]） | 园区「这个终端在哪一跳掉的」端到端取证 | 客户侧、售前侧 |
| **公司内部工程能力** | 对内三判据（省时／提质／赋能 + 一条外部后果，[[#1.5.2 筛二 · 价值性：对外三分类、对内三判据\|§1.5.2]]） | 缺陷复现用的现网时序回放 | 内部开发、内部测试 |
| **售前支撑物** | 对外三分类 + Q5 交付面（[[#1.5.4 筛三 · 可规划性：Q1–Q5 五问与第一段\|§1.5.4]]） | 现场可跑一遍的「与友商差异」取证脚本集 | 售前侧 |

> 四个落点是**并列可选项，不是四选一的门槛**。一条方向只落在其中一个也算成立；落在两个（例如既是设备内功能、又是售前取证物）更好，但不需要凑满。

#### 1.2.2.2 由此产生的三条连带判断

1. **「是不是产品功能」不再是筛选条件，改成「它有没有让某个人多一个动作」。** 这把尺子对内部工具和对客户功能是同一把——也正是 [[#1.2.5 九种不算新功能（反例清单）|§1.2.5]] 第 5 条（换交付形态本身不算方向）能成立的原因：判的是动作，不是位置。
2. **归属只降档、不淘汰。** 落不到任何产品线的方向进 C 档「无主」，不删（[[#1.5.5 判档规则：三档 + 一张补齐清单|§1.5.5]]）。理由很实际：**这类方向被删掉的次数，远多于它被做出来的次数**；而共享层恰好是单设备功能被同款芯片抹平之后，少数还剩差异化的地方。
3. **放宽答案单位 ≠ 放宽产能。** 仍按格子切批、一次只钻一格（[[#1.7.1 批次切分：一次只做一个格子|§1.7.1]]）。它改变的是「这一格里允许出现什么答案」，不改变「一次做几格」。

**一句话收口**：搜索时问「谁被卡住了」，出稿时问「这个动作装到哪儿」。**顺序反过来，就是抄 release note 的开始。**

### 1.2.3 为什么「新功能调研」最常见的产出是一堆抄作业

这不是执行力问题，是三个结构性偏差，任何一个都能单独解释为什么调研最后长成「友商有什么、我们也做什么」。

**偏差一：取材成本决定结论形状。**

友商的功能清单是**最便宜的材料**——官网有功能列表、有配置手册、有 release note，结构化、可批量抓、还自带版本号。真实卡点是最贵的材料——要翻工单、跟驻场、复盘丢标、翻漏测记录，而且拿到的是一堆口语描述，不结构化。

> **谁的材料便宜，调研就长成谁的样子。** 想不抄，必须在流程上强制「A 通道先做、B 通道后做」——顺序反过来，B 的材料会先占满你的框架，A 就变成给 B 找例证。

**偏差二：缺失不可见。**

客户说得出「我希望有个大屏」，说不出「我在第 4 步判断不了这个 AP 为什么反复掉线」；测试说得出「这个用例过了」，说不出「我没有手段构造出那个竞争条件，所以它其实没被验证过」。**缺失不是需求，是动作序列里的一个断点**，只能通过观察「他实际做了什么、在哪一步停下来」发现，访谈问不出来。

**偏差三：抄友商在评审里零风险。**

「友商都有，我们不能缺」这句话在评审会上没人反对；「这个方向没人做过」要背举证责任。**组织默认选择必然是抄**。方法论如果只提供「更聪明的抄法」，就赢不了这个默认选择。

> 所以本文的真正作用不是「帮你想功能」，是**给「不抄」提供一条比「抄」更安全的论证路径**：谁能拿出「友商只到 L1 没到 L2」的证据，谁就能说清「这不是抄，这是补位」。判据见 [[#1.4.3 通道 B · 供给外溢：四类供给源与竞品三层判据|§1.4.3]]。

### 1.2.4 什么算一个「新功能方向」（六要素定义）

**定义**：一条功能方向 = 一个六元组，六要素缺一条就不成立。

| 要素 | 问句 | 空缺时的典型症状 |
|---|---|---|
| **受益人（who benefits）** | 谁，在哪个岗位上，被卡住了：客户侧（园区 IT／驻场／集成商／无线优化）／售前侧／内部开发／内部测试 | 「客户需要」「大家都会用」——说不出具体岗位 |
| **归属（where it lands）** | 落到哪条产品线、哪个交付物、哪个团队 | 「属于大平台」——没人认领 |
| **定位（where it breaks）** | 卡在哪一步——用哪根轴定位都行（生命周期、能力域、角色链或自定义），但**必须写明用的哪根轴** | 只能说「效率低」 |
| **卡点（what fails）** | 他在那一步**判断不了／做不到**什么 | 「不方便」「不直观」 |
| **新能力（what new action）** | 补上之后他**多了一个什么动作**（不是多了一个页面、多了一个开关） | 「做一个看板」「加一个开关」 |
| **度量（what changes）** | 上线后**谁的哪个数字**会变（AP 上线成功率、单故障处理时长、POC 通过率、丢标次数、漏测率、平均定位时长、版本回退次数） | 「提升体验」——无法证伪 |

> 判据同样很土：**说得出「他原来做不到哪一步，现在能做了」的是功能方向；只说得出「我们支持了什么」的是规格**。

**关于「交付形态不设限」的具体含义**：同一个新能力，落在设备内（CLI／转发面）、网管、云管、内部工具、测试工具、还是开放接口，是**方向卡里的一个字段**，不是成立条件。**先定能力，再选形态**；反过来（先定「要做一个平台」再找能力塞进去）是本末倒置，见 [[#1.9 九种反模式|§1.9]] 第 5 条。

### 1.2.5 九种不算新功能（反例清单）

| # | 反例 | 为什么不算 | 它该去哪 |
|---|---|---|---|
| 1 | 支持更多型号、更大表项、更高端口密度 | 硬件规格延伸，使用者的动作没变 | 产品规格表 |
| 2 | 把友商有的补齐 | 入场券，不产生增量，只防丢单 | 补齐清单（[[#1.5.5 判档规则：三档 + 一张补齐清单\|§1.5.5]]） |
| 3 | 支持某标准／某认证（如「支持 Wi-Fi 7」） | 标准必选项是入场券；除非标准给了新数据、而我们把它变成判断 | 补齐清单，或下沉为方向的一个前提 |
| 4 | 加「AI／大模型」字样但没有新增判断动作 | 换了实现方式，没换使用者的动作 | 打回 |
| 5 | 把已有功能搬到另一个交付形态（设备→网管、本地→云、人工→工具） | **形态迁移本身不算**；但搬过去之后若**多了新动作**（云端可跨站点横向对比、工具可批量重放），那算——判据是「有没有新动作」，不是「换没换地方」 | 形态记入形态字段；有新动作则单独成方向 |
| 6 | 单一客户定制 | 只有一家要，不构成方向；抽象不出第三家就不是功能 | 项目定制 |
| 7 | 性能优化 X%（如转发时延降 20%） | 更快，不是多一个动作；除非跨过某个可感知门槛 | 性能专项 |
| 8 | 把两个入口合成一个 | 体验整理 | 交互优化 |
| 9 | 适配某国产化／信创型号 | 合规性补齐，是入场券 | 补齐清单 |

> 这张表的作用是**挡住 80% 的伪方向**。注意第 5 条在 v1.1 有过一次修正：交付形态放开后，「换形态」不再自动算方向，也不自动算反例——**统一用「有没有新动作」判**。

## 1.3 L0 层 · 归属解析：不设边界，但必须能归属

### 1.3.1 五条产品线与四类受益人

**先定口径（本节最关键的两句）**：

1. 调研对象是**能力**（装进某个交付物、让某类受益人多一个动作的东西）。它**可以装进产品，也可以装进公司内部工具**——两者同一把尺子。商业模式与渠道政策不是调研对象，但**不因为它暂时没有一个卖法就否掉它**——那是判档阶段的事，不是发现阶段的事。
2. **四类受益人平权**。不因为「这不是客户要的」就否掉内部开发／内部测试受益的方向；也不因为「这是内部工具」就自动降档。判据统一走 [[#1.5.2 筛二 · 价值性：对外三分类、对内三判据|§1.5.2]]。
3. **下面这张五条线的表是「归属清单」，不是「搜索边界」**。答案允许落在这五条线之外（内部工具、跨线共享层、售前支撑物），见 [[#1.2.2.1 为什么答案单位不是「某条产品线的下一个能力」|§1.2.2.1]] 的四落点表。

| 产品线 | 典型形态 | 客户真正的购买理由 | 能力主战场 |
|---|---|---|---|
| **交换（switch）** | 盒式接入／汇聚、框式核心、工业交换机 | 端口密度与价格、堆叠、PoE 总功率、可靠性 | 接入认证、环网与堆叠、PoE 管理、端口可视化、有线侧终端识别 |
| **路由（router）** | 出口路由器、SD-WAN CPE、核心路由 | 带宽与并发、多出口选路、VPN、NAT 与策略 | 多出口智能选路、应用识别、IPsec／SD-WAN、策略编排 |
| **AC（无线控制器）** | 硬件 AC、虚拟 AC、云 AC | 统一管住 AP、漫游一致性、射频调优 | 漫游决策、射频调优、AP 上线与批量配置、License 管理 |
| **AP（无线接入点）** | 吸顶／面板／室外／高密，Wi-Fi 6／6E／7 | 覆盖与并发、终端体验、漫游不掉线 | 射频与 MLO、终端体验保障、定位与 IoT、能效 |
| **园区（组合层）** | 整网方案 + 云管平台 + 认证系统 | 一体化运维、端到端可视化、准入合规 | 端到端拓扑与定位、跨设备策略一致、一键取证 |

**为什么把「园区」单列成一条**：园区不是一台设备，是**跨设备的组合能力**。而 [[#1.5.3 差异化五来源（D-a 至 D-e）|§1.5.3]] 会说明，单设备功能会被同款芯片和同份标准抹平，**真正的差异化几乎全部产生在组合层**。所以园区这一行不是「第五条产品线」，是**差异化的主要产地**。

**四类受益人与各自的典型卡点**：

| 受益人 | 谁 | 典型卡点（举例，执行时须换成一手原话） | 一手证据源 |
|---|---|---|---|
| **客户侧** | 园区 IT、驻场运维、集成商实施、无线优化工程师 | 上线返工、告警不知道该干什么、证明不了不是自己的问题、调优后拿不出效果 | 售后工单、实施记录、POC 记录 |
| **售前侧** | 方案架构师、投标支持、渠道技术支持 | 参数表里缺一格就丢分；POC 演示不出差异；说不清「和友商的差别在哪」 | 丢标原因、技术参数偏离表、POC 复盘 |
| **内部开发** | 版本开发、平台开发、驱动与转发面开发 | 缺陷定位靠猜、复现不了现场的时序、改一处不知道影响谁 | 缺陷单、版本回退记录、代码评审记录 |
| **内部测试** | 测试工程师、认证测试、准入与互通测试 | 构造不出竞争条件、判定通过但没有证据、漏测在现网才暴露 | 用例库、漏测记录、认证失败项 |

> **四类平权不是口号，它改变的是「样本从哪来」**：如果只采客户侧，内部开发与测试的卡点会整片消失，产出会退化成「又一个客户要的看板」。反过来，内部测试的漏测记录往往是**唯一能证明「这个能力根本没法验证」**的证据源——这类证据在客户侧永远拿不到。

### 1.3.2 三个参数（B1–B3）

不设边界 ≠ 不设参数。三个参数里，两个是**排序与归属用的软参数**，一个是**硬约束**。

| 参数 | 名称 | 性质 | 当前取值 | 卡在哪一步 |
|---|---|---|---|---|
| **B1** | 归属清单（ownership list） | 软（只做归属，不做排除） | 五条产品线 + 各自交付物 + 四类受益人团队 | 方向卡「归属」「受益人」字段；填不出的进 C 档「无主」 |
| **B2** | 能力包线（capability envelope） | **硬（唯一硬约束）** | 现有芯片型号与代际、自研 OS 与软件基线、已获认证（Wi-Fi CERTIFIED、IPv6 Ready、等保） | 筛三·Q1／Q2／Q3 |
| **B3** | 商业口径（commercial posture，可选） | 软（只用于排序） | 哪些是标配卖点、哪些是 License 加价项、哪些进标书技术参数表 | 筛二·对外分支的加权 |

**三条必须分清的事**：

1. **B1 不排除任何形态**。设备内功能、网管、云管、内部工具、测试工具、开放接口，全部在范围内。B1 只问一句：「它落到谁那里？」
2. **B2 不能松**。芯片不给的数据、软件栈没有的钩子、认证不允许的行为，写进方向池就是给自己挖坑。**放开 B2 的后果不是「多做几个方向」，是「整份清单不可排期」。** 这是 v1.1 唯一保留的硬约束。
3. **B3 不是否决项**。「这功能没有卖法」不构成否掉的理由，只构成「排在后面」的理由。很多能力先有、卖法后来才有（云管订阅就是这么长出来的）。

### 1.3.3 参数填错的四种跑偏

| 跑偏 | 表现 | 后果 |
|---|---|---|
| **把「不设边界」理解成「不用归属」** | 方向写着「构建统一的园区数字底座」，问「谁认领」答不出 | 产出无主清单，每条都重要，每条都没人做 |
| **把「形态不限」理解成「能力包线也松」** | 方向写着「基于 AI 的射频预测」，但现有芯片不给所需射频数据 | 做到一半发现要换芯片，方向作废，前期投入沉没 |
| **把「受益人不限」理解成「不用写受益人」** | 方向写着「提升运维效率」，四类受益人一个都没点名 | 评审无法判断谁来验收，也无法归户 |
| **一次扫全部五条线 × 四类受益人** | 平铺 35 格 + 32 格，每格三行 | 每格都只到 L0，全是浅层结论，等于没做 |

> 最后一条是**产能决定的**，不是口径问题。3~4 人小组的真实产能见 [[#1.7.2 产能与样本下限|§1.7.2]]：一格做到可判档质量约需 5~7 人日。全扫是 67 格，约 350 人日——**没有任何一个季度能给出这个预算**。所以必须切批，见 [[#1.7.1 批次切分：一次只做一个格子|§1.7.1]]。

### 1.3.4 参数变更的影响面

| 变了哪个 | 需要重写 | 不需要动 |
|---|---|---|
| B1 归属清单（增减产品线／团队） | 方向卡的「归属」「受益人」字段，[[#1.14 附录 C · 两张覆盖扫描表\|附录 C]] 扫描表 | 三条通道的流程 |
| B2 能力包线（换芯片／换软件基线／认证变化） | [[#1.5.4 筛三 · 可规划性：Q1–Q5 五问与第一段\|§1.5.4]] 的 Q1–Q3，全部方向的「第一段」 | 通道 A 的困难采集 |
| B3 商业口径（标配转 License 或反之） | 判档排序（可能整体位移），对外分支的加权 | 方向卡的技术字段 |
| 受益人增减（如新增渠道侧） | 采样计划与一手证据源清单 | 方法论骨架 |

## 1.4 L1 层 · 发现：三条通道

### 1.4.1 为什么必须是三条

只走一条通道，会产生**可预测的偏误**：

| 通道 | 起点 | 强在 | 盲区（不看另两条会怎样） |
|---|---|---|---|
| **A 场景倒推**（demand-driven） | 谁在哪一步走不通 | **真实**：有人真的被卡住过 | 想不出没见过的解法；容易把「现状的小改良」当方向 |
| **B 供给外溢**（supply-driven） | 友商／标准／芯片已经能做什么 | **可比**：能拿到现成判据和对标基线 | 容易拿锤子找钉子，做出一堆「技术很新、没人需要」的东西 |
| **C 变化驱动**（change-driven） | 什么正在变 | **时机**：能提前半步卡位 | 变化本身不等于需求；标准发布 ≠ 有人会买 |

**合流规则（本文最重要的一条）**：

> **一条方向必须同时被 A 和 B 碰到；C 只决定「什么时候启动」，不单独生成方向。**
> **补充一条硬约束：A 命中、但 B 只到 L0（宣称级）的，按「只有 A」处理。**

### 1.4.2 通道 A · 场景倒推：组织轴可自选（默认四轴）

**A-0：为什么允许自选轴。**

固定一套分类（比如只许用七段生命周期）会把「装不进去」的现象误判成「不合格」。而**装不进去恰恰是最有价值的信息**——它说明你可能发现了一根新轴。所以规则是：

> **轴可以自选，但方向卡里必须写明「用的哪根轴、落在哪一步」。**
> **如果四根默认轴都装不下，不要硬塞，单列成「新轴候选」并写明「为什么装不下」。**

**四根默认轴**（选一根为主，可以叠加第二根作交叉校验）：

| 轴 | 内容 | 最适合发现什么 |
|---|---|---|
| **轴 1 生命周期七段** | 规划→部署→运行→变更→排障→优化→退役 | 客户侧的流程断点（对外） |
| **轴 2 能力域八类** | 转发与转发面／接入与身份／无线射频与移动性／路由组网与 Overlay／可靠性与韧性／安全与合规／运维可观测与自动化／硬件能效与形态 | 技术能力本身的空档（对外＋对内） |
| **轴 3 角色链** | 客户侧／售前侧／内部开发／内部测试 | 内部工程效率类卡点（对内，七段装不下） |
| **轴 4 问题形态** | 按故障／缺陷／返工的实际形态自定义分组 | 尚无既有分类的新场景 |

**轴 1 的展开（客户侧最常用）**：

| 段 | 客户在这一步做什么 | 典型「做不到」 | 一手证据源 |
|---|---|---|---|
| **plan 规划与设计** | 选址、覆盖预测、容量与带宽测算、VLAN／IP 与策略规划 | 「给我一张我敢签字的覆盖热图」「这个点位到底要几个 AP」 | 售前方案、POC 前勘察记录 |
| **deploy 部署与上线** | 设备注册、批量配置下发、AP 上线、链路起局、PoE 预算核对 | 「一次上线 300 台 AP，不要我逐台返工」 | 实施记录、开局检查单、返工记录 |
| **operate 运行与监控** | 看状态、看性能、收告警、做值班交接 | 「告警告诉我该干什么，而不是告诉我哪个灯红了」 | 网管告警数据、值班记录 |
| **change 变更** | 版本升级、扩容、策略调整、配置比对与回滚 | 「改之前告诉我影响谁，改之后告诉我改成了什么」 | 变更单、变更引发的事故 |
| **troubleshoot 排障** | 定位、取证、复现、给结论、与甲方／第三方划责 | 「证明这不是我的问题」 | 售后工单（密度最高） |
| **optimize 优化** | 射频调优、负载均衡、流量调度、容量回收 | 「调完到底有没有变好，拿什么证明」 | 无线优化记录、巡检报告 |
| **retire 替换与退役** | 设备替换、配置迁移、兼容过渡、数据保留 | 「换设备不换配置、换控制器不掉线」 | 项目交付记录、迁移方案 |

**轴 3 的展开（内部受益最常用）**：

| 角色 | 他在哪一步走不通 | 典型「做不到」 | 一手证据源 |
|---|---|---|---|
| **内部开发** | 拿到现场问题 → 复现 → 定位 → 改 → 验证影响面 | 「现场那个时序我复现不出来」「改这里会影响谁我不知道」 | 缺陷单、版本回退记录、代码评审 |
| **内部测试** | 设计用例 → 构造环境 → 执行 → 判定 → 留证 | 「构造不出那个竞争条件，所以它其实没被验证过」「判过了，但拿不出证据」 | 用例库、漏测记录、认证失败项 |

**A-1：不要按产品分组，按「你选的那根轴」分组。**

按产品分组（「交换的痛点」「AP 的痛点」）会得到一堆设备视角的抱怨；按轴分组，才能看到**跨设备、跨角色那一步**——而跨边界正是差异化的产地。

**A-2：每一格填三列**——出现密度（这一格有多少条一手记录）／卡点原话（逐字）／可否判定（这个卡点能不能写成一个可执行的功能判据）。

**A-3：只留「能写成判据」的。** 门槛与 04 同源，但判据换成产品语言：**这个卡点能否被翻译成「输入什么、判什么、输出什么」？** 翻不出来的（如「客户觉得复杂」）不是功能方向，是体验问题。

**A-4：必须留原话或单号。** 没有工单号、没有录音转写、没有缺陷单、没有漏测记录的卡点，是印象不是发现。

> **与 04 的区别要记住**：04 的五类判断动作问的是「这个数能不能用」；本文的轴问的是「这个能力补上之后谁多了一个什么动作」。**不要把「取值有效性」这类数据判据硬套到产品能力上**——它在园区产品语境里没有对应物。

### 1.4.3 通道 B · 供给外溢：四类供给源与竞品三层判据

**B-1：四类供给源，判据是「对象是否相同」。**

| 源 | 盘什么 | 判断标准 | 三种结论及处置 |
|---|---|---|---|
| **S1 同形态竞品** | 华为、新华三、锐捷（自身）、Aruba、Cisco、Juniper、Ubiquiti、TP-Link Omada 等同档位产品 | 同一批客户、同一批设备形态、同一张标书里出现 | ①三家都到 L2 → 入场券；②只有一家到 L2 → 差异化候选；③只到 L1 → **机会窗口**（见下文） |
| **S2 相邻形态** | 云管与订阅制（Mist、Extreme CloudIQ、Meraki、各类 NaaS） | 设备形态可能不同，**交付方式**不同（云管、订阅、AI 运维） | 可借「交付面」的设计，不可直接借功能——客户买的组织方式不一样 |
| **S3 标准与联盟** | IETF RFC、IEEE 802.1／802.3／802.11、Wi-Fi Alliance、ONF、Broadband Forum | 定义的是**接口与能力边界**，不定义产品功能 | 标准新增的「可观测字段」「可协商能力」，是功能方向的原料，不是方向本身 |
| **S4 芯片与 SDK** | Broadcom、Marvell、Realtek、Cisco Silicon One；开源基线 SONiC／OpenWrt／hostapd | 决定 B2 包线的天花板 | 芯片新能力 = 能做；**能做什么 ≠ 该做什么**，仍要回 A 通道验证 |

**B-2：竞品三层判据（本文的核心操作工具）。**

「友商有这个功能」这句话在调研里几乎总是错的，因为它混了三件不同的事。必须分三层取证：

| 层 | 名称 | 证据形态 | 能证明什么 | 不能证明什么 |
|---|---|---|---|---|
| **L0** | 名称级（marketing） | 官网功能列表、彩页、发布会 PPT、白皮书目录 | 友商**有这个词** | 友商真做了；做到什么程度 |
| **L1** | 可配置级（configurable） | 官方**配置手册／命令参考／管理员指南**里出现对应命令、配置项、参数 | 友商**真的实现了**，且知道它的开关在哪 | 效果如何、有什么限制 |
| **L2** | 可验收级（verifiable） | release note 的**限制条款与已知问题**、监控指标／日志字段、报告样例、公开客户案例、招标参数表 | 友商**能被验收**，且知道它的边界 | 它在我们场景里够不够用 |

**三层判据的操作结论（这一段是本文最值钱的一句）**：

> **L1 已到、L2 未到 —— 这就是机会窗口。**
> 友商把功能做出来了（有命令），但没做好（有限制、没有可验收的指标、案例里不讲）。这类格子有三个好处：①需求已被市场验证过（不用教育用户）；②我们的差异化不需要发明新概念，只需要「做到 L2」；③竞品对标材料现成，评审最容易过。

反过来说：**只到 L0 的格子必须记为「友商宣称」，既不进证据、也不进方向**。这是 [[#1.1 体例说明（全文档强制）|§1.1]] 把营销材料降为 C 级的直接原因。

**B-3：标书是入场券的法定证据。**

园区产品大量走招投标。**近 12 个月的招标文件技术参数表**是判断「这是不是入场券」最硬的证据源——三家友商的参数表都写了同一条，那就是入场券，没有讨论空间；只有一家写了，且客户在评标时问了，那是差异化候选。

对**内部受益**的方向，对应的「法定证据」是另一套：**漏测记录、版本回退记录、认证失败项**。它们的作用与标书参数表等价——都是「不解决就一定会出事」的硬证据。

### 1.4.4 通道 C · 变化驱动：四类变化的识别清单

C 通道只回答「什么时候启动」。它的价值在于**提前半步**——早两步是烈士，晚一步是跟随。

| 变化类型 | 识别问句 | 已知候选（执行阶段须核验条款号与日期） | 影响哪类方向 |
|---|---|---|---|
| **标准换代** | 新标准给了哪些**原来拿不到的数据或协商能力**？ | Wi-Fi 7（IEEE 802.11be）的多链路（MLO）；Wi-Fi 8（IEEE 802.11bn，UHR）；800G／1.6T 以太网；SRv6（RFC 8986）；YANG Push（YANG 推送，RFC 8641） | 无线体验、有线遥测、出口选路 |
| **合规与政策** | 有没有新增「必须留下什么记录／必须支持什么算法」的条款？ | 等保 2.0（GB/T 22239-2019）、商用密码应用安全性评估（GB/T 39786-2021）、IPv6 规模部署、数据安全法 | 准入认证、审计取证、配置合规 |
| **场景变化** | 网络的形态本身变了没有？ | 混合办公、教育信创与实训室、医疗物联网、工业与制造边缘、连锁零售多门店 | 部署与运维段全线 |
| **运维模式变化** | 客户「怎么管」、我们「怎么测」变了没有？ | 本地 CLI → 网管 → 云管／订阅（NaaS）；AIOps；意图驱动配置；自动化回归测试 | 交付面字段（全部方向）、内部测试类方向 |

**C 通道的正确用法**：它只往方向卡里写「触发时点」，不写「新能力」。把「支持 Wi-Fi 7」写进方向池是最典型的误用——那是入场券，见 [[#1.2.5 九种不算新功能（反例清单）|§1.2.5]] 第 3 条。

### 1.4.5 合流规则

| 命中情况 | 处置 | 理由 |
|---|---|---|
| **A + B（B 到 L1 及以上）** | 成立，进三道筛 | 有人被卡住，且有人验证过这条路可行 |
| A 命中，B 只到 L0 | **按「只有 A」处理**，降 B 档 | 宣称级不构成供给证据 |
| 只有 A | 降 B 档，写明「要补哪 2 条外部证据」 | 可能是我们自己的特例 |
| 只有 B | **直接否掉** | 「拿锤子找钉子」的准确定义 |
| C 单独命中 | 不生成方向，只给已有方向写触发时点 | 标准发布 ≠ 有人会买 |

> **内部受益方向的一个例外**：内部开发／测试受益的方向，B 通道的可用材料天然稀缺（友商不公开内部工具，竞品也没有「怎么测」的文档）。此时允许用**开源工具与工程实践**替代 S1（如 CI 里的网络仿真、流量重放、故障注入框架）作为 B 通道证据，但**必须仍是 L1 及以上**（能看到它怎么配、怎么用），不能停在「某篇文章说有这么个东西」。

### 1.4.6 三通道合流检查表

- [ ] 这条方向有**具体受益人 + 具体的一步**（A 命中）
- [ ] 方向卡里写明了**用的哪根轴**，落在哪一步
- [ ] 有**至少 2 条 L1 及以上的竞品／标准／开源实践证据**，或 1 条「L1 到、L2 未到」的机会窗口证据（B 命中）
- [ ] 「新能力」写成了**一个动作**，不是一个界面、一个开关
- [ ] 「归属」填得出来（落到哪条产品线、哪个交付物、哪个团队）
- [ ] 只有 A 命中的已降 B 档，并写明补证动作
- [ ] 只有 B 命中的已否掉，并写进「不做的」清单
- [ ] C 只出现在「触发时点」，没有单独成为一条方向
- [ ] 四根默认轴都装不下的，已单列为「新轴候选」并写明理由

## 1.5 L2 层 · 判定：三道筛

顺序不能换：**先合法性（省钱），再价值性（省力），最后可规划性（省时间）**。

### 1.5.1 筛一 · 合法性：三条硬否决 + 一条归属问

v1.1 把原来四条否决收掉两条——**「是否落在产品形态边界内」和「是否需要客户改架构」不再是否决项**，前者放开、后者改为降档因子。

| # | 问句 | 性质 | 处置 |
|---|---|---|---|
| 1 | 与**已承诺的标准／认证**冲突吗？（宣称支持某 RFC 但实现偏离、宣称 Wi-Fi CERTIFIED 但 MLO 行为不合规） | 硬否决 | 淘汰或整改后再评 |
| 2 | 触碰**密码合规／出口管制／法务**吗？（加密算法选型、密钥管理落在密评范围内、数据出境） | 硬否决 | 转合规评审，不进方向池 |
| 3 | 需要我们**违反客户合同或运维规范**才能用吗？（如未经授权采集客户业务流量） | 硬否决 | 淘汰 |
| 4 | 落到哪条产品线／交付物／团队？ | **归属问（不否决）** | 填不出 → 进 C 档「无主」，不淘汰 |

**降档因子（不是否决）**：需要客户改网络架构才能生效的方向，销售卖不动、交付不敢承诺——**降到 B 档，并在方向卡里写明「前置条件：客户侧改造」**。它可能是真实需求，只是不适合做第一批。

> 为什么把「形态」从否决项里拿掉：形态是**方向卡的一个字段**（见 [[#1.2.4 什么算一个「新功能方向」（六要素定义）|§1.2.4]] 的说明），不是成立条件。先定形态再找能力，是本末倒置。同理，「无主」也不该被淘汰——很多方向是「暂时没人认领」，不是「不该做」。

### 1.5.2 筛二 · 价值性：对外三分类、对内三判据

受益人有四类，价值判据不能只有一套。**先分「对外」与「对内」，再各自判**。

**分支一：对外（客户侧、售前侧受益）**

| 类型 | 判据（满足任一） | 规划含义 | 处置 |
|---|---|---|---|
| **入场券（table stakes）** | ①近 12 个月招标参数表里 ≥2 家友商都写；②≥3 家友商到 L2 | 不做就丢单，做了不赢单 | 进**补齐清单**，按成本批量排，不占方向池预算 |
| **差异化（differentiator）** | ①无人在 L2；②只有 1 家在 L2，且我们命中 [[#1.5.3 差异化五来源（D-a 至 D-e）\|§1.5.3]] 任一条 | 做了能赢单／能抬价 | 进**方向池**，判 A／B |
| **增收（monetizable）** | 客户愿单独付费、愿买 License、或因缺此项有明确丢单记录 | 做了能直接进营收 | 加权，优先排 |

**三问（按顺序问，前一问否掉就不用问下一问）**：

1. **友商是不是标配了？** → 查标书参数表 + L2 证据。是 → 入场券，出池。
2. **客户会为它丢单或加钱吗？** → 查丢标原因、报价与 License 记录。否 → 不是方向，是内部优化。
3. **我们有结构性优势吗？** → 查 [[#1.5.3 差异化五来源（D-a 至 D-e）|§1.5.3]] 五条来源。否 → **只能跟随**，进补齐清单。

> 第 3 问是本文的**结构性壁垒判据**：它把「技术难度」换成「位置」。**同款芯片、同份标准、同一批代工，技术难度挡不住任何人**；能挡住人的只有位置——你在端、AP、AC、交换、出口、平台六级里有几级。

**一条必须补的限定**：入场券判定针对的是「**功能项**」，不是「实现质量」。友商都支持 Wi-Fi 7，这是入场券；我们把 Wi-Fi 7 的漫游切换做得比友商稳，这是入场券之上的实现差异——但它**不改变功能项本身的属性**，所以它进补齐清单，差异化只体现在 D-e（用同样成本做到更好）与体验门槛上。**把「我们做得更好」当成「我们做了新东西」，是本文最常见的一种自我欺骗。**

**分支二：对内（内部开发、内部测试受益）**

对内方向没有「入场券／差异化」这组概念——没有标书、没有友商、没有客户付费。判据换成三条 + 一条硬门槛：

| 判据 | 问句 | 合格的写法 | 不合格的写法 |
|---|---|---|---|
| **省时（time saved）** | 一次动作从多久变成多久？ | 「现场问题定位从平均 2 天压到 4 小时」 | 「提升效率」 |
| **提质（quality gained）** | 少几次返工／漏测／回退？ | 「竞争条件类漏测下降，现网暴露次数减少」 | 「提高质量」 |
| **赋能（new capability）** | 原来根本做不到什么判断？ | 「原来无法证明『这个用例没覆盖到』，现在能给出覆盖率缺口清单」 | 「更全面」 |

**硬门槛（对内方向的生死线）**：

> **必须能追到一个外部后果**——少一次现场返工、少一次误判责任、少一次版本回退、少一次认证失败、少一次丢标。
> **追不到外部后果的对内方向，进 C 档**，理由写「无法证明其价值，等出现一次真实事故再评」。

这条门槛的存在理由很实际：内部工具最容易做成「自己觉得好用、但没人能证明它救了谁」。而口径放开意味着「只要有可能都会做」——**可以做，但要有后果锚点**；否则它会在三个季度后变成无人维护的脚本。

**对外与对内同时受益的方向**：两条分支都过一遍，取**较高的价值定性**，但方向卡里必须分别写清两侧的度量（例：一个「批量配置校验」能力，对客户是省部署返工，对内部测试是省用例构造时间）。

### 1.5.3 差异化五来源（D-a 至 D-e）

网络产品有一个残酷事实：**单设备功能会被同款芯片和同份标准抹平**。Broadcom 一颗芯片卖给你也卖给友商，SDK 一样、能力上限一样，差半年。所以「我们做个更好的单设备功能」这句话，在结构上就不成立。

差异化只能来自这五个位置：

| 来源 | 内容 | 典型可做 | 典型做不了（别当优势） |
|---|---|---|---|
| **D-a 跨设备协同** | 端—AP—AC—交换—出口—平台，六级里跨两级以上才能生效的能力 | 无线漫游与有线准入联动（漫游时端口策略跟着变）；AP 上线自动下发对应端口配置；终端画像在无线与有线侧同一份 | 单台 AP 的射频调优（友商同芯片也能调） |
| **D-b 数据独占** | 只有我们的设备能产出、友商拿不到的数据 | 无线侧空口与终端行为数据、自研 OS 的转发面事件、AC 侧全域漫游轨迹 | 通用 SNMP／Syslog 字段（谁都能采） |
| **D-c 形态独占** | 自研芯片／自研 OS／AC 与 AP 同源代码栈带来的能力 | 软硬一体的低时延保障、AC-AP 同源带来的快速特性联动 | 商用芯片已提供的标准能力 |
| **D-d 交付独占** | 本地化合规、信创适配、行业模板、本地服务响应 | 等保与密评的合规模板；教育／医疗行业开局模板；国产化替代路径 | 「我们服务好」（不可产品化） |
| **D-e 成本结构** | 同芯片做更多，或同功能下沉到更低价格带 | 把只在高端框式上有的能力下放到盒式接入 | 「我们更便宜」（那是定价，不是功能） |

**用法**：对外分支第 3 问直接对照这张表打勾。**五条都不命中的差异化候选，降为「跟随」，进补齐清单**——这不是否定它的价值，是承认它不构成壁垒。

**对内分支的对应物**：内部方向的壁垒来源不是 D-a~D-e，而是**「只有我们能看到的现场数据」**——现网工单、现场拓扑、客户真实配置、认证失败样本。这类数据友商拿不到，第三方工具更拿不到，所以「基于自有现场数据做的内部能力」天然有壁垒；反之「基于通用开源工具搭的内部能力」没有壁垒，谁都能搭。

### 1.5.4 筛三 · 可规划性：Q1–Q5 五问与第一段

前四问是**可行包线（feasibility envelope）**，第五问是**交付面**问题。

| # | 问句 | 不合格的样子 |
|---|---|---|
| **Q1** | **不改芯片、不改硬件**能做到吗？ | 「等下一代芯片支持就能做」 |
| **Q2** | 软件栈里**已有钩子**吗？（已有采集点、已有配置框架、已有数据模型） | 「先重构配置框架，再做这个功能」 |
| **Q3** | 依赖的**标准定稿了吗**？（草案可用，还是要等定稿） | 「等 RFC 正式发布」 |
| **Q4** | 能切出**一季可验证**的片段吗？（实验室可复现 + 单一用户可验证 + 有可观测结果） | 「先做半年底座，再看效果」 |
| **Q5** | **交付面能承接吗**？受益人日常用的那个界面上能显示出来吗？ | 「设备上敲命令能看到」 |

> **Q5 在园区场景里是硬门槛，不是加分项。** 园区客户 90% 不敲 CLI，日常操作在网管或云平台上；测试工程师不看 CLI，看的是用例结果与失败原因。**一个只能通过原始命令行看到的能力，在使用者那里等于不存在**——这也是 S2 相邻形态（云管厂商）能在功能并不更强的情况下赢单的原因。
>
> 注意 Q5 与「交付形态不限」不冲突：形态不限说的是**可以落在任何界面上**，Q5 说的是**必须落到某个界面上**。一个是放开选择，一个是禁止「没有界面」。

### 1.5.5 判档规则：三档 + 一张补齐清单

| 档 | 条件 | 规划含义 |
|---|---|---|
| **A 立即可规划** | 筛一三条硬否决全过；对外属差异化或增收／对内过「外部后果」门槛；Q1–Q5 全过；归属填得出 | 可进本季／下季排期，直接写资源需求 |
| **B 取证后可规划** | 缺 1 个可补条件（通常是 B 层证据不足，或 Q1／Q3 依赖外部节奏，或有「客户侧改造」前置） | 只给取证人力，取证完成即升 A |
| **C 观察** | 缺 2 个以上条件，或依赖不可控外部事件（标准定稿、友商动作、政策落地），或**无主**，或**对内方向追不到外部后果** | 只留监控卡，不投人 |
| **补齐（第四类）** | 属入场券，不构成差异化 | **单列，按成本批量做，不占方向池预算** |

**为什么必须把「补齐」单列成第四类**：它消耗的预算和 A 档一样多，但产出的差异化是零。混在方向池里，它会挤掉真正有差异化的方向——而且因为「友商都有」这句话在评审里最安全，它**一定**会挤赢。单列是唯一能挡住它的结构设计。

**判档不是评价好坏，是评价「现在能不能排期」。** 一条 C 档方向可能价值最高——比如依赖 Wi-Fi 8 定稿的可靠性特性，价值大但不可控，就该留在 C 档等触发。

## 1.6 L3 层 · 输出：方向卡、组合视图、一页规划书

### 1.6.1 方向卡（十字段 + 证据行）

| 字段 | 填什么 | 常见填错 |
|---|---|---|
| **编号／名称** | 短、可口头复述 | 「智能园区网络解决方案」 |
| **受益人** | 客户侧／售前侧／内部开发／内部测试，可多选但须分主次 | 「用户」 |
| **归属** | 产品线 + 交付物 + 团队 | 「属于大平台」 |
| **定位** | 轴 + 具体哪一步 | 「运维」 |
| **卡点** | 原话式描述（引号内逐字） | 「缺乏手段」 |
| **新能力** | 一个动作（能判、能比、能证明、能一键做成） | 「一个可视化大屏」 |
| **形态** | 设备内／网管／云管／内部工具／测试工具／开放接口（可多选，写明主形态） | 「全系列」 |
| **价值定性** | 对外：入场券／差异化（命中 D-x）／增收；对内：省时／提质／赋能 + **外部后果** | 「重要且紧急」 |
| **可行包线** | Q1–Q5 逐项结论 + 第一段（一季内验证什么） | 「技术上可行」 |
| **档位／触发** | A／B／C（或补齐）+ 升档需要的证据 + 停止条件 | 「优先级高」 |
| **证据行** | 内部单号 + 外部可点开链接（标注 L0／L1／L2） | 「有研究表明」 |

### 1.6.2 证据四级与三条硬规则

四级定义见 [[#1.1 体例说明（全文档强制）|§1.1]]。**成立门槛：至少 1 条 A 级 + 2 条 B 级**（其中至少 1 条为 L1 及以上的竞品／标准／开源实践证据）。C 级只能出现在「线索」栏，D 级不得单独出现。

三条硬规则：

1. **外部链接必须点开核验**，写核验方式、状态、日期（第 0 条铁律）。
2. **竞品证据必须到 L1（配置手册级）**，L0 不算——这条比「链接能打开」更严格，因为它拦的是「能打开但什么也没证明」。
3. **一手证据必须给单号或原话**，工单号、缺陷单号、漏测记录号、录音转写、实施记录，五者之一。

### 1.6.3 方向组合视图（四层）

| 层 | 方向 | 一句话 | 受益人 | 本次投入 | 升降档条件 |
|---|---|---|---|---|---|
| **差异化** | … | … | … | 给研发资源 | 友商到 L2 则降为补齐 |
| **补齐** | … | … | … | 按成本批量 | 不再单独立项 |
| **取证** | … | … | … | **只给取证人力** | 补到 N 条 B 级即升差异化 |
| **观察** | … | … | … | **不投人** | 出现 X 事件则重评 |

**组合视图必须能一句话说清「本季为什么只投这两条」**。说不清，说明判档没做，只是把清单按感觉排了序。

**四类受益人的配比要显式写出来**。一个常见的失衡是「客户侧占 90%、内部两侧共 10%」——这不算错，但如果不显式写明，内部方向会永远排在队尾，然后以「没有预算」的名义消失。

### 1.6.4 一页规划书模板（给上级看的就这一页）

```
结论：本季可排期 N 条，取证 M 条，补齐 K 条，观察 J 条。
     受益分布：客户侧 a 条 / 售前侧 b 条 / 内部开发 c 条 / 内部测试 d 条。
A 档（差异化／增收／内部赋能）：
  1) <名称> —— 受益人：<客户侧|售前|开发|测试>；归属：<产品线/交付物>
     定位：<轴> / <哪一步>；新能力：<一个动作>；形态：<设备/网管/云管/内部工具>
     价值：差异化（命中 D-x）／增收／对内（省时/提质/赋能）
     度量：<谁的哪个数>；外部后果（对内方向必填）：<少一次 XX>
     证据：内部 <单号>；外部 <L2 链接>、<L1 链接>；机会窗口：<友商到 L1 未到 L2 的证据>
  2) ...
B 档（不排期，只取证）：
  1) <名称> —— 缺的是 <哪一条>，取证动作：<具体动作>，预计 <人日>
补齐清单（入场券，单列预算）：
  - <功能> —— 依据：<招标参数表条款 / 3 家 L2 证据>
不做的（附理由）：
  - <方向> —— 否决依据：<筛几·第几问 / 只有 B 命中 / 无主 / 追不到外部后果>
```

「不做的」这一节不能省。它防的是同一批方向在半年后被重新提出，又走一遍流程。

## 1.7 调研作业规程

方法论不写作业规程，就一定会被执行成「每人分一条产品线、各自上网搜」。

### 1.7.1 批次切分：一次只做一个格子

| 批次规模 | 候选产出 | 收敛后方向 | 人日 |
|---|---|---|---|
| 1 条产品线（或 1 类受益人）× 1~2 步 | 5~8 条候选 | 3~5 条 | 5~7 |

**为什么不按产品线整条做**：一条产品线 × 七段 = 7 格，做到可判档质量约 35~49 人日。3~4 人小组一个季度约 60~80 人日有效产能，一条线就吃掉大半，且拿不到横向对比。

**正确的切法是「先扫后钻」**：第一轮用 [[#1.14 附录 C · 两张覆盖扫描表|附录 C]] 把格子里各填一行「我们有什么／已知空白／谁在做」，只到 L1，约 3~5 人日；然后按「空白 × 证据密度」挑 2~3 格深钻。**扫是为了选题，钻才是调研。**

**一处必须点明的例外**：首轮空扫用的是 B 通道材料（友商手册、标书），这与 [[#1.2.3 为什么「新功能调研」最常见的产出是一堆抄作业|§1.2.3]] 的「A 通道先做」并不矛盾——**空扫只用于选题，不用于生成方向结论；格子选定之后，那一格内部仍必须先做 A 通道再深挖 B**。顺序一旦反了，B 的材料会先占满框架，A 就退化成给 B 找例证。

### 1.7.2 产能与样本下限

| 动作 | 单件耗时 | 一批的下限 |
|---|---|---|
| 工单／缺陷单归一（按选定轴打标） | 约 100 条／人日 | 每个格子 ≥ 30 条可达「有密度」判断 |
| 竞品 L1 核查（翻配置手册找命令） | 6~8 个功能／人日 | 每方向 ≥ 3 家竞品 |
| 标书参数表扫描 | 1 份／2 小时 | 近 12 个月 ≥ 5 份 |
| 标准条款核对（RFC／IEEE） | 2~3 条／人日 | 只核与方向直接相关的条款 |
| 内部访谈（开发／测试各 2~3 人） | 1 小时／人 | 每批 ≥ 4 人，且必须问到「上一次你复现不出来是哪次」 |
| 链接核验 | 40~60 条／人日 | 全量 |

### 1.7.3 落库结构与命名

```
00-待整理/业界分析/
  <产品线>/                      # 交换 / 路由 / AC / AP / 园区
    <产品线>-能力方向调研-<轴>-<步>-<批次号>.md
  内部能力/                      # 受益人为开发或测试的方向
    <团队>-能力方向调研-<轴>-<批次号>.md
  _索引-产品线功能方向.md          # 全批次的入口，一行一条方向
```

命名规则：产品线（或团队）+ 调研类型 + 轴与步 + 批次号。**轴名必须用四轴的标准词**（生命周期／能力域／角色链／自定义），否则索引无法按轴聚合。

### 1.7.4 链接核验规程

| 状态 | 处置 |
|---|---|
| 可打开且内容对得上 | 记 OK + 日期 + 核验方式（如「官方手册 MLO 章节，含 `mlo enable` 命令」） |
| 需登录／区域限制 | 记「受限」+ 日期，并另找一条可公开取回的替代证据 |
| 404／跳转到不相关页 | **必须换源**，不得标「待核」后继续使用 |
| 能打开但正文无相关内容 | 视同 404（这是最常见的误判） |

## 1.8 停止条件与重启条件

### 1.8.1 什么时候该停止找方向

三个信号同时成立时停：

1. **A 档已有 ≥ 3 条**，每条满足 1A + 2B 门槛，且**四类受益人里至少三类各有一条**。
2. **取证层剩下的都是「靠等」的**（等标准、等芯片、等友商），取证动作已无处可做。
3. **再找下去只会产生补齐项和 C 档。**

此时继续找方向是**逃避执行**——找方向比做功能舒服，且永远找得到新材料。

### 1.8.2 什么时候必须重开一轮

| 触发 | 为什么必须重开 |
|---|---|
| **B1／B2 变更**（产品线增减、芯片换代、认证变化） | 能力域变了，旧组合可能整批失效 |
| **差异化方向被证伪**（第一段验证结论相反） | 组合要补位，不能只剩空档 |
| **友商到 L2** | 原「机会窗口」关闭，差异化降为补齐 |
| **新增一类丢标原因或漏测类型** | 说明出现了一个此前没被识别的入场券 |
| **标准定稿** | C 档可能直接升 A |
| **四类受益人配比失衡**（某类连续两季 0 条） | 说明采样口径漏了一类人，要补采不补结论 |

## 1.9 九种反模式

| # | 反模式 | 表现 | 后果 | 对策 |
|---|---|---|---|---|
| 1 | **抄 release note 当方向** | 「友商 3.2 版本加了 X，我们也做」 | 做出入场券，不产生增量 | 三层判据 + 对外第 1 问（[[#1.4.3 通道 B · 供给外溢：四类供给源与竞品三层判据\|§1.4.3]]） |
| 2 | **追标准名词** | 「支持 Wi-Fi 7 是重点方向」 | 提前投入做必选项，无差异 | C 通道只定时点（[[#1.4.4 通道 C · 变化驱动：四类变化的识别清单\|§1.4.4]]） |
| 3 | **大客户定制当通用功能** | 一家客户的特殊流程写成产品特性 | 版本被单客户绑架 | 反例清单第 6 条，必须能抽象出第三家 |
| 4 | **规格延伸当功能** | 「支持 48 口」「表项翻倍」 | 使用者的动作没变 | 反例清单第 1、7 条 |
| 5 | **先定形态再找能力** | 「我们也要做一个云管平台」，然后往里塞功能 | 平台建好了，没人说得清它多了什么动作 | 形态是字段不是条件（[[#1.2.4 什么算一个「新功能方向」（六要素定义）\|§1.2.4]]） |
| 6 | **Demo 视频当证据** | 拿发布会演示当「友商已实现」 | 证据作废，连带整份材料 | 证据必须到 L1（[[#1.6.2 证据四级与三条硬规则\|§1.6.2]]） |
| 7 | **只写做了什么** | 「完成 XX 模块开发」 | 评审无法判断价值 | 只认「他原来做不到哪一步」 |
| 8 | **用「业界趋势」代替条款号** | 「业界普遍认为园区在向云化演进」 | 无法核对，等于没说 | 必须给标准编号或标书条款号 |
| 9 | **内部工具自娱自乐** | 内部方向写不出「少了一次什么」 | 三个季度后变成无人维护的脚本 | 对内硬门槛：追不到外部后果进 C 档（[[#1.5.2 筛二 · 价值性：对外三分类、对内三判据\|§1.5.2]]） |

## 1.11 第一批执行建议（待确认）

按「证据密度 × 差异化产地」排序，建议四批，先做前两批：

| 批 | 范围 | 为什么排这个位置 | 预期产出 |
|---|---|---|---|
| **批 1** | 交换 × 排障（客户侧） | 工单密度最高，A 通道材料现成，最容易出「有密度」结论 | 3~5 条，≥1 条差异化候选 |
| **批 2** | AP + AC × 优化（客户侧） | D-a／D-b 最集中：无线侧数据独占 + AC-AP 同源协同，是唯一能对友商形成结构性优势的格子 | 3~5 条，重点找「友商到 L1 未到 L2」的窗口 |
| **批 3** | 内部测试 × 角色链（对内） | 漏测记录是唯一能证明「这个能力根本没法验证」的证据源，且在客户侧永远拿不到；同时能验证对内三判据是否可用 | 2~4 条，每条必须有「少一次什么」 |
| **批 4** | 路由 × 部署（客户侧）＋ 园区组合层 × 运行 | 多出口与 SD-WAN 开局是丢标高发段，B3 商业口径清晰；园区组合层依赖前三批结论做输入 | 2~3 条，重点看增收与跨设备协同 |

**开工前必须先做的一件事**：用 [[#1.14 附录 C · 两张覆盖扫描表|附录 C]] 做一轮空扫（只填「我们有什么／已知空白／谁在做」，3~5 人日）。**没有这张表，选题就是凭感觉**；有了这张表，上面四批的顺序才有依据。

**批 3 单独说明**：这是 v1.1 新增的一批，用来验证「对内三判据」在真实材料上能不能跑通。如果不做批 3，整份方法论的对内部分就只是纸面设计——**而内部开发与内部测试恰恰是本次口径放开最主要的目的**。

```
────────────────────────────────────────────────
单批合计  ≈ 12~15 人日（含首轮空扫；后续批次可省 Step 1）
产出：一页规划书 + 一份功能方向组合 + 两张覆盖表
```

**五个必须记住的判断**：

1. **只有 B 命中的方向，直接否掉。**
2. **L1 已到、L2 未到，才是机会窗口。**
3. **单设备功能会被同款芯片抹平，差异化只在 D-a~D-e 五个位置；对内的壁垒是「只有我们能看到的现场数据」。**
4. **入场券单列成补齐清单，否则它一定挤掉差异化。**
5. **对内方向追不到「少了一次什么」，就不是方向。**

## 1.18 附录 G · 全景输出规程（供给侧总览）

> 本节回答一个具体问题：**在深挖之前，怎么把「业界与学术界已经有的功能／方向」一次性铺开，铺成一张能做判断的表。** 它是 [[#1.4.3 通道 B · 供给外溢：四类供给源与竞品三层判据|§1.4.3]] 的全量执行版，**不是新方法**，也不替代通道 A。

### G-1 全景是什么、不是什么

| 是 | 不是 |
|---|---|
| 供给侧 S1–S5 的**全量行级清单**，一行一个可替换的动作 | 按厂商分组的「功能罗列」（那是彩页汇编） |
| 给「值不值得深挖」提供依据的**筛选器** | 结论（全景只输出短名单，不输出「要做」） |
| 覆盖度可自证的**网格**：每格要么有行，要么写了「已扫无」 | 想到哪写到哪的笔记 |
| 3~5 人日可完成的**粗粒度**材料（只到 L1） | 每条都追到 L2 的深度调研（那是深挖阶段） |

三句硬规矩：

1. **排序单位是「动作」，不是「厂商」**。写「变更前用快照比对预演影响面」，不写「某厂商的变更管理」。一行一个动作，一行只归一处坐标。
2. **没有 L1 证据的行不进主表**。L0（彩页／发布会）只能进备注列；判断依据见 [[#1.4.3 通道 B · 供给外溢：四类供给源与竞品三层判据|§1.4.3]] 的三层判据。
3. **全景不替代通道 A**。全景回答「别人做了什么」，方向成立仍要 A 侧「有人被卡住」。只靠全景出方向，就是 [[#1.2.3 为什么「新功能调研」最常见的产出是一堆抄作业|§1.2.3]] 里的偏差一。

### G-2 三层结构：坐标系 → 行级卡片 → 五张判定视图

| 层 | 内容 | 产出形态 |
|---|---|---|
| **L-0 坐标系** | 选一根主轴做网格底：默认轴 1 生命周期七段 × 五条线（对外）或轴 2 能力域八类 × 四类受益人（对内），见 [[#1.4.2 通道 A · 场景倒推：组织轴可自选（默认四轴）\|§1.4.2]] | 一张空格表（可直接用 [[#1.14 附录 C · 两张覆盖扫描表\|附录 C]]） |
| **L-1 行级卡片** | 一行一个动作断点，九列（见 G-3） | 主表，120~160 行 |
| **L-2 五张视图** | 从主表派生，用于**做判断**而不是读材料（见 G-5） | 五张派生表 + 一张热图 |

> **顺序不能反**：先有网格再填行，否则行的坐标互相重叠，热图算不出来，空白判断就失效。

### G-3 行级九列（主表口径）

| 列 | 填什么 | 判什么 |
|---|---|---|
| 1 编号 | `P-101` 起，按坐标段分段编号 | 便于短名单引用 |
| 2 供给名 | 功能／机制／论文原名（English）+ 中文 | — |
| 3 类型 | S1 竞品／S2 相邻形态／S3 标准与联盟／S4 芯片与 SDK／S5 学术 | 判断「这类供给通常走到哪层」 |
| 4 层 | L1（手册有命令／章节）或 L2（release note 限制条款、指标案例、论文实验） | **决定这行算不算证据** |
| 5 它补上了谁的哪一步 | 必须写成「原来做不到 X，现在能做到 Y」，一句话 | 是「动作」还是「规格」的唯一分界线 |
| 6 坐标 | 轴-步 + 受益人（如 `troubleshoot-4 / 客户侧`） | 让热图能算 |
| 7 我方现状 | 有／弱／无 | 短名单硬条件之一 |
| 8 初判 | 入场券／机会窗口／差异化候选／对内省时／已过时 | 决定去向：补齐清单／方向池／观察 |
| 9 证据 | 可点开的链接 + 访问日期 + 核验状态 | 第 0 条铁律 |

**第 5 列是整张表的质量闸门**。写不出「原来做不到什么」的行，删掉或降到备注——它多半是「支持了某标准」这类入场券（[[#1.2.5 九种不算新功能（反例清单）|§1.2.5]]）。

### G-4 五个供给源与各自的取数口径

| 源 | 去哪找 | 典型行样例 | 该源特有的偏差 |
|---|---|---|---|
| **S1 同形态竞品** | 友商官方配置手册／命令参考、release note、互操作说明、公开 TAC 文档 | 某厂商在三段式配置校验里给出「差异定位到具体路径」 | 只看到官方口径，看不到失败率 → 容易高估 |
| **S2 相邻形态** | 云管与订阅产品的 API 文档、开放平台、集成市场 | 云管侧「跨站点横向对比同一类 AP 的掉线率」 | 云管能力常依赖云侧数据，设备侧未必能复刻 |
| **S3 标准与联盟** | IETF RFC 与 draft、IEEE、Wi-Fi Alliance（无线联盟）、OpenConfig／gNMI（开放配置与遥测接口）、TIP／ONF（开放网络基金会）等标准组织与开源工作组 | YANG Push 订阅式遥测（替代轮询） | 标准到产品普遍滞后 2~4 年 → 这类行多为「窗口」而非「现状」 |
| **S4 芯片与 SDK** | 芯片厂商公开手册、参考设计、SDK 文档、白皮书 | 交换芯片提供的逐包时延直方图计数器 | 手册给能力不给限制，需 L2 才知精度 |
| **S5 学术** | SIGCOMM／NSDI／IMC／CoNEXT／MobiCom／INFOCOM／EuroSys（网络与系统方向顶会）；arXiv 预印本的 `cs.NI`（网络方向）；专利与学位论文 | 用少量探针推断全网站点级根因的方法 | 实验环境与真实园区差异大 → 必须过 G-6 三条判据 |

**每源必须至少一行，且至少一行到 L1**；某源确实扫过但没有合格行，写「已扫无 + 扫了什么」，不写空白（否则热图会把「没扫」显示成「没人做」）。

### G-5 五张判定视图（全景真正起作用的地方）

| 视图 | 怎么算 | 用来判什么 |
|---|---|---|
| **V1 供给密度热图** | 坐标格 × 行数 | 三类格：≥3 行＝红海（只能做 L2 补位）；1~2 行＝有先例未做完；0 行＝空白（先分辨「没人做」还是「不值得做」） |
| **V2 L1 已到／L2 未到清单** | 按第 4 列筛 | **机会窗口**，直接进方向池优先位 |
| **V3 学术-产品时间差表** | 论文年份 vs 产品首次出现年份 | 3~5 年窗口；差值大的行，说明「这条路验证过但没人产品化」 |
| **V4 我方现状对照** | 第 7 列 × 第 8 列交叉 | 有／弱／无 × 价值，找出「我们有但没当卖点」的沉默资产 |
| **V5 深挖短名单** | 四条硬条件（G-7） | 12~20 条，作为下一阶段的输入 |

> V1 的红海判断要配一句话纪律：**红海格不是不能进，是只能带着「L2 差异」进**。没有 L2 差异的红海格，进去就是价格战。

### G-6 学术行的三条专用判据（与厂商行不同）

厂商行问「做到哪层」，学术行问这三条：

1. **可复现吗** —— 有公开代码／数据集／可重放 trace，等价于 L1；只有公式与仿真，降为线索。
2. **在包线内吗** —— 需要新芯片、新固件接口、未获认证能力的，标「包线外」（[[#1.3.2 三个参数（B1–B3）|§1.3.2]] 的 B2），仍收，但优先级压到 B/C。
3. **时间差多大** —— 论文年与产品年之差；差 ≥3 年且产品侧无对应，是窗口。

> 学术行的价值不只在于「新」。**证伪价值 ≥ 证实价值**：一篇说「这条路在真实园区不可行」的论文，能省掉我们半年；这类行要单独标注「负面结论」，并写清它否掉的是哪个方向。

### G-7 从全景到深挖：短名单四条硬条件

同时满足 ≥3 条才进 V5 短名单；四条全中直接排第一梯队。

1. **命中 D-a~D-e 至少一条**（[[#1.5.3 差异化五来源（D-a 至 D-e）|§1.5.3]]）——不命中，进来也是跟随。
2. **我方现状为「无」或「弱」**——「有」的行先去查为什么没卖出去，别重复建设。
3. **该格行数 ≥3**——说明是共性问题；只有 1 行的多是孤例或厂商定制。
4. **包线内**——不需换芯片、不违认证。

每条短名单必须补一句：**「如果它成立，谁的哪个数字会变」**。写不出来的，退回观察层。

### G-8 产能、停止条件与明令不做

- **规模**：120~160 行（五源 × 五线 × 七段的大致覆盖）。低于 100 行说明漏源；高于 180 行说明把规格也收进来了。
- **单行成本**：≤90 秒；追到 L2 的行控制在 10% 以内（其余靠 [[#1.7.4 链接核验规程|§1.7.4]] 记状态）。
- **总投入**：3~5 人日（含热图与短名单）。
- **停止条件（任一命中即停）**：① 连续 20 行没有出现新的动作断点；② 五源各已覆盖 ≥2 条 L1 且热图无新格；③ 达到 160 行。
- **明令不做**：厂商综述、竞争格局与市占分析、定价与商务比较、逐条功能打分排名。

### G-9 交付物三件

1. `全景-供给侧总览-v0.1.md` —— 主表 + V1~V5 五视图，放 `00-待整理/业界分析/_全景/`。
2. 同名 `.csv` —— 九列同构，可排序可筛选；表与 csv 的编号必须一致。
3. 热图一张 —— 坐标格 × 行数，**格内写行数不写着色**（避免用颜色暗示结论）。

### G-10 三种全景反模式

| 反模式 | 症状 | 后果 |
|---|---|---|
| **按厂商分组** | 章节是「某厂商有什么」「另一厂商有什么」 | 得到九份彩页，动作重复计数，热图算不出 |
| **只收大厂** | 清单里全是前五家，开源与学术缺席 | 漏掉 L2 未到的高发区（开源与学术恰恰最常停在「能跑但没人做产品」） |
| **全景直接排期** | 看完就说「这个我们要做」 | 跳过 A 侧验证与三道筛，把「别人有」当成「客户要」 |
