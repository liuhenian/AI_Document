# 1 方法论 04 · 新方向发现法

> **一句话结论**：这份方法论回答的是「**下一步该做什么新东西**」，产出物是一份**能进规划的方向组合（direction portfolio）**——每条方向带证据、带判定档位、带触发条件；它不回答「某个方向怎么在 90 天里交出来」。后者属于项目立项之后的事，不属于发现阶段。

> **本文与前置约束的关系**：前置约束（`A-前置约束/方向收窄决议-服务对象与产品边界.md` v1.1）里的 F1–F4 在本方法论里只做两件事——**定义合法域**（哪些方向根本不能提）、**定义排序偏好**（同样证据下谁排前面）。它**不替你决定该做什么**。约束变了，改的是本文 §2 的参数表与 §4.1 的否决项，不是整篇重写。

## 1.1 体例说明（全文档强制）

英文一律保留并给中文：正文用 `中文（English）`；专有名词用「原名 + 括注中文」；批量术语用两列表。命令、代码、路径、URL 不翻译。

**证据分级**（沿用本系列口径，全文引用时必须标级别）：

| 级别 | 含义 | 本文用法 |
|---|---|---|
| A | 公司内一手事实（工单、产品手册、内部系统） | 直接作为方向成立依据 |
| B | 公开可查的行业事实（GitHub issue、RFC、标准、厂商文档） | 用于证明「这个坑别人也踩」或「没人做过」 |
| C | 本文推导 | 必须写依据链，不得当事实引用 |

**本条方法论新增一条硬规则（第 0 条铁律）**：

> **链接不通的证据不算证据。**
> 任何一条 B 级证据在写进文档前，必须逐条点开核验，并把「核验方式 + 状态 + 日期」写进附录。核验不通过的，要么换一条，要么降级为「待核」并明确标注。**不接受「我记得有这么一个 issue」**。

理由不是洁癖。规划材料的读者不会去点链接，但**评审会抽查**——抽到一条 404，前面九条真证据一起作废。

## 1.2 这份方法论解决什么问题

### 1.2.1 三句话定位

1. **输入**：一个约束域（服务对象、交付形态、颗粒度下限）+ 一堆已有证据（工单、issue、手册、扫描结果）。
2. **过程**：三条通道生成候选 → 三道筛判档 → 写成方向卡。
3. **输出**：一份 5~8 条的方向组合，分 A/B/C 三档，每条附触发条件与停止条件。

### 1.2.2 与 01／02／03 的分工（不要重复劳动）

| 文档 | 它真正在做的事 | 采样单元 | 它给不出什么 |
|---|---|---|---|
| **01 内部调研** | 把内部人的「判断过程」拍成事件卡，找断点 | 判断事件（谁判、依据什么、被谁反驳） | 拍完之后「这些断点该合成哪几个方向」——它只管到断点 |
| **02 外部调研** | 拍外部客户场景，验证能不能进标书 | 客户场景 | **已被前置约束整体挂起**（服务对象不是外部客户） |
| **03 跨赛道** | 供给先行：先看业界有什么能力，再反向匹配问题 | 能力卡（capability card） | 能力卡 ≠ 方向。34 张卡不会自己变成「该做哪条」 |
| **04 本文** | **把上面三者的碎片收敛成可排期的方向组合** | 方向（direction） | 不负责交付 |

一句话：**01／03 是原料车间，04 是装配线**。04 不重新采集工单，也不重新扫货架——它把已有的原料按统一口径装配成能进规划的东西。

### 1.2.3 为什么不能「选一个最好的方向」

这是本文与绝大多数立项方法论最大的分歧，必须先讲清楚。

**三个理由，每个都独立成立：**

1. **证据永远残缺。** 你手上是 977 条售后工单，没有研发内部缺陷单，没有测试组用例库，没有交付现场记录。**样本缺口不是努力能补上的**，它由权限决定。在一个残缺样本上算出来的「最优方向」，精度是假的。
2. **方向价值随时间变。** 合规条款可能出现，平台边界可能收缩，设备能力可能升级（INT／IPFIX 一上，某些方向的价值立刻变）。**「现在最优」不等于「明年最优」**。
3. **规划的本质是分批投入，不是一次下注。** 规划要回答的不是「做哪个」，是「**先投多少、投到什么时候停、什么信号出现就加注或砍掉**」。一条方向再对，如果它不能给出一句「什么情况下我就不做了」，它就不是规划项，是信念。

**所以正确输出是组合 + 判档 + 触发条件**，而不是一个结论。这也解释了为什么「方向池只有 3 条」是危险状态——3 条里如果第一条被证伪，你没有备选。

### 1.2.4 什么算一个「新方向」（五要素定义）

**定义**：一条方向 = 一个五元组，五要素缺一条就不成立。

| 要素 | 问句 | 空缺时的典型症状 |
|---|---|---|
| **对象（who）** | 谁，在哪个岗位上，被卡住了 | 「行业需要」「客户需要」——说不出具体的人 |
| **卡点（where）** | 他在**哪一步**判断不了 | 只能说「效率低」「不透明」 |
| **新能力（what）** | 补上之后他**多了一个什么动作**（不是多了一个页面） | 「做一个看板」「加一个报表」 |
| **出口（how used）** | 这个动作在**哪份产出物**里被用掉（工单结论 / 验收签字 / 复盘记录） | 「用了之后会更好」——说不出被谁引用 |
| **度量（what changes）** | 上线后**谁的哪个数字**会变 | 「提升可观测性」——无法证伪 |

**六个反例（这些都不算新方向，只是工作量）**：

1. 新的页面／报表／大屏。
2. 支持更多型号、更多厂商、更多 OID。
3. 把已有功能搬到另一个平台（从 A 平台迁到 B 平台）。
4. 加「AI／大模型」字样但没有新增判断动作。
5. 指标数量翻倍、覆盖率从 60% 提到 85%。
6. 把两条已有能力合并成一个入口。

> 判据很土但很有效：**说得出「他原来做不了什么，现在能做什么了」的是方向；只说得出「我们做了什么」的是工作量。**

## 1.3 L0 层 · 约束解析：把边界翻译成搜索参数

### 1.3.1 四个参数（P1–P4）

约束不是用来写在前言里表态的，它必须变成**能卡住候选的开关**。本文把前置约束 F1–F4 翻译成四个参数：

| 参数 | 名称 | 当前取值 | 卡在哪一步 |
|---|---|---|---|
| **P1** | 服务对象（beneficiary） | 内部开发（development）+ 内部测试（test） | 筛一·合法性（一票否决） |
| **P2** | 交付形态（delivery form） | 能力／证据 > 独立产品 | 方向卡「出口」字段 |
| **P3** | 出口通道（handoff channel） | 平台内被调用 / 写进流程文件 / 进标书（本轮基本只前两条） | 方向卡「度量」字段 |
| **P4** | 颗粒度下限（minimum granularity） | **一季内能启动一段、并产出一个可判断的结论** | 筛三·可规划性 |

> **P4 的措辞很重要。** 它说的是「一季内**启动一段**并给出**判断**」，不是「一季内交付一个功能」。前者是规划约束（防你把方向写成三年愿景），后者是交付约束（那属于立项之后）。**这条边界是本文与已移除的落地版方法论 04 的分水岭。**

### 1.3.2 参数填错的三种典型跑偏（每种都有对应现实案例）

| 跑偏 | 表现 | 后果 |
|---|---|---|
| **P1 填成「客户」** | 方向写着「帮助客户快速定位故障」，但客户既不能给你权限，也不在你的交付链上 | 会做出一堆没人签字的东西。本系列 `L1-外部信号卡` 两批共 84K 字节，就是按「外部客户」口径采的，按 F2 判整批出局 |
| **P2 填成「独立产品」** | 方向写着「做成一个独立工具卖给客户」 | 渠道、售前、交付、品牌四项全缺，方案第一轮就被否 |
| **P4 填成「三年愿景」** | 方向写着「构建统一的网络可观测平台」 | 无法排期、无法验收、无法归户 |

### 1.3.3 参数变更的影响面（后续维护用）

| 变了哪个 | 需要重写 | 不需要动 |
|---|---|---|
| P1 服务对象 | §4.1 否决项、全部方向卡的「对象」「出口」字段 | 三条通道的流程（§3） |
| P2 交付形态 | 方向卡的「出口」「度量」字段、§5.3 组合视图的排法 | 供给盘点（§3.3） |
| P3 出口通道 | 「度量」字段、判档里的 B/C 边界 | 困难归一（§3.2） |
| P4 颗粒度下限 | §4.3 可规划性四条件 | 新颖性三问（§4.2） |
| **约束整体作废**（例如公司要求对外） | **整篇重写**，并把 02 从挂起恢复 | — |

## 1.4 L1 层 · 发现：三条通道，缺一不可

### 1.4.1 为什么必须是三条

只走一条通道，会产生**可预测的偏误**：

| 通道 | 起点 | 强在 | 盲区（不看另一条会怎样） |
|---|---|---|---|
| **A 困难倒推**（evidence-driven） | 谁卡在哪一步 | **真实**：有人真的被卡住过 | 想不出没见过的解法；容易把「现状的延伸」当成新方向 |
| **B 供给外溢**（supply-driven） | 别人怎么解 | **新颖**：能拿到跨赛道的现成判据 | 容易拿锤子找钉子；会做出一堆「技术上很新、没人需要」的东西 |
| **C 变化驱动**（change-driven） | 什么正在变 | **时机**：能提前半年卡位 | 变化本身不等于需求；标准发布 ≠ 有人用 |

**合流规则（本文最重要的一条）**：

> **一条方向必须同时被 A 和 B 碰到。C 只能决定「什么时候启动」，不能单独生成方向。**

这条规则的实战含义：如果一条方向只有 A（有困难、但业界也没解法），它进 B 档「取证后可规划」，需要先证明「这个困难值得解」；如果只有 B（有现成技术、但没人被卡住），**直接否掉**——这正是「拿锤子找钉子」的准确定义。

### 1.4.2 通道 A 的操作：困难归一（把现象翻译成判断动作）

**A-1：不要按故障类型分组，按「判断动作」分组。**

故障类型（「MAC 漂移」「配置不生效」）是按现象分的，现象有几百种，不可枚举。判断动作只有五类：

| 判断动作 | 原文问句 | 补不上会怎样 |
|---|---|---|
| **取值有效性** | 「这个数是那一刻的真实值吗？」 | 拿到一个数，但不敢用 |
| **多源一致性** | 「两个来源对不上，哪个对？」 | 有两个数，判不了 |
| **身份与语义** | 「同一个 ID 指的是同一个东西吗？」 | 数是对的，但对应错了对象 |
| **采集完整性** | 「这一轮采集到底成功了没有？」 | 不知道缺的是「没有」还是「没采到」 |
| **现场可复原** | 「那一刻的状态现在还拿得到吗？」 | 知道要什么，但已经没了 |

**A-2：三列归一。** 每个判断动作填三个数：**出现次数（count）／困难纯度（purity = 带困难标签的比例）／可否判定（能不能写成规则）**。

**A-3：只留纯度 ≥ 70% 的。** 这条门槛是被实证逼出来的：

> 本系列实测：M08「解析了但下发失败」命中 **53 条，数量排第 3**，但纯度只有 **37%**——其中 33 条是「等版本修复」，工具帮不上。而 M01「表项残留不老化」命中 **50 条，纯度 100%**。
> **按数量排序会把 M08 排到前面，按「数量 × 纯度」排序 M01 才是第一。**

**A-4：必须写代表 CASE 编号。** 没有 CASE 编号的判断动作是印象，不是发现。

### 1.4.3 通道 B 的操作：四层供给盘点

盘点的判据只有一句：**对象是否相同**。不是「有没有人做过」。

| 层 | 盘什么 | 判断标准 | 三种结论及其处置 |
|---|---|---|---|
| **L1 同赛道** | 开源网管／采集器／仿真器（LibreNMS、SONiC、Telegraf、gNMIc、Batfish…） | 它们是在**同一批设备、同一批指标**上工作 | ①**同对象已有实现** → 放弃自研，直接集成；②**同病不同解** → 最值钱，说明这条路确实走不通；③**完全没有** → 记为空档 |
| **L2 邻赛道** | 数据质量／可观测平台（Great Expectations、Soda、Prometheus 的 staleness 语义…） | 方法是同一套，**对象换成了数仓表／时序库** | 判据可借、对象没换 → 差异化点在「换对象」，必须写清换什么 |
| **L3 跨赛道** | 数字取证／审计／工业检测（ISO/IEC 27037、NIST SP 800-86、Velociraptor…） | 方法是同一套，**对象换成了硬盘／手机／现场** | 同上，且通常给出「判据最全」的那一层 |
| **L4 标准与协议** | IETF RFC、ISO、国标（IPFIX RFC 7011、IOAM RFC 9197…） | 定义的是**数据长什么样**，不定义「可不可信」 | 标准给的是「怎么采」，不给「采到之后能不能用」——**这正是系统性空档的常见位置** |

**这一步最常见的误判**：把 L2／L3 的成熟度当成 L1 的成熟度，得出「这块已经很成熟了，别做」。正确结论是反过来的——**L2／L3 越成熟，说明判据越不用自己发明，工程风险越低**，差异点只在「对象迁移」。

### 1.4.4 通道 C 的操作：三种变化的识别清单

本系列早已记录一条判断：**突破只来自三种变化**（技术迁移、约束变化、边界变化）。在发现阶段，它只用来定「何时启动」，具体识别问句如下：

| 变化类型 | 识别问句 | 本轮已识别到的候选 | 它影响哪条方向 |
|---|---|---|---|
| **技术迁移** | 设备侧新增了哪类数据出口（gNMI／IPFIX／INT）？原来拿不到的东西现在拿得到了吗？ | IPFIX 已成标准（RFC 7011，2013）；IOAM／INT 已成标准（RFC 9197，2022） | 遥测可信层（见 §5.3 的 C 档） |
| **约束变化** | 合规、审计、SLA 里有没有新增「必须留下什么记录」的条款？ | 本轮未取得条款级证据 | 现场保全方向 |
| **边界变化** | APM 的边界是被扩了还是被收了？平台侧有没有改口？ | 平台（UNC／乐享）持续吸收单点能力 | 全部方向的「出口」字段 |

### 1.4.5 三通道合流检查表（写完方向卡后逐条打勾）

- [ ] 这条方向有一个**具体的人 + 具体的一步**（A 命中）
- [ ] 这条方向有**至少 3 条能点开的外部证据**，或 1 条「同病不同解」（B 命中）
- [ ] 这条方向的「新能力」能写成**一个动作**，不是一个界面
- [ ] 如果 B 只命中 L2／L3，**写清了「换什么对象」**
- [ ] 如果只有 A 命中，**降 B 档**并写明要补什么证据
- [ ] 如果只有 B 命中，**直接否掉**

## 1.5 L2 层 · 判定：三道筛

三道筛的顺序不能换：**先合法性（省钱），再新颖性（省力），最后可规划性（省时间）**。

### 1.5.1 筛一 · 合法性（legality）：一票否决

对着 P1–P4 四问，任一为否即淘汰：

| # | 问句 | 否的处置 |
|---|---|---|
| 1 | 受益人是**内部开发或内部测试**吗？（P1） | 淘汰，不辩论 |
| 2 | 交付形态是**能力／证据**，不是独立产品吗？（P2） | 改写成能力形态，改不动就淘汰 |
| 3 | 出口能落到**平台调用／流程文件／标书**三者之一吗？（P3） | 只写「内部试用」的降 C 档 |
| 4 | 能切出一个**一季内可启动、可给出判断**的片段吗？（P4） | 降 C 档，写明卡在哪 |

### 1.5.2 筛二 · 新颖性（novelty）：三问，不是「有没有人做过」

| # | 问句 | 通过标准 | 反例 |
|---|---|---|---|
| 1 | 在我们这个**对象**上有人做过吗？ | 没有，或只有「对象不同」的（L2／L3） | 「Grafana 有埋点质量报告」——它的对象是埋点配置，不是某一次判障 |
| 2 | **换个粒度**还算新吗？ | 从「配置级」下沉到「事件级」仍无人做 | 「已经有 SNMP 采集了」——采到 ≠ 判这次采到的能不能用 |
| 3 | 如果**平台**（UNC／乐享）明天就要做，它做得了吗？ | 做不了，或做了不被采信 | 平台是交付方的一部分，甲方不会把乙方自证当独立证据 |

第 3 问是本文的**结构性壁垒判据**：它把「技术难度」换成「立场」。**平台抢得走能力，抢不走立场**——一个由当事人出具的证据，技术再强也不被第三方采信。

### 1.5.3 筛三 · 可规划性（planability）：四条件

| # | 条件 | 判据 | 不合格的样子 |
|---|---|---|---|
| **C1** | **有第一段** | 2 周内能产出一个**判断结论**（不是功能） | 「先搭框架，再看效果」 |
| **C2** | **有止点** | 写得出「什么情况下我就不做了」 | 「持续优化」 |
| **C3** | **有观测指标** | 写得出「上线后谁的哪个数字会变」 | 「提升可观测性」 |
| **C4** | **不依赖未授权资源** | 不需要等设备团队改固件、不需要等平台开接口、不需要等客户给权限 | 「等 XX 版本支持后就能做」 |

**C4 是最容易被忽略的一条。** 本系列的「端口历史事件序列」方向就是典型：需求最硬（九维矩阵里唯一整列空白），但它重度依赖固件改动，落不进 P4 的颗粒度下限 → 只能作长期参照，不能作第一批。

### 1.5.4 判档规则

| 档 | 条件 | 规划含义 |
|---|---|---|
| **A 立即可规划** | 三筛全过 | 可以进本季／下季排期，直接写资源需求 |
| **B 取证后可规划** | 缺 1 个可补的条件（通常是 B 层证据不足，或 C4 依赖外部节奏） | 先进「取证清单」，取证完成即升 A |
| **C 观察** | 缺 2 个以上条件，或依赖不可控外部事件（条款出现、平台改口） | 只留一张监控卡，不投入 |

**判档不是评价好坏，是评价「现在能不能排期」。** 一条 C 档方向可能价值最高——比如「举证可独立」，它要等合规条款出现，价值大但不可控，就该留在 C 档待触发。

## 1.6 L3 层 · 输出：方向卡与方向组合

### 1.6.1 方向卡（七字段 + 一行证据）

| 字段 | 填什么 | 常见填错 |
|---|---|---|
| **编号／名称** | 短、可口头复述 | 「智能运维平台」 |
| **对象** | 岗位 + 动作（「测试在签字前」「开发在排障时」） | 「用户」 |
| **卡点** | 判断动作 + 一句原话式描述 | 「缺乏手段」 |
| **新能力** | 一个**动作**（能判、能比、能复述、能举证） | 「一个页面」 |
| **出口** | 落在哪份产出物里 | 「在平台上展示」 |
| **度量** | 谁的哪个数字会变 | 「效率提升」 |
| **档位／触发条件** | A/B/C + 升档需要的证据 | 「重要且紧急」 |
| **证据行** | 内部 CASE 号 + 外部可点开链接 | 「有研究表明」 |

### 1.6.2 证据的三条硬规则

1. **外部证据必须可点开**，且带核验日期（第 0 条铁律）。
2. **「别人也踩」必须给原话**，不能转述。原话是唯一能证明「同构」的东西——转述会不自觉地把对方的问题套进自己的框架。
3. **内部证据必须给 CASE 编号**，能回溯到原始工单。**说不出这是哪条工单，就不是证据，是印象。**

### 1.6.3 方向组合视图（规划页就长这样）

| 档 | 方向 | 一句话 | 对象 | 本次投入 | 升档/降档条件 |
|---|---|---|---|---|---|
| A | … | … | … | 可以给资源 | 出现 X 则降到 B |
| B | … | … | … | **只给取证人力** | 补到 N 条证据即升 A |
| C | … | … | … | **不投人** | 出现 Y 事件则重评 |

**组合视图必须能一句话说清「本季为什么只投这两条」**。说不清，说明判档没做，只是把清单按感觉排了序。

### 1.6.4 一页规划书模板（给上级看的就这一页）

```
结论：本季可排期的方向 N 条，需取证 M 条，观察 K 条。
A 档：
  1) <名称> —— 对象：<谁在哪一步>；新能力：<一个动作>；度量：<谁的哪个数>
     证据：内部 <CASE 号>；外部 <链接>、<链接>
  2) ...
B 档（不排期，只取证）：
  1) <名称> —— 缺的是 <哪一条>，取证动作：<具体动作>，预计 <人日>
不做的（附理由）：
  <方向> —— 否决依据：<筛几·第几问>
```

「不做的」这一节不能省。它防的是同一批方向在半年后被重新提出，又走一遍流程。

## 1.7 停止条件与重启条件

### 1.7.1 什么时候该停止找方向（转向执行）

三个信号同时成立时停：

1. **A 档已有 ≥ 2 条，且每条都有 ≥ 3 条可点开的证据。**
2. **B 档剩下的都是「靠等」的**（等条款、等平台、等固件），取证动作已经无处可做。
3. **再找下去只会产生 C 档。**

此时继续找方向是**逃避执行**——因为找方向比做东西舒服，且永远找得到新材料。

### 1.7.2 什么时候必须重开一轮

四个触发条件，任一出现即重开（不必等季度末）：

| 触发 | 为什么必须重开 |
|---|---|
| **约束变更**（P1–P4 任一改） | 合法域变了，旧组合可能整批失效 |
| **A 档方向被证伪**（第一段产出的判断相反） | 组合要补位，不能只剩空档 |
| **外部事件兑现**（条款出现／平台改口／设备能力上线） | C 档可能直接升 A |
| **新增一批一手证据**（如新一季度工单入库） | 困难纯度可能整体漂移 |

## 1.8 七种反模式

| # | 反模式 | 表现 | 后果 | 对策 |
|---|---|---|---|---|
| 1 | **拿锤子找钉子** | 先看到某个开源工具，再找场景套上去 | 做出来没人用 | 只有 B 命中的方向直接否掉（§1.4.1） |
| 2 | **按数量排序** | 「命中 53 条，排第一」 | 做到一半发现 33 条是等版本修复 | 必须乘困难纯度（§1.4.2 A-3） |
| 3 | **把能力卡当方向** | 34 张能力卡直接当 34 个方向 | 无法排期、无法验收 | 能力卡只能进供给盘点（L1 层），不直接进方向池 |
| 4 | **用价值排序** | 按「哪条价值最大」排第一 | 第一步永远做不出来，因为最大那条通常最不可控 | 按「能否切出第一段」排序（§1.5.3 C1） |
| 5 | **把标准当需求** | 「RFC 有了，所以市场有了」 | 提前两年投入，等不到用户 | C 通道只定时机，不定方向（§1.4.4） |
| 6 | **只写做了什么** | 「完成判定器开发」 | 评审无法判断价值，且无法归户 | 只认「他原来做不了什么，现在能做什么」（§1.2.4） |
| 7 | **证据是转述** | 「业界普遍认为…」 | 一条 404 让整份材料作废 | 第 0 条铁律 + 原话要求（§1.6.2） |

## 1.12 附录 C · 术语中英对照

| 英文 | 中文 | 一句话释义 |
|---|---|---|
