# 方法论 02 · 外部调研：面向外部客户找产品方向

**版本** v1.0　|　**日期** 2026-10-26　|　**适用**：服务对象为公司外部客户（园区网场景），产品需进入销售与交付流程

**用法**：按第 7 节节奏执行。每一层都有固定表头，填完第 4 层，方向自己会浮出来。

---

## 0. 目标与边界

### 0.1 一句话目标

> 找出 **3~5 个「客户愿意为它换供应商、且能进标书加分项」的场景**，每个能在一个季度内交出可演示、可报价的东西。

关键限定有两个：**愿意换供应商**（不是"觉得不错"）、**能进标书**（不是"技术上很先进"）。这两个条件决定了后面所有取舍。

### 0.2 三个前提

| 前提 | 内容 | 对方法的约束 |
|---|---|---|
| 买单人在外部 | 客户 IT 部门 / 项目方，走采购流程 | 必须有采购决策链、必须有报价逻辑、必须能进评分项 |
| 园区网业务特征 | 设备海量、单台便宜、客户少有专职运维、靠渠道交付、项目制质保 | 单次故障收益低而定位成本高 → 价值必须落在**减少上门、减少联调、减少扯皮** |
| 季度产出 | 每季度有可演示可报价的东西 | 每个机会必须回答"卖多少钱、卖给谁、怎么进标书" |

### 0.3 外部场景的价值度量

| 维度 | 外部场景的口径 |
|---|---|
| 客户要解决的问题 | **止损**：业务断了，尽快恢复 |
| 最痛的事 | 看不见 → 定位慢 → 损失扩大 |
| 损失的可度量形式 | 停机时长 × 业务价值、上门人天、延期罚则、返修换机成本、口碑与续约 |
| 价值度量 | **客户愿意为此改变采购决定**（换供应商 / 加预算 / 写进标书） |
| 真正的竞品 | 现有供应商、客户自己的土办法、干脆不解决 |
| 不配合的表现 | 「我们暂时用不上」「下次再说」 |

**由这张表推出三条硬结论：**

1. **客户不为"技术先进"付费，只为"损失减少"付费。** 任何功能都必须能换算成一个客户认得的数字：少几次上门、少几天延期、少多少停机。
2. **客户没有运维能力，所以"给他一个更强的工具"往往无效。** 园区网客户的现实是没有专职网络工程师。能力必须**替他做判断**，而不是**给他数据让他判断**。
3. **渠道是必要环节。** 进不了渠道的交付流程、渠道不愿意装、装完不会用，产品就卖不动。渠道诉求要在需求阶段就收进来。

### 0.4 产出物清单

| 编号 | 产出物 | 数量 | 判定标准 |
|---|---|---|---|
| O1 | 客户场景卡 | 100~150 张 | 每张都有「损失量」和「客户现在的应对方式」 |
| O2 | 客户旅程还原 | 3 份 | 同一段反复出现"客户看不懂"或"等人来" |
| O3 | 竞品能力对照表 | 覆盖 5~8 家 | 每个能力都写了「什么条件下它不管用」 |
| O4 | 采购要素清单 | 1 份 | 能回答"进哪个评分项、谁打分、现状几分" |
| O5 | 机会卡 | 12~15 张，砍到 3~5 张 | 通过四道否决 + 打分 ≥ 3.0 |
| O6 | 一页商业建议书 | 1 份 | 含客户、损失、定价、渠道、差异化 |

**失败的定义**：交出一份"竞品功能对比很全、技术很先进"的分析，但说不出"卖给谁、多少钱、进哪条评分项"。

## 1. 总体框架：四层漏斗

| 层 | 输入 | 动作 | 输出 | 淘汰什么 |
|---|---|---|---|---|
| **L1 需求** | 客户真实场景 | 分层抽样 + 场景编码 + 旅程还原 | 场景卡 100~150 张、旅程 3 份 | 偶发的、客户自己能忍的、无法换算损失的 |
| **L2 供给** | 竞品与非竞品 | 能力 × 失效条件对照、定价与商业模式 | 能力对照表、定价结构图 | 已充分供给的、无差异空间的 |
| **L3 采购** | 标书、渠道、决策链 | 评分项逆向分析、渠道诉求收集 | 采购要素清单 | 进不了评分项的、渠道不愿推的 |
| **L4 收敛** | 前三层与自家能力 | 机会卡 + 硬否决 + 打分 | 3~5 个方向 | 无差异化、客户不愿付费、一季交不出 |

**纪律**：L1 的事实决定 L2 该比什么，L3 的结果决定 L4 该砍什么。**顺序不能换**——先比竞品再找需求，会得到一个"我们也做这个"的清单。

## 2. L1 需求层：客户场景

### 2.1 采样单元：客户场景，不是产品缺陷

一张场景卡记录的是**一次业务受损的完整经过**，不是一条缺陷单。区别在于：缺陷单记的是"哪个功能坏了"，场景卡记的是"客户的什么业务停了多久、谁发现了、怎么恢复的、损失多少"。

### 2.2 六类数据源

| 排序 | 数据源 | 取它的哪个字段 | 为什么值钱 |
|---|---|---|---|
| **1** | 售后工单与上门记录 | 上门人天、远程电话轮次、延期天数 | 有财务数字，且反映真实故障形态 |
| **2** | 客户访谈（使用方 + 技术把关方分开做） | 不讲需求，讲"上次怎么处理的" | 唯一能拿到"客户实际怎么做"的方式 |
| **3** | 历史标书与应答文件 | 评分项、加分项、废标条款 | 需求清单 + 付费意愿的双重证据 |
| **4** | 售前与渠道反馈 | "客户最常问的三个问题""为什么丢单" | 丢单理由就是未满足的需求 |
| **5** | 客户侧投诉与续约记录 | 投诉内容、续约时压价的理由 | 口碑损失的量化来源 |
| **6** | 厂商社区与公开抱怨 | 故障的具体形态、客户自己怎么描述 | 客户的语言与厂商的语言不同，这个差别很重要 |

### 2.3 分层抽样

**错误做法**：随机抽 100 条工单 → 80% 是"网线没插好""密码错了"，只能得出"问题很多"。

**正确做法**：三维分层，每格 5~8 条。

| 维度 | 分层 |
|---|---|
| **客户类型** | 高校 / 普教 / 医疗 / 政企 / 制造 / 酒店连锁 |
| **规模** | 单栋楼 / 单校区 / 多校区 / 跨地域 |
| **流程阶段** | 售前 / 交付 / 验收 / 运行 / 变更 / 故障 / 售后 / 退网 |
| **故障类型** | 认证 / 二层环路 / PoE / 光链路 / 性能 / 配置 / 硬件 |

实操：先按"流程阶段 × 故障类型"做 8 格 × 8 条 = 64 条，再按"客户类型 × 规模"补 6 格 × 6 条 = 36 条，合计 100 条。

**为什么这样抽**：流程阶段暴露"客户在哪个阶段最无助"，客户类型暴露"哪类客户最愿意付费"。

### 2.4 场景卡（复制这个表头）

| 字段 | 填写要求 |
|---|---|
| **S-ID** | S001 起编 |
| **客户类型 / 规模** | 6 个标签 + 规模标签 |
| **流程阶段** | 8 个标签之一 |
| **故障类型** | 7 个标签之一 |
| **客户原话** | **必须是客户的原话**，不许转成技术语言。"第三间教室的 AP 老是掉线"比"STA 频繁 deauth"信息量大 |
| **谁发现的** | 客户 / 厂商 / 渠道 / 巡检 / 无人发现 |
| **从异常到恢复** | 总时长（小时/天） |
| **客户做了什么** | 重启、拔插、找集成商、找厂商、放着不管 |
| **卡在哪 K1–K5** | 见 2.5 |
| **转手次数** | 客户→集成商→厂商→研发 的交接次数 |
| **损失类型 / 损失量** | 见 2.6，必须能换算成数字 |
| **客户现在的应对** | 手工、加设备、换方案、忍着 |
| **客户愿意为它付钱吗** | 愿意 / 可能 / 不愿意 + 理由 |

**三条纪律**

1. **「客户原话」不许翻译。** 技术化转写会丢掉场景与损失线索。
2. **「损失量」填不出数字 → 这张卡降级。** 没有损失就没有付费理由。
3. **「客户现在的应对」是必填。** 客户当下的土办法就是你的主要竞争对手，必须知道它是什么。

### 2.5 卡点标签 K1–K5

| 编码 | 含义 | 举例 |
|---|---|---|
| **K1** | 缺数据 | 故障已过，表项 / 计数器没留 |
| **K2** | 缺权限 | 客户不给远程，只能电话指导 |
| **K3** | 缺人 | 只有某一个人会看，客户没有专职运维 |
| **K4** | 缺流程 | 该谁做没定义，客户与集成商互相推 |
| **K5** | 缺共识 | 各方看到的数据不一样，结论打架 |

**K2 与 K3 在园区网场景出现频率极高**，因为它们源自两个结构性事实：客户不给远程权限、客户没有专职运维。这两类卡点对应的是"免权限取证"与"替客户做判断"两类产品形态。

### 2.6 损失类型与换算口径

| 类型 | 换算口径 | 谁认这个账 |
|---|---|---|
| **停机** | 时长 × 受影响人数 × 业务价值 | 客户 IT 主管 |
| **上门** | 人天 × 单价 + 差旅 + 响应时效罚则 | 服务负责人 |
| **延期** | 项目工期延误天数 × 违约条款 | 项目经理、集成商 |
| **返修** | 换机成本 + 物流 + NTF 检测人力 | 质量与售后 |
| **口碑** | 续约压价幅度、丢单、负面案例 | 销售与渠道 |

做完 100 张卡，按 K 分组与按损失类型分组统计，占比最高的组合就是主攻方向。

### 2.7 核心动作：客户旅程还原

场景卡只看结果。要看过程，做这个动作。

**挑一个已经发生的真实项目问题**（最好还在被讨论），从"客户第一次察觉异常"还原到"问题关闭"。

| 时刻 | 谁（客户 / 集成商 / 厂商 / 渠道） | 在做什么 | 看到什么信息 | 卡在哪 | **如果当时有什么，这一段就能跳过** |
|---|---|---|---|---|---|
| T+0 | | | | | |
| T+1h | | | | | |
| … | | | | | |

**判定规则**

- 「如果当时有什么」反复出现同一个东西 → **产品需求，且被真实事件验证过**
- 连续几段是"在等"（等客户回电、等远程权限、等人到现场）→ 流程断点，可做自动化，不能做功能
- 出现"客户看不懂我们给的信息"→ 说明产品设计错在**呈现方式**，不是数据不足
- 出现"多方各说各的没问题"→ 这是**定责类**需求，通常对应最高付费意愿

**做 3 次**，重复项就是方向。三次旅程累计起来的时长，就是"如果当时有这套东西能省多少"的算法依据。

### 2.8 客户访谈脚本（使用方与技术把关方分开做）

**不要问"你需要什么功能"**，客户会说不出，或者说出竞品的功能名。问过去：

1. 上一次网络出问题，你们是怎么发现的？谁先知道的？
2. 从发现到恢复，中间做了哪些事？等了谁？
3. 那次你们自己先试了什么？哪一步就试不下去了？
4. 你们现在靠什么判断"是网络问题还是别的问题"？
5. 出问题时，厂商 / 集成商要多久到？不到现场能解决吗？
6. 采购这类能力时，你们看什么？谁拍板？
7. 如果有个东西能替你们省掉一件事，你希望是哪件？（**放最后**）

**对技术把关方单独补三问**：验收怎么验、出问题怎么定责、什么情况下会退回不验收。

## 3. L2 供给层：竞品与非竞品

### 3.1 能力对照必须带"失效条件"列

功能矩阵本身有缺陷：它只说"有什么"，不说"什么时候不管用"。补救办法是每行加一列失效条件。

| 能力 | 竞品 A | 竞品 B | 我司 | **该能力在什么条件下不管用** |
|---|---|---|---|---|
| | 有 / 部分 / 无 | | | |

**这一列是差异化的唯一来源。** 三家都有某能力时，差别只在失效条件上：谁在"无远程权限""未纳管""故障已过"这些条件下还能用，谁就有位置。

### 3.2 要对照的不只是竞品

| 类别 | 是谁 | 为什么要看 |
|---|---|---|
| **直接竞品** | 同类网络厂商、可观测平台厂商 | 决定标书里的功能对标 |
| **替代方案** | 手持仪表上门检测、第三方验收服务、人力外包 | 它们往往是最真实的竞争者，因为客户已经在付钱给它们 |
| **客户土办法** | Excel 台账、人工巡检、重启大法、忍着 | 成本最低，最难被替代 |
| **不解决** | 客户接受现状 | 这是最强的竞争对手 |

**替代方案和客户土办法必须单独列**，因为它们的报价就是你的价格上限，它们的形态就是你的产品定义参考。

### 3.3 定价与商业模式对照

只看结构，不看价格数字：

| 看什么 | 它说明什么 |
|---|---|
| 计费单位（按设备 / 按端口 / 按数据量 / 按人天） | 厂商认为价值在哪一层 |
| 是否单独售卖，还是捆绑在硬件里 | 这一能力是卖点还是赠品 |
| 是否有免费版 / 试用 | 获客难度 |
| 按年订阅还是一次性 | 客户接受度 |
| 服务如何计价（上门 / 远程 / 驻场） | 人的成本占比 |

**计费单位的变化就是价值计量单位的变化。** 如果全行业都按设备计费，说明端口级价值尚未被定价——这可能是机会，也可能是无人付费，需要 L1 的损失数据来判断是哪一种。

## 4. L3 采购层：能不能卖出去

### 4.1 决策链四问

| # | 问什么 | 怎么拿 |
|---|---|---|
| 1 | **谁用**（日常操作者） | 客户访谈，使用方 |
| 2 | **谁把关**（技术否决权） | 客户访谈，技术把关方 + 历史标书技术条款 |
| 3 | **谁掏钱**（预算科目） | 售前，问"这笔钱从哪个预算出" |
| 4 | **谁签字**（最终决策） | 售前，问"上次这个单谁签的" |

四个角色不是同一个人时，产品必须**同时满足四者**，而不是让使用者满意就够。技术把关方一票否决的情况，在政企采购里很常见。

### 4.2 评分项逆向分析

拿 5 份历史标书，逐条抽取评分项，做成这张表：

| 评分项 | 分值 | 门槛项还是加分项 | 我司现状分 | 竞品现状分 | 能否挂靠我们的新能力 |
|---|---|---|---|---|---|
| | | | | | |

**只有"加分项"值得投入**。门槛项是及格线，拿不到就废标，但拿到了不加分；加分项才是差异化的落点。

### 4.3 渠道诉求清单

| 问渠道什么 | 为什么要问 |
|---|---|
| 装这个要多花多少时间 | 施工成本由渠道承担，多一步就少一次推荐 |
| 需要客户配合什么 | 客户不配合的环节，渠道会直接跳过 |
| 出问题谁来处理 | 渠道最怕"卖了之后变成我的责任" |
| 能不能算进他的服务收入 | 有服务收入的环节才有推力 |

**渠道不推的产品，技术上再好也进不了项目。** 这一层不能省。

## 5. L4 收敛层：从场景到产品

### 5.1 机会卡

| 字段 | 填写要求 |
|---|---|
| **机会名** | 6~12 字，说清做什么，不许用"平台""体系""大脑" |
| **一句话价值** | 为**哪类客户**，在**什么时刻**，把**什么损失**从**多少**降到**多少** |
| **流程阶段** | 8 个标签之一 |
| **支撑场景** | S 编号列表，至少 3 张，且至少 2 类客户 |
| **客户现在的应对** | 引用 2.4 该字段；这是你的主要竞争对手 |
| **竞品失效条件** | 引用 3.1 该列，写清"他们在什么条件下不管用" |
| **差异化一句话** | 为什么客户会因为它而改变采购决定 |
| **定价逻辑** | 计费单位 + 参考价 + 客户可对比的替代成本 |
| **进哪条评分项** | 引用 4.2，写清是门槛项还是加分项 |
| **渠道成本** | 施工多几步、需客户配合什么 |
| **一季最小交付** | 一个可演示、可报价的实物 |
| **四项打分** | 见 5.3 |
| **结论** | 主攻 / 备选 / 放弃 |

### 5.2 四道否决（任何一条不过，直接划掉）

| # | 否决条件 | 判断依据 |
|---|---|---|
| 1 | **没有差异化**：竞品在同条件下也能用 | 3.1 表里，对手的"有"没有失效条件，而你的"有"也没有额外条件 |
| 2 | **客户不愿付费**：损失换算不出数字，或客户已接受现状 | 2.4「客户愿意付钱吗」填的是"不愿意" |
| 3 | **进不了标书或渠道**：没有对应评分项，渠道装不了 / 不愿推 | 4.2 找不到可挂靠的行；4.3 渠道明确抵触 |
| 4 | **一季交不出可演示可报价的东西** | 需要跨代硬件、需要等标准、需要改客户流程 |

### 5.3 打分表

| 维度 | 权重 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|---|
| **价值**（能否改变采购决定） | 0.40 | 客户觉得"更方便" | 客户愿意为此加预算 | 客户会**为此换供应商**，或成为加分项里的决定性项 |
| **差异化**（对手做不到） | 0.30 | 对手同样有 | 对手有但失效条件更多 | 对手在此条件下结构上做不到 |
| **可销售性**（标书 + 渠道） | 0.20 | 无对应评分项 | 有加分项但渠道抵触 | 有明确加分项，渠道装得动 |
| **可行性**（一季） | 0.10 | 需跨代硬件 | 需固件配合但一季可见 | 现有能力组合即可演示 |

**总分 = 价值×0.4 + 差异×0.3 + 可销×0.2 + 可行×0.1**

判定：**≥ 3.5 主攻；3.0–3.5 备选；< 3.0 放弃**。打分必须写理由。

### 5.4 反脆弱检查（四条）

| # | 动作 | 通过标准 |
|---|---|---|
| 1 | **找三个"客户其实不在意"的反证** | 客户接受了现状、或用土办法解决了 |
| 2 | **找三个"对手也能做到"的反例** | 找不到，说明差异化未经检验 |
| 3 | **找一个真实客户，把机会卡念给他听** | 他能说出"这个我上次遇到过"或"这个我用不上"，说明卡写清了 |
| 4 | **问：客户不买，他损失什么？** | 答不出具体数字，这条需求不成立 |

### 5.5 一页商业建议书

```
1. 一句话：为哪类客户，在什么时刻，把什么损失从多少降到多少
2. 证据：3 张场景卡编号 + 1 份旅程还原的关键 3 段 + 1 个损失数字
3. 为什么是我们：竞品在此条件下的失效点 + 我们的独占数据
4. 为什么是现在：客户抱怨的频率 / 竞品刚发生的变化 / 标准或政策窗口
5. 卖多少钱：计费单位 + 参考价 + 客户可对比的替代成本
6. 怎么卖：挂靠的评分项 + 渠道施工步骤 + 谁推
7. 一季交付什么：可演示 + 可报价 + 验收标准
```

**第 5 行和第 6 行是生死线。** 说不出计价方式和销售路径，前面写得再漂亮也进不了产品线。

## 8. 质量守则（八条）

| # | 守则 | 违反后果 |
|---|---|---|
| 1 | 客户原话不许技术化转写 | 场景与损失线索全部丢失 |
| 2 | 每条需求必须换算成损失数字 | 没有数字就没有付费理由 |
| 3 | 竞品对照必须带"失效条件"列 | 只剩"我们也有"，没有差异化 |
| 4 | 替代方案与客户土办法必须单列 | 误判竞争对手，定价失去参照 |
| 5 | 只投入加分项，不为门槛项做创新 | 及格线投入不产生溢价 |
| 6 | 渠道诉求在需求阶段就收集 | 产品做完才发现装不动 |
| 7 | 先做否决，再做打分 | 打分会让每个方向都显得有价值 |
| 8 | 找真实客户念机会卡 | 自评通过的方向，客户常一句话否掉 |
