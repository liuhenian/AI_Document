## 一、场景定义与边界

### 1.1 场景定义

锐捷交换机在运行 BGP/OSPF/OSPFv3/RIP/ISIS 等动态路由协议，以及静态路由、策略路由(PBR)、浮动路由、GRE 隧道选路、BFD 与路由协议联动时，出现的协议进程异常、邻居建立失败、路由计算/学习异常、路由发布/反射/引入失败、路由下发至芯片(SDK)失败、RIB/FIB 表项不一致、BFD 联动震荡等故障的集合。聚焦『控制面协议逻辑 + 路由表项下发』环节的失效，而非纯转发面/物理端口异常。

### 1.2 边界判据

**属于本场景：**

- BGP/OSPF/OSPFv3/RIP/ISIS 邻居建立、进程运行、路由计算与学习
- BGP 路由反射/发布/引入失败
- 静态路由、PBR、浮动路由、GRE 隧道等选路逻辑缺陷
- BFD 与路由协议（BGP/OSPF/ISIS）联动震荡（统一归属，不再按被联动协议拆分）
- 路由表项下发芯片(SDK)失败导致设备重启
- RIB/FIB 一致性、路由表项残留/转发不符（含芯片 LPM 算法、快转、跨 VRF 软转、资源耗尽）

**不属于本场景（易误入，需外归）：**

- 纯转发面 TCAM/ASIC 表项与路由无关的不一致 → 归表项与转发大场景的表项不一致/快转丢包子场景（但本数据集中由路由下发触发的 RIB/FIB 不符已纳入 DS-RT-07）
- 聚合口/物理端口协商与显示异常(row=281) → 归接口与物理层大场景的聚合口显示异常子场景
- DHCPv6 地址获取/租约异常(row=348) → 归 DHCP 大场景的 DHCPv6 绑定表异常子场景
- LLDP/NFPP/PHY 寄存器/端口转发异常(row=512,585,643,808) → 归发现协议大场景/物理层大场景/表项与转发大场景的硬件寄存器异常子场景
- 控制面进程崩溃但非路由机理（LLDP 进程 description 超长 row=317、ARP 异常 row=659） → 归系统大场景的控制面进程崩溃子场景/三层转发大场景
- 无根因描述的记录(row=287,410,613,651,667,680,688,820,837,843) → 本场景『未归类』

## 二、这个场景是怎么拆出来的

### 2.1 拆解维度

| 维度 | 取值 | 为什么按这个维度切 |
|---|---|---|
| 协议种类 | BGP／OSPF/OSPFv3／RIP／ISIS／静态/PBR/GRE／BFD | 不同协议故障机理与排查命令差异大（show ip bgp 与 show ip ospf neighbor 不同），必须分协议拆解；但 BFD 作为联动机制统一归属，不按被联动协议二次拆分 |
| 故障阶段(失效环节) | 协议进程/邻居建立／路由计算/学习／路由发布/反射/引入／路由下发/表项／转发不符／BFD 联动 | 同一协议不同阶段的失效点与排查动作不同，须分开 |
| 路由角色 | 头端/始发设备／RR 反射器／邻居/对等体／透传/中间设备 | 如 BGP 在 RR 场景下主备路由反射失败需区分角色(row=409) |
| 根因性质 | 软件缺陷/BUG／规格/资源限制／配置触发／兼容/机制差异 | 决定是升级版本还是改配置规避，影响 RCA 结论 |

### 2.2 拆解原则

1. **机理优先**：以「根因 + 方案」里的技术失效机理作为第一判据，不按主题字面归类。
2. **排查动作一致**：同一个子场景内的记录，必须能用**同一套排查动作**定位；做不到就再拆。
3. **不硬凑**：机理描述缺失的记录不强行塞进任何子场景；机理明确属于别的大场景的记录，标为「待外归」而非塞进兜底子场景。

### DS-RT-01　BGP 进程异常重启与路由发布/反射失败（4 条）

- **机理定义**：BGP 进程因软件缺陷（非法内存地址访问、coredump、已知质量补丁问题）异常退出或重启，导致 BGP peer 周期性中断、邻居重建、路由撤回重发；或在作为 RR 或将静态/其他协议路由引入 BGP 发布时，特定条件下（主备路由并存、作为 RR）路由反射逻辑缺陷，导致本应反射/发布的路由未进入 BGP 表或未向邻居通告。两类均为纯 BGP 协议机理，合并为本场景。软清除后恢复说明是状态机/缓存问题而非配置缺失。
- **归类判据**：日志/主题含『BGP 重建/BGP 抖动/BGP 进程重启/路由反射失败』；show ip bgp summary 邻居频繁 Idle/Active 或 Up/Down 计时周期性重置；存在 coredump 且堆栈命中已知 BGP 问题；静态路由引入 BGP 后邻居收不到、RR 场景下主备路由无法反射、show ip bgp 本地有路由但邻居 advertised-routes 无。
- **典型现象**：BGP 邻居频繁闪断、路由震荡、业务丢包；设备 coredump；升级质量补丁后恢复；路由引入 BGP 发布不成功、邻居缺路由，修改 RD 或软清除后恢复。
- **排查动作**：1) show ip bgp summary 看 peer 状态与重置次数/计时；2) show ip bgp neighbors 10.1.1.1 看 last error、reset 原因；3) show ip bgp 确认本地 BGP 表，show ip bgp neighbors 10.1.1.1 advertised-routes 看实际通告；4) show logging 检索 BGP/coredump/signal(如 0x8b 非法地址访问)；5) 收集 coredump 交研发比对已知问题库（品控 ID/质量补丁），升级对应版本(如 S6500 RGOS 11.0(5)B9P62S2_SP9；18K 11X→12X 解决 RR 反射问题)或改 RD。

### DS-RT-02　BFD 联动路由协议震荡（BGP/OSPF/ISIS 统一归属）（4 条）

- **机理定义**：BFD 会话因 up-dampening 定时器不匹配、规格上限、FP 安装失败或底层链路/光模块异常产生震荡，并联动或影响路由协议邻居：① BFD down 联动 BGP down 时，BFD UP 默认发出 session Down 消息，配合 bfd up-dampening 超过 BGP 全局邻居状态统一处理定时器，形成 BFD+BGP 循环震荡；② BFD 会话数达规格上限(如 12 组)不回复报文致无法 UP；③ CB 卡 counter 开启致 FP 安装失败致 ISIS 邻居震荡；④ 杂牌光模块 MMU 异常致 BFD 震荡且路由下一跳表项未及时恢复致单边负载。原 v1 将 BFD+BGP(row=702) 与 BFD+IGP(row=123/293/451) 拆为两个子场景，按 A-09 统一归属本场景。
- **归类判据**：show bfd neighbor 震荡/无法 UP；BGP/OSPF/ISIS 邻居随 BFD 同步 down/up；bfd up-dampening 配置 >500ms 且时间戳与 BGP down 同步；BFD 会话达规格上限；路由下一跳表项未及时恢复。
- **典型现象**：BFD 与路由协议邻居周期性同时 down/up，业务反复中断；BFD 会话无法 UP、ISIS/OSPF 邻居频繁震荡、OSPF ECMP 单边负载。
- **排查动作**：1) show bfd neighbor 看会话状态/震荡次数/规格；2) show ip bgp summary / show ip ospf neighbor / show isis neighbor 看路由协议 down 原因与频次；3) show bfd session 计数与规格(show bfd limits)；4) show running-config | sec bfd / router bgp 查 bfd enable、bfd up-dampening、联动配置，对齐 BFD down 与路由协议 down 时间戳；5) 查光模块/FP 安装(counter)，去除不当 up-dampening、升级版本/去 counter/换正规光模块。
- **记录抽样**：
    - Sheet8行 702（CS20250402-4996541）：广州希音高明易商仓RG-S7808C与华三设备互联接口BFD震荡问题
    - Sheet8行 123（CS20230719-2123259）：设备：RG-S6120-20XS4VS2QXS，BFD会话无法UP
    - Sheet8行 293（CS20241211-4567203）：RG-N18010 BFD震荡导致ISIS邻居频繁震荡

### DS-RT-06　路由表项下发至芯片(SDK)失败导致设备重启（4 条）

- **机理定义**：路由更新/安装（含 v6 大路由收敛）时，SDK 调用踩空指针或进程挂死，cms.sda.sw 等路由安装进程被 kill，触发设备自愈重启。
- **归类判据**：设备异常重启；coredump 中 cms.sda.sw 进程被 kill；路由安装/SDK 代码空指针；与芯片已知问题相关。
- **典型现象**：路由变化/收敛时设备突发重启。
- **排查动作**：1) show version / show logging 看重启原因与 coredump；2) 取 coredump 分析 cms.sda.sw/sdk 栈；3) show ip route 看触发时路由规模(尤其 v6 约 5000 条)；4) 升级含芯片补丁版本(如 12.6(2)B0702P1S1)。
- **记录抽样**：
    - Sheet8行 311（CS20241113-4420948）：字节 BYTED-CASE-ID 233580 5760设备异常重启
    - Sheet8行 434（CS20240527-3594446）：S5760C-48GT4XS-X设备异常重启
    - Sheet8行 522（CS20240105-2972363）：字节 FDR-ID 136265 3台 S5760C-48GT4XS-X设备异常重启

### DS-RT-05　RIP 收敛异常（备份路由残留/无抑制计时器）（1 条）

- **机理定义**：RIP 实现未设计抑制计时器且数据库保存备份路由，在环形+备份路由组网中，被撤销的备份路由仍传播更新直到 16 跳或更新源为自己再经 3min 老化才消失，导致收敛慢（与思科/华三/华为实现差异）。本数据集仅 1 条样本(row=162)，且该机理独特、与相邻子场景判据不交叉，按 A-09『与相邻子场景判据交叉才合并』的但书保留为独立子场景，避免与 OSPF 学习假合并。
- **归类判据**：环形且有备份路由组网；RIP 路由撤不掉/收敛需数分钟；灾备演练大面积故障。
- **典型现象**：RIP 收敛慢、备份路由残留、灾备切换大面积故障。
- **排查动作**：1) show ip rip database 看备份路由与超时；2) show ip route rip 看路由表；3) show ip rip 看 timer/更新；4) 规避：断开交叉线路或调整组网；彻底：升级版本。
- **为什么没有与相邻子场景合并**：本子场景仅 1 条。按「同一子场景内可用同一套排查动作定位」的粒度判据，其失效机理与排查动作与相邻子场景不交叉，故保留独立、不作合并；记录数少反映的是该故障模式在市场工单中发生频次低，而非拆分类别有误。
- **记录抽样**：
    - Sheet8行 162（CS20230602-1875311）：【独立服销金牌】广西工行百色&北海分行核心交换机RIP收敛异常，4G灾备演练网点大面积故障。

## 四、RCA 根因分析怎么做（本场景）

### 4.1 技术链

现象(邻居 down/路由不通/设备重启) → 触发路径(路由更新/收敛/配置变更/BFD 事件) → 失效点(协议进程 crash/邻接交互/LSA 计算/路由发布/SDK 下发/表项不一致) → 直接根因(软件 BUG/规格限制/配置触发/机制差异)。BGP 部分：BGP 现象(peer 抖动/邻居缺路由) → 触发(收到异常报文/作为 RR 主备路由/coredump/BFD 联动) → 失效点(BGP 进程非法地址访问、RR 反射逻辑缺陷、BFD-BGP 联动循环) → 根因(质量补丁问题/11X RR 缺陷/up-dampening 定时器 mismatch)，定位靠 show ip bgp summary/neighbors、coredump、bfd 日志。

### 4.2 失效点分类

| 失效点 | 说明 | 典型记录（Sheet8行） |
|---|---|---|

### 4.6 成功 / 失败对比要点

成功定位案例共性：①能通过 show ip bgp/ospf summary + 邻居细节 + debug 快速锁定协议与环节；②coredump/show logging 能关联到具体品控 ID 或已知质量补丁，从而直接给出版本/补丁结论；③RIB/FIB 对比(show ip route vs show ip fib/show forwarding-table) + 清 ARP/重配能验证表项残留假设。失败案例共性：根因字段为空('-')、仅靠『版本 bug/软件问题』定性、缺 coredump/debug/规格数据，无法区分协议/转发/配置，最终只能『升级版本/重启规避』，无法形成可复用 RCA。关键差异在于是否具备『邻居/表项/规格/版本-已知问题』四类可观测证据。

## 八、本场景关键结论

DS-RT（路由协议）共 63 条。真实具备 BGP 协议机理的记录仅 5 条（row 20/34/156/409/702），已如实呈现：其中 row=20/34/156/409 为纯 BGP 进程重启重建与路由发布/反射失败，合并归入 DS-RT-01（4 条）；row=702 为 BFD 与 BGP 联动震荡，按 A-09 统一归入 BFD 子场景 DS-RT-02（不再单列 BGP-BFD）。BFD 震荡原分散在 DS-RT-03(BGP) 与 DS-RT-07(IGP) 两个子场景，已合并为 DS-RT-02（row 702/123/293/451，4 条）。OSPF 相关记录最多（约 19 条），集中在邻居建立失败/异常（DS-RT-03，7 条）与路由学习计算异常（DS-RT-04，5 条）两类。其余为静态/PBR/GRE 选路异常（DS-RT-08，8 条，已移除 ace 资源耗尽的 row=276）、路由表项下发芯片失败致重启（DS-RT-06，4 条）、RIB/FIB 不符（DS-RT-07，11 条）、RIP 收敛异常（DS-RT-05，1 条，唯一 RIP 样本保留）。未归类 19 条：10 条机理缺失（根因『-』）、9 条机理属他场景待外归（含 A-04 指定的 row=281 聚合口显示、row=348 DHCPv6，以及 A-08 指定的 row=276 ace 表项不足）。数据集中根因缺失率约 16%（10/63），转发面不符类（芯片 LPM、快转不一致、资源耗尽、跨 VRF 软转）占比不小，说明路由协议故障常与控制面-转发面一致性、版本质量强相关。综上，BGP 在本数据集中样本量很小（5 条），不足以支撑独立的 BGP 根因统计规律，需补充更多样本才能评估 BGP 专项结论，本次修订未为扩大 BGP 子场景而硬塞记录。
