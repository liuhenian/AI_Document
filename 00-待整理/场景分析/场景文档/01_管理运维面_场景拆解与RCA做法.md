## 一、场景定义与边界

### 1.1 场景定义

管理运维面覆盖交换机的「被管理侧」与「管理侧」全栈：即设备对外提供的管理通道（SNMP/WEB/eWeb/SSH/Console/NETCONF/gRPC/CWMP 等协议与 Agent）以及纳管平台（INC/EMB/MACC/WIS/UNC/乐享/小锐云服等）对设备的上线、配置下发、状态采集、备份与巡检。其技术内涵是「控制面/管理面进程如何为运维系统提供可读、可写、可控的设备状态」——任何导致管理通道不可达、管理信息失真、管理进程失活、配置无法持久化/下发、或管理面资源耗尽，从而让运维系统「看不到、配不动、控不住」设备的故障，都归属本场景。它区别于转发面（业务流量不通属 EXT-FWD/网络连通）、无线接入面（终端上线的空口/关联属 WLAN），本场景只关心「管理意图→管理通道→设备管理面→状态回采」这条链路。

### 1.2 边界判据

**属于本场景：**

- SNMP/WEB/SSH/NETCONF/CWMP 等管理协议不可达、进程卡死、响应异常、信息读写失真
- INC/EMB/MACC/WIS/UNC 等纳管平台的设备上线、配置下发、状态同步、配置备份、拓扑/界面异常
- 管理面进程（rg-snmpd、cwmp、eWeb、EMB 等）因缺陷/资源耗尽导致管理功能失效或设备挂死重启
- 账号/密码/安全策略（强密码、弱加密、漏洞扫描、权限）引发的管理访问异常
- 配置未生效、重启丢失、CLI 与 WEB 不一致、ZTP/零配置上线失败等持久化/下发异常

**不属于本场景（易误入，需外归）：**

- 终端 ping 网关不通、互联网丢包、接入断网等转发/业务中断 → 应归 EXT-FWD 或网络连通性场景（如 row=736 终端 ping 互联网丢包、row=874 接入断网、row=717 UNC 策略下发引发的芯片丢包虽由管理动作触发但本质为转发面，已按管理下发归入 04）
- AP/终端空口接入、无线用户关联 → 应归 WLAN 场景（如 row=371/396/503 零配置向 AP 下发 option43 致 AP 切云模式，虽在管理面触发，机理属 WLAN 共存，按「管理面下发动作」归入 04）
- 纯 QoS 标记、TCAM/ASIC 表项转发不一致（如 row=738 ACL 资源 show 与实际不符、row=666 QinQ+DHCP 标签封装）属转发/表项面，已按「管理视图与实际不一致」分别归入 07/07；注：row=256 小米手机 WEB 页面弹出异常经复核机理为 DSCP 重标记（QoS），已从 02 外归至 QoS 场景
- CDC 透明加解密终端管控（row=766）本质为 endpoint 安全产品副作用，仅因历史归类归入安全策略，单独保留在 09 并标注

## 二、这个场景是怎么拆出来的

### 2.1 拆解维度

| 维度 | 取值 | 为什么按这个维度切 |
|---|---|---|
| 管理通道/协议 | SNMP／WEB/eWeb／SSH/Console／NETCONF/gRPC／CWMP/ACS／INC/EMB/MACC/WIS/UNC 平台 | 管理运维面的首要切分依据就是「走哪条管理通道」。不同通道的失败现象、定位命令（show snmp / show web（待实机核对） / ssh 抓包 / netconf 日志 / cwmp 重连）和修复手段（重启对应 agent 进程 vs 升级平台版本）完全不同，是 RCA 最高区分度维度。 |
| 失效对象 | 管理 Agent 进程／磁盘/内存资源／账号/安全策略／配置持久化与下发／控制面/管理面进程 | 同一通道下，失效点可能是进程卡死、也可能是磁盘写满、也可能是配置没落盘。按失效对象可进一步决定是「重启进程」「清磁盘」「升级版本」还是「改配置」。 |
| 触发来源 | 网管侧请求触发（如 snmpbulkget 占满会话）／设备侧软件缺陷／外部依赖/第三方（华三网管、DNS、FTP）／版本能力缺失／操作/环境（客户网络、掉电） | 区分「是网管采得太狠还是设备自身有 bug」，决定根因归研发还是归运维使用方式，是 APM 里区分「设备缺陷类」与「使用方式类」告警的关键。 |

### 2.2 拆解原则

1. **机理优先**：以「根因 + 方案」里的技术失效机理作为第一判据，不按主题字面归类。
2. **排查动作一致**：同一个子场景内的记录，必须能用**同一套排查动作**定位；做不到就再拆。
3. **不硬凑**：机理描述缺失的记录不强行塞进任何子场景；机理明确属于别的大场景的记录，标为「待外归」而非塞进兜底子场景。

## 三、子场景明细

### DS-MGMT-04　纳管会话失联（CWMP/ACS）与 INC/EMB/MACC/WIS/UNC 平台服务异常（42 条）

- **机理定义**：CWMP/ACS 会话因 socket/fd 重连失效、心跳不上送、cpe url 校验失败、或 INC/EMB/MACC/WIS/UNC 平台因数据库异常/残留数据/内存超水线/版本不识别型号，导致设备上线失败、离线误报、配置下发空、备份失败、拓扑错乱。
- **归类判据**：现象含设备上线失败、在 WIS/INC 上离线或误报离线、零配置（ZTP/CWMP/UNC）下发失败、平台界面不显示/卡顿/拓扑错、配置备份失败、AP 经 INC 被错误切云模式；底层归因为 cwmp 重连、心跳、平台 DB、版本识别、option43 共存等。
- **典型现象**：cwmp 断开、WIS 弹设备离线但第三方监控在线、INC 上线后反复重启、EMB 界面卡顿/远端管理界面消失、UNC 零配置脏数据残留、MACC 备份因域名含『-』解析失败、SG7008L 拓扑无法显示。
- **排查动作**：1) 在设备侧 execute diagnose-cmd process cwmp restart（debug support 进入）恢复会话；2) 看心跳/在线状态日志（WIS 后端查 9 分钟无心跳即误报）；3) debug session 看 check cpe url inform param fail / gsoap cpe fd=-1 等关键字；4) 平台层导出/清理/再导入数据库（如 redis-cli、emb 数据库）修脏数据；5) 核对 INC/EMB/UNC 版本与设备型号支持矩阵，升级平台或设备版本；6) 残留配置用 no boot config / 恢复出厂后重新上线。

    - Sheet8行 112（CS20230801-2183082）：TD3设备ZTP重启冷补丁不生效导致M0故障未解决

### DS-MGMT-05　磁盘/存储与内存资源耗尽（管理面进程致磁盘满/泄漏）（24 条）

- **机理定义**：设备进程定时写文件异常（sda_flexcnt_call_log 等）不被清空致磁盘占满、或 SSH rg_zlib/常驻进程内存泄漏、MGMT 口 buffer 残留，使管理通道（WEB/SSH/Console）无空间可用、内存超水线。

### DS-MGMT-01　SNMP 网管采集异常与 Agent 进程失活（22 条）

- **机理定义**：SNMP Agent（rg-snmpd/INC-EMB 代理）因会话被网管 bulkget 占满、内部变量翻转、消费队列溢出、OID 处理逻辑缺陷、v3 强密码策略误拒、或网管侧拒绝，导致网管读不到/断续/超时。

### DS-MGMT-02　WEB/eWeb 管理访问异常与界面显示错乱（13 条）

- **机理定义**：WEB/eWeb 服务因 https/TLS 握手慢、组件临时文件损坏、页面无法识别某配置条目、WEB 与 CLI 采集指令不一致、或版本不支持 WEB，导致管理页面打不开/加载慢/显示错乱。
- **归类判据**：现象为 WEB 登录慢、https 失败、页面报错、WEB 看到的配置/内存/地址池与 CLI 不一致、WEB 功能不可用；排除由磁盘满（归 05）、纯 QoS 标记机理（row=256 已外归 QoS 场景）、与无根因（归未归类）的条目。

- **排查动作**：1) 对比 http 与 https 访问速度（https 慢多为 TLS 握手，规避：开 http）；2) show web（待实机核对） 服务状态（待实机核对），必要时 run-system-shell 重启 eWeb/web 进程；3) 比对 WEB 与 CLI 同口径命令输出（如 show memory vs show memory slot）；4) 检查版本是否支持 WEB/拓扑，升级通用版本；5) 页面乱码优先清浏览器缓存并核对设备端配置。
- **记录抽样**：

### DS-MGMT-06　控制面/管理面进程异常与设备挂死重启（11 条）

- **机理定义**：管理相关进程（SSH 密钥交互 use-after-free、内核 panic、串口 SysRq 热键、引擎冲突 ldp_mb 异常报文、主控冲突）触发设备死机/重启/挂死，使整网管理乃至业务中断。
- **归类判据**：现象为设备异常重启、疑似死机、SSH/Console 无法登录、主控/引擎冲突日志；根因明确为 ssh key 重交互释放后复用缓冲区、内核 CVE、串口热键、peer_type 异常等控制面崩溃机理。
- **典型现象**：多次密钥交互后堆栈触发重启（putty 默认 1 小时或 1G 重交互）、阿里 57H 内核 panic 重启、串口收 SysRq+o 挂死、2/M1 引擎打印冲突 SYSLOG。
- **排查动作**：1) 收集 exception/堆栈，比对已知品控（如 7274、155460、WN20241016032）；2) 看 SSH 日志是否出现 SSH2_MSG_KEXINIT 重交互；3) show redundancy states 确认引擎热备，必要时 redundancy forceswitch 规避主控冲突；4) 关 INC 与设备的 SSH 长连接规避密钥重交互；5) 升级至修复版本（如 10.4(3b18)、B58P3 等）。
- **记录抽样**：
    - Sheet8行 50（CS20231027-2620389）：RG-S7805C 设备挂死无法登录，整网业务中断
    - Sheet8行 52（CS20231025-2610943）：RG-S7805C 设备一直打印主控冲突的日志

## 四、RCA 根因分析怎么做（本场景）

### 4.1 技术链

现象（网管看不到/配不动/控不住设备）→ 触发路径（网管请求 or 设备定时任务 or 版本缺陷 or 外部依赖）→ 失效点（管理 Agent 进程卡死 / 磁盘满 / 会话占满 / 配置未落盘 / 控制面崩溃 / 平台 DB 异常）→ 直接根因（会话被 bulkget 占满、sda_flexcnt 写满盘、ssh key use-after-free、加密不兼容、cwmp fd 泄漏等）。通用定位顺序：先确认「是通道不可达还是信息失真」→ 区分「设备侧缺陷 vs 网管侧触发」→ 按通道用对应 show/debug/抓包锁定失效点 → 重启对应进程临时恢复 → 升级版本根治。

### 4.6 成功 / 失败对比要点

本场景最快定位法是「正常侧 vs 异常侧」对比：① 同网管下其它同型号设备能读到 SNMP → 异常设备 rg-snmpd 失活或磁盘满（重启进程/清盘验证）；② 同一设备 http 能开、https 慢 → 确认 TLS 握手机理，开 http 即恢复；③ 异常设备重启 cwmp 后 WIS 恢复在线 → 坐实 CWMP 会话失效；④ 同一设备 show running-config 与 show startup-config 不一致 → 配置未落盘；⑤ 同版本设备有的丢配置有的不丢（row=549 S3000 差异）→ 指向版本/加密差异而非操作。核心是用「重启对应 Agent 进程能否瞬时恢复」作为判定「进程失效」的决定性对比实验。

## 八、本场景关键结论

管理运维面共 166 条，已归类 148 条（9 个子场景）、未归类 18 条。最集中的子场景是「DS-MGMT-04 纳管会话失联与平台服务异常」（42 条，占 25%），其次为「DS-MGMT-05 磁盘/内存资源耗尽」（24 条）和「DS-MGMT-01 SNMP 采集异常」（22 条），三者合计已占已归类量的 59%，是管理面故障的绝对主力。较 v1 的变化：① row=256 经 A-08 复核机理属 QoS（DSCP 重标记），已从 DS-MGMT-02 外归至 QoS 场景，DS-MGMT-02 由 14 条降为 13 条；② 进程写文件满盘同机理（本场景 row 8/452/528、EXT-FWD-08 row 321、EXT-SYS-02 row 713）已在跨场景同机理说明登记，主归属建议 DS-MGMT-05；③ 未归类由 17 条增至 18 条，其中 3 条为机理属他场景待外归（row=256 QoS、row=736/874 转发面），其余 15 条为机理缺失。数据质量观察：约 9% 工单根因/方案为空或仅『升级解决』『打补丁』等无机理内容（row=304/308/337/373/384/488/579/608/640/708/727/729/740），另有 row=736/874 实为转发面中断被误归入本场景，说明原始「领域」切分存在少量串场景；此外大量工单仅标注『命中已知软件 bug/预警』而未写具体机理，给 RCA 自动化带来标签稀疏问题。
