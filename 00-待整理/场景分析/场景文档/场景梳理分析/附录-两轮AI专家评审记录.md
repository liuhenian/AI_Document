| 轮次 | 评审视角 | 专家角色 | 关注重点 | 与上一轮的关系 |

**为什么第 2 轮要专门查"修订回归"**：第 1 轮的修订回执声称全部闭合，但第 2 轮逐条比对原文后发现**部分条目只是改了措辞、并未真正落地**（详见第五节）。这暴露出「回执自证」不可信的结构性问题，因此第 2 轮把"回归核查"提升为独立评审维度。

### 3.3 本轮最高优先级发现：4 处「不可落地（高）」

统一根因：**把加密通道上的业务语义当成了可用镜像抓包获取的观测点**。

| 编号 | 文档 | 原始问题 | 修订后 |
|---|---|---|---|
| H1 | 管理面-Web通道 | §8「TLS 握手成功率与耗时」「HTTP vs HTTPS 成功率」用镜像抓包采 HTTPS | 改为 **APM 主动探针**（发起真实 HTTP/HTTPS 请求测握手与响应时延），数据源落 VictoriaMetrics |
| H2 | 管理面-NETCONF | §8 全部行 + §9 步2 + §8.1 用镜像抓包解析 SSH 会话内 `<hello>`/`<rpc>`/`<rpc-reply>` | 主采集改为**设备侧 netconfd 协议日志**（经 Syslog 订阅落 Loki）+ 网管侧 RPC 日志；镜像**仅保留 SSH 握手与报文长度统计** |
| H3 | 管理面-gRPC | §8「gNMI Set 成功率」「北向请求量/错误码」用镜像抓包采 gRPC(TLS) | 改为**采集器侧 gRPC/RPC 指标 + 设备侧 gNMI 服务日志** |
| H4 | 管理面-INC | §8 北向 RESTful 用 `Syslog/Trap 订阅 + 镜像抓包` 采 HTTPS（第 1 轮回执称已删、实际未删） | 删除镜像抓包，改为**平台侧日志 + 平台 API 拉取（需业务确认）** |

四篇 §8 表格下方统一加注：

> **加密通道（HTTPS/SSH/TLS）之上的业务语义不可经镜像抓包获得，本表相关观测点一律采用设备侧/采集器侧日志或探针。**

### 3.4 结构性问题：子节后置致骨架错乱（中）

`NETCONF`、`CWMP`、`ACS`、`gRPC` 四篇的 `### 3.x / 6.x / 8.x / 9.x` 子节被错放在 §9 之后。全部**归位到各自所属主节的紧邻位置**，内容零改动。归位后 21 篇标题序列均严格 `0 → 12` 升序。

### 3.5 系统性问题：§8「数据源」列填错内容（中，9 篇路由全覆盖）

9 篇路由文档 §8 的「数据源」列填的是**命令或观测对象**（如 `show ip bgp summary`、`CLI 回显`、`RIB 表`），而规范 3.5 要求该列只填**载体**。

**回填结果**：**82 行 100% 回填**，载体分布 Vict 70 / Loki 29 / MySQL 12 / Pyroscope 1 / Redis 0；原命令/表名移入「观测对象」或「采集方式」列括注。BGP/OSPF/ISIS/PBR 四篇原有的「采集落点」重复段已删除，表列与落点不再自相矛盾。

## 五、修订回归检查结果（第 2 轮专项，重要）

第 2 轮把「上一轮是否真改对」作为独立维度核查，发现三类情况：

| 情况 | 例子 | 数量 |
|---|---|---:|
| **真闭合** | CWMP 中-1（P0 采集已改设备侧探针）；ACS 中-1；BFD 的 RFC 落地性核对 | 多数 |
| **假闭合**（回执称已改、原文未改） | Web通道「5 次失败锁 10 分钟」6 处仍标本项目实证；NETCONF §10 row 217 仍绑"XML 格式错"；INC §8 北向 RESTful 仍用镜像抓包（**该条第 1 轮回执明确写"已删除镜像抓包"，实际未删**）；MACC/UNC/WIS 的 `ap-mode macc` 待核标注与 `Q-MGMT-04` 挂载声称已改而未改；SNMP §3.5 未按回执拆分 v1/v2c 异常 | **11+** |
| **改出问题** | OSPFv3 §9 步1「per-link **无 DR**」——为修上一条而写入的新错误（OSPFv3 广播网仍选举 DR/BDR）；OSPF 篇引入 row 11/36/38/120 误引 | **2** |

**结论与教训**：
1. **回执不能自证**。第 1 轮三份回执全部声称"100% 闭合"，实际存在系统性假闭合。第 2 轮因此要求回执**逐条给出「修改点节号 + 改后原文片段」作为证据**，禁止只写"已闭合"。
2. **修订可能引入新错误**。为消除一个矛盾而写入的新表述必须复核全局一致性（OSPFv3 的 DR 案即典型）。
3. **流程性失真需在交付物中留痕**——已通过各篇 §12 的加注保留，使后续读者知道第 1 轮记录的可靠性边界。
