# 1 系统启动的各个阶段
这是一个非常关键的Linux启动流程问题。理解这些阶段，才能精准地放置你的eBPF监控点。

## 1.1 Linux启动流程全景图

```text
┌─────────────────────────────────────────────────────────────┐
│                        固件阶段                              │
│  BIOS/UEFI → 硬件初始化 → 加载引导程序                        │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                     引导加载阶段                              │

└────────────────────────┬────────────────────────────────────┘
                         │

│                   ★ initramfs 阶段 ★                         │
```

## 1.2 各阶段详解

### 1.2.1 **固件阶段** (BIOS/UEFI)
- 硬件上电自检
- 初始化基本硬件（CPU、内存、USB键盘等）
- 从启动设备加载引导程序

### 1.2.2 **引导加载阶段** (Bootloader)
- GRUB/systemd-boot/syslinux 工作
- 加载内核 `vmlinuz` 和 initramfs `initrd.img` 到内存
- 传递内核启动参数（如 `root=/dev/sda1`）
- 跳转到内核入口点

### 1.2.3 **★ initramfs 阶段 ★** (早期用户空间)

**这是你关注的重点。**

```text
内核解压 → 初始化页表、内存管理、调度器
    → 挂载 initramfs (内存中的临时根文件系统)
        → 运行 /init
            ├─ 加载存储驱动 (如 ahci, nvme, virtio_blk)
            ├─ 加载文件系统驱动 (如 ext4, xfs)
            ├─ 加载 RAID/LVM 模块 (如果需要)
            ├─ 解密根文件系统 (如果加密)
            └─ 调用 switch_root 切换到真实根
```

**initramfs 阶段的模块加载特点：**
- **手动加载**：通过 `/init` 脚本中的 `modprobe` 命令显式加载
- **关键驱动**：仅加载访问根文件系统所必需的驱动
- **顺序固定**：优先级最高，先于后续阶段的自动加载

### 1.2.4 **根文件系统切换** (pivot_root/switch_root)
- 卸载 initramfs 的内存文件系统
- 挂载真实磁盘分区到 `/`
- 执行新根文件系统中的 `/sbin/init`

### 1.2.5 **系统初始化阶段** (System Init)

**这是大部分模块被加载的阶段。**

```text
systemd 启动
  ├─ systemd-modules-load.service  ← ★ 加载 /etc/modules-load.d/ 下的模块
  ├─ systemd-udevd.service
  │   └─ udev 触发设备探测
  │       ├─ 加载 PCI/USB 设备驱动
  │       ├─ 加载网卡驱动
  │       └─ 加载其他外设驱动
  ├─ systemd-tmpfiles-setup.service
  └─ 其他服务
```

### 1.2.6 **正常运行阶段**
- 用户登录、应用程序运行
- 设备热插拔 → `udev` 或 `modprobe` 自动加载驱动

## 1.3 你的目标模块会在哪个阶段加载？

这取决于模块的类型：

### 1.3.1 情况1：存储/文件系统驱动 (initramfs 阶段)
```bash
# 例如：根文件系统在 NVMe SSD 上
# initramfs 的 /init 脚本中：
modprobe nvme
modprobe ext4
```

### 1.3.2 情况2：`/etc/modules-load.d/` 中配置的模块 (系统初始化早期)
```bash
# /etc/modules-load.d/my_driver.conf
my_driver
```
这会由 `systemd-modules-load.service` 加载，**在 udev 之前**。

### 1.3.3 情况3：设备探测触发的模块 (系统初始化中期)
```bash
# 由 udev 根据设备 ID 自动匹配
# /lib/modules/$(uname -r)/modules.alias
alias pci:v00008086d00001533sv*sd*bc*sc*i* igb
```

## 1.4 你的 eBPF 监控应该挂载在哪个时机？

对照上面的阶段图，**最佳挂载点**：

```bash
# 方案优先级：
1. systemd 服务 (Before=systemd-modules-load.service)
   → 覆盖情况2和3的模块

2. initramfs 阶段挂载
   → 额外覆盖情况1的存储驱动模块

3. 内核启动参数 trace_event
   → 从内核启动瞬间就开始记录
```

### 1.4.1 具体实现参考：

```ini
# /etc/systemd/system/mem-monitor.service
[Unit]
Description=BPF Memory Monitor
DefaultDependencies=no
# ★ 关键：在模块自动加载之前启动
Before=systemd-modules-load.service
Before=systemd-udevd.service

[Service]
Type=simple
ExecStartPre=/bin/mount -t debugfs debugfs /sys/kernel/debug
ExecStart=/usr/local/bin/mem_monitor_loader
RemainAfterExit=yes

[Install]
WantedBy=sysinit.target
```

这样就能确保：
- **initramfs 加载的模块**：需要方案二（initramfs钩子）
- **modules-load.d 加载的模块**：被这个服务拦截 ✓
- **udev 触发的模块**：也被这个服务拦截 ✓

## 1.5 调试技巧：查看模块加载时序

```bash
# 查看所有模块的加载时间和顺序
dmesg | grep -E "modules|driver|modprobe"

# 查看某个模块的详细信息
modinfo my_driver

# 追踪模块加载事件
bpftrace -e 'kprobe:load_module { printf("%s loaded\n", str(arg1)); }'
```

你现在需要监控的模块是哪个类型的驱动？是存储驱动、网卡驱动，还是其他设备驱动？这样我能帮你确定它到底是在 initramfs 阶段还是系统初始化阶段加载的。
