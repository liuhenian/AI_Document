# 20 题库 技术类（PM-A / PM-B / PM-C / PM-G）

## 模块 PM-A 转发原理与协议基础（A-001 ~ A-035）

**A-001**（核心·单）1 KB 报文在 400G 端口上的串行化时延约为：
A 1.3 ns　B 20 ns　C 82 ns　D 200 ns
**答案** B　**解析** 8192 bit ÷ 4×10¹¹ bit/s ≈ 20.5 ns。1 KB 在 100G 上是 82 ns，速率翻 4 倍时延降为 1/4。**点** 时延预算

**A-002**（核心·单）端口 CRC 错误计数与 FEC 纠正计数持续上升，最可能的问题是：
A 路由震荡　B 光链路质量　C 缓存不足　D 哈希不均
**答案** B　**解析** 物理层误码的直接证据。**点** 丢包七位置

**A-003**（核心·多）数据中心放弃生成树的理由包括：
A 收敛在秒级　B 冗余链路被阻塞　C 广播与泛洪不可控　D 不支持 IPv6
**答案** ABC　**解析** 与 IPv6 无关；STP 的问题在收敛、利用率与广播域。**点** 二层局限

**A-004**（核心·单）ECMP 哈希不均（polarization）最直接的后果是：
A 控制面震荡　B 部分链路拥塞而部分空闲　C 报文乱序　D MTU 不匹配
**答案** B　**解析** 多条大象流落入同一哈希桶，链路间负载失衡。**点** ECMP

**A-005**（核心·单）56 个 400G 端口的交换机，标称交换容量约为：
A 22.4 Tbps　B 44.8 Tbps　C 89.6 Tbps　D 11.2 Tbps
**答案** B　**解析** 56 × 400G × 2 = 44.8 Tbps（全双工）。**点** 容量计算

**A-006**（核心·判）交换机时延的主要来源在拥塞时是排队时延，而不是芯片转发时延。
**答案** 正确　**解析** 排队可达毫秒级，设备转发通常在微秒以内。**点** 时延构成

**A-007**（核心·单）三层转发选路的依据是：
A 最短 MAC 地址　B 最长前缀匹配　C 最小 TTL　D 最大 MTU
**答案** B　**解析** 最长前缀匹配是 IP 转发的核心规则。**点** 三层转发

**A-008**（支撑·单）业务"偶发中断、数据面看似正常、CPU 占用偏高"，最可能原因是：
A 光模块故障　B 协议报文上送被限速丢弃　C 缓存溢出　D 布线错误
**答案** B　**解析** 控制面上送（CoPP）限速导致协议报文丢失。**点** 丢包七位置

**A-009**（核心·单）服务器 MTU 为 9000，VXLAN 封装后外层报文至少为：
A 9000　B 9042　C 9050　D 9100
**答案** C　**解析** 14+20+8+8 = 50 字节开销。**点** MTU

**A-010**（核心·多）端到端时延包含：
A 串行化时延　B 传播时延　C 排队时延　D 设备处理时延
**答案** ABCD　**解析** 四段加上光模块时延，构成完整预算。**点** 时延构成

**A-011**（核心·多）大规模数据中心 underlay 选择 eBGP 的理由：
A 扩展性与表项能力　B 策略表达力强　C 故障域隔离　D 默认收敛最快
**答案** ABC　**解析** D 恰好相反——BGP 默认收敛慢，需 BFD 与 GR/NSF 补偿。**点** 路由选型

**A-012**（核心·单）补偿 BGP 收敛慢的常用组合是：
A STP + VRRP　B BFD + GR/NSF　C LACP + M-LAG　D PFC + ECN
**答案** B　**解析** 快速检测 + 平滑重启。**点** BGP 代价

**A-013**（支撑·单）超大 underlay 中 IS-IS 相对 OSPF 的优势主要是：
A 配置更简单　B TLV 扩展性更强　C 不需要邻居　D 天然支持多租户
**答案** B　**解析** TLV 扩展带来 IPv6 与流量工程的天然支持。**点** 路由选型

**A-014**（支撑·单）BGP 防环依赖：
A AS_PATH　B TTL　C RD　D RT
**答案** A　**解析** AS_PATH 中检测到本 AS 即丢弃。**点** BGP

**A-015**（支撑·单）iBGP 全互联不可扩展，解决方案是：
A 改用 OSPF　B 路由反射器　C 增加 MTU　D 关闭多路径
**答案** B　**解析** 反射器把 N² 邻居变为星型。**点** BGP

**A-016**（核心·单）BFD 的作用是：
A 加密控制报文　B 毫秒级故障检测　C 分配 IP 地址　D 抑制广播
**答案** B　**解析** 常见 3.3 ms × 3 倍检测。**点** 高可用

**A-017**（核心·多）M-LAG 相比堆叠的优势：
A 控制面独立、故障域较小　B 可逐台升级、业务中断窗口小　C 配置完全不需要一致性检查　D 双活转发
**答案** ABD　**解析** C 错——M-LAG 恰恰需要一致性检查（如 peer-link、配置匹配）。**点** M-LAG

**A-018**（支撑·单）ISSU 的价值是：
A 提升带宽　B 升级过程业务不中断　C 降低时延　D 替代 BFD
**答案** B　**解析** 不中断业务升级，互联网客户常作为准入要求。**点** 高可用

**A-019**（核心·单）Spine-Leaf 无阻塞的条件是：
A Spine 上行带宽 = Leaf 下行带宽　B Spine 数量 ≥ Leaf 数量　C 全部使用框式设备　D 关闭 ECMP
**答案** A　**解析** 1:1 收敛比即无阻塞。**点** 架构

**A-020**（核心·单）收敛比 1:3 的含义是：
A 三条链路备份一条　B 下行总带宽是上行总带宽的 3 倍　C 三个租户共享一条链路　D 时延为 3 倍
**答案** B　**解析** 超配比，直接决定成本与拥塞风险。**点** 架构

**A-021**（核心·单）64 端口 400G 交换机建两层无阻塞，Leaf 取 32 台（32 下行 + 32 上行），服务器每台 8 张 400G 网卡，可接服务器数为：
A 64 台　B 128 台　C 256 台　D 512 台
**答案** B　**解析** (32 × 32) ÷ 8 = 128 台，对应 1024 张 GPU。**点** 规模计算

**A-022**（核心·单）两级 Spine-Leaf 中任意两台服务器之间的跳数：
A 固定为 2　B 固定为 3　C 随规模变化　D 由 STP 决定
**答案** B　**解析** Leaf→Spine→Leaf，恒为 3 跳（含首尾设备转发），时延可预测。**点** 架构

**A-023**（支撑·单）需要"一次规划、多年演进、单机高密度"的场景应选：
A 盒式　B 框式　C 白盒　D 家用交换机
**答案** B　**解析** 框式可换线卡、容量可演进。**点** 硬件形态

**A-024**（支撑·单）长肥管道（DCI、存储）场景更依赖：
A 浅缓冲　B 深缓冲　C 更大 TCAM　D 更多 VLAN
**答案** B　**解析** 长时延链路的带宽时延积大，需要大缓存吸收突发。**点** 缓存

**A-025**（支撑·单）对产品 Roadmap 影响最直接的芯片因素是：
A 芯片封装颜色　B 交期与功能开放度　C 芯片品牌知名度　D 芯片功耗标签
**答案** B　**解析** 交期决定交付承诺，功能开放度决定差异化空间。**点** 芯片格局

**A-026**（支撑·单）白盒 + SONiC 对商业模式的核心影响是：
A 提升硬件毛利　B 压缩硬件毛利、价值转向软件与方案　C 消除竞争　D 降低运维复杂度
**答案** B　**解析** 硬件同质化，溢价来自软件、方案与服务。**点** 白盒

**A-027**（细节·单）CPO（共封装光学）的主要代价是：
A 功耗上升　B 不可热插拔、可维护性下降　C 带宽下降　D 不支持 800G
**答案** B　**解析** 收益是功耗与信号完整性，代价是运维形态改变。**点** 光互连

**A-028**（支撑·单）FEC 的作用与代价分别是：
A 提升带宽、降低时延　B 纠正误码、增加时延　C 加密报文、增加开销　D 分配波长、降低功耗
**答案** B　**解析** 速率越高越依赖 FEC，代价是数百纳秒级时延。**点** 光互连

**A-029**（核心·单）能把"设备告警"翻译成"业务影响"的指标位于：
A 物理层　B 链路层　C 转发层　D 业务层
**答案** D　**解析** 业务层指标（JCT、重传率、应用时延）才是客户语言。**点** 可观测性

**A-030**（支撑·单）INT（带内遥测）的本质是：
A 加密流量　B 让报文携带逐跳设备与队列信息　C 替代 BGP　D 压缩报文
**答案** B　**解析** 跟包观测，定位到具体跳与队列。**点** 可观测性

**A-031**（核心·判）交换机缓存越大越好。
**答案** 错误　**解析** 大缓存把"丢包"变成"排队"，AI 场景下长队列同样致命。**点** 缓存

**A-032**（核心·判）VXLAN 自带加密能力。
**答案** 错误　**解析** VXLAN 只做封装，加密需 MACsec 或 IPsec 叠加。**点** VXLAN

**A-033**（核心·简）客户报"全网业务都慢"，你的定位顺序是什么？
**答案要点** ① 查控制面：路由震荡、CPU、上送限速 ② 查全局拥塞：队列水位、ECN 标记率、PFC pause 时长 ③ 查物理层：光功率与误码 ④ 查变更：最近配置/DCI 链路 ⑤ 最后给可验证改进项 + 验收指标。**评分** 分层清晰（50%）、有判据（30%）、落到验收（20%）

**A-034**（核心·简）为什么数据中心不用生成树？
**答案要点** 收敛秒级无法满足毫秒/微秒要求；冗余链路被阻塞导致利用率≤50%；广播域不可控；改用三层路由 + ECMP + Overlay 解决。**评分** 三条理由齐全 + 说出替代方案

**A-035**（核心·案）客户要建 2000 台服务器的无阻塞网络，每台双上联 100G。给出组网思路与需要客户确认的问题。
**答案要点** ① 端口账：2000×2 = 4000 个 100G 下行端口 ② 选端口密度，算 Leaf 数（4000 ÷ 每台下行数）③ 上行按 1:1 配，算 Spine 数 ④ 确认：是否需要 Overlay 与多租户、是否需要跨机房、收敛比是否可放宽、机柜与功耗约束 ⑤ 输出两套方案（无阻塞 vs 1:3）与成本差异。**评分** 会算账（40%）、会问需求（30%）、给方案对比（30%）

## 模块 PM-B Overlay 与架构演进（B-001 ~ B-030）

**B-001**（核心·单）VLAN ID 的理论上限是：
A 1024　B 4094　C 8192　D 1600 万
**答案** B　**解析** 12 位，去掉保留值后 4094。**点** VLAN 局限

**B-002**（核心·单）VXLAN 封装带来的外层开销是：
A 36 字节　B 44 字节　C 50 字节　D 64 字节
**答案** C　**解析** 14（以太）+20（IP）+8（UDP）+8（VXLAN）。**点** 封装

**B-003**（核心·单）VNI 的位宽与容量：
A 12 位/4094　B 16 位/65535　C 24 位/约 1600 万　D 32 位/42 亿
**答案** C　**解析** 24 位是 VXLAN 能支撑云规模的关键。**点** 封装

**B-004**（核心·单）VXLAN 默认 UDP 目的端口是：
A 4789　B 4791　C 5000　D 179
**答案** A　**解析** 4791 是 RoCEv2，179 是 BGP。**点** 封装

**B-005**（核心·单）EVPN Type-2 路由的主要作用是：
A 通告 MAC/IP 位置　B 选举指定转发者　C 通告 BUM 流量名单　D 发布网段路由
**答案** A　**解析** MAC/IP 通告，支撑 ARP 抑制与主机路由。**点** EVPN 五类

**B-006**（核心·单）BUM 流量（广播/未知单播/组播）的隧道复制名单由哪类路由决定：
A Type-1　B Type-2　C Type-3　D Type-5
**答案** C　**解析** IMET 路由（包含组播以太标签路由）。**点** EVPN 五类

**B-007**（核心·单）支撑 L3 对称 IRB 与外部网段互联的是：
A Type-2　B Type-3　C Type-4　D Type-5
**答案** D　**解析** IP 前缀路由。**点** EVPN 五类

**B-008**（支撑·单）多归（multi-homing）场景中选举指定转发者（DF）用：
A Type-1 与 Type-4　B Type-2 与 Type-3　C Type-5　D 不需要路由
**答案** A　**解析** A-D 路由与以太段路由配合，避免重复转发。**点** EVPN 五类

**B-009**（核心·多）EVPN 相比泛洪学习的收益：
A 抑制泛洪　B 收敛更快　C 支持多活　D 自动加密
**答案** ABC　**解析** 另有 ARP 抑制；加密不属于 EVPN 能力。**点** EVPN 价值

**B-010**（核心·单）分布式网关相对集中式网关的核心优势是：
A 配置更少　B 东西向流量一跳直达　C 不需要路由　D 成本更低
**答案** B　**解析** 集中式需要流量绕行核心两个来回。**点** 网关形态

**B-011**（核心·单）anycast 网关的含义是：
A 每台设备网关地址不同　B 同一网关 IP/MAC 部署在所有 Leaf 上　C 只有一台网关　D 网关在主备切换
**答案** B　**解析** 虚拟机迁移后网关不变。**点** 网关形态

**B-012**（支撑·单）大规模多租户必须用对称 IRB 的原因是：
A 非对称 IRB 需要所有 VNI 的 ARP 表项，规模不可行　B 对称 IRB 更省 IP　C 非对称不支持 IPv6　D 对称 IRB 不需要封装
**答案** A　**解析** 表项扩展性是决定性因素。**点** IRB 模式

**B-013**（支撑·单）RD（路由区分符）的作用是：
A 决定路由发给谁　B 给相同前缀加唯一标识避免冲突　C 提供独立路由表　D 加密路由
**答案** B　**解析** VRF 提供表，RD 防前缀冲突，RT 控传播。**点** 多租户

**B-014**（核心·单）当前主流的 VTEP 部署位置是：
A 核心网关集中部署　B 分布在各 Leaf　C 服务器软件　D 出口路由器
**答案** B　**解析** 就近封装，东西向一跳直达。**点** VTEP

**B-015**（核心·单）Overlay 上线后"ping 小包通、传大文件卡死"，首先怀疑：
A 路由环路　B MTU 不足　C MAC 漂移　D BGP 震荡
**答案** B　**解析** 封装增加 50 字节导致大包被丢弃。**点** MTU 排障

**B-016**（核心·单）服务器 MTU 1500、Underlay MTU 也配成 1500，会怎样：
A 正常工作　B 大包被丢弃或分片，业务异常　C 时延降低　D 带宽翻倍
**答案** B　**解析** Underlay 至少需 1550，工程上统一 9000。**点** MTU 排障

**B-017**（核心·判）部署 VXLAN 后，underlay 仍然需要全网二层打通。
**答案** 错误　**解析** Underlay 只需 IP 可达，二层能力由 Overlay 提供。**点** Overlay 本质

**B-018**（核心·判）VNI 与 VLAN 必须一一对应。
**答案** 错误　**解析** 可多对多映射，由配置决定。**点** VXLAN 误解

**B-019**（核心·简）EVPN 为什么能抑制泛洪？
**答案要点** 控制面用 BGP 提前通告 MAC/IP 位置（Type-2）与 BUM 名单（Type-3），转发时直接命中表项，不需要向整个 VNI 泛洪；网关代答 ARP 进一步减少广播。**评分** 说清控制面替代数据面 + 提到 Type-2/Type-3

**B-020**（支撑·简）集中式与分布式网关在时延上的差异，如何向客户解释？
**答案要点** 集中式：服务器 A→Leaf→Spine→核心网关→Spine→Leaf→B，两次跨 Spine；分布式：A→Leaf（网关）→Leaf→B，一跳跨设备。用"绕行楼层"类比，并给出可测的时延差。

**B-021**（核心·简）四代数据中心架构各解决什么问题？
**答案要点** 一代：连通与隔离；二代：虚拟机迁移与二层扩展；三代：无阻塞、多路径、多租户；四代：万卡训练的可预测尾时延与无损。各自遗留问题一并说。

**B-022**（支撑·单）第二代大二层架构的主要遗留问题是：
A 带宽不足　B VLAN 上限与控制面耦合、故障域大　C 不支持多租户　D 无法路由
**答案** B　**解析** 4094 上限与堆叠/大二层的单控制面风险。**点** 架构演进

**B-026**（支撑·判）VXLAN 封装与解封装在现代交换芯片上是硬件完成的。

**B-027**（支撑·单）ARP 抑制的实现依赖：

**B-028**（支撑·多）多租户隔离依赖哪三件套：

**B-029**（核心·简）推动架构演进的根本变量是什么？

**C-015**（核心·单）轨对齐（rail-optimized）拓扑的核心价值是：

**C-034**（核心·案）客户说"MFU 只有 40%"，给出排查路径。

**C-035**（核心·简）智算产品与通算产品的功能差异有哪些？
**答案要点** 无损一键化与自愈、DLB/喷洒、微秒级遥测、拓扑自动化与布线校验、慢节点隔离、验收方法与调优服务、交付形态从单机变方案。

## 模块 PM-G 路由协议 BGP 与 OSPF（G-001 ~ G-030）

> 对应精讲：[[06-精讲-路由协议BGP与OSPF]]。本模块 30 题，核心 20 题，做完约 40 分钟。

**G-001**（核心·单）OSPF 属于哪一类路由协议？
A 距离矢量　B 链路状态　C 路径矢量　D 策略路由
**答案** B　**解析** 每台路由器泛洪自己的直连链路，各自用 SPF 算最短路。路径矢量是 BGP。**点** 协议类型

**G-002**（核心·判）OSPF 邻居停在 2-Way 状态一定说明有故障。
**答案** 错误　**解析** 广播网中非 DR/BDR 的路由器彼此停在 2-Way 是**正确的稳定态**，它们只与 DR/BDR 建立 Full。**点** 邻居状态

**G-003**（核心·单）OSPF 邻居卡在 ExStart 状态，最可能的原因是：
A 认证不匹配　B 接口 MTU 不一致　C Area ID 不同　D 组播被 ACL 拦截
**答案** B　**解析** ExStart 协商 DBD 主从与序号，MTU 不一致会导致 DBD 被丢弃而反复重试。**点** 排障

**G-004**（核心·单）广播网段选举 DR 与 BDR 的核心目的是：
A 提供冗余网关　B 把邻接数从 O(N²) 降到 O(N)　C 加快 SPF 计算　D 支持认证
**答案** B　**解析** 所有路由器只与 DR/BDR 建 Full，泛洪集中处理，避免 N×(N−1)/2 条邻接与泛洪风暴。**点** DR/BDR

**G-005**（核心·单）OSPF 的 Type 3 LSA 由谁产生、作用是什么？
A 每台路由器，描述自身链路　B DR，描述网段成员　C ABR，描述其他区域的网段　D ASBR，描述外部路由
**答案** C　**解析** Type 1 是 Router LSA、Type 2 是 Network LSA、Type 3 是 Summary LSA（ABR 产生）、Type 5 是外部路由。**点** LSA

**G-006**（核心·多）关于 OSPF LSA，下列说法正确的有：
A Type 1 在区域内泛洪　B Type 5 由 ASBR 产生、全域泛洪　C Type 7 出现在 NSSA 内　D Type 4 由 DR 产生
**答案** ABC　**解析** Type 4 是 ASBR Summary LSA，由 ABR 产生，用来告诉其他区域"谁去连外部"。**点** LSA

**G-007**（核心·单）OSPF 默认参考带宽 100 Mbps，则 10G 与 100G 接口的开销分别是：
A 10 与 1　B 1 与 1　C 100 与 10　D 1 与 0.1
**答案** B　**解析** 100M ÷ 10G = 0.1 向上取整为 1；100M ÷ 100G 同样为 1。所以默认配置下 OSPF **无法区分链路快慢**，工程上必须改参考带宽。**点** cost 计算

**G-008**（支撑·单）广播网中 OSPF 的 Hello 与 Dead 定时器默认值分别是：
A 5 s / 20 s　B 10 s / 40 s　C 30 s / 120 s　D 60 s / 180 s
**答案** B　**解析** Dead 为 Hello 的 4 倍。30 s / 120 s 是 NBMA 与 P2MP 的默认值。**点** 定时器

**G-009**（核心·单）BGP 使用的传输层协议与端口是：
A UDP 179　B TCP 179　C TCP 89　D UDP 4789
**答案** B　**解析** BGP 跑在 TCP 179 上，靠 TCP 保证可靠传输；协议号 89 是 OSPF 直接封装在 IP 中。**点** BGP 承载

**G-010**（核心·单）BGP 所有报文的公共头部长度是：
A 16 字节　B 19 字节　C 20 字节　D 24 字节
**答案** B　**解析** 16 字节标记 + 2 字节长度 + 1 字节类型 = 19 字节。**点** 报文格式

**G-011**（核心·单）BGP 邻居状态机的正确顺序是：
A Idle → Active → Connect → OpenSent → OpenConfirm → Established
B Idle → Connect → Active → OpenSent → OpenConfirm → Established
C Idle → Connect → OpenSent → Active → OpenConfirm → Established
D Idle → Init → 2-Way → ExStart → Exchange → Loading → Full
**答案** B　**解析** D 是 OSPF 的顺序。BGP 中 Active 表示"TCP 建连失败正在重试"，**不是好事**。**点** 状态机

**G-012**（核心·单）BGP 邻居处于 Active 状态，最不可能的原因是：
A 对端未监听 179 端口　B 未指定 update-source 导致源地址不对　C 路由策略拦截了前缀　D 中间设备拦截了 TCP 建连
**答案** C　**解析** 策略问题发生在 Established 之后。Active 是 TCP 层建连失败。**点** 排障

**G-013**（核心·单）BGP 邻居已 Established 但学不到任何路由，应优先检查：
A 光模块与链路　B 地址族激活、route-map 与前缀列表　C AS 号是否一致　D Hold Time 设置
**答案** B　**解析** 邻居建立说明底层连通与参数协商都通过，问题在策略层。可用 received / accepted 两个计数对比定位。**点** 排障

**G-014**（支撑·判）eBGP 报文的默认 TTL 为 1，因此非直连的 eBGP 邻居必须配置 multihop。
**答案** 正确　**解析** 这是 eBGP 的安全设计；iBGP 默认 TTL 为 255。**点** eBGP 与 iBGP

**G-015**（核心·单）AS 内部必须引入路由反射器（RR）的根本原因是：
A iBGP 收敛比 eBGP 慢　B iBGP 学到的路由不再传给其他 iBGP 邻居（水平分割）　C iBGP 不支持多路径　D iBGP 不改 next-hop
**答案** B　**解析** 水平分割导致必须全互联，N 台设备需 N×(N−1)/2 条会话，不可扩展；RR 用 Cluster List 防环。**点** RR

**G-016**（核心·单）BGP 选路时，最先比较的两个属性通常是：
A AS_PATH 与 MED　B Weight 与 Local Preference　C Origin 与 Router ID　D IGP 开销与路由年龄
**答案** B　**解析** 顺序为 Weight → Local Preference → 本地始发 → AS_PATH → Origin → MED → eBGP 优于 iBGP → IGP 开销 → 决胜项。**点** 选路顺序

**G-017**（核心·判）Local Preference 只在本地 AS 内部传递，不会传给 eBGP 邻居。
**答案** 正确　**解析** 它是"AS 内统一意志"，用来决定出口选谁；跨 AS 影响入口的是 MED。**点** 属性作用域

**G-018**（支撑·单）MED 属性的语义是：
A 告诉邻居"从我这里进更近"　B 告诉本 AS"从哪个出口出去"　C 标记路由来源可信度　D 防止 AS 间环路
**答案** A　**解析** MED 影响的是**入向**流量；Local Preference 影响**出向**。默认只在同一相邻 AS 之间比较。**点** 属性语义

**G-019**（核心·单）两台 Spine 各有一条等价路由，但流量只走其中一条，最可能的原因是：
A 哈希算法缺陷　B eBGP 默认只把最优一条装进转发表　C 链路带宽不一致　D 未开启 BFD
**答案** B　**解析** 需要显式配置 maximum-paths 才能形成 ECMP。这是默认行为，不是故障。**点** 多路径

**G-020**（核心·多）关于 BFD、GR/NSF、路由抑制（dampening），说法正确的有：
A BFD 解决"发现晚"　B GR/NSF 解决"控制面重启期间不断转发"　C dampening 会延长故障恢复时间　D 三者叠加一定更快恢复
**答案** ABC　**解析** 三者解决不同问题，且可能互相干扰：dampening 会把刚恢复的路由压住，BFD 过快会导致会话频繁重建。**点** 收敛加速

**G-021**（支撑·简）路由抑制（dampening）有什么副作用？产品上应该怎么处理？
**答案要点** 抑制抖动的同时会把刚恢复的链路按在惩罚状态，导致二次故障恢复更慢；应按客户类型给不同默认值——金融政企偏稳定可开启，互联网与智算偏恢复建议关闭，并把开关做成可配置项写进交付基线。

**G-022**（核心·单）EVPN 与 BGP 的关系是：
A 两种互相独立的协议　B EVPN 是 BGP 的一个地址族（AFI 25），复用 BGP 的可靠性与策略能力　C EVPN 替代 BGP　D EVPN 只能跑在 OSPF 上
**答案** B　**解析** EVPN 通过 MP-BGP 承载 MAC/IP 可达性，五类路由本质是新的 NLRI 类型，见 [[02-精讲-Overlay与EVPN#4 EVPN：把学习搬到控制面|02 册第 4 节]]。**点** EVPN 与 BGP

**G-023**（核心·单）典型 DC 中，underlay 与 overlay 分别常跑什么协议？
A underlay OSPF、overlay eBGP　B underlay eBGP、overlay iBGP + RR　C 两者都用 OSPF　D 两者都用静态路由
**答案** B　**解析** underlay 用 eBGP 打通 IP 连通性（每台 Leaf 一个私有 AS），overlay 用 iBGP + RR 传 EVPN 路由。**点** 两张网分工

**G-024**（核心·简）为什么 OSPF 不适合超大规模数据中心？
**答案要点** ① 链路状态泛洪在超大域内成为负担，故障域大 ② SPF 计算随规模变贵 ③ 策略表达力弱，难做多租户与流量工程 ④ cost 体系在 DC 失效（默认参考带宽下高速口开销全为 1）⑤ 换来的只是"收敛较快"，而收敛可用 BFD 补偿。

**G-025**（核心·简）客户标书写"支持 BGP"，你应该怎么把它变成可比的指标？
**答案要点** 拆成四项可压测指标：最大 BGP 邻居数、路由条目容量、ECMP 组数（maximum-paths）、BFD 最小间隔与会话数；再加两项能力项：是否支持 EVPN 五类路由、是否支持 GR/NSF。做成对比表，客户一眼看出差异。

**G-026**（支撑·简）客户报障"双上联只跑一条链路"，你怎么定位？
**答案要点** 先分清是"没形成 ECMP"还是"形成了但哈希不均"：查是否开 maximum-paths、两条路的属性是否完全等价（AS_PATH、MED、next-hop 开销）；再看哈希是否因大象流落入同一桶。前者改配置，后者需 DLB 或流量调度。

**G-027**（核心·简）"升级不断业务"在协议层靠什么实现？代价是什么？
**答案要点** 靠 GR/NSF：控制面重启期间保留转发表、由邻居协助恢复状态，配合 ISSU 做主备控制面切换。代价是恢复期路由可能是旧状态，且要求对端支持相应扩展；不能等同于"零风险"，必须用打流验证升级期间零丢包。

**G-028**（支撑·简）多租户隔离在控制面上是怎么实现的？
**答案要点** 每租户一个 VRF 实例，用 route target（RT）控制路由的导入导出，底层是 BGP 扩展团体属性在传递意图；配合 route-map 做过滤与标记。数据面则由 VXLAN 的 VNI 隔离。

**G-029**（核心·案）客户 DC 双出口（两家运营商），要求"主备 + 故障自动切换 + 回程可控"，给出协议层设计与验收方法。
**答案要点** ① 与两家各建 eBGP，用 Local Preference 决定出向主备（主高备低）② 用 MED 或 AS_PATH 预处理影响入向 ③ 配 BFD 做百毫秒级切换，必要时 GR 保证升级不断 ④ 用前缀列表严格过滤，只收默认或指定前缀，防全局表压垮设备 ⑤ 验收：手动断主用链路，测切换时间与丢包数；双向往返路径用 traceroute 双向核验。

**G-030**（核心·案）Leaf 数量要从 8 台扩到 64 台，Overlay 控制面怎么设计？说明理由。
**答案要点** ① 64 台全互联 iBGP 需 2016 条会话，不可维护，必须上 RR ② RR 可部署在 Spine 上（与 underlay 合一）或独立两台，考虑 RR 自身冗余 ③ 用 Cluster List 与多簇设计防环，客户机只与两台 RR 建会话 ④ 注意 next-hop 处理（RR 不改 next-hop，需在入口 Leaf 配 next-hop-self 或依赖 underlay 可达）⑤ 验收：新增 Leaf 零配置上线、路由收敛时间、单 RR 故障不中断。
