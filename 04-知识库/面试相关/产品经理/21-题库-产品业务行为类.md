## 模块 PM-D 产品方法论（D-001 ~ D-030）

**D-001**（核心·单）MRD 与 PRD 的本质区别是：
A 篇幅长短　B 读者与决策对象不同　C 是否含图表　D 是否需要评审
**答案** B　**解析** MRD 决定"投不投"，PRD 决定"做成什么样"。**点** 文档体系

**D-002**（核心·多）判断需求真伪的四道闸是：
A 频次　B 影响　C 可复用　D 可实现
**答案** ABCD　**解析** 任一不过关，就应从产品需求降级为项目支持。

**D-003**（核心·单）痛点四问中最能验证支付意愿的是：
A 多久发生一次　B 影响多少业务　C 你现在怎么绕过去的　D 是否影响品牌
**答案** C　**解析** 现有绕行方案就是真实成本证明。**点** 需求洞察

**D-004**（核心·单）判断一条需求是否合格的最低标准是：
A 客户签了字　B 测试能写出用例、研发能估出工作量　C 竞品有同样功能　D 领导同意
**答案** B　**解析** 不可测、不可估的需求都是伪需求。**点** PRD 质量

**D-005**（核心·单）合格的验收标准应包含：
A 功能描述　B 条件、操作、期望结果与阈值　C 客户名称　D 报价
**答案** B　**解析** 阈值不可缺，否则交付必扯皮。**点** 验收标准

**D-006**（核心·单）影响 40 客户、影响强度 2、信心 80%、投入 8 人周，RICE 得分为：
A 4　B 6　C 8　D 10
**答案** C　**解析** (40×2×0.8)÷8 = 8。**点** 优先级

**D-007**（核心·单）某需求 RICE 低于其他需求，但它是战略客户的准入条件，正确处理是：
A 直接放弃　B 调高参数凑分　C 允许战略权重覆盖排序并说明理由　D 交给领导决定
**答案** C　**解析** 框架是工具不是教条，但必须显式说明覆盖理由。**点** 优先级边界

**D-008**（支撑·单）WSJF 的计算方式是：
A 延迟成本 ÷ 工作量　B 工作量 ÷ 延迟成本　C 价值 × 信心　D 投入 ÷ 收益
**答案** A　**解析** 延迟成本越高、工作量越小，越应优先。

**D-009**（支撑·单）"稳定转发"在 KANO 模型中属于：
A 基本型　B 期望型　C 兴奋型　D 无关型
**答案** A　**解析** 没有会被骂，做好了也不会被夸。**点** KANO

**D-010**（核心·多）DC 产品的四条取舍轴包括：
A 标准 vs 定制　B 平台化 vs 单点最优　C 功能广度 vs 稳定优先　D 短期交付 vs 架构债
**答案** ABCD　**解析** 每条都要能举一个真实例子。

**D-011**（核心·判）对客户承诺后，宁可延期也要保证功能完整。
**答案** 错误　**解析** 范围可谈、日期不可谈；缩小范围保日期才是守信的解法。

**D-012**（支撑·单）Now / Next / Later 三档中，"Next"的承诺强度是：
A 可承诺日期　B 方向确定、日期待评审　C 完全不确定　D 已签合同
**答案** B　**解析** 三档混用是承诺事故的根源。

**D-013**（支撑·单）IPD 六阶段的正确顺序是：
A 概念→计划→开发→验证→发布→生命周期　B 计划→概念→开发→发布→验证→生命周期　C 概念→开发→计划→验证→发布→生命周期　D 需求→设计→开发→测试→上线
**答案** A　**解析** 国内网络厂商普遍采用。**点** IPD

**D-014**（支撑·单）DCP 与 TR 的区别是：
A DCP 技术把关、TR 投资决策　B DCP 投资决策、TR 技术把关　C 二者等价　D DCP 由测试主持
**答案** B　**解析** DCP 由投资决策团队评审，TR 由技术专家评审。**点** IPD

**D-015**（细节·单）$APPEALS 中 "L" 指：
A 价格　B 生命周期成本　C 易用性　D 保证
**答案** B　**解析** Life cycle cost，含功耗、空间、升级与 EOL 成本。**点** 需求分析

**D-016**（支撑·单）交付六道门中，负责"用例覆盖是否足够"的是：
A 需求评审　B 规格冻结　C 测试准入　D 发布评审
**答案** C　**解析** 测试准入由测试方把关。**点** 交付门禁

**D-017**（核心·多）质量问题处理的三条原则：
A 先止血再定位　B 根因要分类　C 必须横向排查同类产品　D 先追究责任人
**答案** ABC　**解析** 追责不是产品经理的第一动作，改进流程才是。

**D-018**（支撑·单）EOL 通知的建议提前期是：
A 1 个月　B 3 个月　C 12 个月以上　D 不需要通知
**答案** C　**解析** 需同步替代机型与迁移方案，否则直接引发投诉。

**D-019**（核心·单）POC 的本质是：
A 产品演示　B 预先约定判据的验证考试　C 商务谈判　D 价格比较
**答案** B　**解析** 先定验证清单与通过标准，再设计拓扑。

**D-020**（核心·单）判断"PFC 一键配置"功能是否成功，最合适的指标是：
A 代码行数　B 开通工时下降比例与无损相关工单数下降　C 客户满意度总分　D 发布会曝光量
**答案** B　**解析** 指标要与功能价值直接对应。

**D-021**（核心·情）只有一个客户提出、需要改架构、无法复用到其他客户的需求，你应该：
A 立即排入 Roadmap　B 转项目支持并评估是否可抽象　C 拒绝且不回复　D 交给销售决定
**答案** B　**解析** 走项目通道，但保留"是否能抽象为平台能力"的判断。

**D-022**（核心·情）版本确定要延期，你先做什么：
A 通知客户延期　B 评估可裁剪范围，用范围保日期　C 让研发加班　D 隐瞒到最后一刻
**答案** B　**解析** 先在公司内部完成取舍，再对外沟通。

**D-023**（核心·情）研发说"这个做不了"，你的第一反应是：
A 上报领导施压　B 追问是"架构不能"还是"这期不能"　C 直接放弃　D 找外包
**答案** B　**解析** 前者改方案，后者拆两期。

**D-024**（核心·情）客户投诉批量质量问题，你先做：
A 查根因　B 止血（回滚/替换/规避）　C 发声明　D 内部追责
**答案** B　**解析** 客户现场第一优先级是恢复业务。

**D-025**（核心·情）销售在客户面前承诺了一个研发未确认的日期，你怎么办：
A 当场否认　B 会后与销售对齐，用"分阶段交付"重构承诺　C 让研发加班　D 不处理
**答案** B　**解析** 不当场打脸，但要立刻把承诺口径拉回可交付范围。

**D-026**（核心·简）你如何判断一个需求是真需求？
**答案要点** 四闸：多客户多次出现（频次）、可量化损失（影响）、能抽象为通用能力（可复用）、不突破现有架构或无替代方案（可实现）；辅以痛点四问，尤其"你现在怎么绕过去的"。

**D-027**（核心·简）写一条可验收的性能需求。
**答案要点** 三段式：给定条件（拓扑规模/流量模型）→ 操作（如单 Leaf 重启）→ 期望结果 + 阈值（收敛 ≤ 3 秒、丢包 ≤ 10 报文）。要求阈值可测、条件可复现。

**D-028**（核心·简）你怎么做竞品分析？输出什么？
**答案要点** 三维：功能对标矩阵、3–5 年 TCO 对比（含功耗/空间/运维/迁移）、竞争定位与话术；输出三样东西：对标表、TCO 表、差异化支点。

**D-029**（核心·案）给你 10 人研发资源、6 个月，为一个 DC 产品线排 Roadmap。
**答案要点** ① 先问战略：主打客户与竞争窗口 ② 分类：丢单项（竞品已有）、准入项（合规/互通）、溢价项（差异化）③ 排期：先补丢单项与准入项，再投溢价项 ④ 明确"本期不做什么"及原因 ⑤ 给风险与依赖（芯片交期、测试资源）⑥ 给度量（中标率、交付准时率）。

**D-030**（核心·案）一个功能上线三个月，你怎么判断它成功？
**答案要点** 三层指标：采用率（是否被用）、效果（如开通工时、工单量、JCT）、商业（中标率/溢价/续采）；设定上线前基线与目标值，并说明未达标时的下一步动作。

## 模块 PM-E 场景生态与竞品（E-001 ~ E-025）

**E-001**（核心·单）互联网客户最核心的诉求是：
A 品牌　B 交付速度、自动化与每端口成本　C 国产化　D 审计合规
**答案** B　**解析** 技术主导 + 价格敏感 + 迭代快。**点** 客户分层

**E-002**（核心·单）政企项目的实际影响方通常是：
A 最终用户直接采购　B 集成商主导并影响评分　C 只由总部决定　D 公开比价决定
**答案** B　**解析** 渠道政策与赋能材料决定落地效率。**点** 客户分层

**E-003**（支撑·单）金融客户对"新功能"的典型态度是：
A 抢先试用　B 要求长周期验证与变更可控　C 不关心　D 只看价格
**答案** B　**解析** 风险厌恶，变更不能出事。**点** 客户分层

**E-004**（支撑·单）运营商市场的关键门槛是：
A 品牌广告　B 集采入围、入网测试与互通性　C 低价　D 定制外观
**答案** B　**解析** 标准化与规模交付能力。**点** 客户分层

**E-005**（核心·单）智算客户最关心的是：
A 端口数量　B 训练效率（JCT/MFU）与交付速度　C 机柜颜色　D VLAN 数量
**答案** B　**解析** 付费买的是"训练跑满"。**点** 客户分层

**E-006**（核心·单）Border Leaf 的主要职责是：
A 服务器接入　B 对接出口、DCI 与安全设备　C 带外管理　D 存储接入
**答案** B　**解析** 多 VRF、策略能力、接口灵活性要求高。**点** 组网

**E-007**（支撑·单）带外管理网的关键要求是：
A 高带宽　B 独立、简单、可靠　C 支持 Overlay　D 低时延
**答案** B　**解析** 管理面与业务面分离，故障时仍可运维。**点** 组网

**E-008**（支撑·单）DCI 长距互联的常见方案不包括：
A DWDM　B 相干光 ZR/ZR+　C EVPN 多域对接　D 生成树跨域扩展
**答案** D　**解析** 生成树跨域会放大广播域与故障域。**点** DCI

**E-009**（支撑·单）多 AZ 双活的关键约束是：
A 机柜高度　B 跨 AZ 时延与二层延伸范围、控制面一致性　C 品牌一致　D 颜色统一
**答案** B　**解析** 同城 1–2 ms 是常见边界。**点** 多 AZ

**E-010**（细节·单）防火墙旁挂与串联的取舍核心是：
A 价格　B 解耦灵活性与路径长度/单点的权衡　C 品牌　D 颜色
**答案** B　**解析** 旁挂流量绕行但解耦，串联路径短但引入单点。**点** 边界

**E-011**（支撑·单）产业链中掌握政企客户关系、影响方案话语权的是：
A 芯片厂商　B 集成商与渠道　C 光模块厂　D 标准组织
**答案** B　**解析** 因此产品经理要产出赋能材料。**点** 产业链

**E-012**（核心·单）对产品 Roadmap 约束最强的产业链环节是：
A 芯片　B 包装　C 物流　D 广告
**答案** A　**解析** 交期与功能开放度直接决定能做什么、什么时候能交。**点** 产业链

**E-013**（支撑·单）光模块对产品经营的主要影响是：
A 无影响　B 成本占比上升、产能与价格波动影响毛利与交付　C 只影响外观　D 只影响保修
**答案** B　**解析** 800G 时代尤其明显。**点** 产业链

**E-014**（细节·单）IETF 主要负责：
A 以太网物理层　B 路由与 Overlay 协议（BGP/EVPN/VXLAN）　C 光接口　D 服务器规范
**答案** B　**解析** IEEE 管物理层与链路层，OIF 管光互连。

**E-015**（支撑·单）竞品定位三角的三个顶点是：
A 性能、成本、可控性　B 价格、渠道、广告　C 功能、颜色、包装　D 服务、物流、账期
**答案** A　**解析** 可控性含供应链、国产化、服务响应。**点** 竞品

**E-016**（核心·单）竞争话术的正确结构是：
A 直接贬低对手　B 承认强项 → 重设评价标准 → 用可验证指标锁死　C 只讲价格　D 回避对比
**答案** B　**解析** 把争论变成测试，是专业度的体现。

**E-017**（支撑·单）智算场景更适合的定价方法是：
A 成本加成　B 竞争定价　C 价值定价　D 随机定价
**答案** C　**解析** 客户收益可量化（训练效率），适合按价值定价。

**E-018**（支撑·单）直销与渠道的差异在于：
A 产品不同　B 覆盖客户类型与能力要求不同　C 价格必须不同　D 服务必须不同
**答案** B　**解析** 直销打大客户与智算项目，渠道覆盖政企区域。

**E-019**（支撑·单）网络设备厂商收入结构中毛利压力最大的是：
A 软件授权　B 硬件　C 服务　D 调优咨询
**答案** B　**解析** 白盒化持续压缩硬件毛利。**点** 商业模式

**E-020**（核心·简）互联网客户与政企客户的需求差异，请从四个维度说明。
**答案要点** 决策链（技术主导 vs 集成商+甲方）、验证方式（实测灰度 vs 招标评分）、价格机制（每端口成本 vs 预算合规）、运维模式（自动化自研 vs 依赖厂商服务）。

**E-021**（核心·简）如何向客户做 TCO 对比？
**答案要点** 3–5 年口径：采购 + 功耗电费 + 机架空间 + 运维人力 + 迁移与停机损失；用客户真实电价与机柜成本参数；给出敏感性分析（电价、负载率变化时结论是否翻转）。

**E-022**（核心·情）客户说"对手比你们便宜 30%"，你怎么回应？
**答案要点** 不否认价格差 → 把比较口径拉到同配置同服务 → 用 TCO 展示三年总成本 → 指出对方方案的隐含成本（功耗、光模块、运维、迁移）→ 提出可验证的对比方法（同流量模型测试）。

**E-023**（核心·情）如何设计 POC 才不至于"陪跑"？
**答案要点** 提前确认判据与判定人 → 测试项对齐我方强项且是客户真实痛点 → 约定失败处理 → 争取独家或分阶段 → 输出书面报告并推动进入决策流程。

**E-024**（支撑·简）白盒厂商低价竞争，我方如何应对？
**答案要点** 承认价格劣势，转向方案交付、调优服务、备件响应、合规与国产化、生态互通；同时用"总拥有成本 + 业务连续性"重构比较维度。

**E-025**（支撑·简）为什么"智算客户买的是训练能跑满，而不是交换机"？
**答案要点** 因为客户 KPI 是模型上线时间与算力成本；设备只是手段；因此交付物必须含验收方法（NCCL 线性度、JCT）与调优服务，这也是溢价来源。

## 模块 PM-F 行为与案例（F-001 ~ F-025）

> F 模块没有标准答案。每题给：**考察点 / 高分要点 / 常见失分**。
> 训练方法：录音，控制在 90 秒，回放检查是否出现"我参与/我们团队"而缺少"我判断"。

**F-001**（核心·行）请做自我介绍（90 秒）。
**考察** 结构化表达、与岗位的匹配度。**高分** 三段：我是谁（一句话定位）→ 我做过的两件与 DC 网络相关的事（带数字）→ 我为什么适合这个岗位（能力映射到 JD 三条）。**失分** 流水账式履历复述，超过 2 分钟。

**F-002**（核心·行）为什么从现在的岗位转到数据中心网络产品经理？
**考察** 动机真实性与自我认知。**高分** 从"我发现的问题"出发：现有岗位看到网络侧可观测性缺口 → 想从"做工具"转向"定义产品" → 与 JD 的"产品竞争力"对应。**失分** 说"想换个环境/钱多"。

**F-003**（核心·行）讲一次你做技术判断的经历。
**考察** 判断依据与取舍能力。**高分** 两种方案 → 三个判据（成本/风险/可复用）→ 你放弃了什么 → 结果可量化。**失分** 只说"我选了 A，因为 A 更好"。

**F-004**（核心·行）讲一次你拒绝客户需求的经历。
**考察** 边界感与客户关系处理。**高分** 先满足真实诉求（换方案而非拒绝人）→ 说明拒绝依据（影响面/不可复用）→ 给替代路径 → 关系未受损的证据。**失分** 把"拒绝"讲成"对抗"。

**F-005**（核心·行）讲一次你说服研发改变技术方案的经历。
**考察** 影响力与论据质量。**高分** 用数据或客户证据而非职级施压 → 给出可验证的中间方案 → 事后复盘。**失分** "我找领导压下去了"。

**F-006**（核心·行）讲一次交付危机或重大质量问题的处置。
**考察** 压力下的优先级判断。**高分** 止血 → 分级 → 根因分类 → 横向排查 → 流程改进（关键：你推动了什么机制）。**失分** 只讲"加班解决了"。

**F-007**（核心·行）讲一次你做错的决策以及补救。
**考察** 反思深度。**高分** 决策时的信息缺口 → 错在哪一步 → 多快发现 → 补救动作 → 后来建立的防护机制。**失分** 把错误包装成成功。

**F-008**（支撑·行）讲一次跨部门冲突的处理。
**考察** 把立场翻译成约束的能力。**高分** 双方真实约束 → 可选项与代价 → 决策人拉齐 → 书面结论。**失分** 描述成"谁对谁错"。

**F-009**（核心·行）如果 KPI 要你推一个你不认同的功能，怎么办？
**考察** 组织成熟度。**高分** 接受目标 → 澄清 KPI 真实意图 → 给更低成本的替代 → 若仍须执行则明确风险与回退条件。**失分** "我坚持专业判断拒绝执行"。

**F-010**（支撑·行）客户在评审会上当众质疑产品，你怎么处理？
**考察** 情绪与场面控制。**高分** 先接情绪 → 要事实（时间、现象、范围）→ 给明确回复时限 → 会后闭环并反馈。**失分** 当场辩解或沉默。

**F-011**（支撑·行）你最近学的一个新技术是什么？怎么学的？
**考察** 学习方法而非知识点。**高分** 三段式笔记：是什么 → 为什么现在重要 → 对产品意味着什么；并能说出一个具体判断。**失分** 只说"看了几篇文章"。

**F-012**（支撑·行）你的职业规划是什么？
**考察** 稳定性与路径合理性。**高分** 三步：1 年内成为该产品线的方案专家 → 2–3 年独立负责一条产品线 → 长期做"技术+商业"的复合型产品负责人。**失分** 规划与岗位无关。

**F-013**（支撑·行）讲一次你在高压下工作的经历。
**考察** 抗压方式是否可持续。**高分** 拆解任务 → 优先级 → 关键干系人对齐 → 结果与恢复方式。**失分** 强调"连续熬夜"。

**F-014**（支撑·行）讲一次你主动承担职责外工作的经历。
**考察** 主动性边界。**高分** 发现了什么缺口 → 为什么没人负责 → 你怎么补位 → 最后是否形成了机制（而不是永久兜底）。**失分** 变成抱怨同事。

**F-015**（细节·行）你如何管理多个并行任务？
**考察** 时间与优先级管理。**高分** 用"丢单项/准入项/溢价项"分类 + 固定节奏评审 + 明确不做清单。

**F-016**（支撑·行）讲一次你用数据改变结论的经历。
**考察** 数据驱动而非经验驱动。**高分** 原有共识 → 数据发现的反例 → 验证方法 → 结论修正 → 影响。

**F-017**（细节·行）你如何看待国产替代？
**考察** 行业视野。**高分** 分环节看（芯片/整机/软件）：中低端已规模、高端追赶；对产品的影响是供应链安全成为投标加分项，同时要防止"唯国产化"牺牲体验。

**F-018**（支撑·行）你的缺点是什么？
**考察** 自我认知。**高分** 一个真实且不致命的短板 + 正在采取的具体改进动作 + 可观测的进展。**失分** "我太追求完美"这类套路答案。

**F-019**（核心·行）你有什么想问我们的？
**考察** 你已经在用产品经理的方式思考。**高分** 问产品路线、考核指标构成、当前最大短板、团队分工边界。**失分** 只问薪资与加班。

**F-020**（细节·行）薪资期望怎么谈？
**考察** 边界与弹性。**高分** 给区间并说明依据（岗位职责范围、当前package结构）→ 强调总包与成长空间 → 不把话说死。

**F-021**（核心·行）STAR 结构自检：你的案例是否具备四段？
**考察** 表达结构。**高分** 背景 15 秒 / 冲突 20 秒 / 判断 35 秒 / 结果 20 秒，且每段都有具体数字。**失分** 背景占了一半时间。

**F-022**（核心·行）你的案例能扛住三层追问吗？
**考察** 经历的真实性。**高分** 第一层问"为什么这么选"，第二层问"还有什么方案"，第三层问"如果条件变成 X 你会怎么做"。**失分** 第三层答不上，说明只有结论没有过程。

**F-023**（支撑·行）为什么离开现在的公司？
**考察** 成熟度与风险。**高分** 讲"追求什么"而非"逃离什么"，不与前雇主对立，指向岗位匹配。**失分** 抱怨领导或团队。

**F-024**（细节·行）你如何理解这个岗位的 KPI？
**考察** 对岗位的理解深度。**高分** 三类：产品竞争力（中标率/份额）、交付质量（缺陷/准时率）、客户信任（满意度/续采），并说明三者的张力（要份额可能牺牲毛利）。

**F-025**（核心·行）如果让你三个月内做出可见成果，你会先做什么？
**考察** 落地能力。**高分** 第 1 月：摸清产品线与客户，输出一张"竞争短板表"；第 2 月：选一个高频痛点做小闭环（如无损开局脚本化）；第 3 月：形成可复用的方案模板与验收方法。

## F 模块自评表

每题按三项打分（各 0–2 分），总分 6 分以上为过关。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 结构 | 无结构、流水账 | 有结构但不均衡 | STAR 四段清晰、节奏合理 |
| 证据 | 全为主观描述 | 有部分数字 | 关键结论均有数字或事实支撑 |
| 反思 | 只讲成功 | 提到代价 | 讲清取舍与后续机制 |

**训练节奏**：25 题分 5 天练完，每天 5 题，录音回放 1 遍。第 6 天做一次全真模拟（连续答 10 题，不中断）。
