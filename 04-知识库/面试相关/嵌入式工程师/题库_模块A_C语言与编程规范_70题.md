## 一、单项选择题（A-001 ~ A-030）

### A-001 ★
关于 `volatile` 关键字，以下说法正确的是：
A. 让变量存放在 volatile 存储区
B. 禁止编译器对该变量的访问做优化，每次都从内存重新读取
C. 保证变量操作的原子性
D. 只能用于中断服务程序中的变量

**答案：B**
**解析**：volatile 告诉编译器该变量可能被程序之外的因素（中断、其他线程、硬件）修改，因此禁止将其缓存到寄存器或合并/省略读写。A 错——它不改变存储位置；C 是常见误区，volatile 不提供原子性（如 `volatile int` 的 `++` 仍是读-改-写三步）；D 错——MMIO 寄存器、多线程共享变量同样需要。
**知识点**：C 语言-volatile

### A-002 ★
`const int *p` 与 `int *const p` 的区别是：
A. 没有区别
B. 前者指向的值不可改，后者指针本身不可改
C. 前者指针本身不可改，后者指向的值不可改
D. 两者都不能通过 p 修改任何东西

**答案：B**
**解析**：读法口诀——`const` 在 `*` 左边修饰"指向的东西"，在 `*` 右边修饰"指针本身"。`const int *p`：*p 只读；`int *const p`：p 只读（不能指向别处），但可改 *p。D 错在 `int *const p` 可以改值。
**知识点**：C 语言-const 与指针

### A-003 ★
以下关于 static 局部变量的说法错误的是：
A. 存储在静态区，函数退出后仍保留
B. 只在第一次进入函数时初始化一次
C. 每次函数调用都重新初始化
D. 作用域仍限于该函数内部

**答案：C**
**解析**：static 局部变量生命周期为整个程序运行期，只在首次执行到定义处初始化一次（C99 起未显式初始化则自动清零），之后每次调用保留上次结果。A、B、D 均为正确描述。
**知识点**：C 语言-static

### A-004 ★
一个未初始化的全局变量 `int g_count;` 会被放在哪个内存段？
A. .text 段
B. .data 段
C. .bss 段
D. 栈

**答案：C**
**解析**：.bss 存放未初始化（或初始化为 0）的全局/静态变量，程序加载时由启动代码统一清零，因此不占用可执行文件空间；.data 存放已初始化为非零值的全局/静态变量；.text 是代码；栈存放局部变量。嵌入式里"RAM 不够但 Flash 够"时常利用该特性。
**知识点**：C 语言-内存布局

### A-005 ★
32 位平台上，`int arr[10]` 作为函数参数 `void f(int a[10])` 传递时，函数内 `sizeof(a)` 的值是：
A. 40
B. 10
C. 4
D. 编译错误

**答案：C**
**解析**：数组作为函数参数会退化为指向首元素的指针，`int a[10]` 等价于 `int *a`，sizeof 结果为指针大小 4（32 位）。因此数组长度必须额外用参数传入——这是嵌入式接口设计的基本常识。
**知识点**：C 语言-数组退化

### A-006 ★
以下代码的输出是：
```c
char *p = "hello";
p[0] = 'H';
printf("%s\n", p);
```
A. Hello
B. hello
C. 编译错误
D. 运行期未定义行为（很可能段错误）

**答案：D**
**解析**：字符串字面量通常存放在只读段（.rodata），通过指针修改它属于未定义行为，多数平台触发段错误。正确写法是 `char p[] = "hello";`——这时字符串被拷贝到栈上的数组中，可修改。C 不对：语法上合法，编译器一般只给警告。
**知识点**：C 语言-字符串字面量

### A-007 ★
`int arr[5]; int *p = arr;` 那么 `*(p + 3)` 等价于：
A. arr[3]
B. arr[4]
C. *(int *)((char *)p + 3)
D. p 的地址加 3 字节

**答案：A**
**解析**：指针加减以"所指类型大小"为单位，`p + 3` 移动 3 个 int（12 字节），正好是 arr[3]。C/D 的错误在于把指针运算按字节理解。这也是"指针步长 = sizeof(所指类型)"的直接应用。
**知识点**：C 语言-指针运算

### A-008 ★
以下哪种情况会产生"悬垂指针（dangling pointer）"？
A.指针未初始化
B. 指针指向的内存被 free 之后继续使用该指针
C. 指针指向 const 变量
D. 两个指针指向同一块内存

**答案：B**
**解析**：悬垂指针 = 指向已释放内存的指针。free 后该内存可能已被分配给别人，继续使用会造成数据破坏或崩溃。规范做法：`free(p); p = NULL;`。A 是"野指针"（未初始化指针），与悬垂指针是两类问题。
**知识点**：C 语言-野指针与悬垂指针

### A-009 ★
`strcmp("abc", "abd")` 的返回值是：
A. 0
B. 正数
C. 负数
D. -1

**答案：C**
**解析**：比较按字典序逐字符进行，'c'(99) < 'd'(100)，返回负值。注意：标准只保证正负关系，**不保证返回 -1/1/差值**，写 `if (strcmp(a,b) == -1)` 是经典 bug，必须写 `< 0`。
**知识点**：C 语言-字符串函数

### A-010 ★★
32 位平台、默认 4 字节对齐下，`struct S { char a; int b; char c; };` 的 sizeof 是：
A. 6
B. 9
C. 12
D. 8

**答案：C**
**解析**：a 占偏移 0；b 需 4 字节对齐，放偏移 4~7；c 放偏移 8；结构体总大小需为其最大成员对齐数（4）的倍数，补齐到 12。若调整为 `char a; char c; int b;` 则只需 8 字节——**按对齐要求降序排列成员可省内存**，嵌入式结构体设计的必备技巧。
**知识点**：C 语言-内存对齐

### A-011 ★★
以下代码在小端（little-endian）机器上输出什么？
```c
union { int i; char c; } u;
u.i = 0x11223344;
printf("%x\n", u.c);
```
A. 11
B. 22
C. 44
D. 11223344

**答案：C**
**解析**：小端机低位字节存低地址，`u.c` 取的是最低地址的字节即 0x44。大端机则输出 0x11。union 所有成员共享同一段内存、大小取决于最大成员——这也是用 union 检测大小端的标准方法。
**知识点**：C 语言-大小端 / union

### A-012 ★
将变量 `x`（int）的第 3 位（bit3，从 0 计数）置 1，正确写法是：
A. `x = x | 0x03;`
B. `x = x | (1 << 3);`
C. `x = x & (1 << 3);`
D. `x = x ^ (1 << 3);`

**答案：B**
**解析**：置 1 用"或"上目标位掩码：`1 << 3` 即 0x08。A 置的是 bit0 和 bit1；C 是"与"，会把其他位清零只留 bit3；D 是"异或"——作用是**翻转** bit3（原为 0 则置 1，原为 1 则清 0）。置位 |、清零 &~、翻转 ^ 是位操作三件套。
**知识点**：C 语言-位操作

### A-013 ★★
`#define MAX(a,b) ((a)>(b)?(a):(b))`，执行 `int i = 3; int r = MAX(i++, 5);` 后 i 和 r 分别是：
A. i=4, r=4
B. i=4, r=5
C. i=5, r=5
D. i=5, r=4

**答案：B**
**解析**：宏展开为 `((i++)>(5)?(i++):(5))`。求值过程：条件表达式 `i++ > 5` 先求值，返回 3（i 自增为 4），3 > 5 为假；条件为假走 `(b)` 分支即返回 5，假分支的 `i++` **不会执行**。最终 r=5、i=4。陷阱在于：如果条件为真，`(a)` 中的 `i++` 会再执行一次——同一个 i 在一个表达式里被求值两次且至少修改一次，这类写法的可读性和正确性都没有保障。**结论：永远不要向函数式宏传入带副作用的表达式（i++、函数调用等），需要安全求值时用 `static inline` 函数替代宏。**

### A-014 ★
`typedef` 与 `#define` 的本质区别是：
A. 没有区别，都是起别名
B. typedef 由编译器处理且遵循作用域规则，#define 由预处理器做纯文本替换
C. #define 由编译器处理
D. typedef 只能用于基本类型

**答案：B**
**解析**：typedef 是编译器层面的类型别名，有块作用域，能正确处理指针连续声明（`typedef int *P; P a, b;` 中 a、b 都是指针；而 `#define P int*` 时 `P a, b;` 中 b 是 int）。#define 是预处理阶段的文本替换，无作用域概念直到 undef。D 错——typedef 可用于结构体、函数指针等任意类型。
**知识点**：C 语言-typedef 与宏

### A-015 ★
`union U { char c[8]; int i; short s; };` 在 32 位平台 sizeof(struct) ——sizeof(U) 是：
A. 2
B. 4
C. 8
D. 14

**答案：C**
**解析**：union 大小 = 最大成员大小，再对齐到最大成员对齐数。c[8] 占 8 字节最大；总大小需为 4（int 对齐数）的倍数，8 满足，故为 8。union 各成员共享首地址，常用于协议解析中的"字节流↔字段"转换（注意大小端影响）。
**知识点**：C 语言-union

### A-016 ★
`enum Color { RED, GREEN = 5, BLUE };` 则 BLUE 的值是：
A. 2
B. 6
C. 7
D. 1

**答案：B**
**解析**：枚举默认从 0 递增；显式赋值后从该值继续递增。RED=0，GREEN=5，BLUE=6。枚举本质是 int 常量，相比 #define 的优势：有类型检查语义、可被调试器识别、自动管理取值序列。
**知识点**：C 语言-枚举

### A-017 ★★
"指向『接收 int 参数、返回 int 的函数』的指针 pf" 的正确声明是：
A. `int pf(int);`
B. `int *pf(int);`
C. `int (*pf)(int);`
D. `int (pf*)(int);`

**答案：C**
**解析**：`(*pf)` 说明 pf 是指针，去掉指针后的 `int (int)` 是它所指函数的签名。B 是"返回 int* 的函数 pf"（pf 是函数不是指针）。typedef 可提高可读性：`typedef int (*callback_t)(int); callback_t pf;`——这正是嵌入式回调/中断向量表的标准写法。
**知识点**：C 语言-函数指针

### A-018 ★
`strlen` 与 `sizeof` 对 `char buf[10] = "abc";` 的返回值分别是：
A. 3 和 3
B. 3 和 10
C. 10 和 10
D. 4 和 10

**答案：B**
**解析**：strlen 是运行期函数，数到 '\0' 为止返回 3；sizeof 是编译期运算符，返回整个数组大小 10。注意若 buf 是 `char *p = "abc"`，sizeof(p) 是指针大小 4。strlen 不含结束符，申请缓冲区时要 +1。
**知识点**：C 语言-字符串函数

### A-019 ★★
以下代码的问题是什么？
```c
char *get_msg(void) {
    char msg[64] = "hello";
    return msg;
}
int main(void) { char *p = get_msg(); puts(p); return 0; }
```
A. 没有问题
B. 返回了栈上局部数组的地址，函数返回后成为悬垂指针
C. msg 未初始化
D. 数组太小放不下 "hello"

**答案：B**
**解析**：msg 在栈上，函数返回后栈帧回收，p 指向失效内存，使用是未定义行为。三种正确替代：① 调用者传入缓冲区（最推荐，无所有权问题）；② 返回 static 局部数组（注意非线程/重入安全）；③ malloc 返回堆内存（调用者负责 free）。
**知识点**：C 语言-栈生命周期

### A-020 ★★
`sprintf(buf, "%d", val)` 在嵌入式开发中应优先替换为哪个函数？
A. printf
B. snprintf
C. vsprintf
D. fprintf

**答案：B**
**解析**：sprintf 不检查目标缓冲区大小，val 很长或格式串拼接失误时溢出栈/全局缓冲区，是 CVE 高发区。snprintf 显式限定写入长度（注意：返回值是"本应写出的长度"，可用于判断是否被截断）。嵌入式编码规范（MISRA C）一般直接禁用无边界函数族。
**知识点**：C 语言-缓冲区安全

### A-021 ★★
以下循环的运行结果是：
```c
size_t len = 3;
for (size_t i = len - 2; i >= 0; i--)
    printf("%zu ", i);
```
A. 输出 1 0 后停止
B. 输出 1 0 后继续输出极大值，死循环
C. 编译错误
D. 输出 1 0 1 0 1 0 循环

**答案：B**
**解析**：size_t 是无符号类型，i 减到 0 再自减会回绕成 SIZE_MAX（约 4G/18E），`i >= 0` 恒为真，死循环。这是有符号/无符号混用的头号陷阱。修复：用 `int i`，或改写为 `for (size_t i = len; i-- > 0; )`（"goes to" 惯用法）。编译器开启 -Wsign-compare/-Wconversion 可提前发现。
**知识点**：C 语言-无符号回绕

### A-022 ★★
以下代码在 32 位平台输出：
```c
unsigned char a = 200;
unsigned char b = 100;
if (a + b > 250) printf("big\n"); else printf("small\n");
```
A. big
B. small
C. 未定义行为
D. 编译错误

**答案：A**
**解析**：C 的整型提升规则——比 int 小的整型参与运算先提升为 int，200+100=300 不回绕，300>250 成立。但若结果再赋回 `unsigned char` 则截断为 44。理解"提升发生在运算、截断发生在赋值/强转"两个阶段是避免此类 bug 的关键。
**知识点**：C 语言-整型提升

### A-023 ★★
以下属于未定义行为（UB）的是：
A. `int x = -8 >> 1;`
B. `int x = 1 << 31;`
C. `unsigned x = 1u << 31;`
D. `int x = 1 << 30;`

**答案：B**
**解析**：对有符号 int 左移到符号位（1<<31，int 为 32 位时结果 -2147483648 无法表示）是 UB。A：负数右移是"算术右移还是逻辑右移"由实现定义（不是 UB，但结果不可移植）。C：无符号左移合法。D：不触及符号位，合法。嵌入式寄存器操作请始终用 `1u << n`（无符号字面量）。
**知识点**：C 语言-移位 UB

### A-024 ★
断言 `assert(ptr != NULL);` 在什么条件下会被编译掉？
A. 定义了 DEBUG 宏
B. 定义了 NDEBUG 宏
C. 包含 <stdio.h> 之后
D. 使用了 -O2 优化

**答案：B**
**解析**：assert 在定义 NDEBUG（通常 release 构建 -DNDEBUG）时变成空操作 `((void)0)`。因此 assert 只能用于开发期捕捉"程序员的逻辑错误"，**不能用于处理运行期可预期的错误**（如用户传入 NULL、外设返回异常）——那需要正常的错误码/返回值检查。
**知识点**：C 语言-断言

### A-025 ★
头文件防护（include guard）的作用是：
A. 防止文件被病毒修改
B. 防止同一翻译单元中头文件被重复包含导致的重复定义
C. 加快编译速度的唯一手段
D. 防止多线程同时包含

**答案：B**
**解析**：`#ifndef XXX_H #define XXX_H ... #endif` 或 `#pragma once`，避免重复包含引发的类型重复定义、重复声明冲突。C 过于绝对——#pragma once 也能加速，但主作用是正确性；D 与线程无关。
**知识点**：C 语言-预处理

### A-026 ★★
`malloc(0)` 的合法返回是：
A. NULL
B. 一个可 free 的非空指针
C. NULL 或非空指针（实现定义），两种都可 free
D. 未定义行为

**答案：C**
**解析**：标准允许返回 NULL 或唯一非空指针，且两种结果都必须能被 free。因此判空逻辑 `if (p == NULL) fail;` 在 size 可能为 0 时会产生歧义——工程上应先判断 `if (size == 0) size = 1;` 或在调用前拦截。
**知识点**：C 语言-动态内存

### A-027 ★★
`memcpy` 与 `memmove` 的区别是：
A. 功能完全相同
B. memmove 处理源和目标内存重叠的情况，memcpy 不处理（重叠时 UB）
C. memcpy 更慢
D. memmove 只能用于字符串

**答案：B**
**解析**：两块内存重叠时 memcpy 行为未定义（可能因正向拷贝破坏尚未读取的源数据）；memmove 保证正确，代价是先探测重叠并选择拷贝方向，略慢。协议解析中"缓冲区内挪动数据"（如丢掉已处理帧头）必须用 memmove。D 错：两者按字节处理任意内存。
**知识点**：C 语言-内存函数

### A-028 ★
`static` 修饰全局函数的作用是：
A. 函数内变量保持值
B. 限制函数的链接可见性为本 .c 文件内部
C. 使函数内联
D. 使函数可重入

**答案：B**
**解析**：static 全局函数/变量具有内部链接（internal linkage），其他文件 extern 不到，实现模块封装——相当于 C 语言的"私有"。同名 static 函数在不同 .c 中不冲突。A 是 static 修饰局部变量的效果。

### A-029 ★★
关于 `inline` 关键字，正确的说法是：
A. 编译器必须内联该函数
B. 只是建议编译器内联，且 C99 中 inline 函数的定义与声明有严格的配套规则
C. inline 函数不能有循环
D. inline 等价于宏定义

**答案：B**
**解析**：inline 是优化建议，编译器有权拒绝（函数大、取了地址等）。C99 规定：头文件中 `inline` 只给定义不给外部符号，需在某一个 .c 中提供 `extern inline` 版本，规则繁琐，工程上普遍用 `static inline` 替代以简化。D 错：inline 有类型检查、无副作用问题，与宏本质不同。

### A-030 ★★
C 程序刚启动（进入 main 之前），以下哪项工作通常已完成？
A. 所有函数调用
B. .data 段搬运（从 Flash 到 RAM）与 .bss 段清零
C. 堆内存分配
D. 中断全部使能

**答案：B**
**解析**：嵌入式启动代码（如 Cortex-M 的 Reset_Handler）在调用 main 前完成：把 .data 初值从 Flash 复制到 RAM、把 .bss 清零、（可能）初始化时钟与 C 库（堆、stdio）。这就是全局变量"天生有正确初值"的原因。D 显然错误——main 之前通常关中断。理解启动流程对定位"全局变量初值异常"类问题至关重要。

### A-040 ★
写出以下程序输出：
```c
int counter(void) { static int n = 0; return ++n; }
int main(void) { counter(); counter(); printf("%d\n", counter()); return 0; }
```
**输出：____**

**答案**：3
**解析**：static 局部变量在调用间保持，三次调用依次返回 1、2、3。该模式可用来实现模块内部计数器；注意非可重入（reentrant），RTOS 多任务调用同一函数会竞争。

### A-041 ★★
32 位平台默认对齐：`struct S { char a; short b; int c; char d; };`，sizeof(S) = ____；若改为 `struct T { int c; short b; char a; char d; };`，sizeof(T) = ____。

**答案**：12；8
**解析**：S：a 偏移 0，b 对齐 2 放偏移 2~3，c 对齐 4 放偏移 4~7，d 放偏移 8，总大小补齐到 4 的倍数 = 12。T：c 偏移 0~3，b 偏移 4~5，a 偏移 6，d 偏移 7，恰好 8。**成员按大小降序排列可最小化 padding**。

### A-042 ★

**答案**：
置位 `#define BIT_SET(x, n) ((x) |= (1u << (n)))`
清零 `#define BIT_CLR(x, n) ((x) &= ~(1u << (n)))`
翻转 `#define BIT_TOGGLE(x, n) ((x) ^= (1u << (n)))`

### A-051 ★★

## 五、简答题（A-053 ~ A-060）

### A-053 ★
简述 C 程序的内存分区（段）及各段存放内容。

**参考答案**：
1. **.text（代码段）**：存放机器指令，通常只读、可在 Flash 中原地执行（嵌入式 XIP）。
2. **.rodata（只读数据）**：const 全局变量、字符串字面量。
3. **.data（已初始化数据）**：初始化为非 0 的全局/静态变量；启动时从 Flash 搬运初值到 RAM。
4. **.bss（未初始化数据）**：未初始化或初始化为 0 的全局/静态变量；启动时统一清零，不占文件空间。
5. **堆（heap）**：malloc/free 管理的动态内存，向高地址增长。
6. **栈（stack）**：局部变量、函数参数、返回地址，向低地址增长，由编译器自动管理。

**解析**：回答时最好能主动带出"启动代码搬运 .data、清零 .bss"这一点，体现对嵌入式启动流程的理解，是面试加分项。
**知识点**：C 语言-内存布局

### A-054 ★★
简述 volatile 的作用、原理与典型使用场景；并说明它为什么不能保证线程安全。

**参考答案**：
- **作用**：告知编译器该对象的值可能在程序控制流之外被改变，禁止把对该对象的访问优化掉（缓存到寄存器、合并读写、删除"冗余"读）。
- **原理**：编译器在生成的每处访问都强制发出真实的 load/store 指令。
- **典型场景**：① 中断与主程序共享的变量；② 内存映射外设寄存器（`#define REG (*(volatile uint32_t *)0x40020000)`）；③ 多线程共享的非同步变量；④ setjmp/longjmp 间修改的局部变量。
- **不保证线程安全的原因**：volatile 不提供原子性、不提供内存屏障（不禁止 CPU 层面的乱序与写合并），`x++`、`x = x + 1` 等复合操作仍是多指令序列，可被打断；可见性/原子性需依赖原子操作、临界区或互斥锁。

**解析**：这是嵌入式面试出现率 Top 3 的题。能区分"编译器优化层面的可见性"与"CPU 层面的原子性/顺序性"两个层次，即可超越大多数候选人。
**知识点**：C 语言-volatile

### A-055 ★★
什么是内存对齐？为什么需要内存对齐？

**参考答案**：
- **定义**：数据在内存中的起始地址须是其对齐值的整数倍；编译器在结构体成员间插入 padding 满足各成员对齐要求，并保证结构体总大小为最大成员对齐数的倍数。
- **原因**：① CPU 按字长访问内存，对齐访问一次总线事务完成，非对齐访问需拆成多次访问或触发异常（如 Cortex-M0 非对齐访问直接 HardFault）；② 某些架构的原子指令只对对齐地址生效；③ 提升缓存行利用效率。
- **代价与权衡**：padding 浪费内存；协议/存储紧凑布局用 `#pragma pack(1)`，代价是访问效率与可移植风险。
- **工程要点**：成员按大小降序排列减少 padding；跨平台传输的结构体必须统一 pack 与字节序处理。

**知识点**：C 语言-内存对齐

### A-056 ★
什么是大端与小端？如何在运行时检测？为什么网络传输需要字节序转换？

**参考答案**：
- **小端（little-endian）**：低字节存低地址（x86、ARM Cortex-M 默认）；**大端（big-endian）**：高字节存低地址（网络字节序、部分 DSP/PowerPC）。
- **检测方法**：
```c
int is_little_endian(void) {
    union { uint32_t i; uint8_t c; } u = { .i = 1 };
    return u.c == 1;
}
```
或指针法：`uint16_t x=1; return *(uint8_t *)&x;`
- **网络转换原因**：TCP/IP 规定网络字节序为大端，发送多字节字段前必须用 htonl/htons 转换，接收端用 ntohl/ntohs 还原，否则两端异构时数值错乱。
- **嵌入式实践**：自定义串口/SPI 协议同样要**在协议文档中明确字节序**，接收代码按文档解析，不依赖主机字节序。

**知识点**：C 语言-大小端

### A-057 ★★
嵌入式 Linux/C 开发中"段错误（Segmentation Fault）"的常见原因有哪些？如何定位？

**参考答案**：
**常见原因**：① 解引用空指针/野指针；② 访问已 free 的内存；③ 数组越界写破坏（破坏的可能是别处的指针，延迟爆发）；④ 栈溢出；⑤ 向只读区（字符串字面量、.rodata）写入；⑥ 函数指针调用错误地址。
**定位手段**：① 打开 core dump（ulimit -c unlimited），用 gdb 调 core 文件看崩溃点与调用栈 `bt`；② 编译加 -g -fsanitize=address（ASan，可精确定位越界/UAF）；③ 日志二分法缩小范围；④ 检查最近改动（新增的指针操作/数组）；⑤ 裸机平台则依赖 HardFault handler 中的栈回溯与故障寄存器（CFSR/HFSR/BFAR）。

**解析**：能报出"core dump + gdb bt + ASan"三件套，基本就能通过这题；若目标平台是 MCU，主动提及 Cortex-M 的 fault 寄存器分析是明显加分项。
**知识点**：C 语言-崩溃定位

### A-058 ★
总结 const 在 C 中的所有常见用法。

**参考答案**：
1. **修饰普通变量**：`const int size = 100;` 只读，不可再赋值。
2. **修饰指针**（三种组合）：`const int *p`（值只读）；`int *const p`（指针只读）；`const int *const p`（都只读）。
3. **修饰函数参数**：`int parse(const char *buf, size_t len)`——向调用者承诺不修改输入缓冲，是最常用场景。
4. **修饰函数返回指针**：`const char *get_name(void)`——返回的字符串不允许调用者修改。
5. **修饰数组**：`const uint8_t table[] = {...}`——常量查找表放入 .rodata 省 RAM。
6. **与 volatile 组合**：`const volatile uint32_t *status_reg`——软件只读但硬件会变的外设状态寄存器。

**知识点**：C 语言-const

### A-059 ★★
比较宏定义、inline 函数、static 函数三者的特点与选型原则。

**参考答案**：
| 维度 | 函数式宏 | static inline 函数 | static 函数 |
|---|---|---|---|
| 处理阶段 | 预处理（文本替换） | 编译期 | 编译期 |
| 类型检查 | 无（易出隐蔽 bug） | 有 | 有 |
| 副作用 | 参数可能重复求值 | 无 | 无 |
| 调试 | 无法单步 | 可调试（取决于是否内联） | 可调试 |
| 适用场景 | 编译期常量、位操作宏、拼接 token（#、##） | 头文件中的短小工具函数 | .c 内部普通函数 |

### A-060 ★★★
嵌入式 C 编码规范（参考 MISRA C 思想）中，最重要的规则方向有哪些？为什么很多规范禁止运行期动态内存分配？

**参考答案**：
**重要规则方向**：
1. **禁止/限制动态内存**：启动后不允许 malloc/free。
2. **指针纪律**：指针初始化、free 后置 NULL、禁用指针算术超出数组范围、禁止隐式指针转换。
3. **类型安全**：显式类型转换、避免有符号/无符号隐式转换、禁用隐式窄化。
4. **控制流**：函数单一出口、限制 goto（仅允许用于统一错误清理）、禁止递归（栈不可控）。
5. **防御式编程**：检查所有外部输入与返回值、断言只用于逻辑错误。
6. **可预测性**：禁用未定义/实现定义行为依赖（移位、有符号溢出、函数指针转换）。
**禁止运行期堆分配的原因**：① 碎片化导致"总空闲够但单块不够"的分配失败，且失败时机不可预测；② 失败处理路径难以全覆盖；③ malloc 非线程安全（或需加锁引入不确定性），中断上下文不可调用；④ 无法静态分析最坏内存占用。替代方案：静态分配、内存池/分区分配（fixed-size block pool）、栈深度静态分析工具。
**学习提示**：面试讲出"内存池替代堆"并说明碎片原理，是高级岗位的关键区分点；相关编程题见 A-068。
**知识点**：C 语言-编码规范

### A-061 ★
编写函数判断当前 CPU 是大端还是小端（至少给出两种方法）。

**参考答案**：
```c
#include <stdint.h>

/* 方法一：union 共享内存 */
int is_little_endian_1(void) {
    union { uint32_t i; uint8_t c; } u = { .i = 1 };
    return u.c == 1;            /* 最低地址字节为 1 → 小端 */
}

/* 方法二：指针重解释 */
int is_little_endian_2(void) {
    uint16_t x = 1;
    return *(uint8_t *)&x == 1; /* 取低地址字节判断 */
}
```
**解析**：两种方法本质相同——用一个多字节对象的最低地址字节探测字节存放顺序。**注意**：方法二存在严格的别名（strict aliasing）问题，用 union 方式（方法一）在 C 标准下更合规；memcpy 探测法则是完全合规的第三种选择。返回值约定要在注释中写清楚。
**知识点**：C 语言-大小端

### A-062 ★★
实现一个简易环形缓冲区（ring buffer）：定义结构体、初始化、写入一字节、读取一字节，并说明如何判断空/满。

**参考答案**：
```c
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>

#define RB_SIZE 64u  /* 建议为 2 的幂 */

typedef struct {
    uint8_t  buf[RB_SIZE];
    volatile uint16_t head;  /* 写位置 */
    volatile uint16_t tail;  /* 读位置 */
} ring_buffer_t;

void rb_init(ring_buffer_t *rb) { rb->head = 0; rb->tail = 0; }

static inline uint16_t rb_next(uint16_t pos) {
    return (uint16_t)((pos + 1u) & (RB_SIZE - 1u)); /* 2 的幂取模优化 */
}

bool rb_is_empty(const ring_buffer_t *rb) { return rb->head == rb->tail; }

bool rb_is_full(const ring_buffer_t *rb) {
    return rb_next(rb->head) == rb->tail;
}

bool rb_put(ring_buffer_t *rb, uint8_t data) {
    if (rb_is_full(rb)) return false;
    rb->buf[rb->head] = data;
    rb->head = rb_next(rb->head);
    return true;
}

bool rb_get(ring_buffer_t *rb, uint8_t *data) {
    if (rb_is_empty(rb)) return false;
    *data = rb->buf[rb->tail];
    rb->tail = rb_next(rb->tail);
    return true;
}
```
**解析**：
- **空/满判断**：只有一个 head/tail 指针时两者相等既可能是空也可能是满。两种解法：① 留一格不存（本答案，head 追上 tail 即满，牺牲 1 字节）；② 额外维护 count 计数（满容量可用，但多一个需原子保护的变量）。
- **工程要点**：单生产者-单消费者（串口 ISR 写 + 主循环读）场景下，head/tail 用 volatile + 单向递增的写法可做到免锁（写者只改 head、读者只改 tail）；容量取 2 的幂可用位与替代取模。
- 这也是串口不定长接收的标准解法，面试笔试双高频。
**知识点**：C 语言-环形缓冲区

### A-063 ★★
找出以下代码的 bug 并改正：
```c
char *dup_str(const char *s) {
    char buf[64];
    strncpy(buf, s, sizeof(buf));
    return buf;
}
```

**参考答案**：
**Bug 分析**（共 3 个）：
1. **返回栈内存地址**：buf 生命周期随函数结束，调用者拿到悬垂指针——致命错误。
2. **strncpy 不保证 '\0' 结尾**：s 长度 ≥ 64 时 buf 无终止符，后续 puts/strlen 越界读。
3. **未检查入参 s 为 NULL**；也未处理长度超限的语义（截断还是失败需明确）。

**修正版（由调用者提供缓冲区，最嵌入式友好）**：
```c
#include <string.h>
#include <stdbool.h>

/* 返回 true 成功；false 参数非法或截断 */
bool dup_str(char *dst, size_t dst_size, const char *src) {
    if (dst == NULL || src == NULL || dst_size == 0u) {
        return false;
    }
    size_t len = strlen(src);
    if (len >= dst_size) {          /* 放不下（含 '\0'），拒绝而非截断 */
        return false;
    }
    memcpy(dst, src, len + 1u);     /* 连同 '\0' 一起拷贝 */
    return true;
}
```
**解析**：嵌入式规范首选"调用者给缓冲区"，避免堆分配与所有权问题。若坚持堆版本（返回 malloc），必须在注释/文档中声明调用者负责 free。
**知识点**：C 语言-字符串安全 / 栈生命周期

### A-064 ★★★
以下代码意图为"截取 src 前 n 个字符到 dst"，请找出 bug：
```c
void copy_n(char *dst, const char *src, int n) {
    int i;
    for (i = 0; i <= n; i++)
        dst[i] = src[i];
}
```

**参考答案**：
**Bug 分析**：
1. **off-by-one**：`i <= n` 拷贝了 n+1 个字符（含 src[n]，可能越界读 src），且未保证 dst 以 '\0' 结尾。
2. **无参数校验**：dst/src 可能为 NULL，n 可能为负（int 类型）。
3. **无长度上限关联 dst 容量**：即使拷 n 个字符也可能写爆 dst。
4. **未利用标准库**：语义为"安全截断拷贝"，应封装 strncpy + 强制结尾。

**修正版**：
```c
#include <string.h>
#include <stdbool.h>
#include <stddef.h>

bool copy_n(char *dst, size_t dst_size, const char *src, size_t n) {
    if (dst == NULL || src == NULL || dst_size == 0u) return false;
    if (n >= dst_size) n = dst_size - 1u;   /* 留 1 字节给 '\0' */
    strncpy(dst, src, n);
    dst[n] = '\0';                           /* strncpy 不补 '\0'，手动补 */
    return true;
}
```
**解析**：off-by-one 是缓冲区溢出 CVE 的第一大来源。笔试中看到"边界符号（< 与 <=）+ 结尾符 + 参数校验"三处都要主动检查。
**学习提示**：凡是写拷贝/填充循环，先在草稿上画一格数组标注下标 0 和 n-1，确认每个下标访问都不越界再动笔。
**知识点**：C 语言-边界检查

### A-065 ★★★
实现 `my_memmove(void *dst, const void *src, size_t n)`，正确处理内存重叠。

**参考答案**：
```c
#include <stddef.h>

void *my_memmove(void *dst, const void *src, size_t n) {
    unsigned char *d = (unsigned char *)dst;
    const unsigned char *s = (const unsigned char *)src;

    if (d == s || n == 0u) {
        return dst;                       /* 同址或零长度，直接返回 */
    }

    if (d < s) {
        /* 目标在源之前：正向拷贝（先拷低地址） */
        for (size_t i = 0; i < n; i++) {
            d[i] = s[i];
        }
    } else {
        /* 目标在源之后（可能重叠）：反向拷贝（先拷高地址） */
        for (size_t i = n; i > 0u; i--) {
            d[i - 1u] = s[i - 1u];
        }
    }
    return dst;
}
```
**解析**：
- **核心思想**：dst < src 时正向拷贝安全（写 d[i] 时 s[i] 尚未被破坏）；dst > src 时若重叠，正向拷会先覆盖待读的源字节，必须从尾部反向拷。这正是标准库 memmove 的实现逻辑。
- **面试常考变体**：让候选人口述"为什么 memcpy 在重叠时是 UB"、memmove 为什么比 memcpy 略慢（多一次比较和分支，可能牺牲向量化）。
- 返回 dst 保持与 memcpy 签名一致（支持链式调用）。
**学习提示**：画一张内存图（src 与 dst 部分重叠）走一遍两个拷贝方向，是彻底理解的最快方式；该题在协议"丢弃已处理帧头、剩余数据前移"场景直接实用。
**知识点**：C 语言-memmove / 内存重叠

### A-067 ★★
编写函数统计一个 32 位无符号整数二进制表示中 1 的个数（两种方法：逐位法与 Brian Kernighan 法）。

**参考答案**：
```c
#include <stdint.h>

/* 方法一：逐位检查 32 次 */
int count_bits_loop(uint32_t v) {
    int count = 0;
    while (v) {
        count += (int)(v & 1u);
        v >>= 1;
    }
    return count;
}

/* 方法二：Brian Kernighan 法，仅循环"1 的个数"次 */
int count_bits_bk(uint32_t v) {
    int count = 0;
    while (v) {
        v &= (v - 1u);   /* 每次消除最低位的 1 */
        count++;
    }
    return count;
}
```
**解析**：
- `v &= v - 1` 的原理：v-1 会把 v 最低位的 1 变 0、其后所有 0 变 1，相与即消去最低位的 1。循环次数 = 1 的个数，对稀疏 1 的数更快。
- `v & 1u` 加 unsigned 字面量、循环内用 `v >>= 1` 对无符号数右移补 0 行为确定。
- **延伸**（面试加分）：查表法（预存 256 个字节的 popcount 表，分 4 段查）以空间换时间；编译器内建 `__builtin_popcount(v)`；硬件指令（ARM NEON 的 CNT/CSSC、x86 POPCNT）。
- 实际工程应用：位图状态管理、汉明重量（Hamming weight）CRC/纠错、协议位标志统计。
**知识点**：C 语言-位操作 / 算法

## 七、设计题（A-068 ~ A-070）

### A-068 ★★★
为一个内存受限的嵌入式系统设计一个**轻量级固定块内存池（memory pool）**，要求：无碎片、O(1) 分配释放、可静态初始化。给出接口设计与核心实现思路，并说明如何检测双重释放。

**参考答案**：

**设计要点**：
1. **固定块大小**：池内所有块同尺寸，天然无碎片，分配/释放只是链表操作。
2. **空闲链表嵌入块内**：空闲块自身的内存用来存 next 指针——零额外 RAM 开销（空闲块被取走时该指针位置随数据被覆盖，无副作用）。
3. **静态分配**：数组定义，无 malloc。

**接口与实现**：
```c
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>

#define POOL_BLOCKS 32u
#define BLOCK_SIZE  32u        /* 必须 >= sizeof(void*) */

typedef struct {
    uint8_t  mem[POOL_BLOCKS][BLOCK_SIZE];
    void    *free_list;        /* 空闲块链表头 */
} mem_pool_t;

void pool_init(mem_pool_t *p) {
    p->free_list = NULL;
    for (uint32_t i = 0; i < POOL_BLOCKS; i++) {
        void **blk = (void **)p->mem[i];
        *blk = p->free_list;   /* 头插法串成链 */
        p->free_list = blk;
    }
}

void *pool_alloc(mem_pool_t *p) {
    if (p->free_list == NULL) return NULL;      /* 池耗尽，可预测失败 */
    void *blk = p->free_list;
    p->free_list = *(void **)blk;               /* 弹出链表头 */
    return blk;
}

void pool_free(mem_pool_t *p, void *blk) {
    void **b = (void **)blk;
    *b = p->free_list;                          /* 头插回链表 */
    p->free_list = b;
}
```

**双重释放检测思路**（任选其一，逐步加强）：
1. **遍历检测（简单）**：释放前遍历 free_list 看块是否已在其中——O(n)，适合调试版。
2. **魔术字（magic number）**：块被分配时在头部写 4 字节 MAGIC；释放时校验并改写为 FREED 标记；再次释放时发现是 FREED 即报错。要求 BLOCK_SIZE 预留头部，业务可用大小 = BLOCK_SIZE - 头部。
3. **位图（bitmap）**：额外维护 POOL_BLOCKS 位的分配状态图 + 块号映射（要求池地址对齐），释放前查位图状态，O(1) 且开销最小，生产推荐。

**讨论要点（体现架构能力）**：
- 多任务环境：pool_alloc/free 需短临界区保护（关中断或互斥锁），操作仅 O(1)，临界区极短。
- 池耗尽的策略：返回 NULL 由调用者处理 / 断言（开发期）/ 统计水位（max_used）用于容量规划。
- 变长需求：多规格池分级（8/16/32/64 字节各一个池，slab 思想），仍是全静态。
**学习提示**：本题是"为什么禁止 malloc 却仍需要动态性"的标准答案，面试二面系统设计高频出现，务必亲手写一遍并测试。
**知识点**：C 语言-内存池设计

### A-069 ★★★
用 C 语言设计一个**表驱动状态机框架**，用于解析带帧头的数据协议（如 `0xAA | LEN | DATA... | CHECKSUM`），要求：结构清晰、易扩展、可处理字节流逐字节输入与帧错位。

**参考答案**：

**设计思路**：
1. **状态定义**：WAIT_HEAD → WAIT_LEN → WAIT_DATA → WAIT_CHECK，逐字节推进。
2. **表驱动**：状态转移表 `state_table[当前状态][事件]`（事件 = 收到的字节类别），代替 switch-case 嵌套，新增状态只改表。
3. **上下文结构体**：状态、缓冲区、期望长度、计数器、校验和全部封装，支持多实例并发解析（多路串口各自一个 context）。

**实现骨架**：
```c
#include <stdint.h>
#include <stdbool.h>

#define FRAME_MAX 256u

typedef enum { ST_HEAD, ST_LEN, ST_DATA, ST_CHECK } frame_state_t;

typedef struct {
    frame_state_t state;
    uint8_t  buf[FRAME_MAX];
    uint16_t idx;
    uint16_t expect_len;      /* DATA 字节数 */
    uint8_t  checksum;
} frame_parser_t;

void parser_init(frame_parser_t *p) { p->state = ST_HEAD; p->idx = 0; }

/* 逐字节喂入；返回 true 表示成功解出一帧（在 p->buf/p->expect_len 中） */
bool parser_feed(frame_parser_t *p, uint8_t byte) {
    switch (p->state) {
    case ST_HEAD:
        if (byte == 0xAAu) {
            p->state = ST_LEN;
            p->idx = 0;
            p->checksum = 0u;
        }
        return false;

    case ST_LEN:
        if (byte == 0u || byte > (FRAME_MAX - 1u)) {  /* 非法长度，回到找帧头 */
            p->state = ST_HEAD;
            /* 注意：此处应考虑把当前字节再按帧头判断一次（重同步） */
            return parser_feed(p, byte);  /* 简化处理，见讨论 */
        }
        p->expect_len = byte;
        p->checksum = byte;
        p->state = ST_DATA;
        return false;

    case ST_DATA:
        p->buf[p->idx++] = byte;
        p->checksum ^= byte;                          /* 累计校验（示例用 XOR） */
        if (p->idx >= p->expect_len) p->state = ST_CHECK;
        return false;

    case ST_CHECK:
        if (byte == p->checksum) {
            p->state = ST_HEAD;                       /* 复位，等待下一帧 */
            return true;                              /* 一帧完成 */
        }
        p->state = ST_HEAD;                           /* 校验失败，重新同步 */
        return false;
    }
    return false;
}
```

**讨论要点（面试官期待的深化）**：
1. **重同步（resync）**：错位/误码时不能丢掉已缓冲字节盲目重启——正确做法是把后续字节继续按状态机推进，DATA 状态超长即判定非法；或保存回滚点。通信健壮性的核心问题。
2. **转义（byte stuffing）**：若 DATA 中可能出现 0xAA，需引入转义字节（如 0x7D）或长度前置帧（本方案 LEN 已定界，DATA 不需转义——说清这一点是加分项）。
3. **校验升级**：XOR 检错能力弱，生产应换 CRC8/CRC16（查表实现，见 G 模块）。
4. **多实例**：context 与逻辑分离，一个解析器函数服务 N 路通道。
5. **纯表驱动进阶**：把 switch 换成 `typedef void (*state_handler_t)(frame_parser_t*, uint8_t);` 的函数指针数组，行为完全数据化。
**学习提示**：状态机是嵌入式笔试设计题的第一名考点，串口/I2C/按键消抖/充电管理全用它。建议默写本骨架并自己加一个"转义处理"扩展练习。
**知识点**：C 语言-状态机设计（连接模块 G）

### A-070 ★★
设计一个**通信协议帧格式**用于 MCU 与上位机的可靠串口通信，要求说明每个字段的作用、字节序约定、校验方式选择与容错设计。

**参考答案**：

**帧格式（示例）**：

| 字段 | 长度 | 说明 |
|---|---|---|
| SOF | 1 | 帧头 0x55 0xAA（双字节帧头，降低数据误同步概率） |
| SEQ | 1 | 帧序号，滚动 +1，用于应答关联与丢帧检测 |
| CMD | 1 | 命令字，区分指令类型 |
| LEN | 2 | payload 字节数（**明确声明小端**） |
| PAYLOAD | 0~N | 数据 |
| CRC16 | 2 | 对 SOF~PAYLOAD 全部字节计算（CCITT 查表法） |

**设计论证（按点作答）**：
1. **双字节帧头**：单字节帧头在 payload 中出现概率 1/256，双字节降到 1/65536，显著减少误同步。
2. **长度前置**：接收方先知道边界，处理粘包/半包只需按长度切割；LEN 本身纳入 CRC 防篡改。
3. **字节序显式约定**：文档写明小端，上位机与 MCU 端各自做本机序↔协议序转换，绝不隐式依赖。
4. **校验选择**：XOR/加法校验检错弱；CRC16-CCITT 查表实现 O(1)/字节，代码 ~200 字节，是串口可靠性的性价比最优解；更高要求（强干扰）用 CRC32 或加交织。
5. **容错机制**：① CRC 失败丢弃整帧并请求重传（NACK + SEQ）；② 超时重传（发送方定时器）；③ 接收状态机重同步（见 A-069）；④ 帧序号去重防重放重复执行。
6. **扩展性**：预留协议版本号字段（VER），或 CMD 高位作版本/方向标志，向后兼容升级。

**解析**：本题综合考查协议设计、字节序、校验、容错四个维度，回答时**主动给出一张帧格式表 + 每个设计决策的理由**，比只罗列字段高一档。CRC 具体实现与更多协议题见模块 G。
**知识点**：C 语言-协议设计（连接模块 G）
