## 一、单项选择题（B-001 ~ B-022）

### B-001 ★
算法的时间复杂度 O(f(n)) 描述的是：
A. 算法的精确运行时间（毫秒）
B. 运行时间随输入规模 n 增长的渐近上界趋势
C. 算法占用的内存大小
D. 代码行数与 n 的关系

**答案：B**
**解析**：大 O 刻画增长趋势量级，忽略常数与低阶项（3n²+10n → O(n²)）。A 错——精确时间依赖硬件；C 是空间复杂度。嵌入式面试常追问：O(1) 不代表快，只代表不随 n 增长（如哈希查找一次可能比小数组线性扫描还慢）。
**知识点**：算法-复杂度分析

### B-002 ★
对含 n 个元素的**有序**数组二分查找，最坏情况比较次数的数量级是：
A. O(1)
B. O(log n)
C. O(n)
D. O(n log n)

**答案：B**
**解析**：每轮把范围折半，最坏 ⌈log₂n⌉+1 次。两个关键词考点：① 前提是**有序**；② 若是链表则不能二分（不支持随机访问）。嵌入式应用：在 Flash 中的有序校准表/命令表查找。
**知识点**：算法-二分查找

### B-003 ★
与数组相比，链表的核心优势是：
A. 支持随机访问
B. 已知节点位置时插入/删除 O(1)，无需移动后续元素
C. 内存利用率一定更高
D. 缓存友好性更好

**答案：B**
**解析**：链表插入删除只改指针；数组插入删除需移动元素 O(n)。A/D 恰是数组的优势（连续内存、随机访问、cache 命中率高）；C 错——链表每个节点有指针开销，且频繁 malloc 产生碎片。
**知识点**：数据结构-数组与链表

### B-004 ★★
单链表 `1→2→3→4` 经"三指针迭代反转"后，原头节点指向：
A. NULL（成为尾节点）
B. 节点 2
C. 节点 4
D. 自身

**答案：A**
**解析**：反转后链表为 `4→3→2→1`，原头节点 1 变为尾节点，其 next 必须置 NULL，否则遍历时死循环。链表反转代码的两大经典 bug：头节点 next 未置 NULL、临时指针保存顺序错导致断链（见 B-046）。
**知识点**：数据结构-链表反转

### B-005 ★
快速排序的平均与最坏时间复杂度分别是：
A. O(n log n) / O(n log n)
B. O(n log n) / O(n²)
C. O(n²) / O(n log n)
D. O(n log n) / O(n)

**答案：B**
**解析**：平均每次划分近似均衡 O(n log n)；最坏（每次 pivot 都是最大/最小，如对已有序数组取首元素为 pivot）退化为 O(n²)。缓解手段：随机选 pivot、三数取中。嵌入式注意：快排递归深度 O(log n)~O(n)，深递归有栈溢出风险。
**知识点**：算法-快速排序

### B-006 ★★
关于排序算法的**稳定性**，以下说法正确的是：
A. 稳定性指排序不会出错
B. 相等元素的相对先后顺序在排序后保持不变即为稳定
C. 快速排序是稳定排序
D. 稳定性只对链表有意义

**答案：B**
**解析**：稳定排序（冒泡、插入、归并）适合多关键字排序（先按 B 排再按 A 稳定排，B 的次序保留）。C 错——快排的跨越交换会打乱相等元素顺序；不稳定排序还有简单选择排序和堆排序。
**知识点**：算法-排序稳定性

### B-007 ★
哈希表发生冲突时，"链地址法（拉链法）"的做法是：
A. 顺延到下一个空槽
B. 把冲突元素组织到该桶的链表中
C. 丢弃冲突元素
D. 直接扩容一倍

**答案：B**
**解析**：链地址法每个桶挂链表（或动态数组），冲突即尾插。A 是开放定址法（线性探测），容易产生"聚集"（clustering）降低性能。嵌入式常用简化版：**固定桶数 + 固定长度小数组**，避免动态分配。
**知识点**：数据结构-哈希表

### B-008 ★★
一棵完全平衡的二叉搜索树（BST）中查找的最坏复杂度是：
A. O(1)
B. O(log n)
C. O(n)
D. O(n²)

**答案：B**
**解析**：平衡 BST 高度 ≈ log₂n。但**普通 BST 按有序序列插入会退化成链表**（高度 n，查找 O(n)）——这是引出 AVL/红黑树的动机。嵌入式冷知识：Linux 内核大量使用红黑树（CFS 调度器、epoll、内存管理 vma），面试可主动提及。
**知识点**：数据结构-BST

### B-009 ★★
含 n 个元素的**二叉堆**（优先队列）执行一次插入的复杂度是：
A. O(1)
B. O(log n)
C. O(n)
D. O(n log n)

**答案：B**
**解析**：插入放到末尾后"上浮"（sift-up），最多交换树高次。取最值（堆顶）是 O(1)，弹出最值需"下沉"也是 O(log n)。应用：RTOS 中按截止时间/优先级就绪队列、Top-K 问题（见 B-016）。
**知识点**：数据结构-堆

### B-010 ★★
循环队列大小为 M，front 指向队头、rear 指向下一个写入位置（留一格判满）。当前队列元素个数的计算公式是：
A. rear - front
B. (rear - front + M) % M
C. (front - rear + M) % M
D. M - rear + front

**答案：B**
**解析**：rear 可能已回绕小于 front，加 M 再取模统一处理两种情况。A 只在未回绕时正确。配套公式：判满 `(rear+1)%M == front`，判空 `rear == front`。该结构是串口收发的标准件（模块 A-062 的计算版考点）。
**知识点**：数据结构-循环队列

### B-011 ★
以下哪个场景**不适合**用栈（stack）？
A. 函数调用与返回地址保存
B. 括号匹配检查
C. 表达式求值（中缀转后缀）
D. 按到达顺序处理任务（FIFO）

**答案：D**
**解析**：栈是 LIFO（后进先出）；D 要求 FIFO，应使用队列。A 是硬件栈的本质用途；B/C 是栈的经典软件应用。嵌入式实例：在中断嵌套中保存/恢复上下文靠的就是 MSP/PSP 栈。
**知识点**：数据结构-栈与队列

### B-012 ★★
用快慢指针（slow 每次走 1 步，fast 每次走 2 步）遍历单链表，当 fast 到达末尾时，slow 停在：
A. 链表第 1 个节点
B. 链表中点（偶数长度时为中间偏左/偏右取决于循环条件）
C. 链表倒数第 2 个节点
D. 链表尾节点

**答案：B**
**解析**：fast 速度是 slow 两倍，fast 走完全程时 slow 走一半，即中点。该技巧衍生出：找中点（链表二分）、判环（Floyd 判圈，fast 追上 slow 即有环）、找倒数第 k 个（fast 先走 k 步）。
**知识点**：算法-快慢指针

### B-013 ★★
Floyd 判圈算法检测链表是否有环的判定条件是：
A. fast 先到达 NULL
B. slow 与 fast 相遇
C. slow 到达 NULL
D. fast 与 slow 都走了 n 步

**答案：B**
**解析**：有环时 fast 必然在环内"套圈"追上 slow（速度差 1，环长有限）；无环时 fast 先到 NULL。注意实现细节：循环条件 `while (fast && fast->next)`，先移动后比较，且初始两者都在头部时需错开一步。扩展：相遇后把一个指针放回头部同速前进，再次相遇点即**环入口**（推导见 B-047）。
**知识点**：算法-链表环

### B-014 ★★
维护数据流的"前 K 大元素"（K 远小于 n），最优的空间与时间方案是：
A. 全部排序后取前 K，O(n log n) / O(n)
B. 大顶堆存全部元素
C. 容量为 K 的小顶堆：新元素大于堆顶则替换，O(n log K) / O(K)
D. 链表顺序插入，O(n²) / O(n)

**答案：C**
**解析**：容量 K 的小顶堆堆顶是"当前第 K 大"，比它小的直接丢弃。嵌入式实例：采集系统只上报"最高温度 Top5"、按键消抖统计。空间 O(K) 是关键优势——RAM 受限场景不能全量存。
**知识点**：算法-堆应用

### B-015 ★★
哈希表的"负载因子（load factor）"指的是：
A. 已用桶数 / 总桶数（链地址法中约为元素数/桶数）
B. 表的内存字节数
C. 最长链表长度
D. 冲突次数 / 查找次数

**答案：A**
**解析**：负载因子越高冲突越密，查找退化。通用策略：负载因子超过约 0.75 时扩容（rehash 到 2 倍桶数）。嵌入式变通：桶数固定、评估最坏链长；或用"装填计数 + 上限拒绝"保护内存。
**知识点**：数据结构-哈希表

### B-016 ★
二维数组 `int a[10][20]`（按行存储，每个 int 4 字节），元素 a[0][0] 地址为 0x1000，则 a[3][5] 的地址是：
A. 0x1000 + (3+5)×4
B. 0x1000 + (3×20+5)×4
C. 0x1000 + (5×10+3)×4
D. 0x1000 + 3×5×4

**答案：B**
**解析**：按行存储（C 语言行主序），地址 = 基址 + (行×列数+列)×元素大小 = 0x1000 + 65×4 = 0x1104。该计算在 LCD 帧缓冲寻址、DMA 二维搬运中天天用到。
**知识点**：数据结构-数组寻址

### B-017 ★★
传感器输出与真实值非线性，用"少量标定点 + 分段查表插值"而非直接公式计算，主要原因是：
A. 查表不需要任何计算
B. 避免在 MCU 上执行昂贵的浮点/超越函数，以少量 Flash 换实时性，且便于现场标定修正
C. 查表精度必然更高
D. 公式计算在 C 语言中无法实现

**答案：B**
**解析**：无 FPU 的 Cortex-M0 上一次 `sinf` 可能数百到上千周期，而查表+一次线性插值只需几十周期；标定点由产线校准写入 Flash，还便于修正器件离散性。A 错——仍需插值计算；C 错——精度取决于标定密度，查表只是工程权衡。
**知识点**：嵌入式算法-查表法

### B-018 ★★
滑动窗口（sliding window）技术的基本特征是：
A. 每次重新遍历整个数组
B. 窗口两端指针单调前进，增量更新窗口内统计量，整体 O(n)
C. 必须配合快排使用
D. 只能用于固定长度窗口

**答案：B**
**解析**：单调性是关键——左右边界都不回头，每个元素最多进出窗口各一次。应用：ADC 采样滑动平均滤波（固定窗）、协议流控窗口（滑动窗口协议）、序列异常检测（可变窗）。D 错——可变窗是该技术的进阶形态。
**知识点**：算法-滑动窗口

### B-019 ★
对基本有序的数据排序，实践中最快（比较次数最少）的简单排序是：
A. 冒泡排序
B. 插入排序
C. 选择排序
D. 快速排序（取首元素为 pivot）

**答案：B**
**解析**：插入排序对基本有序数据接近 O(n)（每个元素只比较一两次即就位）。D 恰恰最差——有序数据 + 首元素 pivot 退化 O(n²)。工程直觉：数据量小（几十个）或基本有序时，插入排序常胜过 O(n log n) 算法（无递归开销、cache 友好），这也是很多标准库在小区间上改用插入排序的原因。
**知识点**：算法-排序选型

### B-020 ★★
归并排序的空间复杂度是：
A. O(1)
B. O(log n)
C. O(n)
D. O(n log n)

**解析**：归并需要与原数组等长的辅助数组 O(n)（链表归并可 O(1) 额外空间）。这是归并在 RAM 受限嵌入式系统中的主要缺点，但它**稳定**且最坏仍是 O(n log n)、适合外排序（大文件分段排序再归并）。
**答案**：C
**知识点**：算法-归并排序

### B-021 ★
状态压缩：用一个 32 位变量的 32 个 bit 记录 32 路开关状态，相比 32 个 uint8 数组，主要收益是：
A. 访问速度必然更快
B. 存储 4 字节 vs 32 字节，且可用一条指令批量判断（与/或/移位）
C. 代码一定更短
D. 没有收益

**答案：B**
**解析**：位图（bitmap）是嵌入式状态管理的基本功：`if ((status & MASK) == MASK)` 一条与运算同时判断多路状态。A 表述过强——对单个 bit 的读写在现代 MCU 上与字节访问相差不大，真正优势在**批量逻辑判断与空间**。
**知识点**：嵌入式算法-位图

### B-022 ★★
二分查找"第一个 ≥ x 的元素位置"（lower bound）与"等于 x 的任一位置"的区别在于循环内的：
A. 循环变量初始值
B. 收缩边界与记录答案的方式：找到满足条件的位置时不停下来，而是继续收缩左边界
C. 是否需要先排序
D. 是否需要递归

**答案：B**
**解析**：普通二分命中即返回；边界变体（lower_bound / upper_bound）命中后继续向一侧收缩以锁定边界。写法要点：`lo=0, hi=n`（左闭右开），`while (lo < hi)`，`mid=(lo+hi)/2`，条件成立时 `hi=mid` 否则 `lo=mid+1`。变体二分是笔试高频题，边界写错即死循环或漏解（完整实现见 B-049）。
**知识点**：算法-二分变体

### B-023 ★
以下哪些操作是 O(1)？（多选）
A. 数组按下标读取 a[i]
B. 单链表头部插入节点
C. 循环队列入队（未满时）
D. 单链表按下标读取第 i 个节点
E. 链表尾部插入（仅持有头指针时）

**答案：A、B、C**
**解析**：A 数组随机访问 O(1)；B 头插只改两个指针；C 环形队列写入后移指针。D 需从头遍历 O(n)；E 同样需遍历到尾（除非维护尾指针或用循环链表）。RTOS 任务就绪队列常用"链表头插 O(1)"实现快速入队。
**知识点**：数据结构-操作复杂度

### B-024 ★★
以下排序中属于**稳定**排序的有：（多选）
A. 冒泡排序
B. 插入排序
C. 简单选择排序
D. 归并排序
E. 堆排序

**答案**：A、B、D
**解析**：冒泡/插入只在相邻（或已排序区间内）比较交换相等元素不动；归并相等时优先取左半部分。选择排序的远距离交换、堆排序的堆顶弹出交换都会打乱相等元素相对次序。记忆口诀：**"冒插归"稳定，"选快堆"不稳定**。
**知识点**：算法-排序稳定性

### B-025 ★
链表相对数组的特点，正确的有：（多选）
A. 节点内存可不连续，适合内存碎片化环境
B. 天然支持动态增长，无需预估容量
C. 随机访问 O(n)
D. 每个节点有指针空间开销
E. cache 命中率通常优于数组

**答案**：A、B、C、D
**解析**：E 恰好相反——链表节点散布内存，cache 局部性差。嵌入式权衡：裸机高可靠性系统倾向"数组实现链表"（节点放在静态池中，用下标代替指针，见 A-068 内存池 + 该思想的组合），兼得链表逻辑与静态分配。
**知识点**：数据结构-链表特性

### B-026 ★★
关于二叉树的遍历，正确的有：（多选）
A. 前序遍历顺序是"根-左-右"
B. 中序遍历 BST 得到升序序列
C. 层序遍历借助队列实现
D. 已知前序和中序可以唯一重建二叉树
E. 已知前序和后序一定可以唯一重建二叉树

**答案**：A、B、C、D
**解析**：A/B/C 基本功；D 是经典题（前序定根，中序分割左右子树，递归）。E 错——前序+后序无法区分"只有左子"还是"只有右子"的节点。嵌入式应用：表达式树求值（前序=波兰式）、文件系统/菜单树遍历、设备树解析。
**知识点**：数据结构-二叉树遍历

### B-027 ★★
嵌入式系统选数据结构时倾向静态数组而非动态链表的原因有：（多选）
A. 避免 malloc 的碎片与不可预测失败
B. 内存占用编译期确定，便于 RAM 预算与栈/堆分析
C. 数组无指针开销，访问 cache 友好
D. 静态数组一定不会越界
E. 便于多任务共享无需加锁

**答案**：A、B、C
**解析**：A/B/C 是三大核心理由。D 错——数组越界一样发生且更隐蔽（写穿相邻变量）；E 错——是否需要加锁取决于访问模式而非存储形式。

### B-028 ★★
哈希表适用的场景与局限，正确的有：（多选）

C. 哈希函数需尽量均匀分布以减少冲突

## 五、简答题（B-040 ~ B-045）

### B-040 ★
对比数组与链表，并说明嵌入式系统中的选型原则。

**参考答案**：
| 维度 | 数组 | 链表 |
|---|---|---|
| 随机访问 | O(1) | O(n) |
| 插入删除 | O(n)（移动元素） | O(1)（已知位置） |
| 内存 | 连续、需预估容量 | 离散、按需分配、指针开销 |
| cache | 友好 | 不友好 |
| 越界风险 | 有且隐蔽 | 相对可控（指针为 NULL 可检测） |
**嵌入式选型原则**：
1. 优先静态数组/数组实现的结构（RAM 可预算、无碎片）；
2. 高频增删用"静态节点池 + 下标链"（数组链表）替代 malloc 链表；
3. 大缓冲用环形缓冲区（串口/LCD/日志）；
4. 只在小数据量、低频路径上才考虑真正动态结构。
**知识点**：嵌入式-数据结构选型

### B-041 ★★
简述哈希表的工作原理、冲突解决方法与扩容机制。

**参考答案**：
1. **原理**：key 经哈希函数映射为桶下标，桶内存储键值，实现平均 O(1) 查找/插入/删除。
2. **冲突解决**：① 链地址法（桶挂链表，实现简单、删除方便、负载因子可 >1）；② 开放定址法（线性/平方探测、双重哈希——无指针开销、cache 友好，但删除需墓碑标记且负载因子须 <0.7 防聚集）；③ 完美哈希（键集合固定时构造无冲突映射，如命令字连续则直接数组下标）。
3. **扩容（rehash）**：负载因子超阈值（常用 0.75）时分配 2 倍桶数组、全部元素重新哈希搬迁，单次 O(n) 但摊还 O(1)。嵌入式注意：扩容的瞬时内存峰值与不可预测性不可接受时，采用固定桶 + 限长策略，或用"预分配 + 上限拒绝"。
4. **哈希函数要求**：分布均匀、计算快、确定性（嵌入式常见：除留余数、FNV-1a、djb2 字符串哈希）。
**知识点**：数据结构-哈希表

### B-042 ★★
简述快速排序的过程、最坏情形与工程改进。

**参考答案**：
1. **过程**：选一个 pivot，一趟 partition 把小于 pivot 的放左、大于的放右（双指针交换法或挖坑法），再对左右两段递归。
2. **复杂度**：平均 O(n log n)（划分均衡）；最坏 O(n²)（划分极度不均，如有序输入 + 首元素 pivot）；空间 O(log n) 递归栈（最坏 O(n)）。
3. **工程改进**：① pivot 三数取中/随机化；② 小区间（<10~16 个）切换插入排序；③ 尾递归优化控制栈深；④ 嵌入式替代：数据量小直接插入/冒泡，或用非递归快排（显式栈）避免栈溢出；要稳定/最坏可控则用归并（牺牲空间）或堆排序。
**知识点**：算法-快排

### B-043 ★
为什么嵌入式开发中"查表法"被大量使用？举出至少三个应用实例。

**参考答案**：
**原因**：① 无 FPU/弱 MCU 上避免浮点与超越函数（sin/cos/log）的昂贵计算；② 时间确定性强（无分支深浅差异），利于硬实时；③ 表可在产线标定，吸收器件离散性；④ 用 Flash 换 RAM 和 CPU 时间，符合嵌入式资源权衡哲学。

### B-044 ★★
解释滑动窗口思想，并给出两个嵌入式应用。

**参考答案**：
**思想**：维护一个连续区间 [left, right]，右指针扩张纳入新元素、左指针收缩移除旧元素，两指针单调前进，把暴力 O(n²) 的区间枚举降为 O(n)；窗口内统计量（和、计数、哈希计数）增量更新。
**应用一：ADC 滑动平均滤波**——窗口固定长度 K，每来一个新采样：`sum += new; sum -= buf[idx]; buf[idx] = new; avg = sum/K;`，一次减法一次加法完成更新，用于抑制白噪声（注意：滑动平均是低通滤波，会引入群延迟 K/2 个采样点）。
**应用二：协议限流/防刷**——滑动时间窗内计数（如 100ms 内最多 50 帧），超窗丢帧防总线过载。
**应用三（加分）**：TCP/串口流量控制的滑动窗口协议本质——接收方通告窗口大小控制发送节奏。
**知识点**：算法-滑动窗口

### B-045 ★★

**参考答案**：
1. **前序**（根左右）、**中序**（左根右）、**后序**（左右根）——递归实现三行核心；中序遍历 BST 输出升序序列。
2. **非递归实现**：前/中序用**显式栈**模拟递归（一路压左子，弹出访问，转右子）；后序用"根右左"的反转或双栈法。
3. **层序遍历**（BFS）用**队列**：根入队，出队访问，左右子依次入队。
4. **应用对应**：前序——序列化/复制树（先建根）；中序——BST 有序输出；后序——表达式树求值/资源释放（先处理子再处理父）；层序——按层级处理（菜单渲染、广度搜索）。
**知识点**：数据结构-遍历

## 六、编程题（B-046 ~ B-053）

### B-046 ★★
迭代法反转单链表，要求 O(n) 时间 O(1) 空间。

**参考答案**：
```c
#include <stddef.h>

typedef struct node {
    int val;
    struct node *next;
} node_t;

node_t *list_reverse(node_t *head) {
    node_t *prev = NULL;
    node_t *cur = head;

    while (cur != NULL) {
        node_t *next = cur->next;  /* 1. 先保存后继 */
        cur->next = prev;          /* 2. 反转当前指针 */
        prev = cur;                /* 3. prev 前进 */
        cur = next;                /* 4. cur 前进 */
    }
    return prev;                   /* prev 即新头节点 */
}
```
**解析**：四步顺序不能乱——先保存 next 再改 cur->next，否则断链丢失后半段。循环结束时 prev 恰好停在最后一个节点。**变体追问**：① 每 k 个一组反转（外层再套一层计数循环）；② 指定区间 [m,n] 反转（找前驱 + 局部反转 + 接回）；③ 递归版（优雅但 O(n) 栈空间，嵌入式不推荐）。递归版一句话：`new_head = reverse(head->next); head->next->next = head; head->next = NULL;`
**知识点**：数据结构-链表反转

### B-047 ★★★
检测单链表是否有环；若有环，返回环的入口节点。

**参考答案**：
```c
typedef struct node {
    int val;
    struct node *next;
} node_t;

/* 返回环入口；无环返回 NULL */
node_t *detect_cycle(node_t *head) {
    node_t *slow = head, *fast = head;

    /* 第一阶段：Floyd 判圈 */
    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) {           /* 相遇，说明有环 */
            /* 第二阶段：找入口 */
            node_t *p = head;
            while (p != slow) {
                p = p->next;
                slow = slow->next;
            }
            return p;                 /* 相遇点即入口 */
        }
    }
    return NULL;                      /* fast 到达 NULL，无环 */
}
```
**解析**：
- **判圈原理**：环内 fast 与 slow 的距离每轮缩小 1，必相遇；无环则 fast 先到 NULL。
- **入口推导**（面试必须会讲）：设头到入口距离 a，入口到相遇点距离 b，环剩余部分长 c。相遇时 slow 走了 a+b，fast 走了 a+b+k(b+c)；由 fast 速度是 2 倍：2(a+b) = a+b+k(b+c) → **a = c + (k-1)(b+c)**，即"从头走 a 步"与"从相遇点走 c + 整数圈"同长——两指针同速前进必在入口相遇。
- 复杂度 O(n) 时间、O(1) 空间（对比哈希法 O(n) 空间）。
**学习提示**：入口推导是面试官验证"是否真理解"的标准追问，建议在纸上画图推一遍。
**知识点**：算法-链表环

### B-048 ★★
合并两个**升序**链表为一个升序链表（不新建节点）。

**参考答案**：
```c
typedef struct node {
    int val;
    struct node *next;
} node_t;

node_t *merge_two_lists(node_t *l1, node_t *l2) {
    node_t dummy = { 0, NULL };       /* 哨兵节点，简化头节点特判 */
    node_t *tail = &dummy;

    while (l1 != NULL && l2 != NULL) {
        if (l1->val <= l2->val) {     /* <= 保证稳定（相等取 l1） */
            tail->next = l1;
            l1 = l1->next;
        } else {
            tail->next = l2;
            l2 = l2->next;
        }
        tail = tail->next;
    }
    /* 拼接剩余部分（至多一条非空） */
    tail->next = (l1 != NULL) ? l1 : l2;
    return dummy.next;
}
```
**解析**：**哨兵/哑节点（dummy）** 是链表题最重要的技巧——消除"结果链表为空"的特判分支。该函数就是归并排序的 merge 步骤；扩展：合并 K 个有序链表可用小顶堆或分治两两合并。稳定性细节（相等取 l1）体现了对稳定排序的理解。
**知识点**：算法-链表合并

### B-049 ★★★
实现 lower_bound：在**升序**数组中返回第一个 ≥ x 的下标；若不存在返回 n。并说明它如何用于"传感器校准表的插值区间查找"。

**参考答案**：
```c
#include <stddef.h>

/* 升序数组 a[0..n-1]，返回第一个 >= x 的下标（可能为 n） */
size_t lower_bound(const int *a, size_t n, int x) {
    size_t lo = 0, hi = n;            /* 左闭右开 [lo, hi) */
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;   /* 防溢出写法 */
        if (a[mid] < x) {
            lo = mid + 1;             /* 答案在右半 */
        } else {
            hi = mid;                 /* mid 可能是答案，保留 */
        }
    }
    return lo;
}
```
**解析**：
- **三个工程细节**：① `lo + (hi-lo)/2` 防止 `lo+hi` 溢出（32 位下标大数组时致命）；② 左闭右开区间 + `hi = mid` 保证"命中不停、继续收缩"，循环不变量清晰不死循环；③ 返回值可为 n，调用者必须检查。
- **插值应用**：校准表 `cal[]`（AD 值升序）→ 实际值。`i = lower_bound(cal, n, adc)` 后，adc 落在区间 [cal[i-1], cal[i]] 内，做线性插值：
`real = y[i-1] + (y[i]-y[i-1]) * (adc - cal[i-1]) / (cal[i] - cal[i-1])`（边界 i=0 或 i=n 时夹取端点）。这就是示波器/万用表/温控产品里的通用标定查找算法。
**学习提示**：lower_bound/upper_bound 的"左闭右开 + 命中不停"写法是二分变体（找左边界/右边界/旋转数组/近似值）的万能模板，务必默写熟练。
**知识点**：算法-二分变体

### B-050 ★★★
在模块 A-062（单字节环形缓冲区）基础上，设计支持**变长帧写入/读取**的环形缓冲区接口（一次搬移一批字节），并处理"写满一半"的场景。

**参考答案**：
```c
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>
#include <string.h>

#define RB2_SIZE 1024u   /* 建议 2 的幂 */

typedef struct {
    uint8_t buf[RB2_SIZE];
    volatile uint16_t write_idx;  /* 总写入字节数（单调递增） */
    volatile uint16_t read_idx;   /* 总读出字节数（单调递增） */
} ring2_t;

static inline uint16_t rb2_used(const ring2_t *rb) {
    return (uint16_t)(rb->write_idx - rb->read_idx);   /* 无符号回绕自动正确 */
}
static inline uint16_t rb2_free(const ring2_t *rb) {
    return (uint16_t)(RB2_SIZE - rb2_used(rb));
}

void rb2_init(ring2_t *rb) { rb->write_idx = 0; rb->read_idx = 0; }

/* 写入 len 字节；空间不足返回 false（不做部分写入） */
bool rb2_write(ring2_t *rb, const uint8_t *data, uint16_t len) {
    if (rb2_free(rb) < len) return false;
    uint16_t w = rb->write_idx & (RB2_SIZE - 1u);      /* 实际物理位置 */
    uint16_t first = (uint16_t)(RB2_SIZE - w);         /* 到缓冲区尾部的连续空间 */
    if (first > len) first = len;
    memcpy(&rb->buf[w], data, first);                  /* 第一段 */
    memcpy(rb->buf, data + first, (size_t)(len - first)); /* 回绕的第二段（可能 0 长度） */
    rb->write_idx = (uint16_t)(rb->write_idx + len);
    return true;
}

/* 读出 len 字节；数据不足返回 false */
bool rb2_read(ring2_t *rb, uint8_t *out, uint16_t len) {
    if (rb2_used(rb) < len) return false;
    uint16_t r = rb->read_idx & (RB2_SIZE - 1u);
    uint16_t first = (uint16_t)(RB2_SIZE - r);
    if (first > len) first = len;
    memcpy(out, &rb->buf[r], first);
    memcpy(out + first, rb->buf, (size_t)(len - first));
    rb->read_idx = (uint16_t)(rb->read_idx + len);
    return true;
}
```
**解析**：
- **单调递增索引 + 掩码取模**是嵌入式环形缓冲的工业标准写法：免取模、免判回绕分支，`used = write - read` 借无符号回绕天然正确（索引需为无符号且缓冲为 2 的幂，注意总字节数回绕前 65536 的量程设计，或用 uint32_t 索引）。
- **两段 memcpy** 处理"数据跨缓冲区尾部"的情况——第一段到尾部、第二段从头开始。
- **拒绝部分写**使"整帧原子性"成立：帧要么完整入队要么不入队，配合帧头+长度字段，读取方 `rb2_read(rb, hdr, 4)` 后再 `rb2_read(rb, payload, hdr.len)`，半包问题消失。
- 单生产者-单消费者时 write_idx 只由写者更新、read_idx 只由读者更新，两个 volatile uint16_t 的读写各自原子（对齐的 16/32 位读写在主流 MCU 上原子），实现免锁。
**学习提示**：这是量产产品串口收发的真实代码形态，比 A-062 的逐字节版高一个工程档次，面试画出"单调索引+两段拷贝"结构图即是强加分。
**知识点**：嵌入式算法-环形缓冲区

### B-051 ★★
传感器校准：`cal_x[]`（AD 值，升序）与 `cal_y[]`（对应真实值）各有 n 个标定点。编写线性插值函数，输入任意 AD 值返回真实值（域外取端点值）。

**参考答案**：
```c
#include <stddef.h>
#include <stdint.h>

float interp(const uint16_t *cal_x, const float *cal_y,
             size_t n, uint16_t adc) {
    if (n == 0u) return 0.0f;
    if (adc <= cal_x[0]) return cal_y[0];            /* 下域外夹取 */
    if (adc >= cal_x[n - 1u]) return cal_y[n - 1u];  /* 上域外夹取 */

    /* 线性查找区间（标定点通常很少，直接线性扫描更优） */
    size_t i = 0;
    while (i < n - 1u && adc > cal_x[i + 1u]) {
        i++;
    }
    /* 在 [cal_x[i], cal_x[i+1]] 之间插值 */
    float t = (float)(adc - cal_x[i]);
    float span = (float)(cal_x[i + 1u] - cal_x[i]);
    return cal_y[i] + (cal_y[i + 1u] - cal_y[i]) * (t / span);
}
```
**解析**：
- **域外夹取**是工程必需——AD 采到略超标定范围的值时不能外推（误差不可控）。
- **查找选型**：标定点通常 <32 个，线性扫描的常数与分支预测都比二分好；点数多时换 lower_bound（B-049），这体现"按数据规模选算法"的工程判断，答出这一点是加分项。
- 进阶：定点化（避免浮点）——用 `(adc - x[i]) * (y[i+1]-y[i]) / (x[i+1]-x[i])` 全整数运算并左移放大保精度。
**知识点**：嵌入式算法-线性插值

### B-052 ★★
实现快速排序（partition 用双指针交换法），并做"小区间切换插入排序"优化。

**参考答案**：
```c
static void swap_int(int *a, int *b) { int t = *a; *a = *b; *b = t; }

static void insertion_sort(int *a, int lo, int hi) {  /* [lo, hi] 闭区间 */
    for (int i = lo + 1; i <= hi; i++) {
        int key = a[i], j = i - 1;
        while (j >= lo && a[j] > key) { a[j + 1] = a[j]; j--; }
        a[j + 1] = key;
    }
}

static int partition(int *a, int lo, int hi) {
    int pivot = a[lo + (hi - lo) / 2];   /* 取中位元素作 pivot，缓解有序输入退化 */
    int i = lo - 1, j = hi + 1;
    for (;;) {
        do { i++; } while (a[i] < pivot);
        do { j--; } while (a[j] > pivot);
        if (i >= j) return j;
        swap_int(&a[i], &a[j]);
    }
}

void quick_sort(int *a, int lo, int hi) {
    while (lo < hi) {
        if (hi - lo < 12) {              /* 小区间切换插入排序 */
            insertion_sort(a, lo, hi);
            return;
        }
        int p = partition(a, lo, hi);
        /* 尾递归优化：先递归小区间，大区间改循环，栈深 O(log n) */
        if (p - lo < hi - p - 1) {
            quick_sort(a, lo, p);
            lo = p + 1;
        } else {
            quick_sort(a, p + 1, hi);
            hi = p;
        }
    }
}
```
**解析**：
- 三个生产级细节：① **pivot 取中位**避免有序输入退化 O(n²)；② **小区间切插入排序**（阈值 8~16）减少递归开销；③ **尾递归消除**（小区间递归、大区间循环）保证栈深 O(log n)——嵌入式上递归栈深失控是真实事故来源。
- Hoare 双指针 partition（`do-while` 前后扫描）比 Lomuto 单向扫描交换次数少。
**知识点**：算法-快排实现

### B-053 ★★
用两个栈实现一个队列，要求均摊 O(1) 的入队/出队。

**参考答案**：
```c
#include <stdbool.h>

#define CAP 32
typedef struct {
    int s1[CAP], s2[CAP];      /* s1: 入队栈  s2: 出队栈 */
    int top1, top2;            /* 栈顶指针，0 表示空 */
} my_queue_t;

void q_init(my_queue_t *q) { q->top1 = 0; q->top2 = 0; }

bool q_push(my_queue_t *q, int v) {          /* 入队：压入 s1 */
    if (q->top1 == CAP) {
        if (q->top2 != 0) return false;      /* s2 非空时不倒腾，直接判满 */
        while (q->top1 > 0) {                /* s1 满且 s2 空：整体倒过去 */
            q->s2[q->top2++] = q->s1[--q->top1];
        }
    }
    q->s1[q->top1++] = v;
    return true;
}

bool q_pop(my_queue_t *q, int *out) {        /* 出队：从 s2 弹 */
    if (q->top2 == 0) {                      /* s2 空：把 s1 全部倒入 s2 */
        while (q->top1 > 0) {
            q->s2[q->top2++] = q->s1[--q->top1];
        }
    }
    if (q->top2 == 0) return false;          /* 两栈皆空：队列空 */
    *out = q->s2[--q->top2];
    return true;
}
```
**解析**：
- **核心思想**：栈负责逆转顺序，经过两次逆转恢复 FIFO 顺序；元素只在"s2 空"时才从 s1 倒入，每个元素一生最多进出各栈一次 → **均摊 O(1)**。
- **考点细节**：只在 s2 清空后才能再次倒入（中途倒入会乱序）；倒栈是 O(n) 但摊还到每次操作是 O(1)。
- **应用**：中断上半部把事件压栈/入队，主循环取出处理——队列结构天然匹配"生产者-消费者"解耦（裸机协作式调度的核心，见 B-054）。
**知识点**：数据结构-栈实现队列

### B-054 ★★★
为一个**无 RTOS 的裸机系统**设计一个"事件驱动消息队列"框架：中断产生事件，主循环消费处理。要求：免动态内存、多事件类型、可统计队列水位。给出结构与核心代码。

**参考答案**：

**结构设计**：
```c
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>

#define EVT_QUEUE_SIZE 32u

typedef enum {
    EVT_UART_RX,        /* 串口收到一帧 */
    EVT_ADC_DONE,       /* ADC 采样完成 */
    EVT_TIMER_TICK,     /* 定时器到期 */
    EVT_KEY_PRESSED,    /* 按键 */
    EVT_TYPE_MAX
} event_type_t;

typedef struct {
    event_type_t type;
    uint32_t     param;      /* 单参数（下标/长度/时间戳） */
} event_t;

typedef struct {
    event_t      q[EVT_QUEUE_SIZE];
    volatile uint8_t head;           /* 消费位置（只主循环写） */
    volatile uint8_t tail;           /* 生产位置（只中断写） */
    uint16_t     max_used;           /* 水位统计 */
    uint16_t     drop_count;         /* 溢出丢弃计数 */
} evt_queue_t;

static evt_queue_t g_eq = { .head = 0, .tail = 0 };

/* ISR 中调用 */
bool evt_post(event_type_t type, uint32_t param) {
    uint8_t next = (uint8_t)((g_eq.tail + 1u) % EVT_QUEUE_SIZE);
    if (next == g_eq.head) {
        g_eq.drop_count++;           /* 队满：丢事件并计数（不得在中断里阻塞） */
        return false;
    }
    g_eq.q[g_eq.tail].type = type;
    g_eq.q[g_eq.tail].param = param;
    g_eq.tail = next;
    return true;
}

/* 主循环调用 */
bool evt_get(event_t *out) {
    if (g_eq.head == g_eq.tail) return false;
    *out = g_eq.q[g_eq.head];
    g_eq.head = (uint8_t)((g_eq.head + 1u) % EVT_QUEUE_SIZE);
    /* 水位统计（仅主循环侧访问，无需加锁） */
    uint16_t used = (uint16_t)((g_eq.tail + EVT_QUEUE_SIZE - g_eq.head)
                               % EVT_QUEUE_SIZE);
    if (used > g_eq.max_used) g_eq.max_used = used;
    return true;
}
```

**主循环框架**：
```c
typedef void (*event_handler_t)(uint32_t param);

/* 命令分发表：按事件类型索引，扩展新事件只加一行 */
static const event_handler_t handler_table[EVT_TYPE_MAX] = {
    [EVT_UART_RX]     = on_uart_frame,
    [EVT_ADC_DONE]    = on_adc_done,
    [EVT_TIMER_TICK]  = on_timer_tick,
    [EVT_KEY_PRESSED] = on_key,
};

int main(void) {
    bsp_init();
    for (;;) {
        event_t ev;
        while (evt_get(&ev)) {                      /* 消费完所有积压事件 */
            if (ev.type < EVT_TYPE_MAX && handler_table[ev.type]) {
                handler_table[ev.type](ev.param);   /* 表驱动分发 */
            }
        }
        __WFI();                                    /* 无事可做，低功耗等待中断 */
    }
}
```

**设计论证（面试讲这些）**：
1. **免锁原理**：单生产者（ISR）-单消费者（主循环），tail 只由写者更新、head 只由读者更新，队列判空判满基于各自可见的一致快照——无需关中断（这是 SPSC 环形队列的标准免锁条件；多生产者则需临界区）。
2. **ISR 极短原则**：中断里只 post 事件（固定几条指令），耗时处理留给主循环——缩短中断延迟、避免嵌套问题。
3. **溢出策略**：ISR 中不能阻塞/等待，只能丢弃+计数；drop_count 与 max_used 是量产现场定位"事件风暴"的关键遥测数据。
4. **表驱动分发**：函数指针数组替代 switch-case，新增事件零逻辑改动（开闭原则的 C 实现）。
5. **演进路线**：换 RTOS 后 evt_post → xQueueSend，主循环 → 任务，框架平滑迁移。
**学习提示**：这套"SPSC 事件队列 + 表驱动 + WFI"是裸机产品的标准骨架，笔试设计题答出免锁分析即达到高级岗水准。
**知识点**：嵌入式-事件驱动框架

### B-055 ★★★
设计一个**掉电安全的运行日志环形存储**方案：RAM 中缓存，周期性刷入内部 Flash，系统重启后可读出最近 N 条日志；Flash 擦写以扇区为单位且寿命有限。

**参考答案**：

**需求拆解**：
1. RAM 环形缓冲收集日志（避免每次 log 都擦写 Flash）；
2. Flash 侧也要"环形"使用以均摊磨损（wear leveling 思想）；
3. 掉电时最多丢失 RAM 中未刷写的少量日志（可接受的窗口要说明）；
4. 重启后能找到日志链的末尾。

**Flash 侧布局**（设每扇区 4KB，预留 2 个扇区循环）：
```
扇区头部（16B）：magic(4B) | seq(4B 全局递增序列号) | count(2B) | crc(2B)
扇区体：紧凑日志条目数组，每条 = {len(1B) | timestamp(4B) | level(1B) | data...}
```

**核心机制**：
1. **追加写（append-only）**：日志只在扇区内向后追加，写满整扇区后擦除"最老的那个扇区"继续写——双扇区轮转即最简 wear leveling；评估寿命：设 1 秒 1 条、每条 32B，4KB 扇区可存 ~127 条，每 ~2 分钟擦一次，1 万次擦写的扇区寿命 ≈ 14 天；改 4 扇区轮转 + 10 秒批量刷 → 寿命数年以上，**必须给出这种量化估算**。
2. **seq 序列号找末尾**：重启后扫描各扇区头部，seq 最大的为"当前扇区"；扇区内从头部 count 与 CRC 校验定位最后一条有效日志（掉电时正在写的最后一条可能 CRC 不过，跳过即可——**这就是掉电安全**：损坏仅限于最后一条，链上历史完好）。
3. **RAM 缓冲 + 批量刷**：RAM 环形缓冲（如 1KB）攒满或定时器到点才执行一次 Flash 写入，把擦写频率压到设计值；紧急级别日志可立即 flush。
4. **读接口**：上位机通过调试口命令读取，或产线工装直接读 Flash，按 seq 排序输出最近 N 条。

**讨论要点（拉开差距）**：
- 为什么不每条直接写 Flash：Flash 擦写粒度大（写前必须擦整扇区）、寿命有限、写期间总线停顿影响实时性；
- 更完善方案：外挂 SPI NOR + littlefs（专为掉电安全的嵌入式文件系统，自带磨损均衡与掉电恢复）；MCU 内部 Flash 方案的优势是零 BOM 成本；
- 数据 vs 日志的区分：关键数据需要双备份 + 序号 + CRC 的 A/B 区方案（比日志要求更严格）。
**学习提示**：本题融合环形结构（B 模块）、Flash 特性（C 模块）、掉电安全设计思想，是"数据结构 × 硬件约束"的综合样板题，面试二面常见。
**知识点**：嵌入式-环形存储设计（连接模块 C）
